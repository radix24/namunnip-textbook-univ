2.1.1왜 상수를 무시하는가

알고리즘의 실행 시간은 컴퓨터, 언어, 컴파일러에 따라 몇 배씩 달라집니다. 그러나 입력 크기 \(n\)이 두 배가 될 때 시간이 두 배인지 네 배인지는 그런 것과 무관한 알고리즘 자체의 성질입니다. 그래서 상수배와 작은 항을 무시하고 "얼마나 빨리 자라는가"만 비교합니다.

정의 2.1.1 (점근 표기)

\(f = O(g)\): \(\exists C > 0,\ \exists n_0,\ \forall n \ge n_0,\ |f(n)| \le C|g(n)|\). (위로 눌림)

\(f = \Omega(g)\): \(\exists C > 0,\ \exists n_0,\ \forall n \ge n_0,\ |f(n)| \ge C|g(n)|\). (아래로 받침)

\(f = \Theta(g)\): \(f = O(g)\)이고 \(f = \Omega(g)\). (같은 빠르기)

예제 2.1.2

\(f(n) = 3n^2 + 10n + 5\)가 \(\Theta(n^2)\)임을 보여라.

풀이. \(n \ge 1\)이면 \(10n \le 10n^2\), \(5 \le 5n^2\)이라 \(f \le 18n^2\) (\(C = 18\), \(n_0 = 1\)). 또 \(f \ge 3n^2\). 따라서 \(\Theta(n^2)\). 상수 \(C\)와 \(n_0\)를 구체적으로 제시하는 것이 정의에 따른 증명입니다.

2.1.2극한으로 판정하기

정리 2.1.3

\(L = \lim_{n\to\infty}\frac{f(n)}{g(n)}\)이 존재할 때 (a) \(0 < L < \infty\)이면 \(f = \Theta(g)\). (b) \(L = 0\)이면 \(f = O(g)\)이지만 \(\Theta\)는 아님(\(f = o(g)\)). (c) \(L = \infty\)이면 \(f = \Omega(g)\)이지만 \(O\)는 아님.

(a)의 증명.극한의 정의로 \(n \ge n_0\)에서 \(\frac L2 \le \frac fg \le 2L\). ∎

로피탈 정리와 함께 쓰면 표준 순서가 나옵니다.

\[1 \ll \log n \ll \sqrt n \ll n \ll n\log n \ll n^2 \ll n^3 \ll 2^n \ll n! \ll n^n.\]

(\(f \ll g\)는 \(\frac fg \to 0\).) 예: \(\frac{\log n}{n^\varepsilon} \to 0\) (어떤 \(\varepsilon > 0\)에도), \(\frac{n^k}{2^n} \to 0\) (어떤 \(k\)에도), \(\frac{2^n}{n!} \to 0\) (\(\frac{2^n}{n!} \le 2\cdot\left(\frac23\right)^{n-2}\)). 로그의 밑은 상수배 차이(\(\log_2n = \frac{\ln n}{\ln 2}\))라 \(O\) 표기에서는 생략합니다.

예제 2.1.4

\(n^{100}\)과 \(1.01^n\) 중 어느 것이 결국 큰가? \(n = 1000\)에서는?

풀이. \(\frac{n^{100}}{1.01^n} \to 0\)이라 \(1.01^n\)이 결국 이깁니다. 그러나 \(n = 1000\)이면 \(n^{100} = 10^{300}\), \(1.01^{1000} \approx 2.1\times10^4\)으로 다항식이 훨씬 큽니다. 둘이 같아지는 것은 \(n \approx 1.1\times10^5\) 근처입니다. 점근 비교는 "충분히 큰 \(n\)"에 대한 말이라, 실제 크기의 입력에서는 상수와 차수를 함께 봐야 합니다. 같은 절의 탐구 카드에서 교차점을 확인할 수 있습니다.

흔한 실수(1) \(O\)를 "정확히 그 빠르기"로 읽는다: \(n = O(n^2)\)도 참이다. 정확한 빠르기는 \(\Theta\). (2) \(f = O(g)\)를 등식처럼 뒤집는다: \(O(n) = n\)은 뜻이 없다. "\(f \in O(g)\)"로 읽는 것이 정확하다. (3) \(2^{2n} = O(2^n)\)이라 생각한다: \(\frac{4^n}{2^n} = 2^n \to \infty\).
요약
  1. \(O\): 상수배로 위에서 누름, \(\Omega\): 아래에서 받침, \(\Theta\): 둘 다.
  2. 비의 극한이 양의 유한값이면 \(\Theta\), 0이면 \(O\)만.
  3. \(\log n \ll n^\varepsilon\), \(n^k \ll c^n\) (\(c > 1\)), \(c^n \ll n!\).

2.1.3연습문제

기본

  1. \(\log(n!) = \Theta(n\log n)\)임을 보여라.
    답

    \(\log n! \le n\log n\). 또 \(n! \ge (n/2)^{n/2}\)이라 \(\log n! \ge \frac n2\log\frac n2 = \Omega(n\log n)\).

응용

  1. \(\sqrt n\)과 \((\log n)^3\)의 증가율을 비교하여라.
    답

    \(\frac{(\log n)^3}{\sqrt n} \to 0\) (\(n = e^{x}\)이면 \(\frac{x^3}{e^{x/2}} \to 0\)). \(\sqrt n\)이 더 빠르다.

심화

  1. \(f = O(g)\), \(g = O(h)\)이면 \(f = O(h)\)임을 정의로 보여라.
    답

    \(|f| \le C_1|g|\) (\(n \ge n_1\)), \(|g| \le C_2|h|\) (\(n \ge n_2\))이면 \(n \ge \max(n_1, n_2)\)에서 \(|f| \le C_1C_2|h|\).

2.1.2

탐구결국 누가 이기는가

탐구 · 점근적 증가율과 교차점

다루는 성취기준 [수학3-02-01]

질문

\(n^{100}\)과 \(1.01^n\) 중 어느 것이 큰가는 \(n\)에 따라 다릅니다. 언제 순서가 바뀌고, "충분히 큰 \(n\)"은 얼마나 큰가요?

복원

\(\frac fg \to 0\)이면 \(f = o(g)\). \(\log n \ll n^\varepsilon\), \(n^k \ll c^n\), \(c^n \ll n!\) (2.1절).

해 보기

  1. 처음 화면 \(n^{100}\) 대 \(1.01^n\)에서 교차점은 약 \(n = 117{,}000\)입니다. 그 전에는 \(n^{100}\)이 압도적으로 크고(\(n = 1000\)에서 \(10^{300}\) 대 약 \(2\times10^4\)), 그 뒤로는 \(1.01^n\)이 이깁니다. 범위를 \(10^5\)로 줄이면 교차점이 사라집니다.
  2. f를 \(n^{10}\), g를 \(2^n\)으로 바꾸면 교차점이 약 59로 훨씬 앞당겨집니다.
  3. \(2^n\) 대 \(n!\), \(n\log n\) 대 \(n^2\)도 비교해 보세요. 세로축이 로그라 지수함수는 직선, 다항식은 \(\log n\) 모양으로 보입니다.
  4. \(\log n\)과 \(\sqrt n\)은 범위를 \(10\)으로 하면 \(\log_2 n\)이 더 큽니다. 범위를 넓혀 교차점(16)을 확인하세요.

설명

  1. 로그 눈금으로 보는 이유\(n^{100}\)과 \(1.01^n\)은 값 자체가 수백 자리라 보통 눈금에 그릴 수 없습니다. \(\log_{10}\)을 취하면 \(100\log_{10}n\)과 \(0.0043n\)이 되어, 로그 함수와 직선의 경주가 됩니다. 직선은 결국 로그를 이깁니다.
  2. 점근 분석의 한계\(O\) 표기는 교차점이 어디인지 말해 주지 않습니다. 실제 알고리즘 선택에서는 입력 크기 범위의 교차점도 확인해야 합니다.

판단

"지수 시간 알고리즘은 다항 시간 알고리즘보다 늘 느리다"는 틀립니다. \(n^{100}\) 알고리즘은 \(n = 10^5\)에서 \(1.01^n\) 알고리즘보다 느립니다. 점근 비교는 충분히 큰 입력에서의 비교입니다.
