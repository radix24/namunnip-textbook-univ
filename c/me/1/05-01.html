5.1.1역할과 규칙

3~5명 팀에서 흔히 나누는 역할입니다. 모두가 설계와 제작에 참여하되, 각 역할은 그 일을 "챙기는" 책임을 집니다.

팀장(일정 담당): 일정표를 관리하고 회의를 연다.

사용자 조사 담당: 요구 사항 표와 사용자 시험을 챙긴다.

제작 담당: 재료, 공구, 제작 일정과 안전을 챙긴다.

시험·기록 담당: 시험 계획, 원자료, 설계 일지와 변경 기록을 챙긴다.

첫 회의에서 정할 규칙: 회의 시간과 연락 방법, 의견이 갈릴 때 결정 방법(평가 행렬로, 그래도 안 되면 다수결), 마감을 못 지킬 때 알리는 방법. 규칙을 문서로 남기면 갈등이 생겼을 때 기준이 됩니다.

5.1.2일정 짜기: 작업, 순서, 주경로

프로젝트를 작업으로 나누고, 작업마다 걸리는 기간과 먼저 끝나야 하는 작업(선행 작업)을 적습니다.

  • A 사용자 조사: 5일, 선행 없음
  • B 요구 사항 표: 2일, A 뒤
  • C 개념 발상과 선정: 4일, B 뒤
  • D 재료 주문(배송): 7일, B 뒤
  • E 간이 시제품 시험: 3일, C 뒤
  • F 최종 시제품 제작: 5일, D와 E 뒤
  • G 시험과 개선: 4일, F 뒤
  • H 발표·보고서: 3일, G 뒤

A → B → C → E → F → G → H의 합은 5 + 2 + 4 + 3 + 5 + 4 + 3 = 26일, A → B → D → F → G → H는 5 + 2 + 7 + 5 + 4 + 3 = 26일입니다. 두 경로가 같아 둘 다 주경로(가장 긴 경로)입니다. 주경로 위의 작업이 하루 늦으면 프로젝트 전체가 하루 늦습니다. 재료 주문(D)을 개념 확정 전에 미리 할 수 없다면, 배송이 하루만 늦어도 전체가 늦으니 주문을 서두르거나 대체 재료를 준비합니다. 이런 표를 막대로 그린 것이 간트 차트입니다(일정 실습).

5.1.3설계 검토

중간에 다른 팀이나 교수자 앞에서 설계를 설명하고 질문을 받는 자리입니다. 준비할 것: 요구 사항 표, 고른 개념과 평가 행렬, 시험 계획과 지금까지의 결과, 걱정되는 위험 요소. 받은 지적은 목록으로 만들어 처리 여부와 이유를 기록합니다.

5.1.4발표와 설계 보고서

발표는 "문제 → 요구 사항 → 개념과 선택 근거 → 시제품 → 시험 결과 → 개선 → 한계와 다음 단계" 순서로 이야기를 만듭니다. 시연이 있으면 실패할 때를 대비한 영상을 준비합니다. 보고서는 같은 순서에 원자료, 계산, 도면, 변경 기록을 부록으로 붙입니다(기계공학실험 6.1절의 보고서 원칙과 같음). 팀원별 기여를 밝힙니다.

주의(1) 모든 일을 잘하는 한 사람에게 몰리지 않게 역할을 돌아가며 맡아 봅니다. 배우는 과목이기 때문입니다. (2) 일정에는 예상치 못한 일에 대비한 여유(전체의 10~20%)를 둡니다. (3) 다른 사람의 사진, 자료, 아이디어를 쓰면 출처를 밝힙니다.
요약
  1. 역할(일정, 사용자, 제작, 시험·기록)과 결정 규칙을 정한다.
  2. 작업, 기간, 선행 작업으로 일정을 짜고 주경로를 관리한다.
  3. 설계 검토로 중간 점검, 발표와 보고서는 근거와 과정을 보여 준다.

5.1.5연습문제

기본

  1. 5.1.2의 일정에서 개념 발상(C)이 2일 늦어지면 프로젝트는 며칠이 되는가?
    답

    C 경로가 28일이 되어 주경로가 되고, 프로젝트는 28일.

응용

  1. 같은 일정에서 재료 배송(D)이 3일로 줄면 프로젝트 길이와 주경로는?
    답

    D 경로 22일, C 경로 26일. 프로젝트 26일, 주경로는 A-B-C-E-F-G-H 하나.

심화

  1. 팀원 한 명이 연락이 되지 않아 시험 일정이 밀렸다. 첫 회의에서 정했으면 좋았을 규칙 두 가지와, 지금 할 수 있는 대응을 써라.
    답

    규칙 예: 연락 응답 기한(24시간), 마감 이틀 전 진행 공유. 대응: 그 사람의 일을 나누어 맡고 일정표를 고쳐 주경로 영향 확인, 교수자에게 상황 공유, 이후 기여를 보고서에 사실대로 기록.

5.1.2

실습어떤 작업이 늦으면 프로젝트가 늦어질까?

실습 · 간트 차트 · 주경로

다루는 성취기준 [기계1-05-01]

질문

5.1.2의 프로젝트 작업 여덟 개의 기간을 바꾸며 간트 차트를 봅니다. 각 작업은 선행 작업이 끝나야 시작합니다. 빨간 막대(주경로)가 하루 늦으면 프로젝트 전체가 하루 늦고, 파란 막대 뒤의 점선 상자는 늦어도 괜찮은 여유입니다.

해 보기와 설명

  1. 기본값프로젝트 26일, 두 경로(C·E를 거치는 경로와 D를 거치는 경로)가 모두 주경로라 모든 작업의 여유가 0입니다. 어느 작업이 늦어도 전체가 늦는 아슬아슬한 일정입니다.
  2. 배송을 3일로D를 3일로 줄이면 프로젝트는 26일 그대로지만 D에 4일의 여유가 생깁니다(5.1절 연습문제 2). 주경로가 아닌 작업을 서둘러도 프로젝트는 빨라지지 않습니다.
  3. 개념 선정이 늦어지면C를 6일로 늘리면 프로젝트가 28일이 되고 D 경로에 2일 여유가 생깁니다.
  4. 일정 줄이기프로젝트를 줄이려면 주경로의 작업을 줄여야 합니다. 기본값에서 두 경로가 모두 주경로이므로 F, G, H처럼 두 경로가 함께 지나는 작업을 줄이는 것이 효과적입니다.

연결과 적용

이 계산을 주경로법(CPM)이라 하며, 건설, 제품 개발, 행사 준비의 일정 관리에 씁니다. 팀 프로젝트 첫 주에 작업 목록과 선행 관계를 만들어 두면 누가 언제 무엇을 끝내야 하는지 분명해집니다.

흔한 오해

  • "모든 작업을 빨리 하면 프로젝트가 빨라진다." 주경로가 아닌 작업을 서두르는 것은 효과가 없습니다.
  • "여유가 있으니 늦어도 된다." 여유를 다 쓰면 그 작업도 주경로가 됩니다.
