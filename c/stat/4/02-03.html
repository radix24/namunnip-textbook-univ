자료는 언제나 지저분하다

숫자여야 할 칸에 "없음"이 적혀 있거나, 파일이 없거나, 0으로 나누는 일이 생깁니다. 프로그램이 첫 오류에서 멈추는 대신 문제를 기록하고 계속 진행하게 하거나, 무엇이 잘못됐는지 분명히 알려 줘야 합니다.

2.3.1try / except

raw = ["12", "7", "없음", "", "3.5"]
values, bad = [], []
for i, r in enumerate(raw):
    try:
        values.append(float(r))
    except ValueError:              # 숫자로 바꿀 수 없을 때만 잡음
        bad.append(i)
print(values, bad)                  # [12.0, 7.0, 3.5] [2, 3]

잡을 오류의 종류를 구체적으로 적습니다. 모든 오류를 잡는 except:는 진짜 버그까지 숨기므로 피합니다. finally 블록은 오류가 있든 없든 실행됩니다(파일 닫기 등). 파일은 with open(...) as f:를 쓰면 자동으로 닫힙니다.

2.3.2오류 일으키기

def variance(xs):
    if len(xs) < 2:
        raise ValueError("분산을 구하려면 관측이 2개 이상 필요합니다.")
    m = sum(xs) / len(xs)
    return sum((x - m) ** 2 for x in xs) / (len(xs) - 1)

잘못된 입력을 조용히 넘기면 나중에 엉뚱한 결과로 나타나 찾기 어렵습니다. 문제를 발견한 곳에서 이유를 담아 오류를 일으키는 편이 낫습니다.

요약
  1. try/except 오류종류로 예상한 오류만 처리.
  2. with로 파일 자동 닫기.
  3. 잘못된 입력은 raise로 분명하게 알림.
