먼저 재고, 그다음 고친다

코드가 느릴 때 짐작으로 고치면 시간을 낭비하기 쉽습니다. 실행 시간의 90%는 보통 코드의 10%에서 쓰입니다. 그곳을 측정으로 찾고 그곳만 고칩니다.

6.1.1측정

system.time(f(x))                      # 전체 시간
bench::mark(f1(x), f2(x))              # 여러 방법 비교 (결과가 같은지도 확인)
Rprof("prof.out"); f(x); Rprof(NULL); summaryRprof("prof.out")   # 함수별 시간
profvis::profvis(f(x))                 # 줄별 시각화

6.1.2벡터화

R의 반복문은 매 단계 해석 비용이 들지만, 벡터 연산은 내부의 C 코드가 한꺼번에 처리합니다.

예제 6.1.1

몬테카를로로 \(E[\max(Z_1, Z_2)]\)를 추정하는 두 코드를 비교하세요.

n <- 1e6
f_loop <- function() { s <- 0; for (i in 1:n) s <- s + max(rnorm(1), rnorm(1)); s / n }
f_vec  <- function() mean(pmax(rnorm(n), rnorm(n)))
system.time(f_loop()); system.time(f_vec())

두 값 모두 \(1/\sqrt\pi \approx 0.564\) 근처이고, 벡터화한 쪽이 수십~수백 배 빠릅니다(컴퓨터에 따라 다름). 그 밖의 요령: 결과를 담을 객체를 미리 만들기, 행렬 연산(crossprod, rowSums) 쓰기, 같은 계산을 반복문 밖으로 빼기. 그래도 느리면 Rcpp로 핵심 부분만 C++로 씁니다.

요약
  1. 프로파일링으로 병목을 찾습니다.
  2. 벡터 연산, 미리 할당, 행렬 함수.
  3. 빠르게 고친 코드도 결과가 같은지 확인합니다.

6.1.3연습문제

기본
