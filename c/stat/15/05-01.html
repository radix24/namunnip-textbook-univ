5.1.1

실습Metropolis 알고리즘: 제안 폭이 너무 작아도, 너무 커도 안 되는 까닭

실습 · MCMC

다루는 성취기준 [응통15-05-01]

목표

봉우리가 두 개인 목표분포에서 Metropolis 알고리즘으로 표본을 뽑습니다. 제안 폭을 바꾸며 수용률, 경로 그림, 히스토그램이 어떻게 달라지는지 보고 알맞은 폭을 고르는 감을 익힙니다. 성취기준 [응통15-05-01].

Metropolis 알고리즘 (대칭 제안의 Metropolis-Hastings): 현재 값 \(x\)에서

  1. 후보 \(y = x + w Z\)를 제안한다(\(Z \sim N(0, 1)\), \(w\)는 제안 폭).
  2. 확률 \(\min\{1, f(y)/f(x)\}\)로 \(y\)로 옮기고, 아니면 \(x\)에 머문다.

\(f\)의 정규화 상수를 몰라도 비 \(f(y)/f(x)\)만 있으면 되는 것이 장점입니다. 이렇게 만든 값들은 \(f\)를 정상분포로 가지는 Markov 연쇄입니다.

수용률: 제안이 받아들여진 비율. 1차원 문제에서는 대략 0.2~0.5가 좋다고 알려져 있습니다.

준비

목표분포는 \(0.3\,N(-2, 0.7^2) + 0.7\,N(2, 1)\)로, 평균은 0.8이고 \(x < 0\)일 확률은 약 0.315입니다. 출발점은 0입니다. 위 그림은 반복에 따른 경로(trace), 아래 그림은 뽑은 값의 히스토그램과 목표분포(빨강)입니다. 난수는 가상이며 "다시 돌리기"는 새 난수로 처음부터 돌립니다.

절차

  1. \(w = 2\)에서 수용률, 표본 평균, \(x < 0\) 비율을 이론값(0.8, 0.315)과 비교합니다.
  2. \(w = 0.1\)로 줄이고 경로와 히스토그램을 봅니다. "다시 돌리기"를 여러 번 누릅니다.
  3. \(w = 20\)으로 늘려 경로 모양과 수용률을 봅니다.
  4. \(w = 0.1\)에서 \(N\)을 20000으로 늘리면 나아지는지 봅니다.

기대 결과

  • \(w = 2\): 수용률이 약 55%이고, 경로가 두 봉우리를 자주 오가며, 히스토그램이 빨간 곡선과 잘 맞습니다. 표본 평균과 \(x < 0\) 비율이 이론값에 가깝습니다.
  • \(w = 0.1\): 수용률은 95% 넘게 높지만 한 걸음이 너무 작아 경로가 천천히 기어갑니다. 한 봉우리에 갇혀 다른 봉우리를 거의 못 가므로 \(x < 0\) 비율이 0.315와 크게 다릅니다. 높은 수용률이 좋은 것이 아닙니다.
  • \(w = 20\): 후보가 대부분 확률이 낮은 먼 곳이라 수용률이 10% 안팎으로 떨어집니다. 경로가 계단 모양(같은 값에 오래 머묾)이 되고 히스토그램이 울퉁불퉁합니다.
  • \(w = 0.1\)에서 \(N\)을 늘리면 조금 나아지지만, 제안 폭을 고치는 것보다 훨씬 비효율적입니다.

분석

  1. 수용률만 보고 표본이 좋다고 판단하면 왜 위험한지 \(w = 0.1\)의 결과로 설명해 보세요.
  2. 출발점을 \(x = 10\)처럼 먼 곳에 두면 처음 몇백 번의 값은 어떻게 될까요? 이 값들을 버리는 것을 번인(burn-in)이라 합니다.
  3. 서로 다른 출발점에서 연쇄를 여러 개 돌려 비교하는 수렴 진단([응통15-05-03])이 이 실습의 어떤 문제를 잡아 줄지 적어 보세요.

더 해 보기

R로 직접 구현해 보세요.

f <- function(x) 0.3*dnorm(x, -2, 0.7) + 0.7*dnorm(x, 2, 1)
x <- numeric(5000); w <- 2
for (i in 2:5000) {
  y <- x[i-1] + w*rnorm(1)
  x[i] <- if (runif(1) < f(y)/f(x[i-1])) y else x[i-1]
}
mean(x); mean(x < 0); plot(x, type = "l")
