석 달 뒤의 나를 위해

관측한 날 밤에는 모든 것이 분명해 보이지만, 석 달 뒤 보고서를 쓸 때는 어느 영상이 구름 낀 영상이었는지, 평탄 영상을 어느 필터로 찍었는지 기억나지 않습니다. 다른 사람이 같은 결과를 다시 얻을 수 있어야(재현성) 과학적 결과로 인정받습니다. 연세대 천체관측법의 성취기준 "관측 기록과 자료 처리 과정을 재현 가능하게 정리"가 이것입니다.

7.2.1관측 일지

관측하는 동안 시간 순서로 적습니다(종이나 전자 문서).

  • 날짜, 관측자, 망원경, 검출기, 설정(냉각 온도, 이득, 비닝)
  • 파일 번호마다: 대상, 영상 종류(과학, 바이어스, 암, 평탄, 비교 광원), 필터, 노출 시간, 시각(UT)
  • 하늘 상태: 구름, 시상, 달, 습도, 바람. 문제가 생긴 영상과 그 이유

7.2.2FITS 머리말과 파일 정리

천문 영상의 표준 형식 FITS는 영상 자료 앞에 "열쇠 = 값" 줄들(머리말)을 둡니다. DATE-OBS(관측 시각), EXPTIME(노출), FILTER, OBJECT, AIRMASS 같은 값이 자동으로 기록되므로, 처리 프로그램은 일지 대신 머리말을 읽어 영상을 분류할 수 있습니다(천우13 1.2절).

from astropy.io import fits
with fits.open("m31_V_0012.fits") as h:
    hdr = h[0].header
    print(hdr["OBJECT"], hdr["FILTER"], hdr["EXPTIME"], hdr["DATE-OBS"])

원시 자료는 절대 고치지 않고 읽기 전용으로 보관하며, 처리 결과는 다른 폴더에 둡니다. 파일 이름은 날짜_대상_필터_번호처럼 정해 두면 찾기 쉽습니다.

7.2.3처리를 코드로 남기기

  1. 스크립트: 화면에서 손으로 클릭하는 대신 처리 단계를 Python 스크립트로 쓴다. 다시 실행하면 같은 결과가 나온다.
  2. 설정 분리: 구경 크기, 다항식 차수, 쓴 표준성 같은 선택을 스크립트 맨 위나 설정 파일에 모아 적는다.
  3. 버전 관리: git으로 스크립트의 변경 이력을 남긴다. 결과 그림과 표에 그것을 만든 코드의 판을 함께 적는다(천우10 1.2절).
  4. 환경 기록: 쓴 프로그램과 라이브러리의 판(예: astropy 6.0)을 적는다.
예제 7.2.1

보고서의 측광 결과 한 줄에 함께 적어야 할 정보를 고르세요: (가) 대상 이름 (나) 관측 시각 (다) 필터 (라) 등급과 오차 (마) 쓴 표준성과 변환식 (바) 처리 스크립트의 판.

풀이. 모두입니다. (가)~(라)는 결과 자체이고, (마)와 (바)가 있어야 다른 사람이 같은 값을 다시 얻을 수 있습니다.

흔한 실수 처리 중간에 "잘 안 맞는" 영상을 말없이 빼 버리는 것. 뺀 영상과 그 이유를 일지와 스크립트에 남겨야 합니다. 결과에 맞춰 자료를 고르는 것은 의도하지 않아도 결과를 치우치게 만듭니다.
요약
  1. 관측 일지: 설정, 파일마다의 종류·필터·노출·시각, 하늘 상태와 문제.
  2. FITS 머리말로 영상을 분류하고, 원시 자료는 고치지 않는다.
  3. 처리는 스크립트로, 선택은 설정으로 모으고, git으로 이력을 남긴다.
  4. 뺀 자료와 그 이유를 기록한다.

7.2.4연습문제

기본

  1. FITS 머리말에서 노출 시간을 나타내는 열쇠는?
    답

    EXPTIME.

  2. 원시 자료를 읽기 전용으로 두는 까닭은?
    답

    처리 실수로 원본을 잃지 않고, 언제든 처음부터 다시 처리할 수 있게 하기 위해서입니다.

응용

  1. 평탄 영상 20장 중 3장에 구름 그림자가 있었습니다. 어떻게 처리하고 무엇을 남깁니까?
    답

    그 3장을 빼고 17장의 중앙값으로 대표 평탄 영상을 만들고, 뺀 파일 번호와 이유를 일지와 스크립트(제외 목록)에 남깁니다.

  2. 같은 스크립트로 다시 처리했더니 등급이 0.01 달라졌습니다. 무엇을 의심합니까?
    답

    라이브러리 판이 바뀌었거나, 무작위 요소(시드)가 고정되지 않았거나, 입력 파일·설정이 바뀌었는지 확인합니다.
