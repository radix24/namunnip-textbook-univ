5.4.1시간 재기

\(\sum_{i=1}^{N} \frac{1}{i^2}\)을 \(N = 10^7\)까지 세 가지로 계산해 걸린 시간을 비교합니다.

program timing
  implicit none
  integer, parameter :: dp = kind(1.0d0)
  integer :: i, N
  real(dp) :: s, t0, t1
  N = 10000000
  call cpu_time(t0)
  s = 0.0_dp
  do i = 1, N
    s = s + 1.0_dp / real(i, dp)**2
  end do
  call cpu_time(t1)
  print '(A, F12.9, A, F8.4, A)', "s = ", s, ",  ", t1 - t0, " s"
end program timing
import time
import numpy as np
N = 10_000_000

t0 = time.perf_counter()
s = 0.0
for i in range(1, N + 1):
    s += 1.0 / i**2
t1 = time.perf_counter()
print("파이썬 반복문", s, t1 - t0)

t0 = time.perf_counter()
i = np.arange(1, N + 1, dtype=float)
s = np.sum(1.0 / i**2)
t1 = time.perf_counter()
print("NumPy", s, t1 - t0)

컴파일할 때 최적화 옵션(gfortran -O2 timing.f90)을 켜고, 같은 컴퓨터에서 여러 번 재서 비교합니다. 결과는 컴퓨터, 컴파일러, 파이썬 판에 따라 다르므로 직접 재 보아야 합니다. 일반적으로는 순수 파이썬 반복문이 가장 느리고(포트란보다 수십~수백 배), NumPy는 포트란에 가깝게 빨라지는 경우가 많습니다(확인 필요: 실제 배수는 환경마다 다름). 세 결과의 \(s\)가 마지막 몇 자리에서 조금 다를 수 있는데, 더하는 순서와 방식이 달라 반올림 오차가 다르게 쌓이기 때문입니다.

5.4.2차이의 이유

  • 포트란: 실행 전에 전체를 기계어로 번역하고, 자료형이 미리 정해져 있어 컴파일러가 반복문을 최적화한다.
  • 순수 파이썬: 한 줄씩 해석하면서, 더하기 한 번마다 두 값의 자료형을 확인하고 새 객체를 만든다. 이 부담이 \(10^7\)번 되풀이된다.
  • NumPy: 반복은 미리 컴파일된 C 코드 안에서 일어나고, 파이썬은 "배열 전체를 더하라"는 명령만 한 번 내린다. 대신 \(10^7\)개짜리 배열을 메모리에 만든다.

5.4.3언어 고르기

기준포트란파이썬 (+NumPy)
실행 속도매우 빠름반복문은 느림, 배열 연산은 빠름
코드 쓰는 시간선언, 컴파일이 필요짧고 바로 실행
그래프, 자료 정리불편함라이브러리가 많음
오래된 과학 코드많이 남아 있음감싸서 부를 수 있음

실제 연구에서는 무거운 계산 부분은 포트란이나 C로 쓰고, 입력 준비와 결과 분석, 그래프는 파이썬으로 하는 경우가 많습니다. NumPy에 들어 있는 f2py로 포트란 서브루틴을 파이썬 함수처럼 불러 쓸 수도 있습니다. "먼저 파이썬으로 맞게 짜고, 느린 곳을 재서 그 부분만 빠르게"가 기본 순서입니다.

요약
  1. 시간은 cpu_time, time.perf_counter로 같은 조건에서 여러 번 잰다.
  2. 순수 파이썬 반복문은 느리고, NumPy와 포트란은 빠르다. 이유는 컴파일과 자료형 확인 부담.
  3. 무거운 계산은 포트란, 준비와 분석은 파이썬. f2py로 이을 수 있다.

5.4.4연습문제

기본

  1. 위 계산에서 \(N\)을 \(10^8\)로 늘리면 NumPy 방법에 어떤 문제가 생길 수 있는가?
    답

    배정도 \(10^8\)개 배열은 약 800 MB라 메모리가 모자랄 수 있다. 몇 덩어리로 나눠 계산하거나 반복문을 컴파일 언어로 쓴다.
