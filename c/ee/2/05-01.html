5.1.1단순한 정렬과 그 한계

삽입 정렬: 앞부분을 정렬된 상태로 유지하며 다음 원소를 알맞은 자리에 끼워 넣는다. 최악(역순) \(n(n - 1)/2\)번 비교, 이미 거의 정렬되어 있으면 O(n). 작은 n에서 빠르다.

n이 커지면 O(n²)이 감당되지 않으므로(1.2절: 10⁶개면 약 17분), 문제를 반으로 나눠 푸는 분할 정복으로 O(n log n)을 얻습니다.

5.1.2병합 정렬

나누기는 쉽게(반으로), 합치기에서 일하는 방법입니다.

def merge_sort(a):
    if len(a) <= 1:
        return a
    mid = len(a) // 2
    left, right = merge_sort(a[:mid]), merge_sort(a[mid:])
    out, i, j = [], 0, 0
    while i < len(left) and j < len(right):     # 두 정렬된 줄의 앞을 비교
        if left[i] <= right[j]:
            out.append(left[i]); i += 1
        else:
            out.append(right[j]); j += 1
    return out + left[i:] + right[j:]

병합은 각 원소를 한 번씩 옮기므로 O(n), 점화식 \(T(n) = 2T(n/2) + O(n)\)은 1.1절 예제처럼 O(n log n)입니다. 입력과 관계없이 언제나 O(n log n)이고, 같은 값의 상대 순서를 지키는 안정 정렬입니다(<= 때문). 대신 병합할 때 n 크기의 추가 메모리가 필요합니다.

5.1.3퀵 정렬

나누기에서 일하고(기준보다 작은 쪽과 큰 쪽으로), 합치기는 이어 붙이기만 합니다.

분할(partition): 기준 p를 골라 p보다 작은 것을 왼쪽, 큰 것을 오른쪽으로 모은다. 비교 n − 1번. 배열 안에서 자리 바꾸기로 하면 추가 메모리가 거의 없다(제자리).

  • 최선: 기준이 늘 가운데값이면 반씩 나뉘어 O(n log n).
  • 최악: 기준이 늘 최솟값(예: 첫 원소를 기준으로 하는데 입력이 이미 정렬됨)이면 크기가 1씩만 줄어 \(T(n) = T(n - 1) + n\), O(n²).
  • 평균: 무작위 입력(또는 무작위 기준)에서 비교 약 \(2n\ln n \approx 1.39n\log_2n\), O(n log n).
예제 5.1.1

서로 다른 수 1000개를 무작위 순서와 정렬된 순서로 주고, 병합 정렬, 첫 원소 기준 퀵 정렬, 무작위 기준 퀵 정렬의 비교 횟수를 세어라(실습 카드의 코드).

풀이. 실행 결과(시드 2026):

알고리즘무작위 입력정렬된 입력
병합8,7074,932
퀵(첫 원소 기준)10,985499,500
퀵(무작위 기준)10,88310,710

참고로 \(n\log_2n = 9966\), \(n(n - 1)/2 = 499{,}500\)입니다. 첫 원소 기준 퀵 정렬은 정렬된 입력에서 정확히 최악(499,500번)이 되고, 재귀 깊이도 n이라 Python의 기본 재귀 한도(1000)를 넘어 한도를 늘려야 했습니다. 기준을 무작위로 고르면 입력이 무엇이든 평균 경우가 됩니다. 병합 정렬은 정렬된 입력에서 비교가 오히려 줄어듭니다(한쪽 줄이 먼저 끝나서).

그럼에도 실제로 퀵 정렬이 많이 쓰이는 이유는 제자리에서 연속된 메모리를 차례로 훑어 캐시 효율이 좋기 때문입니다. Python의 sorted는 병합과 삽입 정렬을 섞은 Timsort(안정, 최악 O(n log n), 부분적으로 정렬된 자료에서 매우 빠름)입니다.

5.1.4힙 정렬

배열을 heapify(O(n), 3.3절)한 뒤 최댓값을 n번 꺼내 뒤에서부터 채우면 제자리 O(n log n) 정렬입니다. 최악도 O(n log n)이지만 안정하지 않고 캐시 효율이 낮아 실제로는 퀵 정렬보다 느린 편입니다.

흔한 오해(1) "퀵 정렬은 언제나 O(n log n)": 평균일 뿐, 기준 선택이 나쁘면 O(n²)입니다. (2) "병합 정렬이 비교가 적으니 언제나 더 빠르다": 메모리 복사와 캐시 효과 때문에 실제 시간은 퀵 정렬이 빠른 경우가 많습니다. (3) 안정성이 필요한 경우(예: 이름순으로 정렬한 뒤 학년순으로 다시 정렬해 같은 학년 안에서 이름순을 유지)에 불안정 정렬을 쓰는 실수.
요약
  1. 병합: 반으로 나누고 O(n)에 합침, 언제나 O(n log n), 안정, 추가 메모리 O(n).
  2. 퀵: 기준으로 분할, 평균 O(n log n), 최악 O(n²), 무작위 기준으로 최악을 피함, 제자리.
  3. 힙 정렬: 제자리 최악 O(n log n), 불안정.

5.1.5연습문제

기본

  1. [5, 2, 4, 6, 1, 3]을 병합 정렬할 때 마지막 병합 직전의 두 줄은?
    답

    [2, 4, 5]와 [1, 3, 6].

응용

  1. [3, 8, 2, 5, 1, 4, 7, 6]을 첫 원소(3)를 기준으로 한 번 분할한 결과는?
    답

    작은 쪽 [2, 1], 기준 3, 큰 쪽 [8, 5, 4, 7, 6](이 구현의 순서 유지 방식 기준).

  2. 퀵 정렬의 기준을 "세 값(처음, 가운데, 끝)의 중앙값"으로 고르면 정렬된 입력에서 비용은?
    답

    정렬된 입력에서는 가운데 원소가 중앙값이라 반씩 나뉘어 O(n log n). 다만 일부러 만든 나쁜 입력에서는 여전히 O(n²)이 가능합니다.

심화

  1. 같은 값이 아주 많은 입력(예: 0과 1만 100만 개)에서 위 quick_sort(>=를 오른쪽으로)의 문제와, 무작위 기준 코드처럼 세 갈래(<, =, >)로 나누는 효과를 설명하라.
    답

    같은 값이 모두 한쪽으로 가 분할이 한쪽으로 쏠려 O(n²)에 가까워집니다. 세 갈래 분할은 기준과 같은 값을 한 번에 끝내므로 서로 다른 값이 k개면 O(n log k) 정도로 빨라집니다.

5.1.2

탐구입력 모양에 따라 달라지는 정렬 비용

탐구 · 네 정렬의 비교 횟수

다루는 성취기준 [전전2-05-01]

질문

병합, 퀵(첫 원소 기준), 퀵(무작위 기준), 삽입 정렬은 무작위·정렬됨·역순·같은 값이 많은 입력에서 각각 몇 번 비교할까요?

준비

0~n−1(또는 0, 1, 2만)을 고른 모양으로 늘어놓고 네 알고리즘의 비교 횟수를 셉니다(정해진 시드의 가상 입력). 막대 높이가 비교 횟수, 점선이 n log₂n입니다. 퀵 정렬은 깊은 재귀를 피하려고 스택으로 구현했습니다.

해 보기와 설명

  1. 무작위(n = 1000)병합 8,724, 퀵(첫 원소) 12,076, 퀵(무작위) 11,988, 삽입 255,311. n log₂n = 9,966입니다.
  2. 정렬됨병합 4,932, 퀵(첫 원소) 499,500(최악), 퀵(무작위) 10,210, 삽입 999(최선). 같은 입력이 퀵에는 최악, 삽입에는 최선입니다.
  3. 역순퀵(첫 원소)과 삽입이 모두 499,500으로 최악입니다.
  4. 값 세 가지퀵(첫 원소)은 같은 값을 한쪽으로 몰아 167,850번이지만, 같은 값을 따로 모으는 퀵(무작위, 세 갈래)은 1,666번으로 가장 적습니다(5.1절 연습 4).

연결과 적용

실습 카드의 Python 코드(시드가 달라 무작위 입력의 숫자는 조금 다름)와 같은 경향입니다. 실제 라이브러리는 입력 모양에 강한 방법(Timsort, introsort)을 씁니다.

흔한 오해

  • "한 정렬이 모든 입력에서 가장 빠르다" 이 표처럼 입력 모양마다 순위가 바뀝니다. 최악 경우 보장과 평균 속도를 함께 봐야 합니다.
5.1.3

실습병합 정렬과 퀵 정렬의 비교 횟수 세기

실습 · 같은 입력, 다른 정렬

다루는 성취기준 [전전2-05-01]

목표

5.1절의 병합 정렬과 두 가지 퀵 정렬을 구현해 무작위·정렬된 입력에서 비교 횟수를 세고 이론과 비교합니다. 성취기준 [전전2-05-01].

준비

Python 3만 있으면 됩니다(추가 라이브러리 없음). 아래 코드를 sort_lab.py로 저장합니다.

import random, sys
sys.setrecursionlimit(5000)          # 정렬된 입력에서 퀵 정렬의 재귀가 n단 깊어짐

def merge_sort(a, cnt):
    if len(a) <= 1:
        return a
    mid = len(a) // 2
    left, right = merge_sort(a[:mid], cnt), merge_sort(a[mid:], cnt)
    out, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        cnt[0] += 1
        if left[i] <= right[j]:
            out.append(left[i]); i += 1
        else:
            out.append(right[j]); j += 1
    return out + left[i:] + right[j:]

def quick_sort(a, cnt):
    if len(a) <= 1:
        return a
    pivot = a[0]                       # 첫 원소를 기준으로(일부러 단순하게)
    cnt[0] += len(a) - 1
    less = [x for x in a[1:] if x < pivot]
    more = [x for x in a[1:] if x >= pivot]
    return quick_sort(less, cnt) + [pivot] + quick_sort(more, cnt)

def quick_sort_random(a, cnt):         # 기준을 무작위로 고름
    if len(a) <= 1:
        return a
    pivot = a[random.randrange(len(a))]
    cnt[0] += len(a) - 1
    less = [x for x in a if x < pivot]
    same = [x for x in a if x == pivot]
    more = [x for x in a if x > pivot]
    return quick_sort_random(less, cnt) + same + quick_sort_random(more, cnt)

random.seed(2026)
n = 1000
data = random.sample(range(10 * n), n)
for name, f in [("병합", merge_sort), ("퀵(첫 원소 기준)", quick_sort), ("퀵(무작위 기준)", quick_sort_random)]:
    for label, arr in [("무작위", data), ("정렬됨", sorted(data))]:
        cnt = [0]
        res = f(list(arr), cnt)
        assert res == sorted(arr)
        print(f"{name} 정렬, {label} 입력 n={n}: 비교 {cnt[0]}회")
print("n log2 n =", round(n * __import__('math').log2(n)), ", n(n-1)/2 =", n * (n - 1) // 2)

절차

  1. 실행해 출력을 적습니다(시드 2026으로 결과가 늘 같음).
  2. sys.setrecursionlimit(5000) 줄을 지우고 다시 실행해 어떤 오류가 어느 경우에 나는지 확인합니다.
  3. n을 2000으로 바꿔 각 비교 횟수가 몇 배가 되는지 봅니다.

  • 병합: 무작위 8,707, 정렬됨 4,932. n log₂n = 9,966보다 조금 적습니다.
  • 퀵(첫 원소 기준): 무작위 10,985, 정렬됨 499,500 = n(n − 1)/2(최악).
  • 퀵(무작위 기준): 입력과 관계없이 1만 번 남짓(10,883, 10,710).
  • 절차 2: 한도를 지우면 정렬된 입력의 첫 원소 기준 퀵 정렬에서 RecursionError가 납니다(재귀 깊이 약 n = 1000).
  • 절차 3: n = 2000이면 병합(무작위) 19,443번으로 2.23배, 퀵(첫 원소, 정렬됨) 1,999,000번으로 4.0배입니다. n log n은 약 2.2배, n²은 4배가 이론입니다.

분석

  1. 퀵(첫 원소 기준) 무작위 입력의 10,985가 \(2(n + 1)H_n - 4n\)(\(H_n\)은 조화수)과 어떻게 비교되는지 계산하세요.
  2. 병합 정렬이 정렬된 입력에서 비교가 거의 절반으로 주는 이유를 병합 과정으로 설명하세요.
