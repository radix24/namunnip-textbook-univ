1.1.1시간을 재지 않고 세는 이유

같은 프로그램도 컴퓨터, 언어, 그날의 다른 작업에 따라 실행 시간이 다릅니다. 그래서 알고리즘끼리 비교할 때는 초가 아니라 "입력이 커지면 일이 얼마나 늘어나는가"를 봅니다. 이 과목은 자료를 담는 방법(자료 구조)과 그 위의 연산(알고리즘)을 다루며, 그 비교의 언어가 복잡도입니다.

입력 크기 n: 정렬할 원소 수, 그래프의 정점 수처럼 문제의 크기를 나타내는 수.

기본 연산: 비교, 대입, 산술처럼 상수 시간이 걸린다고 보는 연산. 알고리즘의 핵심이 되는 연산(예: 정렬의 비교)만 세기도 한다.

최악·최선·평균: 같은 n이라도 입력에 따라 횟수가 다르다. 보통 최악 경우를 기준으로 삼는다(보장이 필요하므로).

1.1.2반복문 세기

구하려는 것: 다음 코드의 비교 횟수. 길이 n인 리스트에서 합이 0인 쌍을 셉니다.

def zero_pairs(a):
    n = len(a); count = 0
    for i in range(n):
        for j in range(i + 1, n):
            if a[i] + a[j] == 0:     # 기본 연산: 이 비교
                count += 1
    return count

i마다 안쪽 반복은 \(n - 1 - i\)번이므로 전체는 \((n - 1) + (n - 2) + \cdots + 0 = \frac{n(n - 1)}{2}\)번입니다. n = 10, 100, 1000이면 45, 4950, 499500번. n이 10배가 되면 약 100배이므로 n²에 비례합니다.

반씩 줄어드는 반복은 다르게 셉니다. 정렬된 리스트에서 값을 찾는 이진 탐색은 매번 구간을 반으로 줄이므로, n이 1이 될 때까지 나누는 횟수 \(\log_2n\) 정도입니다. 정확히는 최대 \(\lfloor\log_2n\rfloor + 1\)번 비교합니다: n = 10, 1000, 10⁶이면 4, 10, 20번. 원소가 백만 개여도 20번이면 됩니다.

1.1.3재귀: 점화식 세우기

재귀 함수는 자기 자신을 더 작은 입력으로 부르므로, 실행 시간도 자기 자신으로 표현됩니다.

점화식: \(T(n)\)을 더 작은 n의 \(T\)로 나타낸 식. 예: 반으로 나눠 한쪽만 보는 이진 탐색 \(T(n) = T(n/2) + c\).

펼치기. \(T(n) = T(n/2) + c = T(n/4) + 2c = \cdots = T(1) + c\log_2n\). 따라서 \(\log n\)에 비례합니다.

예제 1.1.1

병합 정렬처럼 반으로 나눠 둘 다 처리하고 n에 비례하는 일로 합치는 알고리즘 \(T(n) = 2T(n/2) + cn\)을 재귀 트리로 풀어라.

풀이. 맨 위(깊이 0)는 cn의 일, 깊이 1에는 크기 n/2인 문제 2개가 각각 cn/2, 합 cn. 깊이 k에는 \(2^k\)개 × \(cn/2^k\) = cn. 문제 크기가 1이 되는 깊이는 \(\log_2n\)이므로 층이 \(\log_2n + 1\)개, 전체 \(cn(\log_2n + 1)\)입니다. 층마다 같은 양의 일을 한다는 것이 이 트리의 특징이고, 결과는 \(n\log n\)에 비례합니다(5단원).

예제 1.1.2

피보나치 수를 그대로 재귀로 계산하는 fib(n) = fib(n-1) + fib(n-2)의 호출 횟수를 구하여라.

풀이. 호출 횟수 \(C(n) = 1 + C(n - 1) + C(n - 2)\), \(C(0) = C(1) = 1\). 실제로 세면 n = 10, 20, 25에서 177, 21891, 242785번입니다. n이 5 늘 때마다 약 11배(\(\phi^5 \approx 11.1\), \(\phi = 1.618\)), 곧 지수적으로 늘어납니다. 같은 값을 반복해 계산하기 때문이며, 계산한 값을 저장해 두면(메모이제이션) n에 비례하는 호출로 줄어듭니다.

흔한 오해(1) "반복문이 두 개면 n²": 중첩되었을 때 그렇고, 나란히 있으면 \(n + n = 2n\)입니다. 또 안쪽 반복의 범위가 i에 따라 달라지는지 확인해야 합니다. (2) "재귀는 느리다": 피보나치 재귀가 느린 것은 같은 부분 문제를 반복하기 때문이지 재귀 자체 때문이 아닙니다. 병합 정렬은 재귀로도 빠릅니다. (3) Python의 in(리스트), insert(0, x), 슬라이싱처럼 한 줄짜리도 내부에서 n에 비례하는 일을 할 수 있습니다(2단원).
요약
  1. 시간 대신 기본 연산 횟수를 n의 함수로 센다. 보통 최악 경우.
  2. 중첩 반복 \(\frac{n(n - 1)}{2}\), 반씩 줄이는 반복 \(\log_2n\).
  3. 재귀는 점화식으로: \(T(n/2) + c \to \log n\), \(2T(n/2) + cn \to n\log n\), 피보나치 재귀는 지수.

1.1.4연습문제

기본

  1. for i in range(n): for j in range(n): for k in range(n): x += 1의 연산 횟수는?
    답

    \(n^3\).

  2. i = n; while i > 1: i //= 3은 몇 번 도는가?
    답

    약 \(\log_3n\)번.

응용

  1. for i in range(n): j = 1; while j < n: j *= 2의 안쪽 반복 총 횟수는?
    답

    바깥 n번 × 안쪽 \(\lceil\log_2n\rceil\)번 → \(n\log n\)에 비례.

심화

  1. \(T(n) = T(n - 1) + n\), \(T(1) = 1\)을 풀어라. 어떤 알고리즘에서 나오는가?
    답

    \(T(n) = 1 + 2 + \cdots + n = \frac{n(n + 1)}{2}\). 매번 가장 작은 것을 골라 빼는 선택 정렬, 퀵 정렬의 최악 경우.

1.1.2

예제행렬 곱과 거듭제곱의 연산 횟수

예제 · 반복문과 재귀를 세기

다루는 성취기준 [전전2-01-01]

먼저 예측

\(x^{1000}\)을 계산할 때 x를 999번 곱하는 대신 더 적은 곱셈으로 할 수 있을까요?

생각해 본 뒤 열기

제곱을 되풀이하면 약 15번으로 됩니다. \(x^{1000} = (x^{500})^2\)처럼 지수를 반으로 줄이기 때문입니다.

문제

(가) n × n 행렬 두 개를 정의대로 곱하는 세 겹 반복문의 곱셈 횟수, (나) 아래 재귀 거듭제곱의 곱셈 횟수 점화식과 그 해를 구하라. n = 1000일 때 (나)의 곱셈 수는?

def power(x, n):
    if n == 0:
        return 1
    half = power(x, n // 2)
    return half * half if n % 2 == 0 else half * half * x

전략

  1. (가) 각 칸 \(c_{ij} = \sum_ka_{ik}b_{kj}\)에 곱셈 n번, 칸이 n²개.
  2. (나) 한 번 호출에 곱셈 1~2번 + 크기 n//2 호출 하나: \(T(n) = T(n/2) + c\).

풀이

  1. (가) \(n \cdot n \cdot n = n^3\)번, Θ(n³). n = 1000이면 10⁹번. 세 겹 반복
  2. (나) 짝수면 곱셈 1번, 홀수면 2번. 지수가 매번 반 이하로 줄어 호출이 \(\lfloor\log_2n\rfloor + 1\)번(마지막 n = 0 호출은 곱셈 없음). 펼치기
  3. n = 1000(이진수 1111101000, 10자리, 1이 6개): 곱셈 = 10(제곱) + 6(홀수일 때 추가) = 16번. 처음 n = 1인 호출의 제곱(1 × 1)까지 세었으므로 의미 있는 곱셈은 약 15번. 이진수로 세기

의미

지수를 반씩 줄이는 거듭제곱은 999번을 약 15번으로 줄입니다. 공개 키 암호(RSA)는 수백 자리 지수의 거듭제곱을 이 방법(나머지 연산과 함께)으로 계산합니다. 행렬 곱의 n³도 분할 정복으로 줄일 수 있어 Strassen 알고리즘은 약 \(n^{2.81}\)입니다.

검산

n = 8: 8 → 4 → 2 → 1 → 0. 곱셈은 n = 8, 4, 2에서 각 1번, n = 1에서 2번(1 × 1 × x) = 5번. 공식: 이진수 1000은 4자리, 1이 1개 → 4 + 1 = 5. 일치합니다.

이해 확인

for i in range(n): for j in range(i): for k in range(j): x += 1의 횟수는 어떤 Θ인가?

답

\(\sum_i\sum_{j<i}j = \sum_i\frac{i(i - 1)}{2} = \binom{n}{3} \approx n^3/6\), Θ(n³).

확인재귀의 비용

위 power를 return power(x, n // 2) * power(x, n // 2)처럼 같은 호출을 두 번 하도록 바꾸면 곱셈 횟수는?
