6.2.1문자열 해시

구하려는 것: 문자열을 고르게 흩어지는 정수로 바꾸는 방법. 글자 코드를 그냥 더하면 "ab"와 "ba"가 같은 값이 됩니다. 자리마다 다른 가중치를 주는 다항식 해시를 씁니다.

\[ h(s) = \left(s_0b^{L-1} + s_1b^{L-2} + \cdots + s_{L-1}\right) \bmod m. \]

Horner 방법으로 한 글자씩 \(h \leftarrow (h\cdot b + s_i) \bmod m\)을 되풀이하면 O(L)에 계산됩니다. b는 31이나 131 같은 작은 소수를 흔히 씁니다(확인 필요: 언어마다 다른 상수를 씀). 예: b = 31, m = 1009이면 "ab" → (97·31 + 98) mod 1009 = 3105 mod 1009 = 78, "ba" → (98·31 + 97) mod 1009 = 3135 mod 1009 = 108로 다릅니다.

6.2.2체이닝 테이블 구현

class HashMap:
    def __init__(self, m=8):
        self.t = [[] for _ in range(m)]
        self.n = 0

    def _bucket(self, k):
        return self.t[hash(k) % len(self.t)]

    def put(self, k, v):
        b = self._bucket(k)
        for i, (kk, _) in enumerate(b):
            if kk == k:
                b[i] = (k, v)          # 이미 있으면 값만 바꿈
                return
        b.append((k, v))
        self.n += 1
        if self.n > 2 * len(self.t):  # 적재율 2를 넘으면
            self._resize(2 * len(self.t))

    def get(self, k, default=None):
        for kk, v in self._bucket(k):
            if kk == k:
                return v
        return default

    def delete(self, k):
        b = self._bucket(k)
        for i, (kk, _) in enumerate(b):
            if kk == k:
                b.pop(i); self.n -= 1
                return True
        return False

    def _resize(self, m):
        old = [p for b in self.t for p in b]
        self.t = [[] for _ in range(m)]
        for k, v in old:
            self._bucket(k).append((k, v))

재해싱은 칸 수가 바뀌므로 모든 키의 칸을 다시 계산해야 합니다(그냥 복사하면 안 됨). 칸 수를 두 배로 하므로 1.3절과 같은 이유로 put의 분할상환 비용이 O(1)입니다.

6.2.3키의 조건

  • 같은 키는 같은 해시: a == b이면 hash(a) == hash(b)여야 한다. 그렇지 않으면 같은 키가 다른 칸에 들어가 찾지 못한다.
  • 바뀌지 않음: 넣은 뒤 키가 바뀌면 해시도 바뀌어 원래 칸에서 찾지 못한다. 그래서 Python은 리스트를 딕셔너리 키로 허용하지 않고(TypeError), 튜플은 허용한다.

Python의 dict는 개방 주소법(무작위에 가까운 조사 순서)으로 구현되어 있고 적재율 약 2/3에서 키웁니다(확인 필요: 구현 세부는 버전마다 다름). 3.7부터는 넣은 순서도 기억합니다.

흔한 오해(1) 재해싱할 때 옛 배열을 새 배열 앞쪽에 그대로 복사하는 실수: 칸 번호가 \(\bmod m\)으로 정해지므로 m이 바뀌면 모두 다시 계산합니다. (2) 해시 값이 같으면 같은 키라고 판단하는 실수: 충돌이 있으므로 마지막에 키 자체를 ==로 비교해야 합니다. (3) 사용자 정의 클래스에서 __eq__만 고치고 __hash__를 맞추지 않으면 딕셔너리 동작이 깨집니다.
요약
  1. 문자열 해시: \(h \leftarrow (h\cdot b + s_i) \bmod m\), O(길이).
  2. 체이닝 테이블: 칸의 리스트에서 키 비교. 적재율이 넘으면 두 배로 재해싱(모든 키 다시 배치), 분할상환 O(1).
  3. 키는 같으면 같은 해시, 바뀌지 않아야 한다.

6.2.4연습문제

기본

  1. b = 31, m = 1009일 때 "abc"의 다항식 해시는? (a = 97, b = 98, c = 99)
    답

    ((97·31 + 98)·31 + 99) mod 1009 = (3105·31 + 99) mod 1009 = 96354 mod 1009 = 499.

응용

  1. 위 HashMap에 키 20개를 넣으면 재해싱이 몇 번 일어나고 마지막 칸 수는?
    답

    n = 17에서 m = 8 → 16(17 > 16). n = 33이 되지 않으므로 한 번, 칸 16.

  2. 두 문자열이 같은지 매번 끝까지 비교하는 대신, 해시를 먼저 비교하면 무엇이 좋아지는가? 그래도 마지막 비교가 필요한 이유는?
    답

    해시가 다르면 바로 다르다고 판단(대부분의 경우 빠름). 해시가 같아도 충돌일 수 있으므로 같다고 결론 내리려면 실제 비교가 필요합니다(Rabin-Karp 문자열 검색의 원리).

심화

  1. Python에서 d = {}; k = [1, 2]; d[tuple(k)] = 'x'; k.append(3) 뒤 d[(1, 2)]는 무엇인가? 리스트를 키로 허용했다면 어떤 문제가 생겼을까?
    답

    'x'(튜플은 넣을 때 만든 복사본이라 그대로). 리스트를 키로 넣고 나중에 바꾸면 해시가 바뀌어 원래 칸에서 찾을 수 없고, 같은 내용을 새로 만들어도 다른 칸에 가서 못 찾습니다.

목표

6.1·6.2절의 체이닝 표와 선형 조사 표를 구현하고, 적재율에 따른 평균 조사 횟수를 재어 이론과 비교합니다. 성취기준 [전전2-06-02].

준비

Python 3만 있으면 됩니다(추가 라이브러리 없음). 아래 코드를 hash_lab.py로 저장합니다.

import random

class ChainHash:
    def __init__(self, m):
        self.t = [[] for _ in range(m)]
    def put(self, k, v):
        b = self.t[hash(k) % len(self.t)]
        for i, (kk, _) in enumerate(b):
            if kk == k:
                b[i] = (k, v); return
        b.append((k, v))
    def get(self, k):
        b = self.t[hash(k) % len(self.t)]
        probes = 0
        for kk, v in b:
            probes += 1
            if kk == k:
                return v, probes
        return None, probes

class LinearHash:
    def __init__(self, m):
        self.keys = [None] * m
        self.vals = [None] * m
    def put(self, k, v):
        m, i = len(self.keys), hash(k) % len(self.keys)
        while self.keys[i] is not None and self.keys[i] != k:
            i = (i + 1) % m                     # 다음 칸으로(선형 조사)
        self.keys[i], self.vals[i] = k, v
    def get(self, k):
        m, i, probes = len(self.keys), hash(k) % len(self.keys), 1
        while self.keys[i] is not None:
            if self.keys[i] == k:
                return self.vals[i], probes
            i = (i + 1) % m
            probes += 1
        return None, probes

random.seed(7)
m = 1009                                        # 소수 크기 표
universe = random.sample(range(10**6), 2 * m)
for alpha in (0.25, 0.5, 0.75, 0.9):
    n = int(alpha * m)
    keys, absent = universe[:n], universe[m:m + 500]
    row = []
    for cls in (ChainHash, LinearHash):
        h = cls(m)
        for k in keys:
            h.put(k, k * 2)
        hit = sum(h.get(k)[1] for k in keys) / n
        miss = sum(h.get(k)[1] for k in absent) / len(absent)
        assert all(h.get(k)[0] == k * 2 for k in keys)
        row.append(f"{cls.__name__} 성공 {hit:.2f} 실패 {miss:.2f}")
    print(f"적재율 {alpha}: " + " | ".join(row))

절차

  1. 실행해 출력을 적습니다(시드 7).
  2. 각 줄의 값을 6.1절 이론식(체이닝 1 + α/2와 α, 선형 조사 ½(1 + 1/(1 − α))와 ½(1 + 1/(1 − α)²))과 표로 비교합니다.
  3. m = 1009를 m = 1024로 바꾸고, 키를 모두 짝수(k * 2)로 만들어 다시 실행해 결과가 어떻게 되는지 봅니다.

기대 결과

Python 3.12에서 실행한 출력입니다.

적재율 0.5: ChainHash 성공 1.23 실패 0.52 | LinearHash 성공 1.49 실패 2.41
적재율 0.75: ChainHash 성공 1.38 실패 0.75 | LinearHash 성공 2.65 실패 9.29

  • 체이닝은 성공 1.10~1.47, 실패 0.24~0.89로 이론과 거의 같습니다.
  • 선형 조사는 α = 0.9에서 성공 5.49(이론 5.5), 실패 34.82(이론 50.5)로 급격히 나빠집니다. 실패 탐색은 군집 크기에 민감해 표마다 흔들립니다.
  • 절차 3: Python 정수의 hash(k)는 k 자신이므로 크기 1024 표에 짝수 키만 넣으면 짝수 칸만 씁니다. 같은 방식으로 실행하면 체이닝의 실패 탐색이 α = 0.25에서 0.52, α = 0.9에서 1.73으로 약 두 배가 됩니다(실제 적재율이 두 배인 것과 같음). 선형 조사는 빈 홀수 칸이 덩어리를 끊어 주어 덜 나빠집니다(α = 0.9에서 실패 27.91).
