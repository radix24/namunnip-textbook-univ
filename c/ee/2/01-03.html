이 절에서 배울 것
  • 크기가 고정된 배열을 늘려 가는 동적 배열(Python의 list)이 가끔 비싼 복사를 하는 이유를 안다.

1.3.1배열은 늘어날 수 없다

메모리에서 배열은 연속된 칸이라, 다 차면 바로 뒤 칸이 이미 다른 용도로 쓰이고 있을 수 있습니다. 그래서 동적 배열은 더 큰 새 공간을 잡고 원소를 모두 복사한 뒤 옛 공간을 버립니다. 이 복사는 원소 수에 비례하는 비싼 연산입니다.

크기(size): 실제 원소 수. 용량(capacity): 확보해 둔 칸 수. size = capacity일 때 추가하면 재할당이 일어난다.

분할상환 비용: 연산을 여러 번 했을 때의 총비용을 횟수로 나눈 평균. 확률적 평균이 아니라 최악의 연산 순서에서도 보장되는 평균.

1.3.2두 배 전략의 분석

구하려는 것: 빈 배열(용량 1)에 n번 추가할 때의 총 복사 횟수. 용량이 1, 2, 4, 8, …로 늘 때마다 그때까지의 원소를 모두 복사하므로, 마지막 재할당 때 용량이 \(2^k\)(\(2^k < n\))라면

\[ 1 + 2 + 4 + \cdots + 2^k = 2^{k+1} - 1 < 2n. \]

총 복사가 2n보다 작으므로, 각 추가의 분할상환 비용은 복사 2번 미만 + 쓰기 1번 = O(1)입니다. 직접 세면 n = 8, 1000, 10⁶에서 복사가 7, 1023, 1048575번(한 번당 0.88, 1.02, 1.05번)입니다. n이 2의 거듭제곱을 막 넘은 1025이면 2047번(한 번당 약 2.0번)으로 상한 2에 가장 가깝습니다.

은행원 방법으로 보기. 추가할 때마다 3원을 낸다고 합시다: 1원은 자기 쓰기, 2원은 저축. 용량이 m에서 2m으로 늘 때 복사할 m개 중 새로 들어온 m/2개가 각각 2원씩, 합 m원을 저축해 두었으므로 복사 비용을 정확히 댈 수 있습니다. 저축이 음수가 되는 일이 없으니 한 번당 3원 = O(1)입니다.

예제 1.3.1

용량을 두 배 대신 10칸씩 늘리면(처음 10칸) 1000번, 10000번 추가의 총 복사 횟수는?

풀이. 재할당이 n/10번 일어나고, 그때마다 10, 20, 30, … 개를 복사: \(10(1 + 2 + \cdots + (n/10 - 1)) \approx \frac{n^2}{20}\). 실제로 세면 1000번에 49,500번, 10000번에 4,995,000번 복사합니다. n이 10배일 때 100배이므로 한 번당 O(n)입니다. 두 배 전략(10000번 추가에 16,383번 복사)과 비교하면 약 300배 차이입니다.

1.3.3실제 Python 리스트

CPython 3.12에서 sys.getsizeof로 재보면 빈 리스트에 1000번 append하는 동안 재할당이 28번 일어나고, 용량이 4, 8, 16, 24, 32, 40, 52, 64, 76, 92, …, 1100으로 늘어납니다. 큰 크기에서는 약 1.125배씩 늘리는 방식입니다(구현 세부는 버전마다 다를 수 있음). 배율이 2보다 작아도 일정 비율로 늘리기만 하면 등비수열이라 분할상환 O(1)이 유지되고, 남는 메모리를 줄일 수 있습니다.

흔한 오해(1) "append는 언제나 O(1)": 대부분의 append는 O(1)이지만 재할당이 일어나는 한 번은 O(n)입니다. 실시간 제어처럼 한 번의 지연도 허용되지 않는 곳에서는 미리 용량을 잡아 둡니다. (2) 분할상환을 "평균 경우(확률)"로 착각하기: 입력이 무엇이든 n번의 총비용이 보장된다는 뜻입니다. (3) 삭제할 때 용량이 반으로 줄자마자 줄이면, 경계에서 추가·삭제를 반복할 때 매번 복사가 일어납니다. 1/4로 줄었을 때 반으로 줄이는 식으로 여유를 둡니다.
요약
  1. 동적 배열은 다 차면 더 큰 공간으로 전체를 복사한다.
  2. 일정 비율로 늘리면 n번 추가의 총 복사 < cn → 분할상환 O(1). 일정량씩 늘리면 O(n).
  3. 분할상환 = 최악 순서에서도 보장되는 평균. 한 번의 최악은 여전히 O(n).

1.3.4연습문제

기본

  1. 두 배 전략(처음 용량 1)에서 17번째 추가 때 몇 개를 복사하는가?
    답

    용량 16에서 32로: 16개.

응용

  1. 용량을 1.5배씩 늘리면 n번 추가의 총 복사는 대략 몇 n인가?
    답

    등비합 \(n(1 + 2/3 + 4/9 + \cdots) = 3n\) 정도. 여전히 O(1) 분할상환.

심화

  1. 두 진법 카운터(비트 k개)에 1을 n번 더할 때 뒤집히는 비트 수의 합이 2n 미만임을 보여라.
    답

    비트 0은 매번, 비트 1은 2번에 한 번, 비트 i는 \(2^i\)번에 한 번 뒤집힘. 합 \(n(1 + 1/2 + 1/4 + \cdots) < 2n\). 한 번의 증가는 최악 k비트지만 분할상환 O(1).

1.3.2

탐구append를 천 번 하면 복사는 몇 번?

탐구 · 동적 배열의 용량 전략

다루는 성취기준 [전전2-01-03]

질문

동적 배열이 다 차면 더 큰 공간으로 전부 복사합니다. 용량을 두 배씩 늘리는 것과 일정량씩 늘리는 것은 얼마나 다를까요?

준비

처음 용량 1인 동적 배열에 append를 n번 하면서, 다 찰 때마다 정한 전략으로 용량을 늘리고 그때까지의 원소를 모두 복사한다고 셉니다. 파랑: 선택한 전략의 누적 복사, 회색 점선: 두 배 전략, 연한 점선: 2n 직선.

해 보기와 설명

  1. 두 배1000번에 재할당 10번, 총 복사 1023번(한 번당 1.02번). 가장 큰 한 번의 복사는 512개입니다. 계단 모양이 2n 직선 아래에 있습니다.
  2. 1.5배재할당 17번, 총 복사 2137번(한 번당 2.14번). 비율이 작을수록 복사는 늘지만 남는 메모리는 줄어듭니다.
  3. 10칸씩재할당 100번, 총 복사 49,600번(한 번당 49.6번). 포물선으로 늘어나 n에 비례하는 분할상환 비용이 됩니다. k = 1이면 499,500번입니다.

연결과 적용

Python 리스트, C++ vector, Java ArrayList가 모두 일정 비율로 늘립니다. 크기를 미리 알면 처음부터 그만큼 잡아(예: [None] * n) 재할당을 피합니다.

흔한 오해

  • "두 배 전략이면 append가 늘 빠르다" 평균은 O(1)이지만 재할당이 일어나는 그 한 번은 512개를 복사합니다. 지연이 고르게 필요한 곳에서는 문제가 됩니다.
