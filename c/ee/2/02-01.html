2.1.1무엇을 하는가 vs 어떻게 하는가

추상 자료형(ADT): 자료의 모임과 그 위의 연산을 "무엇을 하는가"로만 정한 것. 예: 리스트 ADT = 위치로 읽기, 넣기, 지우기, 찾기.

자료 구조: ADT를 메모리에 "어떻게" 구현하는가. 같은 리스트 ADT를 배열로도, 연결 리스트로도 만들 수 있다.

사용자는 ADT만 알면 되고, 구현은 연산 비용으로 고릅니다. 이 과목의 나머지가 모두 이 구분 위에 있습니다: 스택·큐(2단원), 우선순위 큐(3단원), 사전(4·6단원)이 ADT이고, 배열·트리·힙·해시 테이블이 구현입니다.

2.1.2배열

배열: 같은 크기의 칸이 메모리에 연속으로 놓인 구조. i번째 칸의 주소 = 시작 주소 + i × 칸 크기.

  • 인덱스 접근 a[i]: 주소를 바로 계산하므로 O(1).
  • i 위치에 삽입: 뒤의 \(n - i\)개를 한 칸씩 밀어야 하므로 O(n − i), 맨 앞이면 O(n). 맨 뒤 추가는 분할상환 O(1)(1.3절).
  • 삭제도 마찬가지로 뒤를 당겨야 함. 정렬되지 않은 배열의 탐색은 O(n).

2.1.3연결 리스트

노드: 값과 다음 노드를 가리키는 참조(포인터)를 담은 작은 객체. 메모리 곳곳에 흩어져 있어도 된다.

단일 연결 리스트: 각 노드가 다음 노드만 가리킨다. 머리(head)에서 시작.

이중 연결 리스트: 앞뒤 노드를 모두 가리킨다. 아는 노드를 O(1)에 지울 수 있다.

class Node:
    def __init__(self, value, next=None):
        self.value = value
        self.next = next

def push_front(head, x):          # 맨 앞 삽입: O(1)
    return Node(x, head)

def insert_after(node, x):        # 아는 노드 뒤에 삽입: O(1)
    node.next = Node(x, node.next)
  • i번째 원소 접근: 머리부터 i번 따라가야 하므로 O(i).
  • 위치(노드)를 이미 알면 삽입·삭제는 참조 두어 개만 바꾸므로 O(1). 원소를 밀 필요가 없다.
  • 노드마다 참조를 담는 추가 메모리가 들고, 흩어져 있어 캐시 효율이 나쁘다.
예제 2.1.1

원소 10만 개가 있는 리스트에서 다음 작업을 1000번 반복한다. 배열과 단일 연결 리스트 중 무엇이 나은가? (가) 맨 앞에 삽입, (나) 무작위 위치 i의 값 읽기, (다) 맨 뒤에 추가(연결 리스트는 꼬리 참조를 유지).

풀이.

작업배열연결 리스트나은 쪽
(가) 맨 앞 삽입매번 10만 개 이동, O(n)O(1)연결 리스트
(나) i번째 읽기O(1)평균 5만 번 따라가기, O(n)배열
(다) 맨 뒤 추가분할상환 O(1)꼬리 참조로 O(1)비슷(배열이 실제로는 빠름)

(가)는 약 1억 번의 이동 대 1000번의 참조 변경입니다. Python에서 맨 앞 삽입이 잦으면 list.insert(0, x) 대신 양쪽 끝이 O(1)인 collections.deque를 씁니다.

흔한 오해(1) "연결 리스트의 삽입은 언제나 O(1)": 넣을 위치의 노드를 이미 알 때만입니다. i번째 위치를 찾는 데 O(i)가 듭니다. (2) "Python list는 연결 리스트다": 동적 배열입니다. 그래서 a[i]가 O(1)이고 a.insert(0, x)가 O(n)입니다. (3) 연결 리스트에서 노드를 지울 때 앞 노드의 참조를 먼저 바꾸지 않고 노드를 버리면 뒤쪽 리스트 전체를 잃습니다.
요약
  1. ADT(무엇) ↔ 자료 구조(어떻게). 구현은 연산 비용으로 고른다.
  2. 배열: 인덱스 O(1), 중간 삽입·삭제 O(n). 연결 리스트: 인덱스 O(n), 아는 위치의 삽입·삭제 O(1).
  3. 양 끝 삽입이 잦으면 deque, 임의 접근이 잦으면 배열.

2.1.4연습문제

기본

  1. 원소 n개 배열의 맨 앞 원소를 지우는 비용은? 연결 리스트는?
    답

    배열 O(n)(당기기), 연결 리스트 O(1)(head = head.next).

응용

  1. 단일 연결 리스트를 뒤집는 함수를 O(n), 추가 메모리 O(1)로 쓰라.
    답

    prev = None; cur = head; while cur: cur.next, prev, cur = prev, cur, cur.next; return prev. 각 노드의 참조를 한 번씩 뒤집습니다.

  2. 단일 연결 리스트에서 꼬리 노드를 지우는 비용은? 이중 연결 리스트에서는?
    답

    단일: 꼬리 앞 노드를 찾아야 해서 O(n). 이중: 꼬리의 prev로 O(1).

심화

  1. 연결 리스트에 고리가 있는지(마지막 노드가 앞쪽 노드를 가리키는지) O(1) 추가 메모리로 판정하는 방법은?
    답

    느린 포인터(한 칸씩)와 빠른 포인터(두 칸씩)를 동시에 움직여 만나면 고리(Floyd 알고리즘). 고리가 없으면 빠른 포인터가 끝에 닿습니다.

2.1.2

탐구중간에 끼워 넣기: 밀까, 따라갈까

탐구 · 배열과 연결 리스트의 삽입 비용

다루는 성취기준 [전전2-02-01]

질문

원소 n개 중 위치 i에 하나를 끼워 넣을 때, 배열과 연결 리스트는 각각 몇 번 일해야 할까요?

준비

위 줄은 배열(칸), 아래 줄은 연결 리스트(노드)입니다. 배열은 i 뒤의 원소를 모두 한 칸씩 밀고(주황), 연결 리스트는 머리부터 i번 따라간 뒤(파랑) 참조 두 개만 바꿉니다. 원소가 많으면 일부만 그립니다.

해 보기와 설명

  1. 앞쪽i = 0이면 배열은 n개를 모두 밀고, 연결 리스트는 머리에 바로 붙입니다(O(1)).
  2. 끝쪽i = n이면 배열은 밀 것이 없고, 꼬리 참조가 없는 연결 리스트는 끝까지 n번 따라가야 합니다.
  3. 합배열의 이동 n − i와 리스트의 따라가기 i를 더하면 늘 n입니다. 어디에 자주 넣는지에 따라 구조를 고릅니다(2.1절 예제).

연결과 적용

문서 편집기는 커서 근처에 연속으로 입력하므로 커서 위치에 빈칸을 모아 둔 배열(갭 버퍼)을 많이 씁니다. 연결 리스트와 배열의 장점을 섞은 구조입니다.

흔한 오해

  • "연결 리스트 삽입은 O(1)이라 언제나 빠르다" 위치를 찾는 따라가기가 O(i)이고, 노드가 메모리에 흩어져 실제 속도는 배열보다 느린 경우가 많습니다.
