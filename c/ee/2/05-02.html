5.2비교 정렬의 하한과 선형 시간 정렬

이 절에서 배울 것
  • 비교만으로 정렬하는 알고리즘을 결정 트리로 나타낸다.
  • 결정 트리의 잎이 n!개 이상이어야 하므로 최악 비교 횟수가 \(\log_2n! = \Omega(n\log n)\)임을 증명한다.
  • 비교하지 않는 계수 정렬과 기수 정렬이 O(n + k)에 정렬할 수 있는 조건을 안다.
먼저 알아야 할 것
  • 병합·퀵 정렬 (5.1절), \(\log n! = \Theta(n\log n)\) (1단원 연습 3), 이진 트리의 높이와 잎 수 (3.1절).

5.2.1더 빠른 정렬이 있을까

병합 정렬은 O(n log n)입니다. 누군가 O(n) 비교 정렬을 발견할 수 있을까요? 이 절은 "원소끼리 비교해서만 순서 정보를 얻는" 모든 알고리즘이 최악 경우 \(\Omega(n\log n)\)번 비교해야 함을 증명합니다. 알고리즘 하나가 아니라 가능한 모든 알고리즘에 대한 주장이라는 점이 중요합니다.

결정 트리: 비교 정렬 알고리즘이 크기 n 입력에 대해 하는 비교를 트리로 펼친 것. 각 내부 노드는 "\(a_i \le a_j\)?" 비교, 두 가지는 그 결과, 각 잎은 하나의 최종 순서(순열).

입력이 정해지면 뿌리에서 잎까지 한 경로를 따라가고, 그 경로의 길이가 비교 횟수입니다. 최악 비교 횟수 = 트리의 높이.

5.2.2하한의 증명

정리 5.2.1

서로 다른 n개를 정렬하는 모든 비교 정렬은 최악 경우 적어도 \(\lceil\log_2n!\rceil\)번 비교한다. 따라서 \(\Omega(n\log n)\).

입력의 서로 다른 순서는 n!가지이고, 올바른 정렬 알고리즘은 각각에 대해 다른 재배치를 해야 하므로 결정 트리에 서로 다른 잎이 적어도 n!개 있어야 합니다. 높이 h인 이진 트리의 잎은 많아야 \(2^h\)개이므로 \(2^h \ge n!\), 곧 \(h \ge \log_2n!\). 1단원 연습 3에서 \(\log n! = \Theta(n\log n)\)이므로 \(h = \Omega(n\log n)\). ∎

예제 5.2.1

n = 3, 4, 5, 1000일 때 하한 \(\lceil\log_2n!\rceil\)을 구하고, 병합 정렬과 비교하라.

풀이. 3! = 6 → 3번, 4! = 24 → 5번, 5! = 120 → 7번. n = 1000이면 \(\lceil\log_2 1000!\rceil = 8530\)번. 5.1절 예제에서 병합 정렬이 무작위 입력에 8707번 비교했으므로 하한보다 약 2%만 많습니다. 병합 정렬이 거의 최적이라는 뜻입니다.

(Stirling 근사 \(\log_2n! \approx n\log_2n - 1.44n\)으로 \(9966 - 1443 \approx 8523\)을 어림할 수 있습니다.)

5.2.3비교하지 않으면 더 빠르다

하한은 비교만 쓰는 알고리즘에 대한 것입니다. 키가 작은 정수라는 추가 정보를 쓰면 피할 수 있습니다.

계수 정렬: 키가 0~k−1의 정수일 때, 값마다 개수를 세고(O(n)), 누적 합으로 각 값의 시작 위치를 정해(O(k)) 제자리에 놓는다. O(n + k), 안정.

기수 정렬: d자리 수를 가장 낮은 자리부터 한 자리씩 안정 정렬(계수 정렬)한다. O(d(n + b)), b는 진법. 32비트 정수를 8비트씩 네 번(b = 256)으로 정렬하면 O(4(n + 256)).

예: 시험 점수(0~100) 100만 개는 계수 정렬로 크기 101 배열에 세어 두 번 훑으면 끝입니다. 비교 정렬로는 하한만 약 1,850만 번 비교가 필요합니다.

흔한 오해(1) "하한 증명이 병합 정렬이 최적이라는 것만 보인다": 아직 발명되지 않은 비교 정렬까지 포함해 모두에 대한 한계입니다. (2) "계수 정렬은 늘 O(n)": k가 n보다 훨씬 크면(예: 64비트 정수, k = 2⁶⁴) 쓸 수 없습니다. (3) 기수 정렬에서 각 자리의 정렬이 안정하지 않으면 앞 자리에서 맞춘 순서가 깨집니다.
요약
  1. 비교 정렬 = 결정 트리. 잎 ≥ n! → 높이 ≥ log₂n! = Ω(n log n).
  2. 병합 정렬(n = 1000에서 8707번)은 하한(8530번)에 매우 가깝다.
  3. 키의 범위를 알면 계수·기수 정렬로 O(n + k).

5.2.4연습문제

기본

  1. 원소 3개를 정렬하는 결정 트리의 잎은 몇 개 이상이고 높이는 얼마 이상인가?
    답

    잎 6개 이상, 높이 3 이상.

응용

  1. [3, 1, 4, 1, 5, 9, 2, 6]을 계수 정렬(k = 10)하는 개수 배열과 결과를 쓰라.
    답

    개수 [0, 2, 1, 1, 1, 1, 1, 0, 0, 1] → [1, 1, 2, 3, 4, 5, 6, 9].

  2. 정렬된 두 리스트(길이 n)를 병합하는 데 비교가 최소 몇 번 필요한가(결정 트리로 어림)?
    답

    가능한 병합 결과는 \(\binom{2n}{n}\)가지 → \(\log_2\binom{2n}{n} \approx 2n - \frac12\log_2(\pi n)\). 병합 알고리즘의 2n − 1번이 거의 최적입니다.

심화

  1. n개 중 최댓값 찾기에는 n − 1번 비교가 필요충분하다. 결정 트리 논법(잎 n개 → 높이 log₂n)이 왜 이 경우 느슨한 하한만 주는지 설명하라.
    답

    결정 트리 논법은 log₂n만 주지만, 실제로는 최댓값이 아닌 n − 1개가 각각 한 번 이상 "져야" 하므로 n − 1번이 필요합니다(적대자 논법). 정보량 하한이 늘 꽉 맞지는 않습니다.

5.2.2

예제세 수를 정렬하는 결정 트리

예제 · 하한이 꽉 맞는 경우

다루는 성취기준 [전전2-05-02]

먼저 예측

서로 다른 세 수 a, b, c를 정렬하는 데 비교가 최악 몇 번 필요할까요? 2번으로 되는 방법이 있을까요?

생각해 본 뒤 열기

최악 3번이 필요합니다. 2번 비교의 결과는 4가지뿐인데 가능한 순서는 6가지라 모두 구별할 수 없습니다.

문제

삽입 정렬로 a, b, c를 정렬하는 결정 트리를 그리고, 잎의 수와 높이를 하한 \(\lceil\log_23!\rceil\)과 비교하라.

전략

  1. 삽입 정렬의 비교 순서: 먼저 a:b, 그다음 c를 앞의 정렬된 둘과 비교.
  2. 각 잎에 최종 순서를 적고 깊이를 센다.

풀이

  1. 뿌리 a:b. a < b이면 [a, b]가 정렬됨. 다음 b:c → b < c면 잎 a<b<c(깊이 2). 아니면 a:c → a < c면 a<c<b, 아니면 c<a<b(깊이 3). 왼쪽 가지
  2. a > b이면 [b, a]. 다음 a:c → a < c면 b<a<c(깊이 2). 아니면 b:c → b<c<a 또는 c<b<a(깊이 3). 오른쪽 가지
  3. 잎 6개 = 3!, 높이 3 = \(\lceil\log_26\rceil = \lceil2.58\rceil\). 하한이 꽉 맞는다. 정리 5.2.1

의미

이 트리는 삽입 정렬 하나의 결정 트리이지만, 어떤 비교 정렬 알고리즘이든 잎 6개를 가진 이진 트리여야 하므로 높이 3 미만이 불가능합니다. 평균 비교 횟수도 (2 + 3 + 3 + 2 + 3 + 3)/6 ≈ 2.67로, 평균 경우의 하한 \(\log_26 \approx 2.58\)에 가깝습니다.

검산

a = 2, b = 1, c = 3을 넣으면 a:b(아니오) → a:c(예) → 잎 b<a<c = 1, 2, 3. 비교 2번. 맞습니다.

이해 확인

네 수를 정렬하는 하한은? 다섯 수는?

답

\(\lceil\log_224\rceil = 5\), \(\lceil\log_2120\rceil = 7\). 다섯 수를 7번에 정렬하는 방법이 실제로 있습니다(병합 삽입 정렬).
