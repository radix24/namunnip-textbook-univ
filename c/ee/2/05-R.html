5.R.1

연습정렬 연습 문제

문제 6 · 계산·구현·증명 · 힌트 2단계

다루는 성취기준 [전전2-05-01] [전전2-05-02]

혼자 풀고, 막히면 힌트 1 → 힌트 2 → 풀이 순서로 여세요.

  1. 계산[38, 27, 43, 3, 9, 82, 10]을 병합 정렬할 때 각 병합 단계의 결과를 쓰라(왼쪽 절반이 더 작게 나뉨: 길이 7 → 3 + 4). [05-01]

    힌트 1

    mid = 3: [38, 27, 43]과 [3, 9, 82, 10].

    힌트 2

    가장 작은 조각부터 병합.

    풀이

    [38] | [27, 43] → [27, 43] → [27, 38, 43]. [3, 9] → [3, 9], [82, 10] → [10, 82] → [3, 9, 10, 82]. 최종 [3, 9, 10, 27, 38, 43, 82].

  2. 계산퀵 정렬(첫 원소 기준)이 [1, 2, 3, 4, 5]에서 하는 비교 횟수와 재귀 깊이는? [05-01]

    힌트 1

    분할마다 n − 1번, 한쪽이 비어 있음.

    힌트 2

    4 + 3 + 2 + 1.

    풀이

    10번(= 5·4/2), 깊이 5. 정렬된 입력이 첫 원소 기준의 최악입니다.

  3. 구현계수 정렬을 안정하게 구현하라(키 0~k−1, 원소는 (키, 이름) 쌍). [05-02]

    힌트 1

    누적 개수로 각 키의 끝 위치.

    힌트 2

    입력을 뒤에서부터 놓으면 안정.

    풀이

    cnt[key]를 세고 누적 합으로 바꾼 뒤, 입력을 뒤에서부터 보며 cnt[key] -= 1; out[cnt[key]] = item. 같은 키 중 뒤에 있던 것이 뒤에 놓여 원래 순서가 유지됩니다. O(n + k).

  4. 판단학생이 "점수(0~100) 1억 개를 정렬하는데 O(n log n)보다 빠를 수 없다"고 했다. 평가하세요. [05-02]

    힌트 1

    하한은 비교 정렬에만.

    힌트 2

    k = 101.

    풀이

    틀렸습니다. 키 범위가 작으므로 계수 정렬로 O(n + 101) = O(n)에 정렬됩니다. 비교 정렬의 하한은 키에 대해 비교 말고 아무 정보도 쓰지 않을 때의 이야기입니다.

  5. 계산32비트 정수 100만 개를 기수 정렬(8비트씩, b = 256)할 때 대략의 연산 수를 병합 정렬과 비교하라. [05-02]

    힌트 1

    네 번의 계수 정렬, 각 O(n + 256).

    힌트 2

    병합은 약 \(n\log_2n\).

    풀이

    기수: 약 \(4(10^6 + 256) \approx 4\times10^6\)번의 원소 이동(각 단계 두 번 훑으면 8×10⁶). 병합: 비교 약 \(2\times10^7\). 몇 배 빠르지만 추가 메모리와 키 종류의 제약이 있습니다.

  6. 도전정렬된 배열에서 값 x를 찾는 모든 비교 알고리즘이 최악 \(\Omega(\log n)\)번 비교해야 함을 결정 트리로 보여라. [05-02]

    힌트 1

    결과(위치 0~n−1 또는 없음)는 n + 1가지.

    힌트 2

    비교(<, =, >)는 세 갈래로 보아도 됨.

    풀이

    잎이 n + 1개 이상 필요하고, 비교 하나가 많아야 3갈래이므로 높이 \(\ge\log_3(n + 1) = \Omega(\log n)\). 이진 탐색이 최적입니다.
