반복 가능한 자료 파이프라인

본문

지난 학기 분석은 한 번 돌리고 보고서를 내면 끝났다. 그런데 이번 프로젝트의 고객 이탈 점수는 매주 월요일 새 자료로 다시 만들어야 한다. 매주 노트북을 열어 셀을 위에서부터 차례로 누르다 보면 무슨 일이 생길까? 그리고 어떻게 해야 매번 같은 방식으로 돌릴 수 있을까?

먼저 알아야 할 것재현 가능성(응통3 6단원)과 변수 만들기(응통11 2.2절)를 쓴다.

처음 질문의 답은 언젠가 셀 하나를 빠뜨리거나 순서를 바꿔, 아무도 모르게 다른 결과를 내게 된다는 것이다. 그래서 손으로 하던 단계를 코드로 묶어, 버튼 하나나 예약으로 처음부터 끝까지 돌게 만든다(그림 1). 이것을 파이프라인이라 한다.

2.1.1단계 나누기

pipeline/
  01_extract.R      # 데이터베이스에서 원자료 추출 → data/raw/날짜.parquet
  02_clean.R        # 정제 규칙 적용 → data/clean/
  03_features.R     # 기준일 기준 변수 생성 → data/features/
  04_score.R        # 저장된 모형으로 점수 계산 → output/scores.csv
  05_report.qmd     # 요약 보고서
  run_all.R         # 위를 순서대로 실행, 로그 기록

각 단계는 앞 단계의 결과 파일만 읽고 다음 단계의 입력을 쓴다. 그러므로 중간에 실패해도 그 단계부터 다시 돌릴 수 있다. 또 기준일, 경로, 모형 버전 같은 설정은 한 설정 파일에 두고, 실행 날짜, 행 수, 경고는 기록으로 남긴다. R의 targets나 파이썬의 make, Airflow 같은 도구는 바뀐 단계만 다시 실행해 준다.

2.1.2학습과 적용의 일관성

모형을 학습할 때 쓴 정제 규칙, 변수 규칙과 운영 중 점수를 계산할 때 쓰는 규칙이 다르면 성능이 조용히 무너진다. 따라서 같은 함수를 두 곳에서 부르게 하고, 학습 때 계산한 값을 저장해 적용 때 그대로 쓴다. 표준화의 평균과 표준편차, 범주 목록이 그런 값이다.

예제 2.1.1

학습 때 소득을 표준화했는데, 운영 중에는 매주 새 자료의 평균과 표준편차로 표준화했다. 무엇이 문제인가?

풀이. 같은 소득이 주마다 다른 값으로 바뀌어 모형 입력의 의미가 달라진다. 예를 들어 고소득 고객이 많이 들어온 주에는 평균이 올라가, 같은 소득의 고객이 더 낮은 값으로 입력된다. 그러므로 학습 때의 평균과 표준편차를 저장해 써야 한다(2.4절).

흔한 실수

설정값을 스크립트 여러 곳에 직접 써 두면, 기준일을 바꿀 때 한 곳을 빠뜨려 단계마다 다른 날짜로 계산하게 된다. 설정은 반드시 한 곳에서 읽는다.

마무리

파이프라인은 추출, 정제, 변수, 점수, 보고서를 단계별 스크립트로 나누고 파일로 이어, 처음부터 끝까지 자동으로 돌게 한 것이다. 설정은 한 파일에 두고 실행 기록을 남긴다. 학습과 적용에는 같은 변환 코드와 학습 때 저장한 값을 쓴다.

2.1.3연습문제

기본

  1. 03 변수 단계에서 오류가 났다. 단계를 파일로 이어 둔 구조는 어떤 도움을 주는가?
    답

    01, 02의 결과 파일이 남아 있으므로 03부터 다시 돌리면 된다. 추출을 다시 해 데이터베이스에 부담을 줄 필요가 없다.

응용

  1. 학습 때 범주 목록이 (basic, pro)였는데 운영 코드가 매주 새 자료에서 범주 목록을 다시 만든다. 어떤 문제가 생기는가?
    답

    어떤 주에 pro가 없으면 열이 하나 줄고, 새 범주가 있으면 늘어 모형 입력의 열 순서와 개수가 달라진다. 학습 때의 범주 목록을 저장해 쓴다.

  2. 지난주 점수를 다시 만들어야 한다. 파이프라인에 무엇이 있어야 하는가?
    답

    기준일을 설정으로 받아 그 날짜의 원자료와 그때의 모형 버전으로 돌릴 수 있어야 한다. 실행 기록에 모형 버전이 남아 있으면 같은 결과를 재현할 수 있다.
