  • 수집 → 정제 → 변수 → 모형 → 출력의 단계를 스크립트로 나눈다.
  • 파이프라인을 매번 같은 결과가 나오게 자동화한다.
먼저 알아야 할 것
  • 응통3 06단원 재현 가능성, 응통11 2.2절 변수 만들기.

한 번이 아니라 매주

(1)의 분석은 한 번 하고 끝났지만, 실제 프로젝트의 예측 점수나 대시보드는 매주, 매일 새 자료로 다시 만들어야 합니다. 손으로 하던 단계를 코드로 묶어 버튼 하나(또는 예약)로 처음부터 끝까지 돌게 만든 것이 파이프라인입니다.

2.1.1단계 나누기

pipeline/
  01_extract.R      # 데이터베이스에서 원자료 추출 → data/raw/날짜.parquet
  02_clean.R        # 정제 규칙 적용 → data/clean/
  03_features.R     # 기준일 기준 변수 생성 → data/features/
  04_score.R        # 저장된 모형으로 점수 계산 → output/scores.csv
  05_report.qmd     # 요약 보고서
  run_all.R         # 위를 순서대로 실행, 로그 기록
  • 각 단계는 앞 단계의 결과 파일만 읽고 다음 단계의 입력을 씁니다.
  • 설정(기준일, 경로, 모형 버전)은 한 설정 파일에 둡니다.
  • 실행 날짜, 행 수, 경고를 로그로 남깁니다.
  • R의 targets, 파이썬의 make/Airflow 같은 도구는 바뀐 단계만 다시 실행해 줍니다.

2.1.2학습과 적용의 일관성

모형 학습 때 쓴 정제·변수 규칙과 운영 중 점수 계산 때 쓰는 규칙이 다르면 성능이 조용히 무너집니다. 같은 함수를 두 곳에서 부르게 하고, 학습 때 계산한 값(표준화의 평균·표준편차, 범주 목록)을 저장해 적용 때 그대로 씁니다.

요약
  1. 단계별 스크립트, 파일로 연결, 설정 분리, 로그.
  2. 처음부터 끝까지 자동 실행.
  3. 학습과 적용에 같은 변환 코드와 저장된 값.

2.1.2연습문제

기본

  1. 학습 때 소득을 표준화했는데 운영 중에 매주 새 자료의 평균으로 표준화했습니다. 무엇이 문제인가요?
    답

    같은 소득이 주마다 다른 값으로 바뀌어 모형 입력의 의미가 달라집니다. 학습 때의 평균·표준편차를 저장해 써야 합니다.
