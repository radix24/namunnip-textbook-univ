끝난 뒤에 배운다

프로젝트가 끝나면 다음 일로 바로 넘어가기 쉽지만, 무엇이 잘 되고 무엇이 어려웠는지 정리해 두지 않으면 같은 실수를 되풀이합니다.

4.2.1회고

  1. 목표와 결과 비교: 처음 합의한 지표와 실제 결과.
  2. 잘 된 것: 계속할 것.
  3. 어려웠던 것: 원인(자료 접근 지연, 범위 변경, 기술 문제)을 사람 탓이 아니라 과정의 문제로.
  4. 바꿀 것: 다음 프로젝트에서 구체적으로 다르게 할 일과 담당.

4.2.2인수인계와 운영

  • README: 목적, 자료 출처, 파이프라인 실행 방법, 의존 패키지.
  • 모형 카드: 학습 자료와 기간, 성능(집단별 포함), 알려진 한계, 쓰면 안 되는 상황.
  • 운영 계획: 성능·자료 품질 감시 지표, 재학습 주기와 조건, 장애 시 담당자.
예제 4.2.1

회고에서 "자료 접근 승인이 3주 걸려 일정이 밀렸다"가 나왔습니다. 개선점을 구체적으로 쓰세요.

풀이. "다음 프로젝트부터 착수 회의 전에 필요한 테이블 목록과 접근 신청서를 미리 제출한다(담당: 분석 리드). 보안팀과 표준 승인 양식을 만들어 평균 승인 기간을 1주 이내로 줄인다."

요약
  1. 목표 대비 결과, 잘된 것, 어려운 것, 바꿀 것.
  2. 원인은 과정에서 찾고 개선은 구체적으로.
  3. README, 모형 카드, 운영 계획을 남김.
