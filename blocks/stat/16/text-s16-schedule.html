정기 실행과 실패 알림

본문
이 절에서 배울 것
  • cron 표현식으로 정기 실행 일정을 정한다.
  • 다시 실행해도 결과가 같은(멱등) 작업을 설계한다.
  • 재시도와 실패 알림, 실행 기록을 갖춘다.
먼저 알아야 할 것
  • 파이프라인 객체 (2.4절), 반복 가능한 절차 (2.1절).

사람이 매일 버튼을 누르면 언젠가는 잊는다

매일 아침 자료를 받아 정제하고 예측 명단을 만드는 일은 자동으로 돌아가야 합니다. 자동화의 핵심은 "정해진 때에 실행된다", "실패하면 누군가 안다", "다시 돌려도 망가지지 않는다" 세 가지입니다.

2.5.1일정: cron

cron 표현식은 "분 시 일 월 요일" 다섯 칸입니다. 0 6 * * *는 매일 6시 0분, 30 7 * * 1은 매주 월요일 7시 30분, 0 2 1 * *는 매월 1일 2시입니다. 작업 사이의 의존(자료 적재가 끝나야 예측)이 있으면 Airflow 같은 작업 관리 도구로 순서를 지정합니다.

2.5.2멱등성

같은 날짜의 작업을 두 번 돌려도 결과가 한 번 돌린 것과 같아야 합니다. "결과 표에 추가(append)"는 재실행 때 중복을 만들므로, "그 날짜의 결과를 지우고 다시 쓰기(덮어쓰기)"로 설계합니다. 작업은 실행 시각이 아니라 처리할 날짜를 인자로 받아, 지난 날짜도 다시 처리할 수 있게 합니다.

2.5.3재시도, 알림, 기록

  • 일시적 오류(네트워크)는 간격을 늘려 가며 몇 번 재시도합니다.
  • 끝내 실패하면 담당자에게 메신저나 메일로 알립니다.
  • 성공해도 결과가 이상하면(행 수가 평소의 절반 등) 알립니다. 2.2절의 품질 기준을 자동 점검으로 넣습니다.
  • 실행 시각, 입력 행 수, 소요 시간, 결과를 기록합니다.
예제 2.5.1

재시도 간격을 1분에서 시작해 두 배씩 늘리며 최대 4번 재시도합니다. 모두 실패하면 첫 실패부터 알림까지 몇 분이 걸리나요?

풀이. \(1 + 2 + 4 + 8 = 15\)분(작업 실행 시간 제외). 예측 명단이 8시까지 필요하고 작업이 6시에 시작하면 충분한 여유가 있습니다.

요약
  1. cron: 분 시 일 월 요일.
  2. 날짜 단위 덮어쓰기로 멱등하게.
  3. 재시도, 실패와 이상 결과 알림, 실행 기록.

2.5.4연습문제

기본

  1. 평일(월~금) 오전 9시에 실행하는 cron 표현식은?
    답

    0 9 * * 1-5.

응용

  1. 작업이 "오늘 날짜"를 내부에서 계산하도록 짜여 있습니다. 서버 장애로 사흘 동안 실행되지 않았다면 어떤 문제가 생기나요?
    답

    복구 뒤 실행하면 오늘 날짜만 처리되어 지난 사흘이 빠집니다. 처리할 날짜를 인자로 받으면 빠진 날짜를 하나씩 다시 실행(backfill)할 수 있습니다.
