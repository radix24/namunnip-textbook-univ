배치 예측과 실시간 API

본문
이 절에서 배울 것
  • 배치 예측과 실시간 API의 차이를 안다.
  • 신선도, 지연 시간, 비용으로 배포 방식을 고른다.
  • 배포 전 점검 항목을 정리한다.
먼저 알아야 할 것
  • 회고 (4.2절), 파이프라인 객체 (2.4절), 정기 실행 (2.5절).

모형이 노트북 밖으로 나가는 두 길

학습한 모형이 쓰이려면 예측이 업무 시스템에 전달되어야 합니다. 정해진 때에 대상 전체를 한꺼번에 예측해 표로 넘기는 배치 예측과, 요청이 올 때마다 하나씩 예측해 바로 돌려주는 실시간 API가 있습니다.

4.3.1비교

배치 예측실시간 API
예측 시점매일 밤 등 정기요청 즉시
입력 신선도마지막 실행 시점요청 시점
지연 시간 요구느슨함(몇 시간)엄격함(수십~수백 ms)
운영 부담작음(2.5절의 정기 작업)큼(서버, 확장, 장애 대응)
예이탈 위험 명단, 수요 예측사기 탐지, 실시간 추천

결정이 하루 단위로 이루어지면 배치로 충분합니다. 예측 대상이 요청 순간에야 정해지거나(새 거래), 몇 초 전의 행동이 예측에 중요하면 실시간이 필요합니다.

4.3.2배포 전 점검

  • 학습과 운영에서 같은 파이프라인 객체와 패키지 버전을 쓰는가.
  • 운영 입력으로 계산한 예측이 오프라인 예측과 같은가(같은 사례 몇 개로 대조).
  • 입력이 비거나 이상할 때의 동작(기본값, 오류 응답)이 정해져 있는가.
  • 이전 모형으로 되돌리는 방법이 있는가.
예제 4.3.1

고객 200만 명의 이탈 점수를 매일 계산합니다. 초당 5000건을 예측할 수 있다면 배치 실행에 몇 분이 걸리나요?

풀이. \(2\,000\,000/5000 = 400\)초, 약 6.7분. 매일 밤 실행해도 아침 업무 전에 충분히 끝나므로 이탈 점수에는 배치가 알맞습니다.

요약
  1. 배치: 정기적, 단순. 실시간: 즉시, 복잡.
  2. 결정의 주기와 필요한 입력 신선도로 고릅니다.
  3. 배포 전 대조, 예외 처리, 되돌리기를 준비합니다.

4.3.3연습문제

기본

  1. 상품 추천을 하루 한 번 배치로 계산하면 어떤 한계가 있나요?
    답

    오늘 방금 본 상품이 추천에 반영되지 않고, 오늘 가입한 신규 고객에게는 추천이 없습니다. 기본 추천은 배치로, 최근 행동 반영은 가벼운 실시간 보정으로 나누는 절충도 가능합니다.

응용

  1. 배포 후 운영 예측과 오프라인 예측이 일부 고객에서 다릅니다. 가장 먼저 의심할 원인은?
    답

    학습과 운영의 전처리나 입력 변수 계산 방식의 차이(training-serving skew)입니다. 같은 고객의 입력 변수 값을 두 경로에서 뽑아 열마다 비교합니다.
