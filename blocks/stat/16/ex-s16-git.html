병합 충돌 해결하기

예제 · 충돌 판단

먼저 읽는 법

충돌 표시 위쪽(HEAD)은 내 브랜치, 아래쪽은 합치려는 브랜치의 내용이다. 기계적으로 한쪽을 고르지 말고, 두 변경의 의도를 확인해 합친다.

문제. 내 브랜치에서는 결측 처리를 바꿨고, 동료는 같은 줄에 새 변수를 추가해 다음 충돌이 났다. 어떻게 해결하나요?

<<<<<<< HEAD
df["income"] = df["income"].fillna(df["income"].median())
=======
df["income"] = df["income"].fillna(0)
df["log_income"] = np.log1p(df["income"])
>>>>>>> main

풀이

  1. 내 변경의 의도: 결측을 0 대신 중앙값으로. 동료의 의도: 로그 소득 변수 추가.
    두 의도는 서로 다름.
  2. 둘 다 살려 fillna(median) 다음 줄에 log_income을 둔다. 표시 세 줄을 지운다.
    의도를 합침.
  3. 코드와 테스트를 실행해 확인한 뒤 git add, git commit으로 병합을 마친다.
    실행 확인.

검산

합친 뒤 소득이 결측이던 행의 log_income이 \(\log(1 + \text{중앙값})\)인지 확인한다. 동료의 코드는 0을 가정했으므로(\(\log 1 = 0\)), 결측 처리가 바뀐 사실을 동료에게 알려 다른 곳에서 0을 가정하지 않았는지 확인한다.

의미

충돌은 "누가 맞나"보다 "두 사람이 무엇을 하려 했나"의 문제이다. 분석 코드에서는 겉보기에 잘 합쳐져도 전처리 가정이 바뀌어 결과가 달라질 수 있으므로, 병합 후 핵심 결과(행 수, 평균, 검증 성능)를 다시 확인하는 습관이 필요하다.
