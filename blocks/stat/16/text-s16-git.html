Git 브랜치와 코드 리뷰

본문

팀원 세 명이 같은 분석 코드를 고친다. 공유 폴더에는 최종.R, 최종_수정.R, 최종_진짜최종_v3.R이 쌓이고, 누가 무엇을 왜 바꿨는지 아무도 모른다. 여럿이 같은 코드를 안전하게 고치려면 어떻게 해야 할까?

먼저 알아야 할 것프로젝트 일정(1.3절)과 재현 가능한 보고서(응통3 6장)를 쓴다.

처음 질문의 답은 버전 관리 도구 Git이다. Git은 모든 변경의 이력을 남기고, 브랜치로 각자의 작업을 분리했다가 검토한 뒤 합치게 해 준다(그림 1). 그래서 누가 무엇을 왜 바꿨는지 언제든 확인할 수 있고, 잘못된 변경은 되돌릴 수 있다.

1.4.1기능 브랜치 흐름

git switch main
git pull                          # 최신 main 받기
git switch -c feature/churn-features
# ... 코드 수정 ...
git add src/features.py
git commit -m "가입 기간 변수 추가"
git push -u origin feature/churn-features
# 웹에서 병합 요청(pull request) 열기

main은 언제나 실행되는 상태로 두고, 모든 변경은 브랜치에서 하고 리뷰를 거쳐 합친다. 커밋은 하나의 논리적 변경 단위로 작게 나누고, 메시지에는 무엇을 왜 바꿨는지 쓴다.

1.4.2분석 코드 리뷰

분석 코드의 리뷰는 일반 소프트웨어와 보는 곳이 조금 다르다. 먼저 재현성, 곧 난수 시드, 패키지 버전, 경로가 고정되어 있는지 본다. 다음으로 검증 자료나 미래 정보가 학습에 들어가는 정보 누수(2.3절)가 없는지, 결합 뒤 행 수가 맞는지 확인한다. 또 비밀번호나 개인정보(1.2절)가 코드나 커밋에 없는지, 큰 자료 파일을 저장소에 넣지 않았는지(.gitignore) 살핀다.

예제 1.4.1

리뷰 중 df = pd.read_csv("C:/Users/kim/Desktop/data.csv")와 시드 없는 랜덤 포레스트 model.fit(X, y)를 발견했다. 어떤 의견을 남기는가?

풀이. 개인 컴퓨터 경로는 다른 사람이 실행할 수 없으므로 설정 파일이나 상대 경로로 바꾸도록 요청한다. 또 랜덤 포레스트는 실행마다 결과가 달라지므로 random_state를 고정하도록 요청한다.

1.4.3병합 충돌

두 브랜치가 같은 줄을 다르게 고치면 Git은 자동으로 합치지 못하고, <<<<<<<, =======, >>>>>>> 표시로 두 내용을 보여 준다. 그러면 어느 쪽이, 또는 둘을 합친 것이 맞는지 판단해 표시를 지우고 커밋한다. 충돌을 줄이려면 브랜치를 오래 두지 말고 main을 자주 받아 합친다.

흔한 실수

비밀번호가 든 설정 파일을 커밋해 원격에 올린 뒤 파일을 지우는 새 커밋만 하면, 비밀번호는 이력에 그대로 남는다. 따라서 비밀번호를 즉시 바꾸고, 필요하면 관리자와 함께 이력에서 제거하며, 앞으로는 설정 파일을 .gitignore에 넣는다.

마무리

main은 늘 실행되는 상태로 두고, 작업은 기능 브랜치에서 작은 커밋으로 하며, 병합은 리뷰를 거친다. 분석 코드 리뷰는 재현성, 정보 누수, 자료 단위, 비밀 정보를 본다. 충돌은 자주 합쳐 줄이고, 생기면 내용을 판단해 해결한다.

1.4.4연습문제

기본

  1. 커밋 메시지 "수정"과 "가입 기간 변수 추가, 이탈과 관련이 커서"의 차이는 무엇인가?
    답

    앞의 것은 무엇을 왜 바꿨는지 알 수 없다. 뒤의 것은 변경 내용과 이유를 담아, 나중에 이력을 볼 때 판단 근거가 된다.

응용

  1. 노트북(.ipynb) 파일은 리뷰하기 어렵다. 왜 그런지와 대안을 써라.
    답

    출력과 메타데이터가 JSON으로 저장되어 변경 내용이 길고 읽기 어렵다. 핵심 로직은 .py 모듈로 옮기고 노트북은 호출과 시각화만 하게 하거나, 출력을 지우고 커밋하는 도구를 쓴다.

  2. 두 팀원이 같은 전처리 함수의 결측 처리 줄을 각각 평균 대치와 중앙값 대치로 고쳐 충돌이 났다. 어떻게 해결하는가?
    답

    어느 쪽이 맞는지는 Git이 아니라 분석 판단의 문제이다. 두 사람이 자료의 치우침을 근거로 하나를 고르거나 설정으로 선택하게 만들고, 결정 이유를 커밋 메시지에 남긴다.
