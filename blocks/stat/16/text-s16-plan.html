(2)는 (1)에서 익힌 단계를 실제 프로젝트 규모로 넓힙니다. 프로젝트에는 요청자, 자료를 가진 부서, 결과를 쓸 현장, 보안·법무 담당까지 여러 사람이 얽혀 있고, 이들의 요구가 서로 다를 수 있습니다.

1.1.1이해관계자와 요구

이해관계자관심
요청 부서(마케팅)캠페인 효율, 빠른 결과
자료 담당(IT)시스템 부하, 접근 권한
현장 사용자(상담원)쓰기 쉬운 형태, 업무 변화 최소
법무·보안개인정보, 규제 준수

면담으로 각자의 성공 기준을 듣고, 겹치는 것과 충돌하는 것을 정리해 우선순위를 요청자와 합의합니다.

1.1.2계획

CRISP-DM 같은 표준 과정(사업 이해 → 자료 이해 → 자료 준비 → 모델링 → 평가 → 배포)을 틀로 단계와 산출물, 일정, 위험을 적습니다. 처음부터 완벽을 노리기보다 2~3주 안에 작동하는 최소 결과(기준 모형, 대략적 대시보드)를 보여 주고 피드백으로 고쳐 가는 방식이 실패 위험을 줄입니다.

예제 1.1.1

8주짜리 "고객 상담 요청 분류 자동화" 프로젝트의 단계별 일정을 세우세요.

풀이. 1~2주: 요구 면담, 범위·지표 합의, 자료 접근 승인. 3주: 자료 탐색과 품질 점검, 기준 규칙(키워드) 성능 측정. 4~5주: 모형 개발과 교차검증. 6주: 현장 상담원과 시험 운영, 오분류 사례 검토. 7주: 개선과 배포 준비, 성능 감시 설계. 8주: 최종 보고와 인수인계.

요약
  1. 이해관계자별 관심과 성공 기준을 모음.
  2. 표준 과정으로 단계·산출물·일정·위험을 계획.
  3. 빨리 작은 결과를 보이고 고쳐 감.

1.1.2연습문제

기본

  1. 요청 부서는 "모든 고객"을, IT는 "최근 1년만"을 원합니다. 어떻게 조율하나요?
    답

    분석 목적에 필요한 최소 기간을 근거(계절성, 표본 크기)로 제시하고, 1년 자료로 시작해 결과가 기간에 민감한지 확인한 뒤 필요하면 넓힙니다.
