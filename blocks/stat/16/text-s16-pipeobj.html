파이프라인 객체

본문

학습 노트북에서는 결측을 중앙값으로 채우고 범주를 원핫 인코딩했다. 그런데 운영 코드를 다른 사람이 다시 짜면서 중앙값을 새 자료에서 다시 계산했고, 범주 순서도 바뀌었다. 오류는 하나도 나지 않았다. 예측은 맞게 나오고 있을까?

먼저 알아야 할 것정보 누수(2.3절)와 파이썬 객체(응통4 2장)를 쓴다.

처음 질문의 답은 조용히 틀리고 있다는 것이다. 중앙값과 범주 목록은 모형의 일부인데 코드 밖에 흩어져 있었기 때문이다. 파이프라인 객체는 전처리의 학습된 값까지 모형과 함께 한 객체로 묶어 저장해 이 문제를 없앤다(그림 1).

2.4.1scikit-learn의 파이프라인

from sklearn.pipeline import Pipeline
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.linear_model import LogisticRegression

num = Pipeline([("impute", SimpleImputer(strategy="median")),
                ("scale", StandardScaler())])
cat = OneHotEncoder(handle_unknown="ignore")
prep = ColumnTransformer([("num", num, ["income", "tenure"]),
                          ("cat", cat, ["plan", "region"])])
model = Pipeline([("prep", prep), ("clf", LogisticRegression())])

model.fit(X_train, y_train)        # 중앙값, 평균, 범주 목록을 학습 자료로 계산
p = model.predict_proba(X_new)     # 같은 값으로 변환 후 예측

fit은 각 단계의 값을 학습 자료로 계산하고, predict는 그 값을 그대로 쓴다. 또 열 종류마다 다른 전처리는 ColumnTransformer로 지정한다. 그리고 교차검증에 파이프라인 전체를 넣으면 겹마다 전처리가 다시 학습되므로 2.3절의 전처리 누수도 막힌다. R에서는 recipes와 workflows 패키지가 같은 역할을 한다.

2.4.2저장과 재사용

학습한 파이프라인을 joblib.dump(model, "model.joblib")로 저장하면, 운영 코드는 불러와 predict만 하면 된다. 다만 패키지 버전이 다르면 불러오지 못하거나 결과가 달라질 수 있으므로 버전도 함께 기록한다.

예제 2.4.1

학습 자료의 plan은 basic과 pro 두 범주였는데, 운영에서 새 범주 premium이 들어왔다. handle_unknown="ignore"이면 어떻게 처리되는가?

풀이. basic과 pro 두 열이 모두 0인 행으로 변환되어 오류 없이 예측한다. 반면 기본값 "error"이면 예측이 실패한다. 그런데 새 범주가 많아지면 성능이 떨어지므로, 새 범주의 비율을 4.4절의 감시 항목에 넣는다.

흔한 실수

교차검증 전에 전체 자료에 StandardScaler().fit_transform을 먼저 적용하면 각 겹의 검증 자료가 평균과 표준편차 계산에 들어가 누수가 생긴다. 그러므로 파이프라인을 cross_val_score에 넣어 겹마다 학습시킨다.

마무리

파이프라인 객체는 전처리와 모형을 한 객체로 묶어, fit은 학습 자료로 값을 계산하고 predict는 그 값을 쓰게 한다. 열 종류별 전처리는 ColumnTransformer로 지정하고, 파이프라인 전체를 저장하며 패키지 버전을 기록한다.

2.4.3연습문제

기본

  1. 파이프라인을 fit한 뒤 중앙값 대치 단계가 기억하는 값은 무엇인가?
    답

    학습 자료에서 계산한 income과 tenure의 중앙값이다. 새 자료의 결측은 이 값으로 채운다.

응용

  1. 로그 변환 뒤 표준화를 파이프라인에 넣으려면 어떻게 하는가?
    답

    FunctionTransformer(np.log1p)를 StandardScaler 앞 단계로 넣는다. 로그 변환은 학습할 값이 없지만 파이프라인 안에 두어야 운영에서도 빠짐없이 적용된다.

  2. 운영 서버의 scikit-learn 버전이 학습 때와 다르다는 경고가 떴다. 어떻게 하는가?
    답

    학습 때의 버전을 기록해 둔 대로 운영 환경을 맞추거나, 새 버전에서 다시 학습해 검증한 뒤 함께 배포한다. 경고를 무시하면 예측이 조용히 달라질 수 있다.
