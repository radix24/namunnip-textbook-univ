파이프라인 객체

본문
이 절에서 배울 것
  • 전처리와 모형을 하나의 파이프라인 객체로 묶는다.
  • 열의 종류마다 다른 전처리를 적용한다.
  • 학습한 파이프라인을 저장해 새 자료에 그대로 적용한다.
먼저 알아야 할 것
  • 정보 누수 (2.3절), 파이썬 객체 (응통4 2장).

학습 때와 운영 때의 전처리가 다르면

학습 노트북에서는 결측을 중앙값으로 채우고 범주를 원핫 인코딩했는데, 운영 코드를 다른 사람이 다시 짜면서 중앙값을 새 자료에서 다시 계산하거나 범주 순서가 바뀌면 예측이 조용히 틀어집니다. 파이프라인 객체는 전처리의 "학습된 값"까지 모형과 함께 저장해 이 문제를 없앱니다.

2.4.1scikit-learn의 파이프라인

from sklearn.pipeline import Pipeline
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.linear_model import LogisticRegression

num = Pipeline([("impute", SimpleImputer(strategy="median")),
                ("scale", StandardScaler())])
cat = OneHotEncoder(handle_unknown="ignore")
prep = ColumnTransformer([("num", num, ["income", "tenure"]),
                          ("cat", cat, ["plan", "region"])])
model = Pipeline([("prep", prep), ("clf", LogisticRegression())])

model.fit(X_train, y_train)        # 중앙값, 평균, 범주 목록을 학습 자료로 계산
p = model.predict_proba(X_new)     # 같은 값으로 변환 후 예측

fit은 각 단계의 값을 학습 자료로 계산하고, predict는 그 값을 그대로 씁니다. 교차검증에 파이프라인 전체를 넣으면 겹마다 전처리가 다시 학습되어 2.3절의 누수도 막힙니다. R에서는 recipes와 workflows 패키지가 같은 역할을 합니다.

2.4.2저장과 재사용

학습한 파이프라인을 joblib.dump(model, "model.joblib")로 저장하면 운영 코드는 불러와 predict만 하면 됩니다. 패키지 버전이 다르면 불러오지 못하거나 결과가 달라질 수 있으므로 버전도 함께 기록합니다.

예제 2.4.1

학습 자료의 plan은 basic, pro 두 범주였는데 운영에서 새 범주 premium이 들어왔습니다. handle_unknown="ignore"이면 어떻게 처리되나요?

풀이. basic, pro 두 열이 모두 0인 행으로 변환되어 오류 없이 예측합니다. 기본값("error")이면 예측이 실패합니다. 다만 새 범주가 많아지면 성능이 떨어지므로 4.4절의 감시 항목에 넣습니다.

요약
  1. 전처리와 모형을 한 객체로: fit은 학습 자료로, predict는 그 값으로.
  2. 열 종류별 전처리는 ColumnTransformer.
  3. 파이프라인 전체를 저장하고 버전을 기록합니다.

2.4.3연습문제

기본

  1. 교차검증 전에 전체 자료에 StandardScaler().fit_transform을 먼저 적용하면 어떤 문제가 있나요?
    답

    각 겹의 검증 자료가 평균과 표준편차 계산에 들어가 누수가 생깁니다. 파이프라인을 cross_val_score에 넣어 겹마다 학습시킵니다.

응용

  1. "로그 변환 후 표준화"를 파이프라인에 넣으려면 어떻게 하나요?
    답

    FunctionTransformer(np.log1p)를 StandardScaler 앞 단계로 넣습니다. 로그 변환은 학습할 값이 없지만 파이프라인 안에 두어야 운영에서도 빠짐없이 적용됩니다.
