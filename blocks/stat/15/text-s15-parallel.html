병렬 계산과 재현 가능한 난수

본문

모의실험 하나에 20분이 걸린다. 코어 4개로 나눠 돌렸더니 6.5분, 16개로는 3.1분이었다. 코어를 네 배 늘렸는데 시간은 절반밖에 줄지 않았다. 왜 그럴까? 그리고 코어 수를 바꿔 돌렸더니 결과의 넷째 자리가 달라졌다면 무엇이 잘못된 것일까?

먼저 알아야 할 것벡터화와 프로파일링(6.1절)과 모의실험 연구(6.2절)를 쓴다.

처음 질문의 답은 병렬화할 수 없는 부분이다. 20분 가운데 자료 읽기 2분은 코어가 몇 개든 그대로 걸리므로, 코어를 늘릴수록 그 2분이 전체를 좌우한다(그림 1). 또 결과가 달라진 것은 난수를 작업에 나눠 주는 방식이 재현되지 않았기 때문이다. 모의실험의 반복 1만 번은 서로 독립이라 여러 코어에 나누기 쉽지만, R은 기본적으로 코어 하나만 쓰므로 나누는 일은 직접 해야 한다.

6.3.1암달의 법칙

전체 작업 가운데 병렬화할 수 있는 비율이 \(f\)이고 코어가 \(k\)개면, 속도 향상은 최대 다음과 같다.

\[ S = \frac{1}{(1 - f) + f/k} \]

그러므로 \(f = 0.9\)이면 코어를 무한히 늘려도 10배가 한계이다. 게다가 작업을 나누고 결과를 모으는 비용이 더해지므로, 반복 하나가 아주 짧으면 여러 개를 묶어 한 작업으로 보낸다. 또 순서로는 먼저 6.1절대로 벡터화해 한 코어의 속도를 높이는 것이 앞선다.

예제 6.3.1

모의실험 하나가 자료 읽기 2분(병렬 불가)과 반복 계산 18분으로 이루어져 있다. 코어 4개와 16개로는 각각 얼마나 걸리는가?

풀이. \(f = 0.9\)이다. 코어 4개는 \(2 + 18/4 = 6.5\)분(3.1배), 16개는 \(2 + 18/16 = 3.1\)분(6.4배)이다(그림 1). 즉 코어를 4배 늘렸지만 시간은 절반만 줄었다. 따라서 자료 읽기를 미리 한 번만 해 두는 것이 코어를 더 사는 것보다 효과적이다.

6.3.2난수 흐름

작업마다 set.seed(1)을 똑같이 주면 모든 코어가 같은 난수를 써 반복이 독립이 아니게 된다. 그렇다고 시드를 1, 2, 3, …으로 주면 흐름이 겹치지 않는다는 보장이 없다. 반면 R의 "L'Ecuyer-CMRG" 생성기는 한 시드에서 서로 멀리 떨어져 겹치지 않는 흐름을 작업마다 하나씩 만들어 준다. 그래서 코어 수와 상관없이 같은 결과를 다시 얻을 수 있다.

library(parallel)
RNGkind("L'Ecuyer-CMRG"); set.seed(2026)
one <- function(i) { x <- rexp(20); mean(x) - 1 }
res <- mclapply(1:10000, one, mc.cores = 4)   # 윈도에서는 parLapply
mean(unlist(res))

윈도에는 포크가 없으므로 makeCluster와 parLapply를 쓰고, clusterSetRNGStream(cl, 2026)으로 흐름을 배정한다. 이때 작업자에게 필요한 함수와 자료는 clusterExport로 보내야 한다.

흔한 실수

작업자마다 흐름을 하나씩 주면, 반복이 작업자에게 배분되는 방식이 바뀔 때 각 반복이 받는 난수도 바뀐다. 그러므로 코어 수와 무관하게 재현하려면 반복 번호마다 고정된 흐름을 배정하거나, future.apply의 future.seed = TRUE처럼 배분과 무관한 방식을 쓴다.

마무리

독립인 반복은 병렬화하기 쉽지만 속도 향상은 \(1/\{(1 - f) + f/k\}\)로 제한되므로, 병렬화할 수 없는 부분부터 줄인다. 작업마다 겹치지 않는 난수 흐름(L'Ecuyer-CMRG)을 배정하고, 반복 번호에 흐름을 고정하면 코어 수와 무관하게 재현된다. 벡터화가 먼저이고, 짧은 반복은 묶어서 보낸다.

6.3.3연습문제

기본

  1. \(f = 0.99\)이고 코어가 32개일 때 최대 속도 향상은 얼마인가?
    답

    \(1/(0.01 + 0.99/32) = 1/0.0409 = 24.4\)배이다.

응용

  1. 코어 4개로 돌린 결과와 8개로 돌린 결과의 소수 넷째 자리가 다르다. 원인과 해결책은 무엇인가?
    답

    반복이 작업자에게 배분되는 방식이 바뀌면서 각 반복이 받는 난수가 달라졌을 수 있다. 반복 \(i\)에 흐름 \(i\)를 주는 식으로 반복마다 고정된 흐름을 배정하거나, future.seed = TRUE처럼 배분과 무관하게 재현되는 방식을 쓴다.

  2. 예제 6.3.1에서 자료 읽기를 0.5분으로 줄이면 코어 16개의 시간과 속도 향상은 얼마인가?
    답

    \(0.5 + 18/16 = 1.6\)분이고, 원래 18.5분 대비 약 11배이다.
