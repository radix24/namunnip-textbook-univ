효율적 프로그래밍 단원 마무리 연습

문제 7 · 실습·적용·판단 · 힌트 2단계

혼자 풀고, 막히면 힌트 1 → 힌트 2 → 풀이 순서로 여세요. 문제 끝의 [번호]는 다시 볼 절입니다.

  1. 실습1부터 \(10^7\)까지의 제곱합을 for 반복문과 벡터화로 계산하고 시간을 비교하는 R 코드를 쓰세요. 벡터화가 빠른 까닭은 무엇인가요? [06-01]

    힌트 1

    system.time()으로 시간을 잽니다.

    힌트 2

    R의 반복문은 단계마다 해석기 비용이 듭니다.

    풀이 
    n <- 1e7
system.time({ s <- 0; for (i in 1:n) s <- s + i^2 })
system.time(sum((1:n)^2))

    벡터화한 코드가 보통 수십 배 빠릅니다. 반복문은 단계마다 해석기가 명령을 해석하고 객체를 확인하지만, 벡터화 함수는 컴파일된 C 코드 안에서 한 번에 반복하기 때문입니다. (참고로 \(10^7\)의 제곱합은 \(3.3\times10^{20}\)으로 정수 범위를 넘으므로 숫자형으로 계산됩니다.)

  2. 실습느린 분석 스크립트에서 어느 부분이 시간을 잡아먹는지 찾는 방법을 쓰세요. 흔히 발견되는 병목 두 가지도 쓰세요. [06-01]

    힌트 1

    R에는 함수별 실행 시간을 기록하는 도구가 있습니다.

    힌트 2

    반복문 안에서 자료를 키우거나 같은 계산을 되풀이하는 경우가 많습니다.

    풀이

    Rprof()나 profvis::profvis({ ... })로 프로파일링하면 줄·함수별 시간이 나와, 짐작이 아니라 측정으로 병목을 찾을 수 있습니다. 흔한 병목: (1) 반복문 안에서 벡터나 데이터프레임을 c(), rbind()로 키우기(미리 크기를 정해 두면 해결), (2) 반복문 안에서 바뀌지 않는 계산(행렬 분해, 파일 읽기)을 매번 다시 하기.

  3. 적용"정규성이 깨진 지수분포 자료에서 t 검정과 윌콕슨 검정의 제1종 오류 확률"을 비교하는 모의실험 연구를 설계하세요. 요인, 반복 횟수, 평가 지표를 쓰세요. [06-02]

    힌트 1

    요인으로 표본 크기와 분포를 바꿀 수 있습니다.

    힌트 2

    제1종 오류 확률을 0.05 근처에서 ±0.005 정도로 추정하려면 반복이 얼마나 필요할까요?

    풀이

    요인: 표본 크기(10, 30, 100), 분포(정규, 지수, \(t_3\)), 두 집단이 같은 분포(귀무가설 참). 각 조합에서 자료를 생성해 두 검정을 하고 유의수준 0.05에서 기각 비율을 구합니다.

    반복 횟수: 기각률 0.05의 몬테카를로 표준오차는 \(\sqrt{0.05\times0.95/R}\)이므로 \(R = 10000\)이면 0.0022입니다. 평가 지표는 기각률(과 그 표준오차)이고, 검정력 비교라면 대립가설 조건을 추가합니다. 시드와 코드를 기록해 재현 가능하게 합니다.

  4. 적용모의실험 연구 결과를 보고할 때 지켜야 할 점을 세 가지 이상 쓰세요. [06-02]

    힌트 1

    결과의 불확실성(몬테카를로 오차)도 보고해야 합니다.

    힌트 2

    다른 사람이 같은 결과를 얻을 수 있어야 합니다.

    풀이

    (1) 자료 생성 과정, 요인과 수준, 반복 횟수를 구체적으로 쓴다. (2) 결과에 몬테카를로 표준오차를 함께 보고한다. (3) 결과를 표뿐 아니라 그림(요인별 기각률 선 그림)으로 보여 준다. (4) 시드, 코드, 소프트웨어 버전을 공개해 재현 가능하게 한다. (5) 연구한 조건 밖으로 결론을 넓히지 않는다.

  5. 실습다음 코드는 왜 느린지 설명하고 고치세요. [06-01]

    res <- data.frame()
for (i in 1:5000) {
  x <- rnorm(30)
  res <- rbind(res, data.frame(m = mean(x), s = sd(x)))
}
    힌트 1

    rbind는 매번 새 데이터프레임을 만들어 앞의 행을 모두 복사합니다.

    힌트 2

    결과를 담을 벡터를 미리 만들거나, 리스트에 모은 뒤 한 번에 합칩니다.

    풀이

    반복마다 데이터프레임 전체를 복사하므로 총비용이 \(n^2\)에 비례합니다. 데이터프레임 생성 자체도 비쌉니다.

    m <- s <- numeric(5000)
for (i in 1:5000) { x <- rnorm(30); m[i] <- mean(x); s[i] <- sd(x) }
res <- data.frame(m, s)
# 또는 res <- t(replicate(5000, { x <- rnorm(30); c(m = mean(x), s = sd(x)) }))

  6. 판단신뢰구간의 포함 확률(목표 0.95)을 모의실험으로 ±0.005 이내(95% 신뢰)로 추정하려면 반복이 몇 번 필요한지 구하세요. 1000번 반복으로 0.94가 나왔다면 "포함 확률이 명목값보다 낮다"고 말할 수 있나요? [06-02]

    힌트 1

    \(n = 1.96^2\times0.95\times0.05/0.005^2\)입니다.

    힌트 2

    1000번이면 표준오차는 \(\sqrt{0.95\times0.05/1000} \approx 0.0069\)입니다.

    풀이

    약 7300번이 필요합니다. 1000번 반복의 표준오차는 약 0.0069라 0.94는 0.95에서 1.5 표준오차쯤 떨어져 있을 뿐이므로, 포함 확률이 명목값보다 낮다고 단정할 수 없습니다. 반복을 늘리거나 결과를 몬테카를로 신뢰구간(약 [0.926, 0.954])과 함께 보고해야 합니다.

  7. 적용모의실험 연구의 반복 1만 번을 코어 4개로 나누어 실행하려 합니다. 결과를 재현할 수 있게 하려면 난수를 어떻게 다뤄야 하나요? 작업마다 set.seed(1)을 넣으면 무엇이 잘못되나요? [06-03]

    힌트 1

    작업마다 같은 시드를 쓰면 같은 난수열이 나옵니다.

    힌트 2

    겹치지 않는 난수 흐름을 작업마다 하나씩 배정하는 생성기가 있습니다.

    풀이

    작업마다 set.seed(1)이면 네 코어가 같은 난수로 같은 반복을 되풀이해 사실상 2500개의 독립 반복만 얻고, 표준오차를 과소평가합니다.

    RNGkind("L'Ecuyer-CMRG")로 한 시드에서 겹치지 않는 흐름을 만들고(clusterSetRNGStream, mclapply의 자동 배정), 사용한 시드·패키지 버전·코어 배분 방식을 기록합니다.
