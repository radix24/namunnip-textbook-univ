Shiny로 만드는 탐색용 앱

본문

히스토그램의 막대 폭을 바꾸어 보고, 변환을 로그로 했다가 제곱근으로 바꾸고, 특정 집단만 골라 본다. 탐색적 분석은 이런 시도를 수십 번 되풀이한다. 매번 코드를 고쳐 다시 그리는 대신, 슬라이더와 선택 상자를 움직이면 그림이 바로 바뀌는 앱을 만들면 어떨까? R의 Shiny가 그런 도구이다.

먼저 알아야 할 것일변량 분포의 표현(2.1절), 자료 변환(3.1절)을 쓴다.

7.1.1ui와 server

Shiny 앱은 두 부분으로 이루어진다. ui는 화면 배치로, 슬라이더(sliderInput), 선택 상자(selectInput) 같은 입력과 그림 자리(plotOutput)를 정한다. server는 입력 값 input$bins 등을 읽어 출력을 만드는 함수이다. 출력은 renderPlot({...}) 안에서 계산하는데, Shiny는 그 안에서 읽은 입력을 자동으로 추적한다. 따라서 해당 입력이 바뀌면 그 출력만 다시 계산된다. 이것을 반응형 프로그래밍이라 한다.

library(shiny)
ui <- fluidPage(
  sliderInput("bins", "막대 수", 5, 50, 20),
  selectInput("tf", "변환", c("없음", "로그", "제곱근")),
  plotOutput("hist"))
server <- function(input, output) {
  output$hist <- renderPlot({
    x <- faithful$waiting
    if (input$tf == "로그") x <- log(x)
    if (input$tf == "제곱근") x <- sqrt(x)
    hist(x, breaks = input$bins)
  })
}
shinyApp(ui, server)

7.1.2반응식과 공유

여러 출력이 같은 중간 계산(예를 들어 필터링한 자료)을 쓰면 reactive({...})로 한 번만 계산해 두고 함께 쓴다. 그러면 입력이 바뀌어도 필요한 계산만 되풀이된다. 무거운 계산은 버튼을 눌렀을 때만 하도록 eventReactive를 쓴다. 완성한 앱은 shinyapps.io나 사내 서버에 올려 코드를 모르는 사람도 자료를 탐색하게 할 수 있다. 다만 앱은 탐색과 전달의 도구이다. 그래서 앱에서 찾은 패턴은 재현 가능한 스크립트로 다시 확인해야 한다.

예제 7.1.1

위 앱에서 막대 수를 바꾸면 다시 계산되는 것과 그렇지 않은 것을 구별하여라. 자료를 읽는 데 10초가 걸린다면 어떻게 고쳐야 하는가?

풀이. renderPlot이 input$bins와 input$tf를 읽으므로 둘 중 하나가 바뀌면 그림 전체가 다시 그려지고, ui 배치는 그대로이다. 자료 읽기가 renderPlot 안에 있으면 슬라이더를 움직일 때마다 10초씩 걸린다. 그러므로 자료 읽기는 server 함수 밖(앱 시작 때 한 번)으로 옮기고, 변환은 reactive로 분리한다.

마무리

Shiny 앱은 입력과 출력 배치를 정하는 ui와, 입력에 반응해 출력을 계산하는 server로 이루어진다. 출력 안에서 읽은 입력이 자동으로 추적되어 바뀐 입력에 관련된 출력만 다시 계산되며, 공통 계산은 reactive로 묶는다. 앱은 탐색과 공유를 쉽게 하지만, 찾은 결과는 스크립트로 재현해 확인한다.
