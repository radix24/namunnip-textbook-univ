표 결합과 분석 단위

본문
이 절에서 배울 것
  • 표의 한 행이 무엇을 뜻하는지(분석 단위, grain)를 밝힌다.
  • 일대다 결합에서 생기는 중복 집계를 막는다.
  • 결합 전후의 행 수와 키 중복을 점검한다.
먼저 알아야 할 것
  • SQL 결합 (2.3절).

한 행은 무엇인가

"고객 표"는 한 행이 고객 한 명, "주문 표"는 주문 한 건, "주문 상품 표"는 주문 안의 상품 한 줄입니다. 이 단위를 분석 단위(grain)라 합니다. 서로 다른 단위의 표를 결합하면 행이 복제되고, 복제된 행 위에서 합계나 평균을 구하면 숫자가 부풀려집니다.

2.5.1결합의 종류와 행 수

관계결합 후 행 수주의
일대일그대로키가 정말 유일한지 확인
일대다"다" 쪽 행 수"일" 쪽 값이 복제됨
다대다곱으로 폭증대개 키 설계 오류

결합 전에 각 키가 유일한지 SELECT key, COUNT(*) … GROUP BY key HAVING COUNT(*) > 1로 확인하고, 결합 뒤 행 수가 예상과 같은지 봅니다.

2.5.2먼저 집계하고 결합하기

분석 단위가 고객이면, 주문과 상품 표를 각각 고객 단위로 먼저 집계한 뒤 고객 표에 붙입니다. 이렇게 하면 결합이 모두 일대일이 되어 중복이 생기지 않습니다.

예제 2.5.1

고객 표 100행, 주문 표 350행(고객마다 0건 이상)을 customers LEFT JOIN orders로 결합했더니 360행이 나왔습니다. 주문이 없는 고객은 몇 명인가요?

풀이. 주문이 있는 고객의 행은 모두 주문 수만큼(합 350), 주문이 없는 고객은 1행씩 남으므로 \(360 - 350 = 10\)명입니다.

요약
  1. 표마다 한 행의 의미(grain)를 적어 둡니다.
  2. 일대다 결합은 "일" 쪽 값을 복제합니다.
  3. 분석 단위로 먼저 집계한 뒤 일대일로 결합합니다.

2.5.3연습문제

기본

  1. 예제에서 내부 결합(JOIN)을 쓰면 몇 행이 나오나요?
    답

    350행. 주문 없는 고객 10명이 빠집니다.

응용

  1. 고객 표(나이 포함)와 주문 표를 결합한 뒤 AVG(age)를 구했습니다. 무엇이 잘못되었나요?
    답

    주문이 많은 고객의 나이가 여러 번 들어가 "주문 가중 평균 나이"가 됩니다. 고객 평균 나이는 고객 표만으로 구해야 합니다.
