리스트, 튜플, 딕셔너리, 집합

본문

설문 응답 목록, (위도, 경도) 좌표, 단어별 빈도, 중복 없는 고객 ID는 모두 값의 모음이다. 그런데 파이썬에는 모음을 담는 그릇이 네 가지나 있다. 왜 하나로 충분하지 않을까? 고객 100만 명 가운데 한 명이 있는지 확인할 때 어떤 그릇을 쓰면 빠를까?

먼저 알아야 할 것기본 문법(1.1절)을 쓴다.

1.2.1비교

처음 질문의 답은 자료의 성격에 따라 알맞은 그릇이 다르다는 것이다. 네 그릇을 성질로 비교하면 다음과 같다.

구조예순서변경중복쓰임
리스트[3, 1, 3]있음가능허용순서 있는 값 모음
튜플(37.5, 127.0)있음불가허용고정된 묶음, 함수 반환값
딕셔너리{"서울": 3, "부산": 1}삽입 순가능열쇠는 유일열쇠로 값 찾기
집합{3, 1}없음가능없음중복 제거, 포함 여부

둘째 질문의 답도 여기 있다. 원소가 들어 있는지 물을 때 리스트는 처음부터 하나씩 비교하므로 원소 수에 비례해 느리다. 반면 집합과 딕셔너리는 해시로 바로 찾아가 거의 일정한 시간이 걸린다. 그래서 고객 100만 명의 포함 여부는 집합으로 확인한다.

1.2.2내포

그릇은 반복문 대신 내포(comprehension)로 짧게 만들 수 있다.

squares = [x ** 2 for x in range(5)]                 # [0, 1, 4, 9, 16]
evens = [x for x in range(10) if x % 2 == 0]           # [0, 2, 4, 6, 8]
words = "가 나 가 다 나 가".split()
freq = {}
for w in words:
    freq[w] = freq.get(w, 0) + 1                       # {'가': 3, '나': 2, '다': 1}
unique = set(words)                                    # {'가', '나', '다'}
from collections import Counter
Counter(words).most_common(1)                          # [('가', 3)]
예제 1.2.1

학생 이름과 점수 쌍의 목록에서 80점 이상인 학생 이름의 집합과, 이름으로 점수를 찾는 딕셔너리를 만들어라.

records = [("민지", 85), ("서준", 72), ("하윤", 91)]
high = {name for name, s in records if s >= 80}     # {'민지', '하윤'}
score = dict(records)                               # {'민지': 85, ...}
score["하윤"]                                       # 91

풀이. 쌍 하나를 name, s로 풀어 조건에 맞는 이름만 집합 내포로 모은다. 쌍의 목록은 dict로 바로 딕셔너리가 된다.

흔한 실수빈 집합을 {}로 만들면 빈 딕셔너리가 된다. 빈 집합은 set()으로 만든다.
마무리

순서 있는 값 모음은 리스트, 바뀌지 않는 묶음은 튜플, 열쇠로 값을 찾는 표는 딕셔너리, 중복 없는 모음은 집합에 담는다. 포함 여부를 자주 묻는다면 원소 수에 비례해 느린 리스트 대신 거의 일정한 시간에 찾는 집합이나 딕셔너리를 쓴다. 그릇은 내포로 짧게 만들고, 빈도는 Counter로 센다.

1.2.3연습문제

기본

  1. 두 리스트 a = [1, 2, 3, 4], b = [3, 4, 5]에 공통인 원소를 구하여라.
    답

    set(a) & set(b)는 {3, 4}이다.

응용

  1. 튜플은 딕셔너리의 열쇠가 될 수 있지만 리스트는 안 되는 까닭은 무엇인가?
    답

    열쇠는 해시값이 변하지 않아야 하는데, 리스트는 바꿀 수 있어 해시를 정할 수 없기 때문이다. 그래서 (위도, 경도) 같은 좌표를 열쇠로 쓸 때는 튜플을 쓴다.
