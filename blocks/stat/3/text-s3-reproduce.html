본문

"제 컴퓨터에서는 되는데요." 동료에게 분석 폴더를 보냈더니 실행이 안 된다고 한다. 석 달 뒤의 나도 그 폴더를 열면 어느 파일부터 실행해야 할지 모른다. 다른 사람과 미래의 내가 같은 결과를 다시 얻으려면 무엇을 어떻게 정리해야 할까?

먼저 알아야 할 것코드와 결과를 함께 담은 문서(6.1절)를 쓴다.

6.2.1점검 목록

처음 질문의 문제는 대개 파일 경로가 다르거나, 패키지 버전이 다르거나, 실행 순서를 기억해야만 결과가 나오는 코드에서 생긴다. 그래서 여섯 가지를 점검한다.

먼저 그림 1처럼 폴더를 나눈다. data/raw에는 원자료를 두고 절대 고치지 않으며, 정리한 자료는 data/clean, 스크립트는 R/, 그림과 표는 output/에 둔다. 둘째로 경로는 RStudio 프로젝트(.Rproj) 기준의 상대 경로로 쓰고, setwd("C:/...")를 코드에 넣지 않는다. 셋째로 R을 새로 시작한 상태에서 스크립트가 처음부터 끝까지 돌아가는지 확인하며, 이를 위해 작업 공간 저장(.RData)을 끈다. 넷째로 난수를 쓰면 set.seed를 둔다. 다섯째로 sessionInfo() 출력을 남기거나 renv로 패키지 버전을 고정한다(6.3절). 마지막으로 README에 무엇을 어떤 순서로 실행하면 되는지 적는다.

6.2.2버전 관리

이제 코드가 언제 어떻게 바뀌었는지도 기록하자. git은 파일의 변경 이력을 남기는 도구이다.

git init                          # 저장소 만들기
git add R/clean.R report.qmd      # 바뀐 파일 담기
git commit -m "결측 처리 방식 변경"  # 기록
git log --oneline                  # 이력 보기

원자료나 큰 결과 파일은 보통 .gitignore로 빼고 코드만 관리한다. 그러면 결과가 왜 달라졌는지 바뀐 줄을 비교해 찾을 수 있고, GitHub에 올리면 다른 사람과 공유하기도 쉽다.

예제 6.2.1

동료가 내 분석을 돌렸더니 오류가 났다. 확인할 것 세 가지는 무엇인가?

풀이. 첫째, 절대 경로나 폴더에 없는 파일을 가리키고 있지 않은지 본다. 둘째, 동료의 컴퓨터에 패키지가 설치되지 않았거나 버전이 다르지 않은지 본다. 셋째, 내 작업 공간에만 있던 객체를 코드가 쓰고 있지 않은지 본다. 셋째는 내 컴퓨터에서 새 세션을 열고 처음부터 실행해 보면 바로 드러난다.

흔한 실수원자료 파일을 직접 고치면, 어떤 정리를 했는지 기록이 사라져 아무도 그 과정을 되풀이할 수 없다. 원자료는 그대로 두고, 정리는 늘 코드로 해서 정리된 자료를 새 파일로 저장한다.
마무리

"제 컴퓨터에서는 되는" 분석을 누구나 재현하게 하려면, 원자료를 고치지 않는 폴더 구조와 프로젝트 기준 상대 경로를 쓰고, 새 세션에서 처음부터 끝까지 돌아가는지 확인한다. 난수는 set.seed로, 환경은 sessionInfo나 renv로 남기며, README에 실행 순서를 적는다. 코드의 변경 이력은 git으로 관리해 결과가 바뀐 까닭을 추적한다.

6.2.3연습문제

기본

  1. 작업 공간 저장(.RData)을 끄라고 권하는 까닭은 무엇인가?
    답

    지난 세션의 객체가 되살아나면, 코드에 없는 객체 덕분에 돌아가는 분석을 알아채지 못한다. 끄면 코드만으로 결과가 만들어지는지 늘 확인하게 된다.
