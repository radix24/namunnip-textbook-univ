패키지 버전과 실행 환경 기록

본문

6.2절의 점검 목록을 모두 지켰는데도, 1년 뒤 같은 코드를 돌리니 결과가 조금 다르다. 패키지가 업데이트되며 함수의 기본값이 바뀌었거나, R 버전이 바뀌어 난수 생성 방식이 달라졌기 때문이다. 실제로 R 3.6에서 sample의 방식이 바뀐 일이 있었다. 코드 말고 무엇을 더 남겨야 할까?

먼저 알아야 할 것재현 가능한 정리(6.2절)와 문자열과 날짜(2.5절)를 쓴다.

6.3.1환경 기록

처음 질문의 답은 코드와 함께 어떤 환경에서 돌렸는지를 남기는 것이다. 가장 간단한 방법은 다음 두 줄이다.

sessionInfo()           # R 버전, 운영체제, 불러온 패키지와 버전
packageVersion("dplyr") # 특정 패키지 버전

예를 들어 보고서 끝에 sessionInfo() 출력을 붙여 두면 최소한 무엇으로 돌렸는지 알 수 있다.

6.3.2renv로 고정하기

기록에서 한 걸음 더 나아가, 같은 환경을 되살릴 수 있게 하자.

renv::init()       # 프로젝트 전용 패키지 폴더와 renv.lock 생성
renv::snapshot()   # 지금 쓰는 패키지 버전을 renv.lock에 기록
renv::restore()    # 다른 컴퓨터에서 같은 버전으로 설치

패키지 이름과 버전 목록인 renv.lock 파일을 코드와 함께 git에 넣는다(6.2절). 그러면 받은 사람은 restore 한 번으로 같은 패키지 환경을 만든다. 더 엄격하게는 도커 같은 컨테이너로 운영체제까지 고정한다. 그림 1의 층마다 이렇게 맞는 도구가 있다.

6.3.3컴퓨터마다 다른 것

패키지 말고도 컴퓨터마다 다른 것이 네 가지 있다. 먼저 경로는 setwd("C:/Users/나/...") 대신 프로젝트 폴더 기준 상대 경로(here::here("data", "raw.csv"))로 쓴다. 다음으로 난수는 set.seed와 함께 RNGkind() 결과를 기록하고, 병렬 계산에서는 응통15 6.3절처럼 난수 흐름을 고정한다. 로케일은 요일과 월 이름, 정렬 순서, 소수점 기호를 바꾸므로(2.5절) 기록해 둔다. 그리고 인코딩은 한글 파일을 read.csv(..., fileEncoding = "UTF-8")처럼 명시한다.

예제 6.3.1

동료가 보낸 분석 폴더를 실행했더니 could not find function "pivot_longer" 오류가 났다. 원인과 해결을 써라.

풀이. pivot_longer는 tidyr 1.0(2019)에서 생긴 함수이므로, 내 컴퓨터의 tidyr가 오래됐거나 library(tidyr)를 빠뜨렸다. 따라서 폴더에 renv.lock이 있으면 renv::restore()로 동료와 같은 버전을 설치하고, 없으면 동료에게 sessionInfo 기록을 요청한다.

주의패키지를 무조건 최신으로 올리는 것이 늘 좋은 것은 아니다. 진행 중인 분석은 renv로 버전을 고정해 두고, 업데이트는 결과가 바뀌는지 확인하며 따로 한다.
마무리

같은 코드라도 패키지 버전, R 버전과 난수 생성 방식, 운영체제와 로케일이 바뀌면 결과가 달라질 수 있으므로, 코드와 함께 실행 환경을 남긴다. sessionInfo로 버전을 기록하고, renv의 snapshot과 restore로 패키지 환경을 고정하고 되살리며, 더 엄격하게는 컨테이너로 운영체제까지 고정한다. 경로, 시드와 생성 방식, 로케일, 인코딩은 코드 안에 명시한다.

응용

  1. 2018년에 set.seed(1); sample(10, 3)으로 만든 결과를 지금 그대로 재현하려면 어떻게 하는가?
    답

    R 3.6부터 sample의 기본 방식이 바뀌었으므로 RNGkind(sample.kind = "Rounding")을 먼저 실행하고 같은 시드를 쓴다. 이런 일이 있으므로 RNGkind() 결과를 함께 기록한다.
