같은 코드, 다른 결과

6.2절의 점검 목록을 지켜도, 1년 뒤 패키지가 업데이트되어 함수의 기본값이 바뀌거나, R 버전이 바뀌어 난수 생성 방식이 달라지면 결과가 바뀔 수 있습니다(R 3.6에서 sample의 방식이 바뀐 일이 실제로 있었습니다). 코드와 함께 "어떤 환경에서 돌렸는지"를 남겨야 합니다.

6.3.1환경 기록

sessionInfo()           # R 버전, 운영체제, 불러온 패키지와 버전
packageVersion("dplyr") # 특정 패키지 버전

보고서 끝에 sessionInfo() 출력을 붙여 두면 최소한 무엇으로 돌렸는지 알 수 있습니다.

6.3.2renv로 고정하기

renv::init()       # 프로젝트 전용 패키지 폴더와 renv.lock 생성
renv::snapshot()   # 지금 쓰는 패키지 버전을 renv.lock에 기록
renv::restore()    # 다른 컴퓨터에서 같은 버전으로 설치

renv.lock 파일(패키지 이름과 버전 목록)을 코드와 함께 버전 관리(6.2절의 Git)에 넣습니다. 받은 사람은 restore 한 번으로 같은 환경을 만듭니다. 더 엄격하게는 도커 같은 컨테이너로 운영체제까지 고정합니다.

6.3.3컴퓨터마다 다른 것

  • 경로: setwd("C:/Users/나/...") 대신 프로젝트 폴더 기준 상대 경로(here::here("data", "raw.csv")).
  • 난수: set.seed와 함께 RNGkind() 결과를 기록. 병렬 계산은 응통15 6.3절처럼 흐름을 고정.
  • 로케일: 요일·월 이름, 정렬 순서, 소수점 기호가 언어 설정에 따라 다름(2.5절).
  • 인코딩: 한글 파일은 read.csv(..., fileEncoding = "UTF-8")처럼 명시.
예제 6.3.1

동료가 보낸 분석 폴더를 받아 실행했더니 could not find function "pivot_longer" 오류가 났습니다. 원인과 해결을 쓰세요.

풀이. pivot_longer는 tidyr 1.0(2019)에서 생긴 함수라, 내 컴퓨터의 tidyr가 오래됐거나 library(tidyr)를 빠뜨렸습니다. 폴더에 renv.lock이 있으면 renv::restore()로 동료와 같은 버전을 설치하고, 없으면 sessionInfo 기록을 요청합니다.

요약
  1. sessionInfo로 버전을 기록합니다.
  2. renv의 snapshot/restore로 환경을 고정·복원합니다.
  3. 상대 경로, 시드와 생성기, 로케일, 인코딩을 명시합니다.

기본

  1. setwd("C:/Users/kim/project")가 들어간 스크립트의 문제와 대안은?

응용

  1. 2018년에 set.seed(1); sample(10, 3)으로 만든 결과를 지금 그대로 재현하려면?
    답

    R 3.6부터 sample의 기본 방식이 바뀌었으므로 RNGkind(sample.kind = "Rounding")을 먼저 실행하고 같은 시드를 씁니다. 이런 일이 있으니 RNGkind() 결과를 함께 기록합니다.
