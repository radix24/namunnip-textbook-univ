오류 메시지 읽기와 디버깅

본문
이 절에서 배울 것
  • 오류, 경고, 메시지의 차이를 알고 오류 메시지를 읽는다.
  • traceback, browser, print로 문제 위치를 찾는다.
  • stopifnot으로 함수 입력을 점검해 오류를 일찍 드러낸다.
먼저 알아야 할 것
  • 조건, 반복, 함수 (1.2절).

코드는 처음에 거의 틀린다

잘 짠 코드도 처음에는 오류가 납니다. 실력 차이는 오류를 얼마나 빨리 찾느냐에서 납니다. 무작정 고쳐 보기보다, 메시지를 읽고 문제를 작게 줄여 원인을 찾는 순서를 익히면 시간이 크게 줄어듭니다.

1.4.1오류, 경고, 메시지

  • 오류(Error): 실행이 멈춤. 예: object 'x' not found(변수 이름 오타, 아직 만들지 않음), non-numeric argument(문자에 산술 연산).
  • 경고(Warning): 실행은 되지만 결과가 의심스러움. 예: NAs introduced by coercion(as.numeric("1,234")처럼 바꿀 수 없는 문자가 있음). 경고를 무시하면 조용히 틀린 결과가 남습니다.
  • 메시지: 참고 정보.

오류 메시지의 앞부분 Error in f(x) :는 어느 함수에서 났는지, 뒷부분은 무엇이 문제인지 알려 줍니다. 검색할 때는 자기 변수 이름을 뺀 일반적인 부분을 씁니다.

1.4.2위치 찾기

  • traceback(): 오류 직후 실행하면 함수가 호출된 순서를 보여 줘 어느 단계에서 터졌는지 압니다.
  • browser(): 함수 안에 넣으면 그 줄에서 멈춰 변수 값을 직접 볼 수 있습니다. n(다음 줄), c(계속), Q(멈춤). RStudio의 중단점과 같습니다.
  • 문제를 작게: 큰 자료 대신 3~5개 값으로 같은 오류가 나는지 확인하면 원인이 잘 보입니다.

1.4.3미리 막기

se <- function(x) {
  stopifnot(is.numeric(x), length(x) > 1)    # 조건이 거짓이면 즉시 오류
  x <- x[!is.na(x)]
  sd(x) / sqrt(length(x))
}

입력이 잘못되면 엉뚱한 곳에서 이상한 오류가 나는 대신 처음에 분명한 오류가 납니다. tryCatch로 오류를 잡아 대체 값을 돌려줄 수도 있지만, 오류를 숨기지 않도록 조심합니다.

예제 1.4.1

se <- function(x) sd(x) / sqrt(length(x))에 c(2, 4, NA, 6)을 넣으면 결과가 NA입니다. 원인을 찾고 고치세요.

풀이. sd(c(2, 4, NA, 6))이 결측 때문에 NA. sd(x, na.rm = TRUE)로만 고치면 표준편차는 2이지만 length(x)가 4라 \(2/\sqrt4 = 1\)로 틀립니다. 결측을 먼저 빼고(x <- x[!is.na(x)]) 계산하면 \(2/\sqrt3 = 1.155\). 오류가 나지 않는 버그가 더 위험하다는 예입니다.

요약
  1. 오류는 멈추고, 경고는 의심하고, 메시지는 참고합니다.
  2. traceback, browser, 작은 예로 위치를 찾습니다.
  3. stopifnot으로 입력을 점검해 오류를 일찍 드러냅니다.

1.4.4연습문제

기본

  1. mean(df$Age)에서 argument is not numeric or logical: returning NA 경고가 났습니다. 가능한 원인과 확인 방법은?
    답

    열 이름 오타(NULL)이거나 숫자가 문자로 읽혔습니다. names(df), str(df$Age)로 확인하고 필요하면 as.numeric으로 바꾼 뒤 생긴 NA를 점검합니다.

응용

  1. as.numeric(c("1,234", "567"))의 결과와 경고를 설명하고 올바르게 바꾸는 코드를 쓰세요.
    답

    NA 567과 강제 변환 경고. 쉼표를 지운 뒤 바꿉니다: as.numeric(gsub(",", "", x)) → 1234 567.
