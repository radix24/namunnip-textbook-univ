재현 가능한 보고서 단원 마무리 연습

문제 7 · 실습·판단 · 힌트 2단계

혼자 풀고, 막히면 힌트 1 → 힌트 2 → 풀이 순서로 열어 보자. 문제 끝의 [번호]는 다시 볼 절이다.

  1. 실습R Markdown(또는 Quarto) 코드 청크 옵션 echo = FALSE, eval = FALSE, include = FALSE, message = FALSE가 각각 무엇을 하는지 써라. [06-01]

    힌트 1

    코드를 보여 줄지, 실행할지, 결과를 보여 줄지는 서로 다른 문제이다.

    힌트 2

    패키지를 불러올 때 나오는 안내문을 숨기는 옵션도 있다.

    풀이

    echo = FALSE: 코드를 실행하고 결과는 보이되 코드는 숨긴다.

    eval = FALSE: 코드를 보이기만 하고 실행하지 않는다.

    include = FALSE: 실행은 하지만 코드와 결과를 모두 문서에 넣지 않는다(설정 청크에 씀).

    message = FALSE: 실행 중 나오는 메시지(패키지 불러오기 안내 등)를 숨긴다.

  2. 실습보고서 본문에 "평균 점수는 81.7점이다"라고 숫자를 직접 적는 대신 인라인 코드로 쓰는 방법과 그 장점을 써라. [06-01]

    힌트 1

    R Markdown에서 인라인 코드는 백틱 안에 r을 붙여 쓴다.

    힌트 2

    자료가 바뀌면 직접 적은 숫자는 어떻게 되나요?

    풀이

    본문에 평균 점수는 `r round(mean(d$score), 1)`점이다처럼 쓴다. 문서를 만들 때마다 계산해 넣으므로, 자료를 고치거나 이상값을 빼서 결과가 바뀌어도 본문 숫자가 자동으로 맞춰진다. 손으로 옮겨 적을 때 생기는 오타와 "그림은 새 결과, 본문은 옛 결과"인 불일치를 막는다.

  3. 판단동료에게 받은 분석 스크립트 첫 줄이 setwd("C:/Users/kim/Desktop/분석")이다. 이 줄의 문제와 더 나은 방법을 써라. [06-02]

    힌트 1

    이 경로는 동료 컴퓨터에만 있다.

    힌트 2

    RStudio 프로젝트나 here 패키지는 프로젝트 폴더를 기준으로 한 상대 경로를 쓴다.

    풀이

    절대 경로는 작성자 컴퓨터에서만 맞으므로 다른 사람(또는 다른 컴퓨터의 자신)이 실행하면 바로 오류가 난다.

    프로젝트 폴더를 하나 정하고(RStudio 프로젝트, Quarto 프로젝트), 그 안에서 read.csv("data/raw.csv")처럼 상대 경로를 쓰거나 here::here("data", "raw.csv")를 쓴다. 그러면 폴더째 복사해도 그대로 돌아간다.

  4. 판단스크립트 첫 줄에 rm(list = ls())를 두면 "깨끗한 상태에서 실행된다"고 믿는 사람이 있다. 이 믿음의 문제를 설명하고, 정말로 깨끗한 상태에서 실행됐음을 확인하는 방법을 써라. [06-02]

    힌트 1

    rm(list = ls())는 작업 공간의 객체만 지운다. 불러온 패키지와 바꾼 옵션은 어떻게 되나요?

    힌트 2

    R 세션을 새로 시작하는 것과 비교해 보아라.

    풀이

    rm(list = ls())는 객체만 지우고, 이미 불러온 패키지, 바꾼 옵션(options()), 작업 디렉터리는 그대로 남긴다. 그래서 스크립트 안에 library()가 빠져 있어도 내 컴퓨터에서는 돌아가는 일이 생긴다.

    R 세션을 새로 시작한 뒤(RStudio의 Restart R) 처음부터 실행하거나, 문서를 렌더링(knit, quarto render)해 보면 된다. 렌더링은 새 세션에서 실행되므로 숨은 상태에 기대지 않는지 확인할 수 있다.

  5. 실습분석을 1년 뒤에도 똑같이 다시 돌릴 수 있도록, 사용한 R과 패키지 버전을 기록하고 고정하는 방법을 두 가지 써라. [06-02]

    힌트 1

    현재 세션의 버전 정보를 출력하는 함수가 있다.

    힌트 2

    프로젝트마다 패키지 버전을 따로 관리해 주는 패키지가 있다.

    풀이

    (1) 보고서 끝에 sessionInfo() 출력을 넣어 R과 패키지 버전을 기록한다. (2) renv 패키지로 renv::init(), renv::snapshot()을 하면 프로젝트의 패키지 버전이 renv.lock 파일에 저장되고, 다른 사람은 renv::restore()로 같은 버전을 설치할 수 있다. 더 엄격하게는 도커 같은 컨테이너로 운영체제까지 고정하기도 한다.

  6. 판단부트스트랩 신뢰구간을 계산하는 보고서를 만들 때마다 구간 끝 값이 조금씩 달라진다. 원인과 고치는 방법을 쓰고, "값이 조금씩 다르다"는 사실 자체가 알려 주는 정보도 써라. [06-01]

    힌트 1

    부트스트랩은 무작위 재표본을 쓴다.

    힌트 2

    반복 횟수와 결과의 흔들림은 어떤 관계인가요?

    풀이

    시드를 정하지 않아 렌더링할 때마다 다른 재표본이 뽑히기 때문이다. 설정 청크에 set.seed(2026)을 넣으면 같은 결과가 나온다.

    값이 흔들리는 폭은 모의실험 오차의 크기를 알려 준다. 흔들림이 결론에 영향을 줄 만큼 크다면 시드만 고정하지 말고 부트스트랩 반복 횟수(예: 1000 → 10000)를 늘려야 한다.

  7. 실습분석 프로젝트에 renv를 도입하고, 동료가 같은 환경을 만들 수 있게 하는 순서를 명령과 함께 써라. [06-03]

    힌트 1

    init, snapshot, restore.

    힌트 2

    어떤 파일을 버전 관리에 넣어야 하나요?

    풀이

    나: renv::init() → 분석 → renv::snapshot()으로 renv.lock 갱신 → renv.lock을 Git에 커밋(renv/library는 제외).

    동료: 저장소를 받은 뒤 renv::restore()로 같은 버전의 패키지를 설치하고 실행한다.
