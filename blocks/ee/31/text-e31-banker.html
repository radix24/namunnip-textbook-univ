은행원 알고리즘과 안전 상태

본문

자원이 여러 종류이고 프로세스도 여럿이면, 지금 상태가 안전한지 손으로 따지기 어렵다. 프로세스마다 앞으로 더 필요한 양과 지금 남은 양을 비교해, 모두 끝낼 수 있는 순서를 찾아야 한다. 이 순서는 어떻게 체계적으로 찾을까? 그리고 그 결과로 요청을 들어줄지 말지는 어떻게 정할까?

먼저 알아야 할 것교착 상태 조건(3.2절)을 쓴다.

3.4.1모두 끝낼 수 있는 순서

먼저 프로세스마다 앞으로 더 필요한 양 Need = Max − Allocation을 구한다. 그리고 남은 자원(Work)으로 Need를 채울 수 있는 프로세스를 찾아, 끝났다고 보고 그 할당을 돌려받는다. 이 일을 반복해 모두 끝낼 수 있으면 안전 상태이다(그림 1). 처음 질문의 첫째 답이 이 안전성 검사이다.

그러면 요청을 들어준 뒤에도 안전할 때만 실제로 할당한다. 처음 질문의 둘째 답이 이 규칙이다. 아래 코드는 안전성 검사를 그대로 따라 한다.

alloc = {"P0": [0, 1, 0], "P1": [2, 0, 0], "P2": [3, 0, 2], "P3": [2, 1, 1], "P4": [0, 0, 2]}
maxm  = {"P0": [7, 5, 3], "P1": [3, 2, 2], "P2": [9, 0, 2], "P3": [2, 2, 2], "P4": [4, 3, 3]}
work = [3, 3, 2]
need = {p: [m - a for m, a in zip(maxm[p], alloc[p])] for p in alloc}
print("Need:", need)
order, done = [], set()
while len(done) < len(alloc):
    for p in alloc:
        if p not in done and all(n <= w for n, w in zip(need[p], work)):
            work = [w + a for w, a in zip(work, alloc[p])]
            order.append(p); done.add(p)
            break
    else:
        break
print("안전 순서:", order, "/ 끝난 뒤 Work:", work)

실행 결과는 아래와 같다(Python 3.12에서 실제 실행).

Need: {'P0': [7, 4, 3], 'P1': [1, 2, 2], 'P2': [6, 0, 0], 'P3': [0, 1, 1], 'P4': [4, 3, 1]}
안전 순서: ['P1', 'P3', 'P0', 'P2', 'P4'] / 끝난 뒤 Work: [10, 5, 7]
예제 3.4.1

위 상태(자원 3종류, 남은 자원 (3, 3, 2))는 안전한가?

풀이. 실행 결과에서 안전 순서 P1 → P3 → P0 → P2 → P4가 있으므로 안전하다(순서는 하나가 아닐 수 있다). 그리고 모든 작업이 끝나면 Work가 전체 자원 (10, 5, 7)이 된다.

즉 이 검사는 최악의 경우, 곧 모든 프로세스가 최대량을 요구하는 경우를 가정한다. 그러므로 안전하다고 판정되면 프로세스들이 어떤 순서로 요청하더라도 교착 없이 끝낼 수 있다.

한편 요청이 올 때마다 이 검사를 하므로, 프로세스 n개와 자원 m종류이면 검사 한 번에 대략 n²m번의 비교가 든다. 따라서 프로세스가 많은 일반 운영체제에서는 부담이 크다.

그리고 실제 시스템에서는 프로세스가 미리 최대 요구량을 알리기 어렵다. 그래서 이 알고리즘은 자원과 작업이 미리 정해진 임베디드 시스템이나 데이터베이스의 잠금 관리처럼 특수한 곳에서 생각을 빌려 쓴다.

흔한 오해불안전 상태가 곧 교착 상태라고 여기기 쉽다. 불안전하면 교착이 생길 수 있을 뿐이다. 또 은행원 알고리즘이 실무에서 흔하다고 생각하기 쉬운데, 최대 요구를 미리 알아야 해 일반 OS에서는 드물다.
마무리

필요량은 Need = Max − Allocation이다. Work로 채울 수 있는 프로세스를 반복해 골라 끝내 본다. 요청 뒤에도 안전할 때만 승인한다.

3.4.2연습문제

기본

  1. P1의 Need는?
    답

    (1, 2, 2)이다.

응용

  1. 처음 Work (3, 3, 2)로 바로 끝낼 수 있는 프로세스는?
    답

    P1, P3이다.

심화

  1. 교착 상태 예방과 회피의 차이는?
    답

    예방은 네 조건 중 하나를 막고, 회피는 상태를 보며 위험한 요청을 미룬다.
