은행원 알고리즘과 안전 상태

본문
이 절에서 배울 것
  • 최대 요구량, 할당량, 남은 자원으로 필요량 행렬을 만든다.
  • 안전 순서를 찾아 안전 상태인지 판정한다.
  • 요청을 들어줄지 결정한다.
먼저 알아야 할 것
  • 교착 상태 조건 (3.2절).

3.4.1모두 끝낼 수 있는 순서

Need = Max − Allocation. 남은 자원(Work)으로 Need를 채울 수 있는 프로세스를 찾아 끝냈다고 보고 그 할당을 돌려받는 일을 반복해, 모두 끝낼 수 있으면 안전 상태입니다. 요청을 들어준 뒤에도 안전할 때만 실제로 할당합니다.

alloc = {"P0": [0, 1, 0], "P1": [2, 0, 0], "P2": [3, 0, 2], "P3": [2, 1, 1], "P4": [0, 0, 2]}
maxm  = {"P0": [7, 5, 3], "P1": [3, 2, 2], "P2": [9, 0, 2], "P3": [2, 2, 2], "P4": [4, 3, 3]}
work = [3, 3, 2]
need = {p: [m - a for m, a in zip(maxm[p], alloc[p])] for p in alloc}
print("Need:", need)
order, done = [], set()
while len(done) < len(alloc):
    for p in alloc:
        if p not in done and all(n <= w for n, w in zip(need[p], work)):
            work = [w + a for w, a in zip(work, alloc[p])]
            order.append(p); done.add(p)
            break
    else:
        break
print("안전 순서:", order, "/ 끝난 뒤 Work:", work)

실행 결과(Python 3.12에서 실제 실행):

Need: {'P0': [7, 4, 3], 'P1': [1, 2, 2], 'P2': [6, 0, 0], 'P3': [0, 1, 1], 'P4': [4, 3, 1]}
안전 순서: ['P1', 'P3', 'P0', 'P2', 'P4'] / 끝난 뒤 Work: [10, 5, 7]
예제 3.4.1

위 상태(자원 3종류, 남은 자원 (3, 3, 2))는 안전한가?

풀이. 실행 결과 안전 순서 P1 → P3 → P0 → P2 → P4가 있어 안전합니다(순서는 하나가 아닐 수 있음). 모든 작업이 끝나면 Work가 전체 자원 (10, 5, 7)이 됩니다.

흔한 오해(1) "불안전 상태 = 교착 상태": 불안전하면 교착이 생길 수 있을 뿐입니다. (2) "은행원 알고리즘은 실무에서 흔하다": 최대 요구를 미리 알아야 해 일반 OS에서는 드뭅니다.
요약
  1. Need = Max − Allocation.
  2. Work로 채울 수 있는 프로세스를 반복 선택.
  3. 요청 후에도 안전할 때만 승인.

3.4.2연습문제

기본

  1. P1의 Need는?
    답

    (1, 2, 2).

응용

  1. 처음 Work (3, 3, 2)로 바로 끝낼 수 있는 프로세스는?
    답

    P1, P3.

심화

  1. 교착 상태 예방과 회피의 차이는?
    답

    예방은 네 조건 중 하나를 막고, 회피는 상태를 보며 위험한 요청을 미룹니다.
