세마포어로 푸는 생산자-소비자 문제

본문

한 스레드는 데이터를 만들어 버퍼에 넣고, 다른 스레드는 그것을 꺼내 처리한다. 버퍼가 가득 차면 만드는 쪽이, 비면 꺼내는 쪽이 기다려야 한다. 그리고 둘이 동시에 버퍼를 건드리면 내용이 꼬인다. 이 세 가지를 어떻게 한꺼번에 맞출까? 그리고 대기와 잠금의 순서를 잘못 정하면 어떤 일이 생길까?

먼저 알아야 할 것프로세스와 스레드(2.1절), Python 스레드를 쓴다.

3.1.1세 개의 동기화 객체

크기 N 버퍼에서 생산자는 빈 칸이 있어야, 소비자는 찬 칸이 있어야 진행한다. 그래서 empty(처음 N)와 full(처음 0) 세마포어로 개수를 세고, 락으로 버퍼 조작의 상호 배제를 맡긴다(그림 1). 처음 질문의 첫째 답이 이 세 객체이다.

즉 세마포어의 acquire는 값이 0이면 기다렸다가 1을 빼고, release는 1을 더하며 기다리는 스레드를 깨운다. 아래는 크기 5 버퍼로 100개를 주고받는 Python 코드이다.

import threading
N, SIZE = 100, 5
buf, lock = [], threading.Lock()
empty, full = threading.Semaphore(SIZE), threading.Semaphore(0)
got = []
def producer():
    for i in range(N):
        empty.acquire()
        with lock: buf.append(i)
        full.release()
def consumer():
    for _ in range(N):
        full.acquire()
        with lock: x = buf.pop(0)
        empty.release()
        got.append(x)
t1, t2 = threading.Thread(target=producer), threading.Thread(target=consumer)
t1.start(); t2.start(); t1.join(); t2.join()
print("소비한 개수:", len(got), "합:", sum(got), "순서 유지:", got == list(range(N)))

예제 3.1.1

생산자가 empty.acquire() 전에 락을 먼저 잡으면 무슨 일이 생기는가?

풀이. 버퍼가 가득 찬 상태에서 생산자가 락을 쥔 채 empty를 기다리면, 소비자는 락을 얻지 못해 꺼낼 수 없다. 그러면 서로 영원히 기다린다(교착). 처음 질문의 둘째 답이 이것이다. 따라서 개수 세마포어를 먼저, 락을 나중에 잡아야 한다.

즉 기다릴 수 있는 일을 하는 동안에는 다른 스레드가 필요로 하는 락을 쥐고 있으면 안 된다. 그래서 락은 버퍼를 고치는 아주 짧은 구간에만 잡는다.

한편 같은 문제는 조건 변수로도 풀 수 있다. 예를 들어 Python의 queue.Queue는 내부에서 락과 조건 변수로 이 구조를 구현해 두어, 응용에서는 put과 get만 부르면 된다.

그리고 생산자-소비자 구조는 운영체제 곳곳에 있다. 따라서 키보드 입력 버퍼, 네트워크 수신 버퍼, 프린터 대기열이 모두 같은 원리로 동작한다.

흔한 오해락 하나면 충분하다고 여기기 쉽다. 락은 동시 접근만 막고, 버퍼가 비었을 때 기다리게 하는 것은 계수 세마포어(또는 조건 변수)가 한다. 또 Python에는 GIL이 있어 동기화가 필요 없다고 생각하기 쉬운데, 리스트 조작 여러 단계 사이에 스레드가 바뀔 수 있어 필요하다.
마무리

생산자-소비자는 empty(N), full(0), 락으로 푼다. 예제 프로그램은 100개, 합 4950을 순서대로 전달한다(실제 실행). 세마포어를 먼저, 락을 나중에 잡으며, 반대면 교착이다.
