세마포어로 푸는 생산자-소비자 문제

본문
이 절에서 배울 것
  • 경쟁 조건과 임계 구역을 정의한다.
  • empty, full 계수 세마포어와 상호 배제 락으로 유한 버퍼 문제를 푼다.
  • 세마포어 순서를 바꾸면 교착이 생기는 경우를 안다.
먼저 알아야 할 것
  • 프로세스와 스레드 (2.1절), Python 스레드.

3.1.1세 개의 동기화 객체

크기 N 버퍼에서 생산자는 빈 칸이 있어야, 소비자는 찬 칸이 있어야 진행합니다. empty(처음 N), full(처음 0) 세마포어로 개수를, 락으로 버퍼 조작의 상호 배제를 맡깁니다. 아래는 크기 5 버퍼로 100개를 주고받는 Python 코드입니다.

import threading
N, SIZE = 100, 5
buf, lock = [], threading.Lock()
empty, full = threading.Semaphore(SIZE), threading.Semaphore(0)
got = []
def producer():
    for i in range(N):
        empty.acquire()
        with lock: buf.append(i)
        full.release()
def consumer():
    for _ in range(N):
        full.acquire()
        with lock: x = buf.pop(0)
        empty.release()
        got.append(x)
t1, t2 = threading.Thread(target=producer), threading.Thread(target=consumer)
t1.start(); t2.start(); t1.join(); t2.join()
print("소비한 개수:", len(got), "합:", sum(got), "순서 유지:", got == list(range(N)))

실행 결과(Python 3.12에서 실제 실행):

소비한 개수: 100 합: 4950 순서 유지: True
예제 3.1.1

생산자가 empty.acquire() 전에 락을 먼저 잡으면 무슨 일이 생기는가?

풀이. 버퍼가 가득 찬 상태에서 생산자가 락을 쥔 채 empty를 기다리면, 소비자는 락을 얻지 못해 꺼낼 수 없어 서로 영원히 기다립니다(교착). 개수 세마포어를 먼저, 락을 나중에 잡아야 합니다.

흔한 오해(1) "락 하나면 충분하다": 락은 동시 접근만 막고, 버퍼가 비었을 때 기다리게 하는 것은 계수 세마포어(또는 조건 변수)가 합니다. (2) "Python에는 GIL이 있어 동기화가 필요 없다": 리스트 조작 여러 단계 사이에 스레드가 바뀔 수 있어 필요합니다.
요약
  1. empty(N), full(0), 락.
  2. 예: 100개, 합 4950, 순서 유지(실제 실행).
  3. 세마포어 → 락 순서. 반대면 교착.
