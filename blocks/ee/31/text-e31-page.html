페이지 교체 알고리즘의 페이지 부재 수

본문

물리 메모리가 가득 찬 상태에서 새 페이지가 필요하면, 운영체제는 이미 올라와 있는 페이지 하나를 내보내야 한다. 곧 다시 쓸 페이지를 내보내면 금방 또 디스크에서 읽어야 한다. 어떤 페이지를 내보내야 페이지 부재가 가장 적을까? 그리고 메모리 프레임을 늘리면 부재는 언제나 줄어들까?

먼저 알아야 할 것가상 메모리(전전14 6단원)를 쓴다.

4.1.1세 알고리즘

FIFO는 가장 먼저 들어온 페이지를 내보낸다. 그리고 LRU는 가장 오래 쓰지 않은 페이지를 내보낸다. 한편 OPT는 앞으로 가장 늦게 쓰일 페이지를 내보내며, 미래를 알아야 하므로 비교 기준으로만 쓴다. 처음 질문의 첫째 답이 이 세 가지이다.

예제 4.1.1

참조열 7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2, 1, 2, 0, 1, 7, 0, 1에서 프레임 3개와 4개의 페이지 부재 수.

아래 코드는 세 알고리즘을 그대로 흉내 내어 부재 수를 센다.

ref = [7,0,1,2,0,3,0,4,2,3,0,3,2,1,2,0,1,7,0,1]
def fifo(r, n):
    f, q, c = set(), [], 0
    for p in r:
        if p not in f:
            c += 1
            if len(f) == n: f.remove(q.pop(0))
            f.add(p); q.append(p)
    return c
def lru(r, n):
    f, c = [], 0
    for p in r:
        if p in f: f.remove(p)
        else:
            c += 1
            if len(f) == n: f.pop(0)
        f.append(p)
    return c
def opt(r, n):
    f, c = [], 0
    for i, p in enumerate(r):
        if p in f: continue
        c += 1
        if len(f) == n:
            nxt = [r[i+1:].index(x) if x in r[i+1:] else 99 for x in f]
            f.pop(nxt.index(max(nxt)))
        f.append(p)
    return c
for n in (3, 4): print(n, "프레임: FIFO", fifo(ref, n), "LRU", lru(ref, n), "OPT", opt(ref, n))

실행 결과는 아래와 같다(Python 3.12에서 실제 실행).

3 프레임: FIFO 15 LRU 12 OPT 9
4 프레임: FIFO 10 LRU 8 OPT 8

즉 LRU는 OPT에 가깝고 FIFO보다 낫다(그림 1). 그런데 LRU를 정확히 구현하려면 참조마다 시각을 기록해야 해 비싸다. 그래서 참조 비트를 돌며 확인하는 클록(두 번째 기회) 알고리즘으로 근사한다.

한편 FIFO는 프레임을 늘렸는데 부재가 늘어나는 Belady 이상이 생길 수 있다. 처음 질문의 둘째 답이 이것이다. 예를 들어 1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5에서 3프레임은 9번, 4프레임은 10번이다.

그래서 실제 운영체제는 LRU의 생각을 값싸게 흉내 내는 쪽을 택한다. 즉 최근에 쓴 페이지는 남기고 오래 쓰지 않은 페이지를 내보낸다는 원칙은 같고, 그 판단을 참조 비트 몇 개로 어림한다.

그리고 내보낼 페이지가 메모리에서 바뀌지 않았다면 디스크에 다시 쓸 필요가 없다. 따라서 수정 비트가 0인 페이지를 먼저 내보내면 교체 비용이 더 준다.

흔한 오해프레임을 늘리면 어떤 알고리즘이든 부재가 준다고 여기기 쉽다. FIFO는 아닐 수 있다(LRU, OPT는 보장한다). 또 OPT를 구현할 수 있다고 생각하기 쉬운데, 미래 참조를 알 수 없어 비교 기준으로만 쓴다.
마무리

교체 알고리즘에는 FIFO, LRU, OPT가 있다. 예제의 3프레임은 15, 12, 9번이다(실제 계산). LRU는 클록 알고리즘으로 근사하고, FIFO에는 Belady 이상이 있다.

4.1.2연습문제

기본

  1. 처음 세 참조 7, 0, 1은 어떤 알고리즘이든 부재인가?
    답

    그렇다(빈 프레임에 처음 적재한다).

응용

  1. 참조열 1, 2, 3, 1, 4, 1(3프레임)의 LRU 부재 수는?
    답

    4번이다(1, 2, 3, 4를 적재하고, 4가 2를 내보낸다).

심화

  1. 작업 집합이 프레임 수보다 크면 무슨 일이 생기는가?
    답

    부재가 폭증해 디스크 입출력만 하는 스래싱이 생긴다.
