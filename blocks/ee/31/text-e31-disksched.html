디스크 스케줄링

본문

하드 디스크는 회전하는 원판 위를 헤드가 오가며 읽고 쓴다. 여러 프로그램이 디스크 곳곳의 블록을 동시에 요청하면, 들어온 순서대로 처리할 때 헤드가 이쪽 끝과 저쪽 끝을 바쁘게 오간다. 요청 순서를 어떻게 바꾸면 헤드를 덜 움직일까? 그리고 그 대가로 생기는 문제는 무엇일까?

먼저 알아야 할 것파일 시스템(5.1절)을 쓴다.

5.3.1팔을 덜 움직이기

하드 디스크는 헤드 이동(탐색)이 가장 오래 걸린다. 그래서 요청 순서를 바꿔 이동 거리를 줄인다. 처음 질문의 첫째 답이 아래 두 방법이다.

SSTF는 지금 위치에서 가장 가까운 요청부터 처리해 이동이 짧다. 그런데 먼 요청이 계속 밀려 굶을 수 있다. 처음 질문의 둘째 답이 이 기아이다. 한편 SCAN은 엘리베이터처럼 한쪽 끝까지 가며 처리하고 돌아오면서 처리한다. 아래 코드는 세 방식의 이동 거리를 계산한다.

q = [98, 183, 37, 122, 14, 124, 65, 67]
start = 53
def total(seq, s=start):
    t = 0
    for x in seq:
        t += abs(x - s); s = x
    return t
sstf, pos, left = [], start, q[:]
while left:
    nxt = min(left, key=lambda x: abs(x - pos))
    sstf.append(nxt); left.remove(nxt); pos = nxt
scan = sorted([x for x in q if x < start], reverse=True) + [0] + sorted(x for x in q if x > start)
print("FCFS 이동:", total(q))
print("SSTF 순서:", sstf, "이동:", total(sstf))
print("SCAN(0 쪽 먼저) 순서:", scan, "이동:", total(scan))

실행 결과는 아래와 같다(Python 3.12에서 실제 실행).

FCFS 이동: 640
SSTF 순서: [65, 67, 37, 14, 98, 122, 124, 183] 이동: 236
SCAN(0 쪽 먼저) 순서: [37, 14, 0, 65, 67, 98, 122, 124, 183] 이동: 236
예제 5.3.1

실린더 0~199, 헤드 53, 요청 98, 183, 37, 122, 14, 124, 65, 67의 세 방식 이동 거리는?

풀이. 실행 결과에서 FCFS 640, SSTF 236, SCAN 236실린더이다(그림 1). 그런데 SSTF는 이 예에서 짧지만, 가운데 요청이 계속 오면 끝 쪽 요청이 오래 기다릴 수 있다. 한편 SSD는 탐색이 없으므로, 요청 합치기와 공평성 위주의 스케줄러를 쓴다.

즉 디스크 스케줄링은 처리량과 공평성 사이의 맞바꿈이다. 그래서 실제 운영체제는 SCAN 계열을 바탕으로 하되, 요청마다 마감 시간을 두어 너무 오래 기다린 요청을 먼저 처리하기도 한다.

그리고 디스크 안의 제어기도 자체 큐로 요청 순서를 다시 바꾼다. 따라서 운영체제와 디스크 제어기가 함께 순서를 다듬어, 회전 지연까지 줄인다.

예를 들어 SSTF와 SCAN이 이 예에서 같은 236실린더를 움직였지만, 요청이 계속 들어오는 실제 상황에서는 SCAN이 끝 쪽 요청도 한 번의 왕복 안에 처리한다는 점에서 더 예측 가능하다. 그러므로 대기 시간의 최댓값이 중요한 시스템은 SCAN 계열을 고른다.

흔한 오해SSTF가 늘 최적이라고 여기기 쉽다. 최소 이동을 보장하지도 공평하지도 않다. 또 SSD에도 엘리베이터 알고리즘이 필수라고 생각하기 쉬운데, 탐색 시간이 없어 의미가 작다.
마무리

예제의 이동 거리는 FCFS 640, SSTF 236, SCAN 236이다. SSTF는 기아가 생길 수 있다. SSD는 탐색이 없어 다른 기준의 스케줄러를 쓴다.

5.3.2연습문제

기본

  1. 헤드 50에서 요청 10, 90의 FCFS 이동은?
    답

    120이다.

응용

  1. 같은 경우 SSTF 이동은?
    답

    120(10까지 40 후 90까지 80)이다.

심화

  1. C-SCAN이 SCAN보다 공평한 이유는?
    답

    한 방향으로만 서비스해 양 끝의 대기 시간이 고르게 된다.
