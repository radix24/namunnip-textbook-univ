스케줄링 알고리즘과 평균 대기 시간

본문

CPU는 하나인데 실행하려는 프로그램은 여럿이다. 운영체제는 누구에게 먼저 CPU를 줄지 정해야 한다. 오래 걸리는 작업이 먼저 오면 짧은 작업들이 줄줄이 기다리게 된다. 순서를 정하는 방법에는 어떤 것이 있을까? 그리고 방법에 따라 평균 대기 시간은 얼마나 달라질까?

먼저 알아야 할 것프로세스 개념(이 절에서 정리)을 쓴다.

2.1.1세 알고리즘

FCFS는 온 순서대로 실행한다. 그리고 SJF는 실행 시간이 가장 짧은 것부터 실행하며, 평균 대기 시간이 최소이다. 한편 RR은 시간 할당량 q씩 돌아가며 실행한다. 처음 질문의 첫째 답이 이 세 가지이다.

즉 프로세스는 실행 중인 프로그램이며, 운영체제는 실행할 준비가 된 프로세스들을 대기열에 두고 그 가운데 하나를 골라 CPU를 준다. 그래서 이 고르는 규칙이 스케줄링 알고리즘이다.

예제 2.1.1

P1(24), P2(3), P3(3)가 시각 0에 P1, P2, P3 순으로 도착했다. FCFS, SJF, RR(q = 4)의 평균 대기 시간은?

풀이. FCFS는 대기가 0, 24, 27이므로 평균 17이다. 그리고 SJF는 P2, P3, P1 순으로 0, 3, 6이므로 평균 3이다. 한편 RR은 P1 0–4, P2 4–7, P3 7–10, P1 10–30이므로, 대기가 P1 = 10 − 4 = 6, P2 = 4, P3 = 7로 평균 5.67이다(그림 1). 처음 질문의 둘째 답이 이 값들이다.

따라서 긴 작업 하나가 앞에 서면 짧은 작업들이 오래 기다리는 호위 효과가 FCFS의 약점이다.

그런데 SJF는 실행 시간을 미리 알아야 하므로, 실제로는 과거 실행 시간으로 추정한다. 그리고 RR은 q가 너무 크면 FCFS가 되고, 너무 작으면 문맥 교환 비용이 커진다(2.3절).

한편 실제 운영체제는 여러 대기열에 우선순위를 두고, 대화형 작업처럼 짧게 자주 쓰는 프로세스를 앞에 둔다. 즉 짧은 작업을 먼저 처리한다는 SJF의 생각을 추정과 우선순위로 흉내 낸다.

흔한 오해RR이 언제나 평균 대기가 가장 작다고 여기기 쉽다. 응답성은 좋지만 평균 대기는 SJF가 최소이다. 또 SJF는 공정하다고 생각하기 쉬운데, 긴 작업이 계속 밀리는 기아가 생길 수 있어 노화(aging)를 쓴다.
마무리

FCFS는 도착 순, SJF는 평균 대기 최소, RR은 응답성이 좋다. 예제에서 평균 대기는 17, 3, 5.67이다. q는 크면 FCFS가 되고, 작으면 문맥 교환 비용이 커진다.

2.1.2연습문제

기본

  1. 예제에서 P2, P3, P1 순 FCFS의 평균 대기는?
    답

    3(SJF와 같음)이다.

응용

  1. RR q = 2면 P2의 대기 시간은?
    답

    P1 0–2, P2 2–4, P3 4–6, P1 6–8, P2 8–9 … P2 대기 = 2 + 4 = 6이다.

심화

  1. 대화형 시스템에서 q를 정하는 기준은?
    답

    대부분의 짧은 상호 작용이 한 번에 끝날 만큼 크고, 문맥 교환 비용보다 충분히 크게 정한다.
