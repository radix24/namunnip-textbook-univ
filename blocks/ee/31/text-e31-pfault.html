페이지 부재 비용과 스래싱

본문
이 절에서 배울 것
  • 페이지 부재율로 유효 접근 시간을 계산한다.
  • 성능 저하를 제한하는 부재율 상한을 구한다.
  • 작업 집합과 스래싱의 관계를 안다.
먼저 알아야 할 것
  • 페이지 교체 (4.1절), TLB (4.3절).

4.5.1디스크는 백만 배 느리다

부재율 p, 메모리 접근 t_m, 부재 처리 시간 t_f이면 EAT = (1 − p)t_m + p·t_f입니다. 디스크 부재 처리는 수 ms라 p가 아주 작아야 합니다. 프로세스들의 작업 집합 합이 메모리보다 크면 계속 부재가 나 CPU가 놀고(스래싱), 프로세스 수를 줄여야 합니다.

예제 4.5.1

t_m = 100 ns, t_f = 8 ms. 성능 저하를 10% 이내로 하려면 부재율이 얼마 이하여야 하나?

풀이. 110 > 100 + p(8×10⁶ − 100) → p < 1.25×10⁻⁶(약 80만 번 접근에 한 번). SSD(약 0.1 ms)면 10⁻⁴까지 허용됩니다. 스래싱 때는 다중 프로그래밍 수를 늘릴수록 CPU 이용률이 오히려 떨어집니다.

흔한 오해(1) "메모리가 부족하면 조금 느려질 뿐": 스래싱이 나면 수백 배 느려집니다. (2) "프로세스를 더 넣으면 CPU 이용률이 오른다": 스래싱 영역에서는 떨어집니다.
요약
  1. EAT = (1 − p)t_m + p·t_f.
  2. 10% 이내: p < 1.25×10⁻⁶(디스크).
  3. 작업 집합 합 > 메모리 → 스래싱.

4.5.2연습문제

기본

  1. p = 10⁻⁵, t_f = 8 ms의 EAT는?
    답

    약 180 ns.

응용

  1. t_f = 0.1 ms(SSD)의 10% 한계 p는?
    답

    약 10⁻⁴.

심화

  1. 스래싱을 막는 OS 방법은?
    답

    부재율 감시로 프로세스를 일시 내보내 다중 프로그래밍 수를 줄입니다.
