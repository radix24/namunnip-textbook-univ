프로세스 생성 시스템 호출로 프로그램 작성

본문

터미널에 ls를 치면 셸이 ls 프로그램을 실행하고, 그 출력이 끝나면 다시 명령을 기다린다. 셸은 자기 자신을 멈추지 않으면서 어떻게 다른 프로그램을 실행할까? 운영체제는 새 프로세스를 어떤 시스템 호출로 만들까? 그리고 끝난 프로세스의 뒷정리는 누가 할까?

먼저 알아야 할 것시스템 호출(1.1절), C 기초를 쓴다.

2.2.1fork-exec-wait

fork는 지금 프로세스를 그대로 복제해 자식 프로세스를 만든다. 그리고 자식에게는 0을, 부모에게는 자식의 PID를 돌려주므로, 같은 코드가 반환값으로 갈라진다. 처음 질문의 첫째 답이 이 fork이다. 아래 프로그램은 셸이 명령을 실행하는 방식을 그대로 따라 한다.

#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>

int main(void) {
    pid_t pid = fork();                 /* 이 줄 뒤로 프로세스가 둘 */
    if (pid < 0) { perror("fork"); return 1; }
    if (pid == 0) {                     /* 자식 */
        execlp("ls", "ls", "-l", (char *)NULL);
        perror("exec");                 /* exec가 성공하면 여기에 오지 않음 */
        return 1;
    }
    int status;
    waitpid(pid, &status, 0);           /* 부모: 자식이 끝날 때까지 기다림 */
    printf("child %d exited with %d\n", (int)pid, WEXITSTATUS(status));
    return 0;
}

자식은 exec로 ls가 되어 목록을 출력하고, 부모는 기다렸다가 종료 코드를 출력한다(리눅스와 macOS에서 컴파일해 실행하며, Windows에는 fork가 없다). 그리고 부모가 wait로 기다리므로 "child … exited" 줄은 언제나 ls 출력 뒤에 나온다(그림 1).

즉 exec는 프로세스를 새로 만들지 않고, 지금 프로세스의 내용을 다른 프로그램으로 갈아 끼운다. 그래서 fork와 exec를 나눠 두면, 그 사이에 자식의 입출력 방향을 바꾸는 등의 준비를 할 수 있다.

예제 2.2.1

fork()를 연달아 세 번 부르면(조건 없이) 프로세스는 몇 개가 되는가? 자식이 끝났는데 부모가 wait하지 않으면?

풀이. 매번 두 배가 되므로 2³ = 8개이다. 그리고 끝난 자식은 종료 상태를 부모가 거둘 때까지 프로세스 표에 남는 좀비가 된다. 처음 질문의 둘째 답이 이 wait의 역할이다. 한편 부모가 먼저 끝나면 자식은 고아가 되어 init(systemd)이 거둔다.

그러므로 자식을 많이 만드는 서버 프로그램은 자식의 종료를 반드시 거둔다. 좀비가 쌓이면 프로세스 표의 자리가 차서, 결국 새 프로세스를 만들지 못한다.

한편 셸에서 명령 끝에 &를 붙이면 부모가 기다리지 않고 바로 다음 명령을 받는다. 즉 같은 fork-exec 구조에서 wait만 나중으로 미룬 것이다.

흔한 오해fork 뒤에 자식이 먼저 실행된다고 여기기 쉽다. 순서는 스케줄러가 정하며 보장되지 않는다. 또 fork는 메모리를 모두 복사해 느리다고 생각하기 쉬운데, 쓰기 시 복사(copy-on-write)로 실제 복사는 쓸 때만 한다.
마무리

fork는 자식에게 0, 부모에게 PID를 돌려준다. exec로 다른 프로그램을 실행하고, wait로 종료를 거둔다. 거두지 않은 자식은 좀비, 부모가 먼저 끝난 자식은 고아가 된다.
