저널링이 충돌 일관성을 지키는 원리

본문
이 절에서 배울 것
  • 파일 추가가 여러 블록(비트맵, inode, 데이터)을 바꿔 중간 충돌 시 불일치가 생김을 안다.
  • 선행 기록(저널 기록 → 커밋 → 제자리 반영 → 해제) 순서를 설명한다.
  • 데이터 저널링과 순서 모드(메타데이터만)의 차이를 안다.
먼저 알아야 할 것
  • 파일 할당 (5.1절).

5.2.1문제

파일에 블록 하나를 붙이려면 데이터 블록, inode(크기와 포인터), 블록 비트맵 세 곳을 써야 합니다. 디스크는 한 번에 한 블록씩 쓰므로 그 사이 전원이 끊기면 "inode는 블록을 가리키는데 비트맵은 비어 있음" 같은 불일치가 남습니다. 예전에는 부팅 때 fsck로 전체를 검사해 오래 걸렸습니다.

5.2.2저널링

  1. 바꿀 블록들을 저널 영역에 먼저 쓴다.
  2. 모두 쓰였으면 커밋 블록을 쓴다(원자적 한 블록).
  3. 제자리(실제 위치)에 반영한다(체크포인트).
  4. 저널 공간을 해제한다.
예제 5.2.1

(가) 1단계 도중, (나) 2단계 후 3단계 도중 충돌하면 복구는 어떻게 되는가?

풀이. (가) 커밋이 없으니 저널을 버리면 됩니다. 제자리는 손대지 않았으므로 옛 상태로 일관됩니다. (나) 커밋이 있으니 저널 내용을 다시 제자리에 씁니다(재실행). 두 경우 모두 저널만 훑으면 되어 복구가 빠릅니다.

모든 데이터를 저널에 두 번 쓰면 느리므로, ext4의 기본 순서 모드는 데이터 블록을 제자리에 먼저 쓰고 메타데이터만 저널링합니다.

흔한 오해(1) "저널링이면 데이터 손실이 없다": 커밋되지 않은 최근 쓰기는 잃을 수 있고, 일관성(구조가 깨지지 않음)을 지키는 것입니다. (2) "커밋 블록은 아무 때나 써도 된다": 앞의 저널 블록이 다 쓰인 뒤(쓰기 장벽)여야 합니다.
요약
  1. 여러 블록 갱신 중 충돌 → 불일치.
  2. 저널 기록 → 커밋 → 체크포인트 → 해제.
  3. 커밋 전 충돌은 버림, 후 충돌은 재실행. 순서 모드.

5.2.3연습문제

기본

  1. 커밋 블록이 하나의 블록이어야 하는 이유는?
    답

    블록 쓰기는 원자적이라 커밋이 반쯤 쓰이는 일이 없도록.

응용

  1. 순서 모드에서 데이터를 먼저 쓰는 이유는?
    답

    메타데이터가 아직 쓰레기 데이터를 가리키는 일을 막기 위해.

심화

  1. 저널 크기가 작으면 무엇이 성능을 제한하는가?
    답

    저널이 차면 체크포인트를 기다려야 해 쓰기가 멈춥니다.
