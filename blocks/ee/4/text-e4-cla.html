본문
이 절에서 배울 것

먼저 알아야 할 것
  • 전가산기와 리플 캐리 가산기 (4.1절).

4.3.1문제: 올림이 기다리게 한다

게이트는 입력이 바뀌고 조금 뒤에 출력이 바뀝니다(전파 지연, 수십 ps ~ 수 ns). 리플 캐리 가산기에서 i자리의 올림 \(C_{i+1}\)은 \(C_i\)가 정해져야 계산되므로, 맨 위 자리는 아래 자리 올림이 모두 차례로 전해질 때까지 기다립니다. 비트마다 AND와 OR 두 단이 더해져 n비트의 최악 지연은 약 \(2n + 1\)단입니다(디지털실험 가산기 카드에서 4비트 9단 확인). 64비트면 129단으로, 클록 주기를 크게 늘려야 합니다(5.3절 최대 클록).

4.3.2생성과 전파

각 자리에 대해 두 신호를 정의합니다.

생성 \(G_i = A_iB_i\): 이 자리 혼자서 올림을 만든다(둘 다 1).

전파 \(P_i = A_i \oplus B_i\): 이 자리가 아래에서 온 올림을 위로 넘긴다(하나만 1).

그러면 전가산기의 올림은 \(C_{i+1} = G_i + P_iC_i\)이고 합은 \(S_i = P_i \oplus C_i\)입니다. \(G_i, P_i\)는 입력만으로 게이트 한 단 만에 모든 자리에서 동시에 정해진다는 것이 핵심입니다.

4.3.3올림을 펼쳐 쓰기

\(C_{i+1} = G_i + P_iC_i\)에 \(C_i\)를 계속 대입합니다.

\[ C_1 = G_0 + P_0C_0, \] \[ C_2 = G_1 + P_1G_0 + P_1P_0C_0, \] \[ C_3 = G_2 + P_2G_1 + P_2P_1G_0 + P_2P_1P_0C_0, \] \[ C_4 = G_3 + P_3G_2 + P_3P_2G_1 + P_3P_2P_1G_0 + P_3P_2P_1P_0C_0. \]

읽는 법: "\(C_4\)가 1인 것은, 3자리가 생성했거나, 2자리가 생성하고 3자리가 전파했거나, …, 맨 아래 \(C_0\)이 모든 자리를 지나 전파된 경우다." 이 식들은 모두 곱의 합, 곧 AND 한 단 + OR 한 단이므로, 입력 → G,P(1단) → 모든 올림(2단) → 합 XOR(1단)으로 비트 수와 상관없이 약 4단이면 끝납니다.

예제 4.3.1

A = 1011, B = 0110, \(C_0 = 0\)일 때 G, P와 모든 올림을 캐리 예측 식으로 구하고 합을 검산하여라.

풀이. 자리 0부터: A = 1,1,0,1(아래부터), B = 0,1,1,0. G = 0,1,0,0, P = 1,0,1,1. \(C_1 = G_0 + P_0C_0 = 0\). \(C_2 = G_1 + P_1G_0 + \cdots = 1\). \(C_3 = G_2 + P_2G_1 + \cdots = 0 + 1\cdot1 = 1\). \(C_4 = G_3 + P_3G_2 + P_3P_2G_1 = 0 + 0 + 1 = 1\). 합 \(S_i = P_i \oplus C_i\): \(S_0 = 1\oplus0 = 1\), \(S_1 = 0\oplus0 = 0\), \(S_2 = 1\oplus1 = 0\), \(S_3 = 1\oplus1 = 0\). 결과 \(C_4S_3S_2S_1S_0 = 1\,0001 = 17\). 11 + 6 = 17. 맞습니다.

4.3.4비용과 절충

펼친 식은 자리가 올라갈수록 항이 늘어(\(C_n\)은 항 n+1개, 가장 큰 AND는 입력 n+1개) 비트 수가 크면 게이트가 너무 커집니다. 그래서 실제로는 다음과 같이 나눕니다.

  • 블록 캐리 예측: 4비트 블록 안은 캐리 예측, 블록 사이는 리플. 지연이 약 n/4에 비례로 줄어든다.
  • 계층(트리)형: 블록의 G, P를 다시 묶어 위층에서 예측. 지연이 \(\log_2 n\)에 비례한다. 고성능 CPU의 가산기 방식(병렬 접두 가산기).

속도를 위해 게이트와 배선을 더 쓰는 것, 이것이 디지털 설계의 전형적인 절충입니다. 이 절의 탐구 카드에서 비트 수에 따른 지연을 비교합니다.

주의캐리 예측도 "\(C_0\)부터 모든 올림을 한꺼번에 계산"할 뿐, 합 \(S_i\)를 위해 XOR 한 단은 여전히 필요합니다. 또 4단이라는 것은 다입력 게이트를 한 단으로 센 이상적인 값이고, 실제로는 입력 수가 많은 게이트가 느려서 블록 크기를 4 안팎으로 둡니다.
요약
  1. 리플 캐리 지연은 n에 비례(약 2n+1단).
  2. \(G_i = A_iB_i\), \(P_i = A_i \oplus B_i\), \(C_{i+1} = G_i + P_iC_i\)를 펼치면 모든 올림이 2단 곱의 합.
  3. 펼친 식은 크기가 커져 블록·트리로 나눈다. 트리형은 지연 \(\propto \log n\).

4.3.5연습문제

기본

  1. 4비트 블록의 "블록 생성" \(G^* = G_3 + P_3G_2 + P_3P_2G_1 + P_3P_2P_1G_0\)과 "블록 전파" \(P^* = P_3P_2P_1P_0\)의 뜻을 말로 설명하여라.
    답

    \(G^*\): 블록 안에서 올림이 생겨 위로 나간다. \(P^*\): 블록 아래에서 들어온 올림이 블록을 그대로 통과한다. 블록 올림 \(C_4 = G^* + P^*C_0\).

응용

  1. 16비트를 4비트 블록 넷으로 나누고 블록 사이는 리플로 이었다. 블록 안 캐리 예측 2단, 블록 사이 한 블록당 2단, G·P 1단, 합 XOR 1단으로 최악 지연을 세어라.
    답

    1 + 2 + 2×3 + 1 = 10단(리플 캐리 33단).

심화

  1. \(P_i\)를 \(A_i \oplus B_i\) 대신 \(A_i + B_i\)로 정의해도 올림 식이 맞는 이유는? 그럴 때 합을 구하는 데 무엇이 달라지는가?
    답

    둘 다 1이면 \(G_i = 1\)이라 올림은 이미 1이므로 \(P_i\)의 값과 무관하다. 그러나 합 \(S_i = P_i \oplus C_i\)에는 XOR형 P가 필요하므로 따로 만들어야 한다.
