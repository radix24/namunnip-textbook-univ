캐리 예측 가산기

본문

64비트 리플 캐리 가산기는 맨 위 자리가 아래 자리의 올림을 차례로 기다리느라 게이트 129단을 지나야 답이 나온다. CPU의 클록을 빠르게 하려면 이 기다림을 줄여야 한다. 아래 자리를 다 더해 보기 전에 위 자리의 올림을 미리 알 수 있을까?

먼저 알아야 할 것전가산기와 리플 캐리 가산기(4.1절)를 쓴다.

4.3.1올림이 기다리게 한다

게이트는 입력이 바뀌고 수십 ps에서 수 ns 뒤에 출력이 바뀐다. 이를 전파 지연이라 한다. 리플 캐리 가산기에서 i자리의 올림 \(C_{i+1}\)은 \(C_i\)가 정해져야 계산되므로, 맨 위 자리는 아래 자리 올림이 모두 차례로 전해질 때까지 기다린다. 비트마다 AND와 OR 두 단이 더해지므로 n비트의 최악 지연은 약 \(2n + 1\)단이다. 4비트면 9단, 64비트면 129단으로, 그만큼 클록 주기를 늘려야 한다(5.3절 최대 클록).

4.3.2생성과 전파

각 자리에 대해 두 신호를 정의하자. 생성 \(G_i = A_iB_i\)는 이 자리 혼자서 올림을 만든다는 뜻으로, 둘 다 1일 때 1이다. 전파 \(P_i = A_i \oplus B_i\)는 이 자리가 아래에서 온 올림을 위로 넘긴다는 뜻으로, 하나만 1일 때 1이다. 그러면 전가산기의 올림은 \(C_{i+1} = G_i + P_iC_i\)이고 합은 \(S_i = P_i \oplus C_i\)이다. 여기서 \(G_i\)와 \(P_i\)는 입력만으로 게이트 한 단 만에 모든 자리에서 동시에 정해진다는 점이 요긴하다.

4.3.3올림을 펼쳐 쓰기

이제 \(C_{i+1} = G_i + P_iC_i\)에 \(C_i\)를 계속 대입하자.

\[ C_1 = G_0 + P_0C_0, \qquad C_2 = G_1 + P_1G_0 + P_1P_0C_0, \] \[ C_3 = G_2 + P_2G_1 + P_2P_1G_0 + P_2P_1P_0C_0, \] \[ C_4 = G_3 + P_3G_2 + P_3P_2G_1 + P_3P_2P_1G_0 + P_3P_2P_1P_0C_0 \]

\(C_4\)는 이렇게 읽는다. 3자리가 생성했거나, 2자리가 생성하고 3자리가 전파했거나, 그렇게 내려가 맨 아래 \(C_0\)이 모든 자리를 지나 전파된 경우에 1이다. 그런데 이 식들은 모두 곱의 합, 곧 AND 한 단과 OR 한 단이다. 따라서 입력에서 G와 P까지 1단, 모든 올림까지 2단, 합 XOR 1단으로 비트 수와 상관없이 약 4단이면 끝난다. 처음 질문의 답이 이것이다.

예제 4.3.1

A = 1011, B = 0110, \(C_0 = 0\)일 때 G, P와 모든 올림을 캐리 예측 식으로 구하고 합을 검산하여라.

풀이. 자리 0부터 아래에서 위로 쓰면 A는 1, 1, 0, 1이고 B는 0, 1, 1, 0이다. 따라서 G는 0, 1, 0, 0이고 P는 1, 0, 1, 1이다. \(C_1 = G_0 + P_0C_0 = 0\), \(C_2 = G_1 + P_1G_0 + \cdots = 1\), \(C_3 = G_2 + P_2G_1 + \cdots = 0 + 1\cdot1 = 1\), \(C_4 = G_3 + P_3G_2 + P_3P_2G_1 = 0 + 0 + 1 = 1\)이다. 합 \(S_i = P_i \oplus C_i\)는 \(S_0 = 1\oplus0 = 1\), \(S_1 = 0\oplus0 = 0\), \(S_2 = 1\oplus1 = 0\), \(S_3 = 1\oplus1 = 0\)이다. 결과 \(C_4S_3S_2S_1S_0 = 1\,0001 = 17\)은 11 + 6 = 17로 맞는다.

4.3.4비용과 절충

그러나 펼친 식은 자리가 올라갈수록 항이 늘어, \(C_n\)은 항이 n+1개이고 가장 큰 AND는 입력이 n+1개이다. 그래서 비트 수가 크면 게이트가 너무 커진다. 실제로는 4비트 블록 안은 캐리 예측으로, 블록 사이는 리플로 잇는 블록 캐리 예측을 써서 지연을 약 n/4에 비례하도록 줄인다(그림 1의 16비트 10단). 또 블록의 G와 P를 다시 묶어 위층에서 예측하는 계층형(트리형)은 지연이 \(\log_2 n\)에 비례하며, 고성능 CPU의 병렬 접두 가산기가 이 방식이다.

다시 말해 속도를 위해 게이트와 배선을 더 쓰는 것이며, 이것이 디지털 설계의 전형적인 절충이다.

흔한 오해캐리 예측은 \(C_0\)부터 모든 올림을 한꺼번에 계산할 뿐이므로, 합 \(S_i\)를 위한 XOR 한 단은 여전히 필요하다. 또 4단은 다입력 게이트를 한 단으로 센 이상적인 값이다. 실제로는 입력 수가 많은 게이트가 느려서 블록 크기를 4 안팎으로 둔다.
마무리

리플 캐리 가산기는 올림이 자리마다 기다려 지연이 약 \(2n + 1\)단이다. 생성 \(G_i = A_iB_i\)와 전파 \(P_i = A_i \oplus B_i\)로 \(C_{i+1} = G_i + P_iC_i\)를 펼치면 모든 올림이 입력만으로 2단 곱의 합이 되어, 위 자리의 올림을 미리 알 수 있다. 다만 펼친 식은 크기가 커지므로 블록이나 트리로 나누며, 트리형의 지연은 \(\log n\)에 비례한다.

4.3.5연습문제

기본

  1. 4비트 블록의 블록 생성 \(G^* = G_3 + P_3G_2 + P_3P_2G_1 + P_3P_2P_1G_0\)과 블록 전파 \(P^* = P_3P_2P_1P_0\)의 뜻을 말로 설명하여라.
    답

    \(G^*\)는 블록 안에서 올림이 생겨 위로 나간다는 뜻이고, \(P^*\)는 블록 아래에서 들어온 올림이 블록을 그대로 통과한다는 뜻이다. 블록 올림은 \(C_4 = G^* + P^*C_0\)이다.

응용

  1. 16비트를 4비트 블록 넷으로 나누고 블록 사이는 리플로 이었다. 블록 안 캐리 예측 2단, 블록 사이 한 블록당 2단, G와 P 1단, 합 XOR 1단으로 최악 지연을 세어라.
    답

    1 + 2 + 2×3 + 1 = 10단으로, 리플 캐리의 33단보다 훨씬 짧다.

심화

  1. \(P_i\)를 \(A_i \oplus B_i\) 대신 \(A_i + B_i\)로 정의해도 올림 식이 맞는 이유는? 그럴 때 합을 구하는 데 무엇이 달라지는가?
    답

    둘 다 1이면 \(G_i = 1\)이라 올림은 이미 1이므로 \(P_i\)의 값과 무관하다. 그러나 합 \(S_i = P_i \oplus C_i\)에는 XOR형 P가 필요하므로 따로 만들어야 한다.
