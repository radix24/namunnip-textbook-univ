무료 시뮬레이터로 카운터와 검출기 확인하기

실습 · Icarus Verilog와 GTKWave

목표

7.1절의 4비트 카운터와 "11" 검출기를 Verilog로 쓰고, 테스트벤치로 시뮬레이션해 파형을 확인합니다. 파형에서 동기 리셋, 카운터의 넘어감(15 → 0), 밀리 출력의 시점(6.2절)을 읽습니다. 성취기준 [전전4-07-01].

준비

  • Icarus Verilog(iverilog, 무료)와 GTKWave(파형 보기, 무료)를 설치합니다. 설치가 어렵다면 웹 브라우저에서 돌리는 무료 온라인 Verilog 시뮬레이터를 써도 됩니다(Icarus 선택).
  • 7.1절의 counter4, det11 모듈을 design.v에 저장합니다.
  • 아래 테스트벤치를 tb.v로 저장합니다.
`timescale 1ns/1ps
module tb;
  reg clk = 0, rst = 1, x = 0;
  wire [3:0] q;  wire z;
  counter4 c (.clk(clk), .rst(rst), .q(q));
  det11    d (.clk(clk), .rst(rst), .x(x), .z(z));
  always #5 clk = ~clk;                 // 10 ns 주기 클록
  reg [11:0] pat = 12'b0110_1110_0110;  // x로 넣을 비트(왼쪽부터)
  integer k;
  initial begin
    $dumpfile("wave.vcd"); $dumpvars(0, tb);
    #12 rst = 0;                        // 첫 모서리 뒤 리셋 해제
    for (k = 11; k >= 0; k = k - 1) begin
      x = pat[k];  #10;
      $display("t=%0t x=%b z=%b q=%0d", $time, x, z, q);
    end
    #120 $finish;                       // 카운터가 15 → 0으로 넘어가는 것까지
  end
endmodule

절차

  1. iverilog -o sim design.v tb.v, 이어서 vvp sim을 실행합니다. 명령 창에 12줄이 찍힙니다.
  2. gtkwave wave.vcd를 열고 clk, rst, x, z, q를 파형 창에 끌어다 놓습니다.
  3. z가 1인 구간을 찾고, 그때 x와 직전 x가 모두 1인지 확인합니다.
  4. q가 15에서 0으로 넘어가는 시각을 찾습니다.
  5. det11의 assign z를 assign z = (state == B);로 바꿔(무어 비슷하게) 다시 돌리고 z의 시점을 비교합니다.

기대 결과

  • 입력 비트 0, 1, 1, 0, 1, 1, 1, 0, 0, 1, 1, 0 중 "앞 비트가 1이고 지금 비트가 1"인 칸(3, 6, 7, 11번째)에서 z = 1입니다. 밀리 출력이라 x가 1인 그 클록 구간 동안 1입니다.
  • 리셋을 푼 첫 모서리(15 ns)부터 q가 1씩 늘고, 0이 된 지 16클록 뒤 15에서 0으로 넘어갑니다.
  • z를 상태만으로 바꾸면 "1이 하나라도 들어온 다음 클록"마다 1이 되어 11 검출이 아니게 됩니다. 무어로 만들려면 6.2절처럼 상태를 하나 더 두어야 합니다.

명령 창에 찍히는 z 값은 #10 뒤, 곧 다음 모서리를 지난 직후의 값이라 파형의 z와 반 칸 어긋나 보일 수 있습니다. 파형을 기준으로 판단하세요. 이 결과는 위 코드로 직접 확인해야 하며, 출력 형식은 시뮬레이터 버전에 따라 조금 다를 수 있습니다.

분석

  1. 밀리 출력 z가 클록 모서리가 아닌 때(x가 바뀌는 순간)에 바뀌는 것을 파형에서 찾을 수 있나요? 이것이 6.2절에서 말한 밀리의 단점과 어떻게 이어지나요?
  2. 카운터의 q + 4'd1은 합성 도구가 어떤 회로로 만들까요? 5.2절의 \(D_k = Q_k \oplus (Q_{k-1}\cdots Q_0)\)와 비교하세요.
