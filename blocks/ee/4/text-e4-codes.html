BCD와 그레이 코드

본문

로봇 팔 관절의 회전 인코더가 각도를 3비트로 읽는다. 3(011)에서 4(100)로 넘어가는 순간 세 비트가 모두 바뀌는데, 세 센서가 정확히 같은 순간에 바뀌지는 않는다. 그 짧은 틈에 컴퓨터는 엉뚱한 각도 7을 읽을 수도 있다. 이런 사고를 막는 수 표기법이 있을까?

먼저 알아야 할 것2진수와 2의 보수(1.1절), 두 비트가 다를 때 1이 되는 XOR을 쓴다.

1.2.1두 코드

BCD는 10진수 각 자리를 0000에서 1001로 따로 쓰는 부호여서, 2026은 0010 0000 0010 0110이 된다. 7세그먼트 표시와 계산기처럼 10진 자리를 다루는 곳에 편하지만, 1010에서 1111을 쓰지 않으므로 비트를 낭비한다. 반면 그레이 코드는 \(g = b \oplus (b \gg 1)\)로 만든다. 이웃한 수가 한 비트만 다르므로, 회전 인코더처럼 여러 비트를 동시에 읽을 때 경계에서 엉뚱한 값을 읽는 일이 없다. 처음 질문의 답이 이것이다. 거꾸로 그레이 코드를 2진수로 되돌릴 때는 위쪽 비트를 차례로 XOR한다.

for b in range(8):
    g = b ^ (b >> 1)
    back, x = 0, g
    while x:                       # 그레이 → 2진: 위쪽 비트를 차례로 XOR
        back ^= x; x >>= 1
    print(b, format(b, "03b"), "→ 그레이", format(g, "03b"), "→ 되돌림", back)
print("BCD 2026:", " ".join(format(int(c), "04b") for c in "2026"))

실행 결과는 다음과 같다(Python 3.12에서 실제 실행).

0 000 → 그레이 000 → 되돌림 0
1 001 → 그레이 001 → 되돌림 1
2 010 → 그레이 011 → 되돌림 2
3 011 → 그레이 010 → 되돌림 3
4 100 → 그레이 110 → 되돌림 4
5 101 → 그레이 111 → 되돌림 5
6 110 → 그레이 101 → 되돌림 6
7 111 → 그레이 100 → 되돌림 7
BCD 2026: 0010 0000 0010 0110

출력의 그레이 열을 위에서 아래로 읽으면 이웃한 두 줄이 늘 한 비트만 다르고, 마지막 100과 처음 000도 한 비트만 다르다. 그래서 회전처럼 한 바퀴 도는 위치에도 쓸 수 있다.

예제 1.2.1

2진수로 3(011)에서 4(100)로 넘어갈 때 센서가 세 비트를 조금씩 다른 순간에 읽으면 어떤 값이 잠깐 보일 수 있는가? 그레이 코드는?

풀이. 세 비트가 모두 바뀌므로 000에서 111까지 어느 값이든 잠깐 보일 수 있다. 가령 111, 곧 7이 보일 수 있다. 반면 그레이 코드는 010에서 110으로 한 비트만 바뀌므로 3 또는 4만 보인다(그림 1).

흔한 오해"BCD로 1001 + 0001 = 1010이 답"은 틀리다. BCD에서는 한 자리가 9를 넘으면 6(0110)을 더해 자리올림을 맞추므로 답은 0001 0000이다. 또 그레이 코드로 바로 더할 수 있다고 생각하기 쉬운데, 산술에는 2진수로 바꿔 쓴다.
마무리

BCD는 10진 자리마다 4비트를 써서 7세그먼트 표시와 계산기에 편하고, 그레이 코드 \(g = b \oplus (b \gg 1)\)는 이웃한 수가 한 비트만 다르므로 여러 비트를 동시에 읽는 회전 인코더의 경계 오류를 막는다. 같은 성질 덕분에 그레이 순서는 카르노 맵의 칸 배치에도 쓰인다.

1.2.2연습문제

기본

  1. 59의 BCD는?
    답

    0101 1001이다.

응용

  1. 2진 1011의 그레이 코드는?
    답

    1011 ⊕ 0101 = 1110이다.

심화

  1. 그레이 1101을 2진수로 바꾸어라.
    답

    맨 앞은 1, 다음은 1⊕1 = 0, 그 다음은 0⊕0 = 0, 마지막은 0⊕1 = 1이므로 1001이다.
