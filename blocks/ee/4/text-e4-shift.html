시프트 레지스터

본문

USB나 UART 같은 직렬 통신은 선 하나로 비트를 하나씩 보낸다. 그런데 CPU는 8비트나 32비트를 한꺼번에 다룬다. 한 줄로 들어오는 비트를 모아 한 번에 읽을 수 있게 하는 회로는 어떻게 만들까? 플립플롭을 줄지어 이으면 될까?

먼저 알아야 할 것D 플립플롭(5.1절), 카운터(5.2절)를 쓴다.

5.4.1한 칸씩 옮기기

D 플립플롭 \(Q_0\), \(Q_1\), \(Q_2\), \(Q_3\)을 같은 클록으로 앞에서 뒤로 이으면, 클록마다 입력 비트가 한 칸씩 이동한다. 처음 질문의 답이 이것이다. 직렬로 들어온 비트를 4클록 뒤에 병렬로 읽는 방식(SIPO)은 직렬 통신의 수신에 쓰고, 병렬로 넣고 한 비트씩 내보내는 방식(PISO)은 송신에 쓴다. UART와 SPI가 그 예이다.

한편 마지막 출력을 처음 입력으로 되돌리면 카운터가 된다. 마지막 비트를 그대로 처음으로 보내면 1 하나가 도는 링 카운터이고, 마지막 비트를 뒤집어 처음으로 보내면 존슨 카운터이다. 아래 코드는 직렬 입력과 두 카운터를 흉내 낸다.

q = [0, 0, 0, 0]
for clk, bit in enumerate([1, 0, 1, 1], 1):     # 직렬 입력 1, 0, 1, 1
    q = [bit] + q[:-1]
    print(f"클록 {clk}: Q0..Q3 = {q}")
ring, john = [1, 0, 0, 0], [0, 0, 0, 0]
rs, js = [], []
for _ in range(8):
    rs.append("".join(map(str, ring))); js.append("".join(map(str, john)))
    ring = [ring[-1]] + ring[:-1]                   # 링: 마지막 비트를 처음으로
    john = [1 - john[-1]] + john[:-1]               # 존슨: 마지막 비트를 뒤집어 처음으로
print("링 카운터 :", rs[:4])
print("존슨 카운터:", js)

실행 결과는 다음과 같다(Python 3.12에서 실제 실행).

클록 1: Q0..Q3 = [1, 0, 0, 0]
클록 2: Q0..Q3 = [0, 1, 0, 0]
클록 3: Q0..Q3 = [1, 0, 1, 0]
클록 4: Q0..Q3 = [1, 1, 0, 1]
링 카운터 : ['1000', '0100', '0010', '0001']
존슨 카운터: ['0000', '1000', '1100', '1110', '1111', '0111', '0011', '0001']

첫 네 줄이 그림 1이다. 넷째 클록 뒤의 1101을 오른쪽에서 왼쪽으로 읽으면 들어온 순서 1, 0, 1, 1이 된다. 즉 먼저 들어온 비트일수록 멀리 밀려나 있다.

예제 5.4.1

4비트 링 카운터와 존슨 카운터는 각각 몇 개의 상태를 도는가?

풀이. 링 카운터는 1 하나가 도는 1000, 0100, 0010, 0001의 4상태이고, 존슨 카운터는 0000, 1000, 1100, 1110, 1111, 0111, 0011, 0001의 8상태, 곧 2n상태이다. 두 경우 모두 상태마다 두 비트 이하만 보면 해독할 수 있어서 단계 신호를 만드는 데 쓴다.

흔한 오해"같은 클록이면 모든 비트가 한꺼번에 첫 칸으로 간다"는 틀리다. 각 플립플롭이 클록 직전의 앞 칸 값을 잡으므로 한 칸씩만 이동한다. 또 링 카운터는 아무 초기값에서나 시작해도 되는 것이 아니라, 1이 정확히 하나 들어 있게 초기화해야 한다.
마무리

같은 클록의 D 플립플롭을 줄지어 이은 시프트 레지스터는 클록마다 비트를 한 칸씩 옮기므로, 직렬 입력을 병렬로 모으거나(SIPO, 수신) 병렬 값을 직렬로 내보내는(PISO, 송신) 데 쓴다. 마지막 출력을 처음 입력으로 되돌리면 n상태를 도는 링 카운터가, 뒤집어 되돌리면 2n상태를 도는 존슨 카운터가 된다.
