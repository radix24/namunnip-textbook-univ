UART 한 글자를 선 위에서 읽기

실습 · 프레임 구조와 보율 오차

목표

UART는 클록 선 없이 데이터 선 하나로 바이트를 보냅니다. 보내는 쪽과 받는 쪽이 같은 속도(보율)를 미리 약속하고, 받는 쪽은 시작 비트의 모서리에 맞춰 각 비트의 가운데에서 값을 읽습니다. 한 글자의 파형을 직접 해석하고, 두 쪽의 보율이 조금 다를 때 어디까지 견디는지 계산과 시뮬레이션으로 확인합니다. 성취기준 [전전34-04-01], [전전34-04-03].

준비

  • 쉬는 상태는 1입니다. 시작 비트 0이 프레임의 시작을 알립니다.
  • 데이터 8비트를 최하위 비트(b0)부터 보냅니다.
  • 정지 비트 1로 끝납니다. 이 형식을 8N1(8비트, 패리티 없음, 정지 비트 1)이라고 합니다.
  • 받는 쪽은 시작 모서리에서 반 비트 뒤(시작 비트 가운데)를 첫 표본으로 하고, 이후 자기가 생각하는 비트 시간마다 표본을 뜹니다. 보율이 다르면 표본이 조금씩 밀려, 마지막 정지 비트에서 가장 많이 밀립니다.

정지 비트 표본은 시작 모서리에서 9.5비트 뒤입니다. 표본이 반 비트 넘게 밀리면 옆 비트를 읽게 되므로, 견딜 수 있는 보율 오차는 약 \(0.5/9.5 \approx 5.3\%\)입니다(실제로는 모서리가 깨끗하지 않아 더 작게 잡습니다).

절차

  1. 'A'의 파형을 보고 시작 비트 다음 8비트를 읽어, 거꾸로 적어 8비트 2진수를 만든 뒤 아스키 코드 0x41과 비교합니다.
  2. 'U'(0x55)를 보내 봅니다. 파형이 어떤 모양인가요? 보율을 재는 데 이 글자를 자주 쓰는 이유를 생각해 봅니다.
  3. 보율 오차를 +1%씩 올리며 받은 바이트가 처음 틀리는 오차를 찾습니다. −쪽도 같은 방법으로 찾습니다.
  4. 9600 bps에서 한 비트 시간과 한 글자(10비트) 시간을 계산합니다.

기대 결과

  • 'A' = 0x41 = 01000001. 선 위에는 시작 0 다음에 1, 0, 0, 0, 0, 0, 1, 0(b0부터)과 정지 1이 나옵니다.
  • 'U' = 01010101은 선 위에서 0과 1이 번갈아 나오는 구형파가 되어, 오실로스코프로 비트 시간을 재기 쉽습니다.
  • 보율 오차가 약 ±5.3%를 넘으면 정지 비트 표본이 옆 비트로 넘어가 프레임 오류나 틀린 값이 납니다. 글자에 따라 그보다 조금 일찍 틀리기도 합니다(이웃 비트 값이 같으면 밀려도 우연히 맞음).
  • 9600 bps: 한 비트 약 104 μs, 한 글자 약 1.04 ms, 초당 약 960글자.

분석

  1. FPGA 50 MHz 클록을 나눠 115200 bps를 만들면 분주비는 정수 434가 됩니다. 이때 실제 보율과 오차는 얼마인가요? UART가 견딜 만한가요?
  2. 받는 쪽이 비트 가운데가 아니라 비트 시작 부분에서 표본을 뜨면 견딜 수 있는 오차가 어떻게 바뀌나요?
  3. 많은 UART 수신기는 비트 하나를 16번 표본으로 뜹니다. 그 이유를 바운스·잡음 카드와 연결해 설명해 보세요.
