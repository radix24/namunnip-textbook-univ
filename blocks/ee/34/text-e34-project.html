작은 디지털 시스템 설계 프로젝트

본문
이 절에서 배울 것
  • 요구 사항을 명세로 바꾸고 블록도로 나눈다.
  • 블록마다 테스트벤치로 시뮬레이션 검증한 뒤 합친다.
  • FPGA에서 시연하고, 자원 사용량과 타이밍 보고를 포함한 보고서를 쓴다.
먼저 알아야 할 것
  • 이 과목의 앞 단원 전체, 보고서 쓰기 (전전9 6.2절), 이 절의 예제 카드.

5.1.1진행 순서

  1. 명세: 입력, 출력, 동작을 측정 가능한 문장으로. "0.01초 단위로 59.99초까지 센다, 시작/정지 버튼, 리셋 버튼, 4자리 표시."
  2. 블록도: 분주기, 카운터, 제어 FSM, 표시 구동, 입력 디바운스처럼 역할별로 나누고 블록 사이 신호를 정한다.
  3. 블록 구현과 검증: 블록마다 HDL을 쓰고 테스트벤치로 시뮬레이션한다. 기대값을 자동으로 비교하는 테스트가 좋다.
  4. 통합: 블록을 합쳐 다시 시뮬레이션하고, 합성 후 타이밍 보고(여유가 음수인 경로가 없는지)를 확인한다.
  5. 시연과 보고서: 명세의 각 항목이 동작하는지 보여 주고, 설계·검증·결과·한계를 쓴다.

5.1.2예: 스톱워치

예제 5.1.1

50 MHz 클록으로 0.01초 단위 스톱워치(최대 59.99초)를 만든다. 필요한 블록과 각 블록의 핵심 수치를 정하라.

풀이.

  • 100 Hz 허용 신호: 500,000클록마다 1클록 동안 1(0~499,999를 세는 19비트 카운터).
  • BCD 카운터 네 자리: 0.01초 자리와 0.1초 자리는 0~9, 1초 자리 0~9, 10초 자리 0~5. 아래 자리가 9(또는 5)에서 넘어갈 때 위 자리를 1 올린다.
  • 제어 FSM: 정지, 동작 두 상태. 시작/정지 버튼으로 바뀌고, 리셋은 정지 상태에서만 카운터를 0으로.
  • 버튼: 동기화 플립플롭 두 개 + 디바운서(4.2절) + 한 번 누름을 1클록 펄스로 바꾸는 모서리 검출.
  • 표시: 4자리 시분할(4.1절), BCD → 7세그먼트 디코더(1.3절), 10초 자리 다음에 소수점.

검증 계획: 시뮬레이션에서는 100 Hz 대신 작은 분주값(예: 10클록마다)으로 바꿔 짧은 시간에 59.99 → 00.00 넘어감을 확인하고, 보드에서는 휴대폰 스톱워치와 1분 동안 비교합니다(50 MHz 수정 발진기 오차가 수십 ppm이면 1분에 수 ms 이내, 확인 필요).

흔한 오해(1) "보드에 올려 보며 고치는 것이 빠르다": 합성에 수 분이 걸리고 내부 신호가 보이지 않아, 시뮬레이션 검증이 훨씬 빠릅니다. (2) "동작하면 끝이다": 타이밍 보고의 경고, 사용하지 않는 상태 처리, 리셋 동작을 확인해야 시연 날 갑자기 실패하지 않습니다.
요약
  1. 명세 → 블록도 → 블록 검증 → 통합·타이밍 → 시연·보고서.
  2. 블록마다 테스트벤치. 시뮬레이션에서는 분주값을 줄여 빠르게.
  3. 스톱워치: 100 Hz 허용, BCD 카운터, 제어 FSM, 버튼 처리, 시분할 표시.

5.1.3연습문제

기본

  1. 50 MHz에서 100 Hz 허용 신호를 만드는 카운터의 끝 값과 비트 수는?
    답

    499,999, 19비트(\(2^{19} = 524288\)).

응용

  1. 스톱워치의 10초 자리가 0~5만 쓰는 이유와, 59.99 다음 값은?
    답

    60초가 1분이 되므로. 59.99 다음 00.00(명세상 최대 59.99에서 처음으로).

심화

  1. 수정 발진기 오차가 ±50 ppm이면 59.99초 동안 최대 몇 ms 틀리는가?
    답

    \(60 \times 50\times10^{-6} = 3\) ms. 0.01초 단위 표시에는 드러나지 않습니다.
