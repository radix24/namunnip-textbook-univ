UART 프레임과 보율 오차의 한계

본문
이 절에서 배울 것
  • 8N1 프레임(시작 비트, 데이터 8비트, 정지 비트)을 선 위의 파형으로 해석한다.
  • 보율에서 비트 시간과 초당 전송 문자 수를 계산한다.
  • 송수신 클록 차이로 표본이 밀리는 양을 계산하고 견딜 수 있는 오차를 구한다.
먼저 알아야 할 것
  • 시프트 레지스터 (2.1절), 분주 (2.1절), 이 절의 실습 카드.

4.3.1프레임

쉬는 동안 선은 1입니다. 시작 비트 0으로 프레임 시작을 알리고, 데이터 8비트를 최하위 비트부터 보내고, 정지 비트 1로 끝냅니다(8N1). 한 문자에 10비트가 듭니다. 보율 9600 bps면 비트 시간 104.2 μs, 초당 960문자입니다.

받는 쪽은 시작 비트의 떨어지는 모서리를 보고, 반 비트 뒤(시작 비트 가운데)에서 첫 표본을 뜬 뒤 비트 시간마다 표본을 떠 시프트 레지스터에 넣습니다. 보통 보율의 16배 클록으로 시간을 잽니다.

4.3.2보율 오차

보내는 쪽과 받는 쪽 클록이 다르면 표본이 조금씩 밀려, 마지막 정지 비트 표본(시작 모서리에서 9.5비트 뒤)에서 가장 많이 밀립니다. 밀림이 반 비트를 넘으면 옆 비트를 읽으므로 두 쪽 보율 차이의 한계는 대략 \(0.5/9.5 \approx 5.3\%\)입니다. 모서리의 흔들림과 표본화 오차를 생각하면 실제로는 두 쪽 합쳐 2~3% 이내로 맞춥니다(확인 필요: 설계 기준은 문헌마다 다름).

예제 4.3.1

(가) 50 MHz 클록에서 115200 bps를 정수 분주로 만들 때의 실제 보율과 오차. (나) 16 MHz 클록, 16배 표본화(분주 정수)일 때는?

풀이. (가) 50,000,000/115,200 = 434.03 → 434, 실제 115,207 bps, 오차 +0.006%로 문제없습니다. (나) 16,000,000/(16 × 115,200) = 8.68 → 9, 실제 111,111 bps, 오차 −3.5%. 상대가 정확하면 합계 3.5%로 여유가 적어, 긴 문자열에서 가끔 오류가 날 수 있습니다. 클록을 보율에 맞는 값(예: 14.7456 MHz)으로 고르거나 8배 표본화 등으로 바꿉니다.

흔한 오해(1) "9600 bps면 초당 9600바이트": 시작·정지 비트 포함 10비트에 1바이트라 960바이트입니다. (2) "UART는 클록 선이 없으니 클록이 필요 없다": 양쪽이 각자의 클록으로 같은 보율을 맞춰야 합니다. (3) 데이터는 최하위 비트부터 나가므로, 파형을 왼쪽부터 읽으면 비트 순서가 반대입니다.
요약
  1. 8N1: 시작 0, 데이터 8(LSB 먼저), 정지 1, 문자당 10비트.
  2. 비트 시간 = 1/보율. 9600 bps → 104.2 μs, 960문자/s.
  3. 보율 차이 한계 약 5.3%(이론), 실제로는 2~3% 이내.

4.3.3연습문제

기본

  1. 115200 bps 8N1의 초당 최대 문자 수는?
    답

    11,520문자.

응용

  1. 문자 'A'(0x41 = 0100 0001)를 8N1로 보낼 때 선 위의 10비트를 시간 순서로 쓰라.
    답

    0(시작), 1, 0, 0, 0, 0, 0, 1, 0(LSB부터), 1(정지).

심화

  1. 보내는 쪽이 +2%, 받는 쪽이 −2%라면 정지 비트 표본은 몇 비트만큼 밀리는가? 통신이 되는가?
    답

    상대 차이 약 4%, 9.5비트 × 0.04 ≈ 0.38비트. 반 비트 안이라 이론상 되지만 여유가 작습니다.
