클록 분주기 설계

본문
이 절에서 배울 것
  • 고속 보드 클록을 카운터로 나눠 느린 클록이나 활성 신호를 만든다.
  • 필요한 카운터 최댓값과 비트 수를 계산한다.
  • 분주 클록 대신 클록 활성(enable)을 쓰는 이유를 안다.
먼저 알아야 할 것
  • 카운터 (2.1절), 최대 주파수 (2.2절).

2.3.1세어서 느리게

f_in을 f_out으로 나누려면 카운터가 N = f_in/f_out 클록마다 한 번 펄스를 내면 됩니다(듀티 50% 출력이면 N/2마다 반전). FPGA에서는 분주된 신호를 클록으로 쓰기보다 원래 클록에 한 주기 폭 활성 펄스를 만들어 쓰는 편이 타이밍 분석과 클록 배선에 안전합니다.

// 50 MHz -> 2 Hz 활성 펄스
reg [24:0] cnt;               // 0 .. 24_999_999 에는 25비트 필요
always @(posedge clk)
  if (cnt == 25_000_000 - 1) begin cnt <= 0; tick <= 1; end
  else begin cnt <= cnt + 1; tick <= 0; end
예제 2.3.1

위 코드(50 MHz → 2 Hz)의 카운터 최댓값과 비트 수는? 1 Hz로 바꾸려면?

풀이. 2 Hz: N = 25,000,000 → 최댓값 24,999,999, 2²⁴ = 16.8M < 25M ≤ 2²⁵이라 25비트. 1 Hz: N = 50,000,000 → 최댓값 49,999,999, 26비트(2²⁵ = 33.5M < 50M). 비트 수를 하나 덜 잡으면 카운터가 비교 값에 닿지 못해 tick이 나오지 않으므로 시뮬레이션으로 주기를 꼭 확인합니다.

흔한 오해(1) "분주한 신호를 클록으로 바로 쓰면 된다": 클록 스큐와 타이밍 분석 문제가 생깁니다. (2) "카운터 비트 수는 대충 넉넉히": 최댓값을 담는 최소 비트를 계산해야 비교가 맞습니다.
요약
  1. N = f_in/f_out, 0~N − 1.
  2. 비트 = ⌈log₂N⌉.
  3. 분주 클록보다 활성 펄스.
