클록 분주기 설계

본문

FPGA 안의 여러 블록은 서로 다른 속도로 움직여야 한다. 표시기는 수백 Hz로, 스톱워치는 100 Hz로, LED는 1 Hz로 바뀐다. 이 느린 박자를 빠른 클록 하나에서 얻는 회로가 분주기이다. 몇 클록마다 박자를 내면 될까? 그리고 만든 박자를 회로에 어떤 모양으로 나눠 주어야 안전할까?

먼저 알아야 할 것카운터(2.1절)와 최대 주파수(2.2절)를 쓴다.

2.3.1세어서 느리게

f_in을 f_out으로 나누려면 카운터가 N = f_in/f_out 클록마다 한 번 펄스를 내면 된다. 처음 질문의 첫째 답이 이 N이며, 듀티 50% 출력이 필요하면 N/2마다 반전한다.

그런데 FPGA에서는 분주된 신호를 클록으로 쓰기보다, 원래 클록에 한 주기 폭의 활성 펄스를 만들어 쓰는 편이 안전하다. 처음 질문의 둘째 답이 이것으로, 타이밍 분석과 클록 배선이 원래 클록 하나로 정리되기 때문이다. 아래는 50 MHz에서 2 Hz 활성 펄스를 만드는 코드이다.

// 50 MHz -> 2 Hz 활성 펄스
reg [24:0] cnt;               // 0 .. 24_999_999 에는 25비트 필요
always @(posedge clk)
  if (cnt == 25_000_000 - 1) begin cnt <= 0; tick <= 1; end
  else begin cnt <= cnt + 1; tick <= 0; end
예제 2.3.1

위 코드(50 MHz → 2 Hz)의 카운터 최댓값과 비트 수를 구하여라. 1 Hz로 바꾸려면 어떻게 하는지도 구하여라.

풀이. 2 Hz는 N = 25,000,000이므로 최댓값은 24,999,999이고, 2²⁴ = 16.8M < 25M ≤ 2²⁵이라 25비트이다. 그리고 1 Hz는 N = 50,000,000이므로 최댓값 49,999,999, 26비트이다(2²⁵ = 33.5M < 50M)(그림 1).

비트 수를 하나 덜 잡으면 카운터가 비교 값에 닿지 못해 tick이 나오지 않는다. 그러므로 시뮬레이션으로 주기를 꼭 확인한다.

즉 tick을 쓰는 블록은 if (tick) 조건 안에서만 상태를 바꾼다. 그러면 모든 플립플롭이 같은 50 MHz 클록으로 움직이면서도, 실제 변화는 2 Hz로만 일어난다.

한편 시뮬레이션에서 2천5백만 클록을 돌리면 오래 걸린다. 따라서 분주값을 매개변수로 두고, 시험할 때만 작은 값으로 바꿔 몇 번의 tick을 빨리 확인한다.

결국 분주기는 FPGA 설계에서 가장 자주 쓰는 블록이며, 스톱워치(5.1절)나 표시기 시분할(4.1절)도 같은 구조로 박자를 얻는다.

흔한 오해분주한 신호를 클록으로 바로 쓰면 된다고 여기기 쉽다. 클록 스큐와 타이밍 분석 문제가 생긴다. 또 카운터 비트 수는 대충 넉넉히 잡으면 된다고 생각하기 쉬운데, 최댓값을 담는 최소 비트를 계산해 두어야 비교가 맞는지 확인할 수 있다.
마무리

분주비는 N = f_in/f_out이고 카운터는 0~N − 1을 센다. 비트 수는 ⌈log₂N⌉이다. 분주 클록보다 활성 펄스를 쓴다.
