간단한 RISC 프로세서의 HDL 설계와 시뮬레이션

본문

RISC-V 같은 간단한 명령어 집합으로 프로세서를 직접 HDL로 만들어 보면, 컴퓨터 구조 시간에 배운 블록도가 실제 회로가 된다. 그런데 만든 프로세서가 맞게 동작하는지는 무엇과 비교해 판단할까? 그리고 단일 사이클 구조와 파이프라인 구조는 같은 프로그램을 얼마나 다른 속도로 실행할까?

먼저 알아야 할 것데이터패스와 파이프라인(전전14 4단원, 5단원), 테스트벤치(2.2절)를 쓴다.

6.1.1기대 결과 먼저

프로세서 HDL을 짜기 전에, 같은 명령어를 해석하는 소프트웨어 모형을 만들어 기대 결과(레지스터 값, 실행 명령 수)를 얻는다. 처음 질문의 첫째 답이 이 모형이다. 아래는 addi, add, blt만 해석하는 모형으로 1부터 10까지 더한다.

그리고 사이클 수는 단일 사이클(명령당 1사이클, 8 ns)과, 5단 파이프라인(2 ns, 채우기 4사이클, 실제로 뛴 분기마다 2사이클 손실)의 단순 모형으로 센다.

# RV32I 일부(addi, add, blt)만 해석하는 아주 작은 명령어 수준 모형
prog = [
    ("addi", 1, 0, 0),    # x1 = 0  (합)
    ("addi", 2, 0, 1),    # x2 = 1  (i)
    ("addi", 3, 0, 11),   # x3 = 11 (끝)
    ("add",  1, 1, 2),    # loop: x1 += x2
    ("addi", 2, 2, 1),    #       x2 += 1
    ("blt",  2, 3, -2),   #       if x2 < x3 goto loop (2칸 위)
]
x = [0] * 32; pc = 0; count = 0
while pc < len(prog):
    op, a, b, c = prog[pc]; count += 1; nxt = pc + 1
    if op == "addi": x[a] = x[b] + c
    elif op == "add": x[a] = x[b] + x[c]
    elif op == "blt" and x[a] < x[b]: nxt = pc + c
    x[0] = 0; pc = nxt
print("x1(합) =", x[1], " 실행한 명령어 수 =", count)
for name, cpi, tclk in [("단일 사이클", 1, 8.0), ("5단 파이프라인(분기 지연 2)", None, 2.0)]:
    cycles = count if cpi else count + 4 + 2 * 9   # 채우기 4 + 실제로 뛴 분기 9번 × 2
    print(f"{name}: 사이클 {cycles}, 시간 {cycles * tclk:.0f} ns")

실행 결과는 아래와 같다(Python 3.12에서 실제 실행).

x1(합) = 55  실행한 명령어 수 = 33
단일 사이클: 사이클 33, 시간 264 ns
5단 파이프라인(분기 지연 2): 사이클 55, 시간 110 ns

HDL 쪽 단일 사이클의 주요 부분은 아래와 같다(일부). 그러면 테스트벤치는 명령어 메모리에 같은 프로그램을 넣고, 정지한 뒤 x1이 55인지, 실행 명령 수가 33인지 비교한다(그림 1).

always @(posedge clk) begin
  pc <= rst ? 32'd0 : (take_branch ? pc + imm : pc + 32'd4);
  if (reg_write && rd != 5'd0) regs[rd] <= alu_out;   // x0은 언제나 0
end
assign take_branch = is_blt && ($signed(rs1_val) < $signed(rs2_val));
예제 6.1.1

위 결과에서 파이프라인이 단일 사이클보다 몇 배 빠른가? 분기 손실을 없애면(예측 완벽)?

풀이. 264/110 = 2.4배이다. 그리고 분기 손실 18사이클을 없애면 37사이클 × 2 ns = 74 ns이므로 3.6배이다. 처음 질문의 둘째 답이 이 비교이다. 그런데 이상적인 5배에 못 미치는 것은 채우기와 분기 때문이며, 긴 프로그램에서는 채우기 비중이 준다.

즉 명령어 수준 모형은 프로세서의 "정답지"이다. 그러므로 실제 프로세서 개발에서도 명령어 집합 시뮬레이터를 먼저 만들고, 같은 프로그램을 돌려 HDL과 명령마다 레지스터 값을 비교한다.

흔한 오해HDL을 먼저 짜고 결과를 눈으로 확인하면 된다고 여기기 쉽다. 기대 결과 모형 없이는 맞는지 판단하기 어렵다. 또 x0에도 쓸 수 있다고 생각하기 쉬운데, RISC-V x0은 언제나 0이라 쓰기를 막아야 한다.
마무리

프로세서는 PC, 명령어 메모리, 레지스터 파일, ALU, 분기로 이루어진다. 명령어 수준 모형으로 기대 결과를 얻어 HDL과 비교한다. 예제는 합 55, 33명령, 264 ns 대 110 ns이다(실제 모형 실행).

6.1.2연습문제

기본

  1. 1부터 20까지 더하면 실행 명령 수는(같은 구조)?
    답

    3 + 3 × 20 = 63이다.

응용

  1. 단일 사이클 클록이 8 ns인 이유(파이프라인 2 ns와 비교)는?
    답

    한 사이클에 인출~쓰기 모든 단계가 들어가 가장 긴 명령 경로가 주기를 정하기 때문이다.

심화

  1. load 바로 뒤에 그 값을 쓰는 add가 오면 파이프라인에서 무엇이 필요한가?
    답

    1사이클 지연(스톨)과 전달(포워딩)이다.
