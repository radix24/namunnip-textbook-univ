테스트벤치로 설계 검증

본문

설계한 회로를 칩으로 만들기 전에, 그 회로가 정말 의도대로 동작하는지 시뮬레이션으로 확인해야 한다. 파형을 눈으로 하나하나 보는 것은 수십 클록이면 몰라도 수백만 클록이면 불가능하다. 시뮬레이션이 스스로 맞고 틀림을 판단하게 하려면 테스트벤치를 어떻게 만들까? 그리고 통과했다고 해서 안심해도 될까?

먼저 알아야 할 것HDL(2.1절)을 쓴다.

2.2.1자기 검사 테스트벤치

자기 검사 테스트벤치는 클록을 만들고, 자극을 주고, 기대값 모형을 계산해, 설계의 출력과 자동으로 비교한다(그림 1). 처음 질문의 첫째 답이 이 네 부분이다. 아래는 2.1절 계수기를 시험하는 예이다.

`timescale 1ns/1ps
module tb_counter;
  reg clk = 0, rst_n = 0, en = 0;
  wire [7:0] q;
  integer errors = 0, i;
  reg [7:0] model = 0;                       // 기대값 모형

  counter dut (.clk(clk), .rst_n(rst_n), .en(en), .q(q));
  always #5 clk = ~clk;                      // 100 MHz

  initial begin
    #12 rst_n = 1;
    for (i = 0; i < 300; i = i + 1) begin
      en = $random;                          // 무작위 사용 가능 신호
      @(posedge clk); #1;
      if (en) model = model + 1;
      if (q !== model) begin
        errors = errors + 1;
        $display("불일치: t=%0t q=%0d 기대=%0d", $time, q, model);
      end
    end
    if (errors == 0) $display("PASS"); else $display("FAIL: %0d", errors);
    $finish;
  end
endmodule

테스트벤치는 합성하지 않는 코드라 지연(#), 무작위 함수, 출력문을 자유롭게 쓴다. 그리고 300클록 동안 무작위 en으로 255 → 0 넘침도 거치게 되며, 기대값 모형과 다르면 시각과 값을 출력한다. (이 교재 환경에는 Verilog 시뮬레이터가 없어 실행 결과는 싣지 않았다. Icarus Verilog 등에서 iverilog tb.v counter.v로 돌려 본다.)

예제 2.2.1

위 테스트벤치가 PASS를 내도 놓칠 수 있는 버그의 예는?

풀이. 리셋을 동작 중에 다시 거는 경우를 시험하지 않으므로, 리셋 중 en의 처리 버그를 놓칠 수 있다. 그래서 어떤 상황을 시험했는지 재는 기능 커버리지(넘침, 리셋 중 en 등)를 정해 빈 곳을 채운다. 처음 질문의 둘째 답이 이것이다.

즉 PASS는 시험한 경우에서 틀린 곳을 찾지 못했다는 뜻일 뿐이다. 그러므로 검증 계획에서는 어떤 기능과 경계 상황을 꼭 시험할지 목록을 만들고, 그 목록이 다 채워졌는지를 함께 본다.

한편 기대값 모형은 설계와 다른 방식으로 써야 효과가 있다. 예를 들어 설계를 그대로 복사해 모형으로 쓰면, 같은 실수가 양쪽에 들어가 비교가 언제나 맞게 나온다.

그리고 큰 설계의 검증에는 설계보다 더 많은 시간과 인력이 든다. 따라서 업계는 무작위 자극과 커버리지 측정을 체계화한 검증 방법론과 전용 언어를 쓴다.

흔한 오해파형을 눈으로 보면 충분하다고 여기기 쉽다. 길고 복잡한 시험은 자동 비교가 필수이다. 또 !==와 !=가 같다고 생각하기 쉬운데, !==는 X와 Z까지 비교해 초기화되지 않은 값을 잡는다.
마무리

테스트벤치는 클록 생성, 자극, 기대값 모형, 자동 비교로 이루어진다. 무작위와 경계값 시험을 하고 커버리지를 잰다. !==로 X와 Z까지 검사한다.

2.2.2연습문제

기본

  1. always #5 clk = ~clk의 클록 주파수(1 ns 단위)는?
    답

    100 MHz이다.

응용

  1. en이 항상 1이면 300클록 뒤 q는(리셋 해제 직후 0)?
    답

    300 mod 256 = 44이다.

심화

  1. 테스트벤치에서 입력을 클록 가장자리와 같은 시각에 바꾸면 생기는 문제는?
    답

    경쟁 조건으로 시뮬레이터마다 결과가 달라질 수 있어, #1처럼 조금 비켜 준다.
