테스트벤치로 설계 검증

본문
이 절에서 배울 것
  • 클록 생성, 자극 입력, 기대값 비교를 하는 테스트벤치를 쓴다.
  • 자기 검사(self-checking)로 사람 눈 대신 비교를 자동화한다.
  • 경계값과 무작위 시험, 커버리지의 뜻을 안다.
먼저 알아야 할 것
  • HDL (2.1절).

2.2.1자기 검사 테스트벤치

`timescale 1ns/1ps
module tb_counter;
  reg clk = 0, rst_n = 0, en = 0;
  wire [7:0] q;
  integer errors = 0, i;
  reg [7:0] model = 0;                       // 기대값 모형

  counter dut (.clk(clk), .rst_n(rst_n), .en(en), .q(q));
  always #5 clk = ~clk;                      // 100 MHz

  initial begin
    #12 rst_n = 1;
    for (i = 0; i < 300; i = i + 1) begin
      en = $random;                          // 무작위 사용 가능 신호
      @(posedge clk); #1;
      if (en) model = model + 1;
      if (q !== model) begin
        errors = errors + 1;
        $display("불일치: t=%0t q=%0d 기대=%0d", $time, q, model);
      end
    end
    if (errors == 0) $display("PASS"); else $display("FAIL: %0d", errors);
    $finish;
  end
endmodule

테스트벤치는 합성하지 않는 코드라 지연(#), 무작위 함수, 출력문을 자유롭게 씁니다. 300클록 동안 무작위 en으로 255 → 0 넘침도 거치게 되고, 기대값 모형과 다르면 시각과 값을 출력합니다. (이 교재 환경에는 Verilog 시뮬레이터가 없어 실행 결과는 싣지 않았습니다. Icarus Verilog 등에서 iverilog tb.v counter.v로 돌려 봅니다.)

예제 2.2.1

위 테스트벤치가 PASS를 내도 놓칠 수 있는 버그의 예는?

풀이. 리셋을 동작 중에 다시 거는 경우를 시험하지 않으므로, 리셋 중 en의 처리 버그를 놓칠 수 있습니다. 어떤 상황을 시험했는지 재는 기능 커버리지(예: 넘침, 리셋 중 en)를 정해 빈 곳을 채웁니다.

흔한 오해(1) "파형을 눈으로 보면 충분": 길고 복잡한 시험은 자동 비교가 필수입니다. (2) "!==와 !=는 같다": !==는 X, Z까지 비교해 초기화 안 된 값을 잡습니다.
요약
  1. 클록 생성 + 자극 + 기대값 모형 + 자동 비교.
  2. 무작위·경계값 시험, 커버리지.
  3. !==로 X/Z까지 검사.

2.2.2연습문제

기본

  1. always #5 clk = ~clk의 클록 주파수(1 ns 단위)는?
    답

    100 MHz.

응용

  1. en이 항상 1이면 300클록 뒤 q는(리셋 해제 직후 0)?
    답

    300 mod 256 = 44.

심화

  1. 테스트벤치에서 입력을 클록 가장자리와 같은 시각에 바꾸면 생기는 문제는?
    답

    경쟁 조건으로 시뮬레이터마다 결과가 달라질 수 있어, #1처럼 조금 비켜 줍니다.
