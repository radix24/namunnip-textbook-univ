본문
이 절에서 배울 것
  • valid-ready 핸드셰이크에서 전송이 일어나는 조건을 안다.
  • 버스 대역폭을 폭과 클록으로 계산한다.
  • IP 재사용에 표준 버스(AMBA AXI 등)가 필요한 이유를 안다.
먼저 알아야 할 것
  • SoC 구성 (1.1절).

1.2.1둘 다 준비됐을 때

AXI 같은 버스는 채널마다 보내는 쪽의 valid와 받는 쪽의 ready를 두고, 클록 가장자리에서 둘 다 1일 때만 한 번 전송합니다. 어느 쪽도 상대를 기다리며 자유롭게 멈출 수 있어, 서로 다른 회사가 만든 IP도 같은 규칙으로 연결됩니다.

예제 1.2.1

5클록 동안 valid = 1, 1, 0, 1, 1, ready = 0, 1, 1, 1, 0이면 전송은 몇 번, 몇째 클록인가? 64비트, 500 MHz 버스의 최대 대역폭은?

풀이. 둘 다 1인 2, 4클록에서 2번. 최대 대역폭 8바이트 × 500 MHz = 4 GB/s. 읽기·쓰기 채널이 따로라 동시에 쓰면 합이 두 배가 됩니다.

흔한 오해(1) "valid를 올리면 바로 전송된다": ready도 1이어야 합니다. (2) "valid가 ready를 기다려도 된다": AXI는 valid가 ready에 의존하면 교착 위험이 있어 금지합니다(확인 필요).
요약
  1. 전송 = valid ∧ ready(클록마다).
  2. 대역폭 = 폭 × 클록.
  3. 표준 버스 → IP 재사용.

1.2.2연습문제

기본

  1. 32비트, 200 MHz 최대 대역폭은?
    답

    800 MB/s.

응용

  1. ready가 평균 75%만 1이면 실효 대역폭(예제 버스)은?
    답

    3 GB/s.

심화

  1. 버스 대신 NoC를 쓰는 이유는?
    답

    코어가 많으면 공유 버스가 병목이 되어 패킷 망으로 동시 전송을 늘립니다.
