HDL로 조합과 순차 회로 기술

본문

수백만 개의 게이트로 된 회로를 회로도로 그리는 사람은 없다. 대신 Verilog 같은 하드웨어 기술 언어로 회로의 동작을 글로 쓰고, 합성 도구가 그것을 게이트로 바꾼다. 조합 회로와 순차 회로는 각각 어떻게 기술할까? 그리고 소프트웨어 코드처럼 보이는 이 글이 실제 하드웨어와 어긋나지 않으려면 무엇을 지켜야 할까?

먼저 알아야 할 것디지털 논리(전전4 5단원)를 쓴다.

2.1.1두 예

아래 코드의 위쪽은 조합 회로인 4:1 멀티플렉서이고, 아래쪽은 순차 회로인 사용 가능 신호가 있는 8비트 계수기이다. 처음 질문의 첫째 답이 이 두 가지 기술 방식이다.

// 4:1 멀티플렉서(조합)
module mux4 (input [1:0] sel, input [7:0] a, b, c, d, output reg [7:0] y);
  always @(*) begin
    case (sel)
      2'd0: y = a;
      2'd1: y = b;
      2'd2: y = c;
      default: y = d;      // 모든 경우를 덮어 래치를 막음
    endcase
  end
endmodule

// 사용 가능 신호가 있는 8비트 계수기(순차)
module counter (input clk, rst_n, en, output reg [7:0] q);
  always @(posedge clk or negedge rst_n) begin
    if (!rst_n)  q <= 8'd0;
    else if (en) q <= q + 8'd1;   // 논블로킹 대입
  end
endmodule

조합 always 블록은 블로킹(=), 순차 블록은 논블로킹(<=)이 원칙이다. 즉 논블로킹은 같은 클록 가장자리의 대입을 모두 오른쪽 값으로 계산한 뒤 한꺼번에 바꾸므로, 하드웨어 플립플롭과 같이 동작한다(그림 1). 처음 질문의 둘째 답이 이 원칙이다.

예제 2.1.1

순차 블록에 b = a; c = b;(블로킹)와 b <= a; c <= b;(논블로킹)를 쓰면 각각 어떤 회로가 되는가?

풀이. 블로킹은 c가 새 b(= a)를 받으므로, b와 c가 같은 값을 가진 플립플롭 하나 거리가 된다. 그런데 논블로킹은 c가 옛 b를 받으므로, a → b → c의 두 단 시프트 레지스터가 된다. 따라서 시프트 레지스터를 의도했다면 논블로킹이 맞다.

즉 HDL 코드를 읽을 때는 문장의 순서가 아니라, 어떤 신호가 언제 바뀌는 회로인지를 그려 보아야 한다. 그래서 숙련된 설계자는 코드를 쓰기 전에 블록도와 타이밍을 먼저 정한다.

한편 조합 블록에서 어떤 경우에 출력값을 정하지 않으면, 합성 도구는 이전 값을 기억하는 래치를 만든다. 그러므로 case에는 default를, if에는 else를 두어 모든 경우에 값을 준다.

그리고 합성할 수 있는 코드와 시뮬레이션에만 쓰는 코드는 다르다. 예를 들어 지연(#)이나 출력문은 테스트벤치에서만 쓰고, 설계 코드에는 넣지 않는다(2.2절).

흔한 오해HDL은 소프트웨어처럼 위에서부터 실행된다고 여기기 쉽다. 모든 always 블록이 동시에 동작하는 하드웨어 기술이다. 또 if에 else가 없어도 된다고 생각하기 쉬운데, 조합 블록에서 값이 정해지지 않는 경우가 있으면 래치가 생긴다.
마무리

조합 회로는 assign이나 always @(*)와 블로킹으로 기술한다. 순차 회로는 always @(posedge clk)와 논블로킹으로 기술한다. 모든 경우에 값을 지정해 래치를 막는다.
