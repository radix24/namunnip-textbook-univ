데이터패스와 FSM 제어기로 나누어 설계

본문
이 절에서 배울 것
  • 알고리즘을 레지스터·연산기(데이터패스)와 제어 상태 기계(FSM)로 나눈다.
  • GCD 예로 상태 전이와 제어 신호를 정의한다.
  • 클록 수 모형으로 성능을 계산한다.
먼저 알아야 할 것
  • FSM (전전4 6단원), HDL (2.1절).

3.1.1GCD

while (a ≠ b) { if (a > b) a −= b; else b −= a; }를 하드웨어로 만듭니다. 데이터패스: 레지스터 a, b, 뺄셈기, 비교기(a = b, a > b), 멀티플렉서. 제어기: IDLE(입력 적재) → CALC(비교 결과에 따라 a 또는 b 갱신) → DONE. 아래 Python 모형은 클록마다 상태와 레지스터를 갱신해 클록 수를 셉니다.

# 뺄셈 GCD 데이터패스 + FSM 제어기를 클록 단위로 흉내 낸 모형
def gcd_hw(a_in, b_in):
    state, a, b, cyc = "IDLE", 0, 0, 0
    while True:
        cyc += 1
        if state == "IDLE":            # start: 레지스터 적재
            a, b, state = a_in, b_in, "CALC"
        elif state == "CALC":          # 비교기 결과로 다음 동작 선택
            if a == b:   state = "DONE"
            elif a > b:  a = a - b     # a_sel = 뺄셈 결과
            else:        b = b - a
        else:
            return a, cyc
for x, y in [(48, 18), (21, 6), (17, 5)]:
    g, c = gcd_hw(x, y)
    print(f"gcd({x}, {y}) = {g}, 클록 {c}개")

실행 결과(Python 3.12에서 실제 실행):

gcd(48, 18) = 6, 클록 7개
gcd(21, 6) = 3, 클록 7개
gcd(17, 5) = 1, 클록 9개
예제 3.1.1

gcd(48, 18)의 7클록을 상태별로 나눠라. 뺄셈을 줄이는 개선은?

풀이. IDLE 1, CALC에서 뺄셈 4번(30, 12, 12/6, 6/6)과 같음 판정 1, DONE 1. 뺄셈 대신 나머지 연산(유클리드)이나 2의 거듭제곱을 이용하는 이진 GCD는 몇 번에 끝나지만 데이터패스가 커집니다. 면적과 클록 수의 절충입니다.

흔한 오해(1) "FSM에 연산을 넣으면 된다": 연산은 데이터패스에, 제어는 FSM에 두어야 재사용과 타이밍 분석이 쉽습니다. (2) "클록 수가 적으면 빠르다": 한 클록의 지연(임계 경로)도 함께 봐야 합니다.
요약
  1. 데이터패스(레지스터, 연산기, mux) + FSM(제어 신호).
  2. GCD: IDLE → CALC → DONE.
  3. 예: gcd(48, 18) 7클록(실제 모형 실행).

3.1.2연습문제

기본

  1. gcd(10, 10)의 클록 수는(같은 모형)?
    답

    IDLE 1, CALC 1, DONE 1 = 3.

응용

  1. FSM의 출력이 아닌 데이터패스의 출력은?
    답

    비교기 결과(a = b, a > b)는 데이터패스에서 FSM으로 가는 상태 신호.

심화

  1. GCD 블록을 버스에 달려면 무엇이 더 필요한가?
    답

    입력·결과 레지스터와 start/done 상태 레지스터, 버스 인터페이스.
