블로킹과 논블로킹 할당

본문
이 절에서 배울 것
  • 블로킹(=)과 논블로킹(<=) 할당의 평가 순서 차이를 안다.
  • 순차 블록에서 논블로킹을 써야 하는 이유를 시프트 레지스터로 보인다.
  • 조합 블록의 래치 추론을 피하는 규칙을 안다.
먼저 알아야 할 것
  • HDL 기술 (2.1절), 테스트벤치 (2.2절).

2.3.1동시에 바뀌는가, 차례로 바뀌는가

블로킹 할당은 문장마다 즉시 값을 바꾸고, 논블로킹은 오른쪽을 모두 먼저 평가한 뒤 블록 끝에서 한꺼번에 바꿉니다. 플립플롭은 같은 클록에 동시에 바뀌므로 always @(posedge clk)에는 논블로킹을, 조합 논리 always @*에는 블로킹을 씁니다.

// 3단 시프트 레지스터
always @(posedge clk) begin
  q1 <= d;
  q2 <= q1;
  q3 <= q2;
end
예제 2.3.1

위 코드를 블로킹(=)으로 바꾸면 한 클록 뒤 q1, q2, q3는? 처음 d = 1, q1 = q2 = q3 = 0.

풀이. 논블로킹: q1 = 1, q2 = 0, q3 = 0(시프트). 블로킹: q1 = 1 → q2 = q1 = 1 → q3 = q2 = 1로 세 값이 모두 1이 되어 플립플롭 하나처럼 합성됩니다. 시뮬레이션과 합성이 어긋나는 흔한 원인입니다.

흔한 오해(1) "=와 <=는 취향 차이": 순서 의존 동작이 달라 회로가 바뀝니다. (2) "조합 블록에서 일부 경우에 값을 안 줘도 된다": 래치가 추론됩니다.
요약
  1. 순차: <=, 조합: =.
  2. 블로킹 시프트 레지스터 → 1단으로 합성.
  3. 조합 블록 모든 경우에 값 → 래치 방지.

2.3.2연습문제

기본

  1. 논블로킹으로 a <= b; b <= a;의 효과는?
    답

    두 값이 맞바뀝니다.

응용

  1. 블로킹으로 a = b; b = a;의 효과는?
    답

    둘 다 b 값이 됩니다.

심화

  1. case에 default가 없으면 조합 블록에서 생기는 일은?
    답

    빠진 경우 이전 값을 유지하는 래치가 생깁니다.
