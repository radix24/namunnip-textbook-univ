블로킹과 논블로킹 할당

본문

Verilog의 대입에는 =와 <= 두 가지가 있다. 둘 다 값을 넣는 것처럼 보여 아무거나 써도 될 것 같지만, 잘못 고르면 시뮬레이션은 맞는데 실제 칩은 다르게 동작하는 일이 생긴다. 두 대입은 무엇이 다를까? 그리고 어느 블록에 어느 것을 써야 할까?

먼저 알아야 할 것HDL 기술(2.1절), 테스트벤치(2.2절)를 쓴다.

2.3.1동시에 바뀌는가, 차례로 바뀌는가

블로킹 할당은 문장마다 즉시 값을 바꾼다. 그런데 논블로킹은 오른쪽을 모두 먼저 평가한 뒤, 블록 끝에서 한꺼번에 바꾼다. 처음 질문의 첫째 답이 이 차이이다.

그리고 플립플롭은 같은 클록에 동시에 바뀐다. 그러므로 always @(posedge clk)에는 논블로킹을, 조합 논리 always @*에는 블로킹을 쓴다. 처음 질문의 둘째 답이 이 규칙이며, 아래 3단 시프트 레지스터가 그 예이다.

// 3단 시프트 레지스터
always @(posedge clk) begin
  q1 <= d;
  q2 <= q1;
  q3 <= q2;
end
예제 2.3.1

위 코드를 블로킹(=)으로 바꾸면 한 클록 뒤 q1, q2, q3는? 처음 d = 1, q1 = q2 = q3 = 0.

풀이. 논블로킹이면 q1 = 1, q2 = 0, q3 = 0으로 한 칸씩 밀린다(시프트). 그런데 블로킹이면 q1 = 1 → q2 = q1 = 1 → q3 = q2 = 1로 세 값이 모두 1이 되어, 플립플롭 하나처럼 합성된다(그림 1). 따라서 시뮬레이션과 합성이 어긋나는 흔한 원인이 된다.

즉 순차 블록에서 블로킹을 쓰면 문장 순서에 따라 회로가 달라진다. 예를 들어 같은 세 줄을 거꾸로 쓰면 블로킹으로도 시프트가 되지만, 이런 순서 의존은 실수를 부르므로 처음부터 논블로킹을 쓴다.

한편 조합 블록에서 논블로킹을 쓰면, 같은 블록 안의 중간 결과가 다음 문장에 바로 반영되지 않아 시뮬레이션이 여러 번 다시 돌거나 잘못된 값을 보인다. 그래서 조합 블록에는 블로킹을 쓴다.

그리고 한 블록 안에서 두 가지를 섞어 쓰지 않는 것이 안전하다. 따라서 많은 설계 팀은 이 규칙을 검사 도구로 자동 확인한다.

흔한 오해=와 <=는 취향 차이라고 여기기 쉽다. 순서에 따른 동작이 달라 회로가 바뀐다. 또 조합 블록에서 일부 경우에 값을 주지 않아도 된다고 생각하기 쉬운데, 래치가 추론된다.
마무리

순차 블록에는 <=, 조합 블록에는 =를 쓴다. 블로킹으로 쓴 시프트 레지스터는 1단으로 합성된다. 조합 블록의 모든 경우에 값을 주어 래치를 막는다.

2.3.2연습문제

기본

  1. 논블로킹으로 a <= b; b <= a;의 효과는?
    답

    두 값이 맞바뀐다.

응용

  1. 블로킹으로 a = b; b = a;의 효과는?
    답

    둘 다 b 값이 된다.

심화

  1. case에 default가 없으면 조합 블록에서 생기는 일은?
    답

    빠진 경우 이전 값을 유지하는 래치가 생긴다.
