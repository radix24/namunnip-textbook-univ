병합 정렬과 퀵 정렬

본문

퀵 정렬은 이름처럼 빠르다고 알려져 있다. 그런데 이미 정렬된 1000개를 넣었더니 비교를 50만 번 가까이 했다. 같은 입력에서 병합 정렬은 5천 번이 채 안 된다. 무엇이 퀵 정렬을 이렇게 느리게 만들었고, 어떻게 하면 피할 수 있을까?

먼저 알아야 할 것재귀와 점화식(1.1절), 힙(3.3절)을 쓴다.

5.1.1단순한 정렬과 그 한계

앞부분을 정렬된 상태로 두고 다음 원소를 알맞은 자리에 끼워 넣는 삽입 정렬은 이해하기 쉽고, 거의 정렬된 자료에서는 \(O(n)\)으로 빠르다. 하지만 역순 입력에서는 \(n(n - 1)/2\)번을 비교한다. 1.2절에서 본 대로 10⁶개라면 약 17분이 걸린다. 그래서 문제를 반으로 나누어 푸는 분할 정복으로 \(O(n\log n)\)을 얻는다. 나누는 방법에 따라 두 정렬이 나온다.

5.1.2병합 정렬

병합 정렬은 나누기를 쉽게, 그냥 반으로 한다. 일은 합치기에서 한다. 두 반쪽을 재귀로 정렬한 뒤, 정렬된 두 줄의 앞을 비교해 작은 것부터 하나씩 꺼내 이어 붙인다.

def merge_sort(a):
    if len(a) <= 1:
        return a
    mid = len(a) // 2
    left, right = merge_sort(a[:mid]), merge_sort(a[mid:])
    out, i, j = [], 0, 0
    while i < len(left) and j < len(right):     # 두 정렬된 줄의 앞을 비교
        if left[i] <= right[j]:
            out.append(left[i]); i += 1
        else:
            out.append(right[j]); j += 1
    return out + left[i:] + right[j:]

병합은 원소마다 한 번씩 옮기므로 \(O(n)\)이고, 점화식 \(T(n) = 2T(n/2) + O(n)\)은 1.1절의 예제처럼 \(O(n\log n)\)이다. 나누는 방법이 입력과 상관없으므로 언제나 \(O(n\log n)\)이다. 또 <= 덕분에 같은 값끼리는 원래 순서가 지켜지는데, 이런 정렬을 안정 정렬이라 한다. 대신 병합할 때 \(n\) 크기의 메모리가 더 든다.

5.1.3퀵 정렬

퀵 정렬은 거꾸로 나누기에서 일한다. 기준 \(p\)를 하나 골라 \(p\)보다 작은 것은 왼쪽, 큰 것은 오른쪽으로 모으는데, 이를 분할이라 한다. 분할은 \(n - 1\)번 비교하며, 배열 안에서 자리를 바꾸어 하면 추가 메모리가 거의 들지 않는다. 그 다음 두 쪽을 재귀로 정렬하면 이어 붙이기만 하면 끝난다.

그러면 빠르기는 기준이 무엇이냐에 달려 있다. 기준이 늘 가운데값이면 반씩 나뉘어 \(O(n\log n)\)이다. 하지만 기준이 늘 최솟값이면 한쪽이 비고 크기가 1씩만 줄어 \(T(n) = T(n - 1) + n\), 곧 \(O(n^2)\)이 된다. 첫 원소를 기준으로 삼는데 입력이 이미 정렬되어 있으면 바로 이 경우가 된다. 처음 질문의 답이 이것이다. 무작위 입력이나 무작위 기준에서는 평균 비교가 약 \(2n\ln n \approx 1.39n\log_2 n\)으로 \(O(n\log n)\)이다.

예제 5.1.1

서로 다른 수 1000개를 무작위 순서와 정렬된 순서로 주고, 병합 정렬, 첫 원소 기준 퀵 정렬, 무작위 기준 퀵 정렬의 비교 횟수를 세어라(실습 카드의 코드).

풀이. 시드 2026으로 실행한 결과는 다음과 같다.

알고리즘무작위 입력정렬된 입력
병합8,7074,932
퀵(첫 원소 기준)10,985499,500
퀵(무작위 기준)10,88310,710

견주어 볼 값은 \(n\log_2 n = 9966\)과 \(n(n - 1)/2 = 499{,}500\)이다. 첫 원소 기준 퀵 정렬은 정렬된 입력에서 정확히 최악인 499,500번을 비교했고, 재귀 깊이도 \(n\)이 되어 Python의 기본 재귀 한도(1000)를 늘려야 했다. 반면 기준을 무작위로 고르면 입력이 무엇이든 평균 경우가 되어 10,710번이다. 따라서 퀵 정렬의 최악은 기준을 무작위로 골라 피한다. 병합 정렬은 정렬된 입력에서 오히려 비교가 줄었는데, 한쪽 줄이 먼저 끝나 나머지를 비교 없이 붙이기 때문이다.

그럼에도 실제로 퀵 정렬이 널리 쓰이는 까닭은 제자리에서 이어진 메모리를 차례로 훑어 캐시 효율이 좋기 때문이다. 한편 Python의 sorted는 병합과 삽입 정렬을 섞은 Timsort이며, 안정하고 최악에도 \(O(n\log n)\)이고 부분적으로 정렬된 자료에서 매우 빠르다.

5.1.4힙 정렬

세 번째 방법은 3.3절의 힙을 쓰는 것이다. 배열을 \(O(n)\)에 heapify한 뒤 최댓값을 \(n\)번 꺼내 뒤에서부터 채우면 제자리에서 \(O(n\log n)\)에 정렬된다. 최악도 \(O(n\log n)\)이지만 안정하지 않고, 배열의 먼 곳을 오가 캐시 효율이 낮아 실제로는 퀵 정렬보다 느린 편이다.

흔한 오해병합 정렬이 비교가 적으니 언제나 더 빠르다고 생각하기 쉽다. 하지만 메모리 복사와 캐시 효과 때문에 실제 시간은 퀵 정렬이 빠른 경우가 많다. 또 안정성이 필요한 곳에 불안정한 정렬을 쓰는 실수도 흔하다. 이름순으로 정렬한 뒤 학년순으로 다시 정렬해 같은 학년 안에서 이름순을 지키려면 둘째 정렬이 안정해야 한다.
마무리

정렬된 입력에서 첫 원소를 기준으로 삼은 퀵 정렬은 기준이 늘 최솟값이 되어 한쪽만 남으므로 \(O(n^2)\), 곧 499,500번을 비교한다. 기준을 무작위로 고르면 평균 \(O(n\log n)\)으로 돌아온다. 병합 정렬은 반으로 나누고 합치기에서 일해 언제나 \(O(n\log n)\)이고 안정하지만 메모리가 더 들며, 퀵 정렬은 나누기에서 일하고 제자리에서 빠르다.

5.1.5연습문제

기본

  1. [5, 2, 4, 6, 1, 3]을 병합 정렬할 때 마지막 병합 직전의 두 줄은?
    답

    [2, 4, 5]와 [1, 3, 6]이다.

응용

  1. [3, 8, 2, 5, 1, 4, 7, 6]을 첫 원소(3)를 기준으로 한 번 분할한 결과는?
    답

    작은 쪽 [2, 1], 기준 3, 큰 쪽 [8, 5, 4, 7, 6]이다(순서를 유지하는 구현 기준).

  2. 퀵 정렬의 기준을 "세 값(처음, 가운데, 끝)의 중앙값"으로 고르면 정렬된 입력에서 비용은?
    답

    정렬된 입력에서는 가운데 원소가 중앙값이어서 반씩 나뉘어 \(O(n\log n)\)이다. 다만 일부러 만든 나쁜 입력에서는 여전히 \(O(n^2)\)이 가능하다.

심화

  1. 같은 값이 아주 많은 입력(0과 1만 100만 개)에서, 기준과 같은 값을 모두 오른쪽으로 보내는 퀵 정렬의 문제와, 세 갈래(<, =, >)로 나누는 효과를 설명하여라.
    답

    같은 값이 모두 한쪽으로 가 분할이 한쪽으로 쏠리므로 \(O(n^2)\)에 가까워진다. 세 갈래 분할은 기준과 같은 값을 한 번에 끝내므로, 서로 다른 값이 \(k\)개면 \(O(n\log k)\) 정도로 빨라진다.
