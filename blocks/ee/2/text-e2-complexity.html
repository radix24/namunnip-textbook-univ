반복문과 재귀의 시간 복잡도

본문

같은 정렬 프로그램이 내 노트북에서는 2초, 친구 컴퓨터에서는 0.5초 걸렸다. 그렇다면 두 알고리즘 가운데 어느 쪽이 빠른지는 무엇으로 비교해야 할까? 실행 시간을 재지 않고, 코드만 보고 "입력이 10배가 되면 일이 몇 배가 되는가"를 알아낼 수 있을까?

먼저 알아야 할 것Python의 반복문과 함수, 재귀(공통10 2.3절, 3.1절), 고교 수학의 등차·등비수열의 합과 로그를 쓴다.

1.1.1시간을 재지 않고 세는 이유

실행 시간은 컴퓨터의 속도, 언어, 그 순간 돌고 있는 다른 프로그램에 따라 달라진다. 그래서 알고리즘끼리 비교할 때는 초를 재는 대신 입력이 커질 때 일이 얼마나 늘어나는지를 센다. 이 과목은 자료를 담는 방법인 자료 구조와 그 위에서 일하는 알고리즘을 다루며, 그 비교에 쓰는 말이 복잡도이다.

세려면 무엇을 셀지부터 정해야 한다. 정렬할 원소 수나 그래프의 정점 수처럼 문제의 크기를 나타내는 수를 입력 크기 \(n\)이라 한다. 그리고 비교, 대입, 산술처럼 한 번에 일정한 시간이 걸린다고 보는 연산을 기본 연산이라 하며, 정렬이라면 비교처럼 알고리즘의 중심이 되는 연산만 세기도 한다. 한편 같은 \(n\)이라도 입력에 따라 횟수가 달라질 수 있는데, 보통은 가장 나쁜 입력, 곧 최악 경우를 기준으로 삼는다. 성능을 보장해야 하기 때문이다.

1.1.2반복문 세기

길이 \(n\)인 리스트에서 합이 0인 쌍을 세는 코드를 보자.

def zero_pairs(a):
    n = len(a); count = 0
    for i in range(n):
        for j in range(i + 1, n):
            if a[i] + a[j] == 0:     # 기본 연산: 이 비교
                count += 1
    return count

안쪽 반복은 \(i\)마다 \(n - 1 - i\)번 돈다. 따라서 전체 비교 횟수는 등차수열의 합이다.

\[ (n - 1) + (n - 2) + \cdots + 0 = \frac{n(n - 1)}{2} \]

\(n\)이 10, 100, 1000이면 45, 4950, 499500번이다. 다시 말해 \(n\)이 10배가 될 때 횟수는 약 100배가 되므로 \(n^2\)에 비례한다.

그런데 매번 반씩 줄어드는 반복은 사정이 다르다. 정렬된 리스트에서 값을 찾는 이진 탐색은 비교할 때마다 구간을 반으로 줄이므로, \(n\)을 2로 몇 번 나누어야 1이 되는가를 세면 된다. 정확히는 최대 \(\lfloor\log_2 n\rfloor + 1\)번이며, \(n\)이 10, 1000, 10⁶이면 4, 10, 20번이다. 원소가 백만 개여도 20번이면 충분하다.

1.1.3재귀는 점화식으로

재귀 함수는 자기 자신을 더 작은 입력으로 부르므로, 실행 시간도 자기 자신으로 표현된다. \(T(n)\)을 더 작은 \(n\)의 \(T\)로 나타낸 식을 점화식이라 한다. 이진 탐색이라면 반으로 나눈 한쪽만 다시 보므로 \(T(n) = T(n/2) + c\)이다. 이 식을 거듭 펼치면 \(T(n) = T(n/4) + 2c = \cdots = T(1) + c\log_2 n\)이 되어 \(\log n\)에 비례한다.

예제 1.1.1

병합 정렬처럼 반으로 나눠 둘 다 처리하고 \(n\)에 비례하는 일로 합치는 알고리즘 \(T(n) = 2T(n/2) + cn\)을 재귀 트리로 풀어라.

풀이. 그림 1처럼 맨 위 층은 \(cn\)의 일을 한다. 그 아래 층에는 크기 \(n/2\)인 문제가 2개 있어 각각 \(cn/2\), 합이 \(cn\)이다. 깊이 \(k\)에서는 \(2^k\)개의 문제가 각각 \(cn/2^k\)씩 일하므로 역시 합이 \(cn\)이다. 문제 크기가 1이 되는 깊이는 \(\log_2 n\)이므로 층은 \(\log_2 n + 1\)개이고, 전체 일은 \(cn(\log_2 n + 1)\)이다. 층마다 같은 양의 일을 한다는 것이 이 트리의 특징이며, 결과는 \(n\log n\)에 비례한다(5단원).

예제 1.1.2

피보나치 수를 그대로 재귀로 계산하는 fib(n) = fib(n-1) + fib(n-2)의 호출 횟수를 구하여라.

풀이. 호출 횟수는 \(C(n) = 1 + C(n - 1) + C(n - 2)\), \(C(0) = C(1) = 1\)을 따른다. 실제로 세면 \(n\)이 10, 20, 25일 때 177, 21891, 242785번이다. \(n\)이 5 늘 때마다 약 11배가 되는데, 이는 \(\phi^5 \approx 11.1\)(\(\phi \approx 1.618\))과 같다. 곧 호출 수는 지수적으로 늘어난다. 그 까닭은 같은 값을 반복해서 다시 계산하기 때문이며, 한 번 계산한 값을 저장해 두는 메모이제이션을 쓰면 \(n\)에 비례하는 호출로 줄어든다.

흔한 오해반복문이 두 개면 무조건 \(n^2\)이라고 생각하기 쉽다. 중첩되었을 때 그렇고, 나란히 있으면 \(n + n = 2n\)이다. 재귀가 느리다는 생각도 맞지 않다. 피보나치 재귀가 느린 것은 같은 부분 문제를 되풀이하기 때문이고, 병합 정렬은 재귀로도 빠르다. 또 Python의 리스트 in, insert(0, x), 슬라이싱처럼 한 줄짜리도 안에서는 \(n\)에 비례하는 일을 할 수 있다(2단원).
마무리

알고리즘은 실행 시간이 아니라 기본 연산의 횟수를 \(n\)의 함수로 세어 비교하며, 보통 최악 경우를 기준으로 한다. 중첩 반복은 \(n(n-1)/2\), 반씩 줄이는 반복은 \(\log_2 n\)이고, 재귀는 점화식을 세워 \(T(n/2) + c\)는 \(\log n\), \(2T(n/2) + cn\)은 \(n\log n\)으로 푼다. 피보나치 재귀처럼 같은 계산을 되풀이하면 호출 수가 지수적으로 늘어난다.

1.1.4연습문제

기본

  1. for i in range(n): for j in range(n): for k in range(n): x += 1의 연산 횟수는?
    답

    \(n^3\).

  2. i = n; while i > 1: i //= 3은 몇 번 도는가?
    답

    약 \(\log_3 n\)번.

응용

  1. for i in range(n): j = 1; while j < n: j *= 2의 안쪽 반복 총 횟수는?
    답

    바깥 \(n\)번에 안쪽 \(\lceil\log_2 n\rceil\)번씩이므로 \(n\log n\)에 비례한다.

심화

  1. \(T(n) = T(n - 1) + n\), \(T(1) = 1\)을 풀어라. 어떤 알고리즘에서 나오는가?
    답

    \(T(n) = 1 + 2 + \cdots + n = \frac{n(n + 1)}{2}\)이다. 매번 가장 작은 것을 골라 빼는 선택 정렬이나 퀵 정렬의 최악 경우에서 나온다.
