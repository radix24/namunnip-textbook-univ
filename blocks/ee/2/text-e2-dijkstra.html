Dijkstra 최단 경로와 음의 간선

본문

내비게이션은 도로마다 걸리는 시간이 다른 지도에서 가장 빠른 길을 찾는다. 간선 수가 적은 길이 가장 짧은 길은 아니므로 BFS로는 안 된다. 그렇다면 가까운 곳부터 하나씩 "이제 확정"이라고 못 박아 가는 방법은 언제 옳고, 언제 틀릴까?

먼저 알아야 할 것BFS(7.1절), 힙과 우선순위 큐(3.3절), Prim 알고리즘(7.2절)을 쓴다.

7.3.1완화

BFS는 간선 무게가 모두 같을 때의 최단 거리를 준다. 무게가 다르면 간선 수가 적다고 짧지 않다. 그림 1에서 A–B는 간선 하나이지만 무게가 4이고, A–C–B는 간선 둘이지만 3이다. 내비게이션, 네트워크 라우팅(OSPF), 칩의 배선 경로 찾기가 모두 이 문제이다.

최단 경로 알고리즘은 모두 같은 연산 하나를 쓴다. 지금까지 찾은 \(s\)에서 \(v\)까지의 경로 가운데 가장 짧은 길이를 거리 추정값 \(d[v]\)라 하자. 처음에는 \(d[s] = 0\)이고 나머지는 무한대이다. 이제 간선 \(u \to v\)(무게 \(w\))에 대해 \(d[u] + w < d[v]\)이면 \(d[v]\)를 \(d[u] + w\)로 줄인다. 이를 완화라 한다. 알고리즘들의 차이는 완화를 어떤 순서로 하느냐뿐이다.

7.3.2Dijkstra 알고리즘

Dijkstra 알고리즘은 아직 확정하지 않은 정점 가운데 \(d\)가 가장 작은 것을 꺼내 확정하고, 그 정점에서 나가는 간선을 모두 완화한다. 가장 작은 것을 꺼내는 데는 힙을 쓴다.

import heapq
def dijkstra(adj, s):
    dist, pq = {s: 0}, [(0, s)]
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist[u]:
            continue                    # 더 짧은 길을 이미 찾은 낡은 항목
        for v, w in adj.get(u, []):
            if d + w < dist.get(v, float("inf")):
                dist[v] = d + w
                heapq.heappush(pq, (dist[v], v))
    return dist

각 간선은 힙에 많아야 한 번 들어가므로 힙 연산은 \(O(E)\)번이고, 각각 \(O(\log E) = O(\log V)\)이다. 따라서 전체는 \(O((V + E)\log V)\)이다.

그런데 꺼낸 순간 "확정"이라고 해도 되는 근거는 무엇일까? 무게가 모두 0 이상이라고 하자. 꺼낸 정점 \(u\)의 \(d[u]\)가 진짜 최단 거리보다 크다고 가정해 보자. 그러면 진짜 최단 경로는 어딘가에서 아직 확정되지 않은 정점 \(x\)를 처음 지나야 하고, \(x\)까지의 부분 경로는 확정된 정점만 지나므로 \(d[x]\)는 이미 그 길이로 완화되어 있다. 이 때 무게가 음수가 아니면 \(x\) 다음 구간의 길이가 0 이상이므로 \(d[x] \le\) 진짜 거리 \(< d[u]\)이다. 그렇다면 \(u\)보다 \(x\)가 먼저 꺼내졌어야 하므로 모순이다.

예제 7.3.1

7.1·7.2절의 가중 그래프(A–B 4, A–C 1, B–C 2, B–D 5, C–D 8, D–E 3)에서 A로부터의 최단 거리를 구하여라.

풀이. A(0)를 확정하면 C = 1, B = 4가 된다. 가장 작은 C(1)를 확정하면 B = min(4, 1 + 2) = 3, D = 9가 된다. 이어서 B(3)를 확정하면 D = min(9, 3 + 5) = 8이고, D(8)를 확정하면 E = 11이다. 결과는 A 0, C 1, B 3, D 8, E 11이며 그림 1과 같다. 간선 수로는 A–B가 한 번이지만 A–C–B가 3으로 더 짧다.

7.3.3음의 간선에서 실패하는 이유

예제 7.3.2

방향 그래프 S → A(2), S → B(5), A → C(4), B → A(−4)에서 S로부터의 최단 거리를 구하여라. 꺼낸 정점을 다시 고치지 않는 Dijkstra는 무엇을 내놓는가?

풀이. 진짜 최단 거리는 A가 S → B → A로 \(5 - 4 = 1\), C가 \(1 + 4 = 5\)이다. 그런데 Dijkstra는 S를 꺼내 A = 2, B = 5로 둔 뒤, 가장 작은 A(2)를 확정하고 C = 6을 만든다. 다음에 B(5)를 꺼내면 A를 1로 줄일 수 있지만, A는 이미 확정되어 고치지 않는다. 그래서 A 2, C 6으로 틀린다. 위 증명의 "\(x\) 다음 구간의 길이는 0 이상"이 음의 간선 때문에 깨진 것이다. 처음 질문의 답이 이것이다. 확정은 무게가 0 이상일 때만 옳다.

음의 간선이 있으면 Bellman-Ford를 쓴다. 모든 간선의 완화를 \(V - 1\)번 되풀이하는 방법으로, 최단 경로는 간선을 많아야 \(V - 1\)개 지나므로 음의 간선이 있어도 맞는다. 비용은 \(O(VE)\)이다. 한 번 더 했을 때 줄어드는 값이 있으면 돌수록 짧아지는 음의 고리가 있다는 뜻이다. 이 예제에 쓰면 A 1, C 5를 올바르게 얻으며, 7.5절에서 자세히 다룬다.

흔한 오해음의 간선은 모든 무게에 같은 상수를 더해 없애면 된다고 생각하기 쉽다. 하지만 간선 수가 다른 경로마다 더해지는 양이 달라 최단 경로가 바뀐다. 간선의 순서만 쓰는 MST와 다른 점이다. 또 힙에서 꺼낸 항목이 낡았는지(d > dist[u]) 확인하지 않으면 같은 정점을 여러 번 처리한다. 결과는 맞아도 느려진다.
마무리

Dijkstra는 확정되지 않은 정점 가운데 거리 추정값이 가장 작은 것을 힙으로 꺼내 확정하고 이웃을 완화하며, 무게가 모두 0 이상일 때 \(O((V + E)\log V)\)에 정확한 최단 거리를 준다. 음의 간선이 있으면 이미 확정한 정점으로 더 짧게 오는 길이 나중에 나타나 틀릴 수 있으므로, 모든 간선을 \(V - 1\)번 완화하는 Bellman-Ford를 쓴다.

7.3.4연습문제

기본

  1. 예제 7.3.1에서 A → E 최단 경로를 정점 순서로 써라.
    답

    A → C → B → D → E이고, 길이는 \(1 + 2 + 5 + 3 = 11\)이다.

응용

  1. 최단 경로 자체를 얻으려면 Dijkstra 코드를 어떻게 고치는가?
    답

    \(d[v]\)를 줄일 때 prev[v] = u를 기록한다. 도착점에서 prev를 거꾸로 따라가면 경로가 나온다.

  2. 정점 10만, 간선 50만인 도로망에서 Dijkstra(힙)와, 배열에서 최솟값을 매번 찾는 \(O(V^2)\) 버전의 연산 수를 어림하여라.
    답

    힙 버전은 \((V + E)\log_2 V \approx 6\times10^5\times17 \approx 10^7\), 배열 버전은 \(V^2 = 10^{10}\)으로 약 천 배 차이이다.

심화

  1. 환율 그래프(간선 무게 \(-\log(\text{환율})\))에서 음의 고리가 있다는 것은 무엇을 뜻하는가?
    답

    고리를 한 바퀴 돌며 환전하면 원래 통화가 늘어나는 차익 거래 기회이다. Bellman-Ford의 음의 고리 검출로 찾을 수 있다.
