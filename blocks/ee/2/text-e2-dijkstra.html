Dijkstra 최단 경로와 음의 간선

본문
이 절에서 배울 것
  • 가중 그래프의 단일 출발점 최단 경로 문제와 완화(relaxation) 연산을 안다.
  • Dijkstra 알고리즘을 힙으로 구현하고 O((V + E) log V)임을 보인다.
  • 음의 간선이 있으면 Dijkstra가 틀리는 이유를 반례로 보이고, Bellman-Ford가 해결하는 방식을 안다.
먼저 알아야 할 것
  • BFS (7.1절), 힙과 우선순위 큐 (3.3절), Prim 알고리즘 (7.2절).

7.3.1완화

BFS는 간선 무게가 모두 같을 때의 최단 거리입니다. 무게가 다르면 간선 수가 적다고 짧지 않습니다. 내비게이션, 네트워크 라우팅(OSPF), 칩 배선 경로 찾기가 이 문제입니다.

거리 추정값 d[v]: 지금까지 찾은 s → v 경로 중 가장 짧은 길이. 처음에는 d[s] = 0, 나머지 ∞.

완화: 간선 u → v(무게 w)에 대해 d[u] + w < d[v]이면 d[v]를 d[u] + w로 줄인다. 모든 최단 경로 알고리즘은 완화를 어떤 순서로 하느냐의 차이다.

7.3.2Dijkstra 알고리즘

아직 확정하지 않은 정점 중 d가 가장 작은 것을 꺼내 확정하고, 그 정점에서 나가는 간선을 모두 완화합니다. 가장 작은 것을 꺼내는 데 힙을 씁니다.

import heapq
def dijkstra(adj, s):
    dist, pq = {s: 0}, [(0, s)]
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist[u]:
            continue                    # 더 짧은 길을 이미 찾은 낡은 항목
        for v, w in adj.get(u, []):
            if d + w < dist.get(v, float("inf")):
                dist[v] = d + w
                heapq.heappush(pq, (dist[v], v))
    return dist

각 간선이 힙에 많아야 한 번 들어가므로 힙 연산 O(E)번, 각각 O(log E) = O(log V): 전체 O((V + E) log V).

왜 맞는가(무게가 모두 0 이상일 때). 꺼낸 정점 u의 d[u]가 진짜 최단 거리보다 크다고 가정해 봅시다. 진짜 최단 경로는 어딘가에서 아직 확정하지 않은 정점 x를 처음 지나야 하고, x까지의 부분 경로는 확정된 정점들만 지나므로 d[x]는 이미 그 길이로 완화되어 있습니다. 무게가 음수가 아니면 x 다음 구간의 길이가 0 이상이라 d[x] ≤ 진짜 거리 < d[u]인데, 그러면 u가 아니라 x가 먼저 꺼내졌어야 하므로 모순입니다.

예제 7.3.1

7.1·7.2절의 가중 그래프(A–B 4, A–C 1, B–C 2, B–D 5, C–D 8, D–E 3)에서 A로부터의 최단 거리를 구하라.

풀이. A(0) 확정 → C = 1, B = 4. C(1) 확정 → B = min(4, 1 + 2) = 3, D = 9. B(3) 확정 → D = min(9, 3 + 5) = 8. D(8) 확정 → E = 11. 결과 A 0, C 1, B 3, D 8, E 11. 간선 수로는 A–B가 한 번이지만 A–C–B(3)가 더 짧습니다.

7.3.3음의 간선에서 실패하는 이유

예제 7.3.2

방향 그래프 S → A(2), S → B(5), A → C(4), B → A(−4)에서 S로부터의 최단 거리를 구하라. 꺼낸 정점을 다시 고치지 않는 Dijkstra는 무엇을 내놓는가?

풀이. 진짜 최단 거리: A는 S → B → A로 5 − 4 = 1, C는 1 + 4 = 5. Dijkstra는 S를 꺼내 A = 2, B = 5로 둔 뒤, 가장 작은 A(2)를 확정하고 C = 6을 만듭니다. 그다음 C(6)보다 작은 B(5)를 꺼내 A를 1로 줄일 수 있지만 A는 이미 확정되어 고치지 않습니다. 결과 A 2, C 6으로 틀립니다. 위 증명의 "x 다음 구간 ≥ 0"이 음의 간선 때문에 깨진 것입니다.

Bellman-Ford: 모든 간선의 완화를 V − 1번 되풀이한다. 최단 경로는 간선이 많아야 V − 1개이므로 음의 간선이 있어도 맞는다. O(VE). 한 번 더 했을 때 줄어드는 값이 있으면 음의 고리(돌수록 짧아지는 고리)가 있다는 뜻이다. 예제에 쓰면 A 1, C 5를 올바르게 얻습니다.

흔한 오해(1) "음의 간선은 모든 무게에 상수를 더해 없애면 된다": 간선 수가 다른 경로마다 다른 양이 더해져 최단 경로가 바뀝니다(MST와 다른 점). (2) 힙에서 꺼낸 항목이 낡았는지(d > dist[u]) 확인하지 않으면 같은 정점을 여러 번 처리합니다(결과는 맞아도 느려짐). (3) Dijkstra는 무가중 그래프에서도 맞지만 BFS(O(V + E))보다 느립니다.
요약
  1. 완화: d[u] + w < d[v]이면 줄인다.
  2. Dijkstra: 가장 작은 d를 힙으로 꺼내 확정. 무게 ≥ 0에서 정확, O((V + E) log V).
  3. 음의 간선이면 확정이 틀릴 수 있다 → Bellman-Ford(O(VE)), 음의 고리 검출.

7.3.4연습문제

기본

  1. 예제 7.3.1에서 A → E 최단 경로를 정점 순서로 쓰라.
    답

    A → C → B → D → E(1 + 2 + 5 + 3 = 11).

응용

  1. 최단 경로 자체를 얻으려면 Dijkstra 코드를 어떻게 고치는가?
    답

    d[v]를 줄일 때 prev[v] = u를 기록. 도착점에서 prev를 거꾸로 따라가면 경로.

  2. 정점 10만, 간선 50만인 도로망에서 Dijkstra(힙)와 배열로 최솟값을 매번 찾는 O(V²) 버전의 연산 수를 어림하라.
    답

    힙: \((V + E)\log_2V \approx 6\times10^5 \times 17 \approx 10^7\). 배열: \(V^2 = 10^{10}\). 약 천 배 차이.

심화

  1. 환율 그래프(간선 무게 \(-\log(\text{환율})\))에서 음의 고리가 있다는 것은 무엇을 뜻하는가?
    답

    고리를 한 바퀴 돌며 환전하면 원래 통화가 늘어나는 차익 거래 기회. Bellman-Ford의 음의 고리 검출로 찾을 수 있습니다.
