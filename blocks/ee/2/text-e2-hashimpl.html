해시 테이블 구현: 해시 함수, 재해싱, 삭제

본문

문자열 "ab"와 "ba"의 글자 코드를 더하면 똑같이 195이다. 이것을 해시 값으로 쓰면 두 키가 늘 충돌한다. 문자열을 고르게 흩어지는 수로 바꾸려면 어떻게 해야 할까? 그리고 표가 차서 칸 수를 두 배로 늘릴 때, 옛 표를 새 표 앞쪽에 그대로 복사하면 왜 안 될까?

먼저 알아야 할 것체이닝과 개방 주소법(6.1절), 동적 배열의 분할상환(1.3절), Python 클래스(공통10 3.3절)를 쓴다.

6.2.1문자열 해시

글자 코드를 그냥 더하면 글자의 순서가 사라진다. "ab"와 "ba"가 같아지는 까닭이다. 그래서 자리마다 다른 가중치를 주는 다항식 해시를 쓴다. 길이 \(L\)인 문자열의 글자 코드를 \(s_0, s_1, \dots\)라 할 때 다음과 같다.

\[ h(s) = \left(s_0 b^{L-1} + s_1 b^{L-2} + \cdots + s_{L-1}\right) \bmod m \]

이 때 거듭제곱을 따로 계산할 필요는 없다. 호너 방법으로 한 글자씩 \(h \leftarrow (h\cdot b + s_i) \bmod m\)을 되풀이하면 \(O(L)\)에 끝나고, 중간값도 \(m\)보다 커지지 않는다. \(b\)는 31이나 131 같은 작은 소수를 흔히 쓴다(언어마다 다른 상수를 쓰므로 확인 필요). \(b = 31\), \(m = 1009\)로 계산하면 "ab"는 \((97\cdot31 + 98) \bmod 1009 = 78\), "ba"는 \((98\cdot31 + 97) \bmod 1009 = 108\)로 달라진다. 처음 질문의 첫째 답이 이것이다.

6.2.2체이닝 테이블 구현

class HashMap:
    def __init__(self, m=8):
        self.t = [[] for _ in range(m)]
        self.n = 0
    def _bucket(self, k):
        return self.t[hash(k) % len(self.t)]
    def put(self, k, v):
        b = self._bucket(k)
        for i, (kk, _) in enumerate(b):
            if kk == k:
                b[i] = (k, v)          # 이미 있으면 값만 바꿈
                return
        b.append((k, v))
        self.n += 1
        if self.n > 2 * len(self.t):  # 적재율 2를 넘으면
            self._resize(2 * len(self.t))
    def get(self, k, default=None):
        for kk, v in self._bucket(k):
            if kk == k:
                return v
        return default
    def delete(self, k):
        b = self._bucket(k)
        for i, (kk, _) in enumerate(b):
            if kk == k:
                b.pop(i); self.n -= 1
                return True
        return False
    def _resize(self, m):
        old = [p for b in self.t for p in b]
        self.t = [[] for _ in range(m)]
        for k, v in old:
            self._bucket(k).append((k, v))

그러면 코드에서 두 곳을 눈여겨보자. 하나는 get과 put이 칸을 찾은 뒤에도 kk == k로 키 자체를 비교한다는 점이다. 해시가 같아도 충돌일 수 있기 때문이다. 다른 하나는 _resize이다. 적재율이 2를 넘으면 칸 수를 두 배로 늘리는데, 이 때 옛 키들을 모두 꺼내 새 표에서 칸을 다시 계산해 넣는다.

왜 그냥 복사하면 안 될까? 칸 번호는 \(k \bmod m\)으로 정해지므로 \(m\)이 바뀌면 칸 번호도 바뀐다. 그림 1에서 12는 칸 4개일 때 칸 0에 있었지만 칸 8개에서는 칸 4로 가야 한다. 옛 자리에 둔 채로 두면 get(12)가 칸 4를 보고 "없다"고 답한다. 처음 질문의 둘째 답이 이것이다. 따라서 재해싱은 모든 키를 다시 배치하는 \(O(n)\)의 일이지만, 칸 수를 두 배로 늘리므로 1.3절과 같은 이유로 put의 분할상환 비용은 \(O(1)\)이다.

6.2.3키가 지켜야 할 조건

한편 해시 테이블이 제대로 돌려면 키가 두 조건을 지켜야 한다. 첫째, a == b이면 hash(a) == hash(b)여야 한다. 그렇지 않으면 같은 키가 다른 칸에 들어가 찾지 못한다. 둘째, 넣은 뒤에 키가 바뀌면 안 된다. 그러면 해시도 바뀌어 원래 칸에서 찾을 수 없다. Python이 리스트를 딕셔너리 키로 받지 않고(TypeError) 튜플은 받는 까닭이 이것이다.

그런데 Python의 dict는 체이닝이 아니라 무작위에 가까운 조사 순서를 쓰는 개방 주소법으로 구현되어 있고, 적재율 약 2/3에서 표를 키운다(구현 세부는 버전마다 달라 확인 필요). 3.7부터는 넣은 순서도 기억한다.

흔한 실수해시 값이 같으면 같은 키라고 판단하는 실수가 흔하다. 충돌이 있으므로 마지막에 키 자체를 ==로 비교해야 한다. 또 사용자 정의 클래스에서 __eq__만 고치고 __hash__를 그에 맞추지 않으면 첫째 조건이 깨져 딕셔너리 동작이 망가진다.
마무리

문자열은 자리마다 \(b\)의 거듭제곱을 곱하는 다항식 해시를 호너 방법으로 \(O(L)\)에 계산해 순서를 살린다. 칸 번호가 \(k \bmod m\)이므로 표를 키울 때는 모든 키의 칸을 다시 계산해야 하며, 두 배씩 키우면 분할상환 \(O(1)\)이다. 키는 같으면 같은 해시를 내야 하고, 넣은 뒤 바뀌지 않아야 한다.

6.2.4연습문제

기본

  1. \(b = 31\), \(m = 1009\)일 때 "abc"의 다항식 해시는? (a = 97, b = 98, c = 99)
    답

    \(((97\cdot31 + 98)\cdot31 + 99) \bmod 1009 = (3105\cdot31 + 99) \bmod 1009 = 96354 \bmod 1009 = 499\)이다.

응용

  1. 위 HashMap에 키 20개를 넣으면 재해싱이 몇 번 일어나고 마지막 칸 수는?
    답

    \(n = 17\)에서 \(17 > 16\)이므로 칸 8개가 16개로 늘어난다. \(n\)이 33이 되지 않으므로 한 번뿐이고 마지막 칸 수는 16이다.

  2. 두 문자열이 같은지 매번 끝까지 비교하는 대신 해시를 먼저 비교하면 무엇이 좋아지는가? 그래도 마지막 비교가 필요한 이유는?
    답

    해시가 다르면 바로 다르다고 판단할 수 있어 대부분 빨라진다. 그러나 해시가 같아도 충돌일 수 있으므로 같다고 결론 내리려면 실제 비교가 필요하다. Rabin-Karp 문자열 검색의 원리이다.

심화

  1. Python에서 d = {}; k = [1, 2]; d[tuple(k)] = 'x'; k.append(3) 뒤 d[(1, 2)]는 무엇인가? 리스트를 키로 허용했다면 어떤 문제가 생겼을까?
    답

    튜플은 넣을 때 만든 복사본이라 그대로이므로 'x'이다. 리스트를 키로 넣고 나중에 바꾸면 해시가 바뀌어 원래 칸에서 찾을 수 없고, 같은 내용을 새로 만들어도 다른 칸으로 가서 찾지 못한다.
