추상 자료형, 배열, 연결 리스트

본문

원소 10만 개가 든 리스트의 맨 앞에 값을 1000번 넣는다. 배열로 만든 리스트에서는 약 1억 번의 이동이 필요하고, 다른 방법으로 만든 리스트에서는 1000번의 참조 변경으로 끝난다. 같은 "리스트"인데 왜 이렇게 다를까?

먼저 알아야 할 것Python 리스트와 클래스(공통10 2.1절, 3.3절), 포인터(공통10 5.2절), 동적 배열(1.3절)을 쓴다.

2.1.1무엇을 하는가와 어떻게 하는가

"리스트"라는 말에는 두 층이 섞여 있다. 하나는 위치로 읽고, 넣고, 지우고, 찾는다는 약속, 곧 무엇을 하는가이다. 이렇게 자료의 모임과 그 위의 연산을 하는 일로만 정한 것을 추상 자료형(ADT)이라 한다. 다른 하나는 그 약속을 메모리에 어떻게 구현하는가이고, 이것을 자료 구조라 한다. 같은 리스트 ADT를 배열로도, 연결 리스트로도 만들 수 있다.

사용하는 쪽은 ADT만 알면 되고, 구현은 연산의 비용을 보고 고른다. 처음 질문의 답도 여기서 나온다. 두 리스트는 ADT는 같지만 자료 구조가 달라 같은 연산의 비용이 다르다. 이 과목의 나머지도 모두 이 구분 위에 서 있다. 스택과 큐(2단원), 우선순위 큐(3단원), 사전(4, 6단원)은 ADT이고, 배열, 트리, 힙, 해시 테이블은 구현이다.

2.1.2배열

배열은 같은 크기의 칸이 메모리에 이어져 놓인 구조이다. 그래서 \(i\)번째 칸의 주소는 시작 주소에 \(i\times\)칸 크기를 더하면 바로 나오고, 인덱스 접근 a[i]는 \(O(1)\)이다. 하지만 그림 1처럼 \(i\) 위치에 넣으려면 뒤의 \(n - i\)개를 한 칸씩 밀어야 하므로 \(O(n - i)\)이고, 맨 앞이면 \(O(n)\)이다. 지울 때도 뒤를 당겨야 한다. 맨 뒤에 추가하는 것만은 1.3절에서 본 대로 분할상환 \(O(1)\)이다.

2.1.3연결 리스트

연결 리스트는 값과 다음 노드를 가리키는 참조를 담은 작은 객체, 곧 노드를 이어 만든다. 노드는 메모리 곳곳에 흩어져 있어도 된다. 각 노드가 다음 노드만 가리키면 단일 연결 리스트, 앞뒤 노드를 모두 가리키면 이중 연결 리스트이다.

class Node:
    def __init__(self, value, next=None):
        self.value = value
        self.next = next
def push_front(head, x):          # 맨 앞 삽입: O(1)
    return Node(x, head)
def insert_after(node, x):        # 아는 노드 뒤에 삽입: O(1)
    node.next = Node(x, node.next)

비용은 배열과 정반대이다. 넣을 자리의 노드를 이미 알면 참조 두어 개만 바꾸면 되므로 삽입과 삭제가 \(O(1)\)이고 원소를 밀 필요가 없다. 반면 \(i\)번째 원소를 읽으려면 머리부터 \(i\)번 따라가야 하므로 \(O(i)\)이다. 또 노드마다 참조를 담는 메모리가 더 들고, 노드가 흩어져 있어 캐시 효율이 나쁘다.

예제 2.1.1

원소 10만 개가 있는 리스트에서 다음 작업을 1000번 반복한다. 배열과 단일 연결 리스트 가운데 무엇이 나은가? (가) 맨 앞에 삽입, (나) 무작위 위치 \(i\)의 값 읽기, (다) 맨 뒤에 추가(연결 리스트는 꼬리 참조를 유지).

풀이. (가)에서 배열은 매번 10만 개를 밀어 약 1억 번을 이동하고, 연결 리스트는 1000번의 참조 변경으로 끝나므로 연결 리스트가 낫다. (나)에서 배열은 \(O(1)\)이지만 연결 리스트는 평균 5만 번씩 따라가야 하므로 배열이 낫다. (다)는 배열이 분할상환 \(O(1)\), 연결 리스트가 꼬리 참조로 \(O(1)\)이어서 비슷하지만, 실제로는 캐시 덕분에 배열이 빠르다. Python에서 맨 앞 삽입이 잦다면 list.insert(0, x) 대신 양쪽 끝이 \(O(1)\)인 collections.deque를 쓴다.

흔한 오해연결 리스트의 삽입은 언제나 \(O(1)\)이라고 생각하기 쉽지만, 넣을 자리의 노드를 이미 알 때만 그렇다. \(i\)번째 자리를 찾는 데 \(O(i)\)가 든다. 또 Python의 list는 연결 리스트가 아니라 동적 배열이다. 그래서 a[i]는 \(O(1)\)이고 a.insert(0, x)는 \(O(n)\)이다.
마무리

두 리스트는 하는 일(ADT)은 같지만 구현(자료 구조)이 다르다. 이어진 칸인 배열은 인덱스 접근이 \(O(1)\)인 대신 맨 앞 삽입에 모든 원소를 밀어야 해 \(O(n)\)이고, 참조로 이은 연결 리스트는 아는 자리의 삽입이 \(O(1)\)인 대신 \(i\)번째 접근이 \(O(n)\)이다. 그래서 구현은 자주 쓰는 연산의 비용을 보고 고른다.

2.1.4연습문제

기본

  1. 원소 \(n\)개 배열의 맨 앞 원소를 지우는 비용은? 연결 리스트는?
    답

    배열은 뒤를 당겨야 해 \(O(n)\), 연결 리스트는 head = head.next로 \(O(1)\)이다.

응용

  1. 단일 연결 리스트를 뒤집는 함수를 \(O(n)\), 추가 메모리 \(O(1)\)로 써라.
    답

    prev = None; cur = head; while cur: cur.next, prev, cur = prev, cur, cur.next; return prev. 각 노드의 참조를 한 번씩 뒤집는다.

  2. 단일 연결 리스트에서 꼬리 노드를 지우는 비용은? 이중 연결 리스트에서는?
    답

    단일은 꼬리 앞 노드를 찾아야 해 \(O(n)\), 이중은 꼬리의 prev로 \(O(1)\)이다.

심화

  1. 연결 리스트에 고리가 있는지(마지막 노드가 앞쪽 노드를 가리키는지) \(O(1)\) 추가 메모리로 판정하는 방법은?
    답

    한 칸씩 가는 느린 포인터와 두 칸씩 가는 빠른 포인터를 함께 움직여 둘이 만나면 고리가 있다(Floyd 알고리즘). 고리가 없으면 빠른 포인터가 끝에 닿는다.
