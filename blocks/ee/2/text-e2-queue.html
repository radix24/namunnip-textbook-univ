큐, 원형 큐, 덱

본문

프린터 대기열처럼 먼저 온 것을 먼저 내보내는 줄을 Python 리스트로 만들고 pop(0)으로 앞을 빼면, 뺄 때마다 남은 원소를 모두 한 칸씩 당긴다. 크기가 정해진 배열 하나로, 넣기와 빼기를 모두 원소 수와 상관없이 한 번에 끝낼 수 있을까?

먼저 알아야 할 것스택(2.2절), 배열 비용(2.1절), 나머지 연산과 클래스(공통10 3.3절)를 쓴다.

2.3.1먼저 온 것이 먼저 나간다

뒤(rear)에서 넣고(enqueue) 앞(front)에서 빼는(dequeue) 리스트를 큐라 한다. 먼저 들어간 것이 먼저 나오므로 FIFO라고도 한다. 프린터 대기열, 네트워크 패킷 버퍼, 키보드 입력 버퍼, 그리고 7단원의 너비 우선 탐색이 큐이다. 하드웨어에서도 UART 수신 버퍼나 오디오 표본 버퍼처럼 크기가 고정된 링 버퍼를 많이 쓴다.

그런데 리스트의 pop(0)은 앞을 당기느라 \(O(n)\)이다. 처음 질문의 실마리는 원소를 당기는 대신 "앞이 어디인지"를 가리키는 위치를 옮기는 데 있다.

2.3.2원형 큐

앞의 위치 front와 원소 수 size를 기억해 두자. 빼면 front를 한 칸 옮기고, 넣을 자리는 front에서 size만큼 뒤이다. 이렇게 하면 배열의 끝에 곧 닿는데, 끝에 닿으면 처음으로 감아 돌면 된다. 그 감아 돌기를 나머지 연산 % cap이 맡는다. 그림 1처럼 배열을 고리로 이어 쓰는 셈이어서 이 구조를 원형 큐라 한다.

class CircularQueue:
    def __init__(self, cap):
        self.buf = [None] * cap
        self.front = 0          # 맨 앞 원소의 위치
        self.size = 0
    def enqueue(self, x):
        if self.size == len(self.buf):
            raise OverflowError("가득 참")
        rear = (self.front + self.size) % len(self.buf)
        self.buf[rear] = x
        self.size += 1
    def dequeue(self):
        if self.size == 0:
            raise IndexError("비어 있음")
        x = self.buf[self.front]
        self.buf[self.front] = None
        self.front = (self.front + 1) % len(self.buf)
        self.size -= 1
        return x

두 연산 모두 원소 하나를 쓰거나 읽고 숫자 몇 개만 바꾸므로 \(O(1)\)이다. 처음 질문의 답이 이것이다.

예제 2.3.1

용량 4인 원형 큐에 10, 20, 30을 넣고 둘을 뺀 뒤 40, 50, 60을 넣으면 배열의 모습과 front는? 70을 더 넣으면?

풀이. 10, 20, 30은 칸 0~2에 들어간다. 두 번 빼면 front는 2, size는 1이 되어 30만 남는다. 40은 칸 \((2 + 1)\%4 = 3\)에, 50은 \((2 + 2)\%4 = 0\)에, 60은 칸 1에 들어가 감아 돈다. 그러면 배열은 [50, 60, 30, 40], front는 2, size는 4로 가득 찬다(그림 1). 따라서 70은 "가득 참" 오류를 낸다. 이후 네 번 빼면 30, 40, 50, 60 순서로 나온다. 배열 안의 순서와 나오는 순서가 다르다는 점에 주목하자. 순서는 front에서부터 감아 돌며 읽는다.

2.3.3가득 참과 비어 있음

size 대신 front와 rear 두 위치만 기억하면 어떻게 될까? 비어 있을 때도 가득 찼을 때도 front와 rear가 같아져 둘을 구별할 수 없다. 해결책은 두 가지이다. 위 코드처럼 size를 따로 두거나, 한 칸을 일부러 비워 두고 \((rear + 1)\%cap = front\)를 가득 참으로 정하는 것이다. 하드웨어 버퍼는 뒤의 방법을 많이 쓴다. 읽는 쪽은 front만, 쓰는 쪽은 rear만 바꾸므로 둘이 동시에 일해도 서로의 변수를 건드리지 않기 때문이다.

양쪽 끝 모두에서 넣고 뺄 수 있는 리스트는 덱(deque)이라 한다. 원형 배열이나 이중 연결 리스트로 만들면 네 연산이 모두 \(O(1)\)이고, Python에는 collections.deque가 있다.

흔한 실수rear를 \(rear + 1\)로만 늘리고 % cap을 빠뜨리면 배열 범위를 넘는다. 또 가득 찼을 때 가장 오래된 자료를 덮어쓰게 만드는 정책은 오디오 버퍼에서는 맞지만, 명령 큐에서는 명령을 잃는다. 어느 정책인지를 분명히 정해 두어야 한다.
마무리

배열의 앞을 당기는 대신 앞의 위치를 옮기고 끝에서는 나머지 연산으로 처음에 이으면, 크기가 정해진 배열 하나로 넣기와 빼기를 모두 \(O(1)\)에 하는 원형 큐가 된다. 비어 있음과 가득 참은 size를 두거나 한 칸을 비워 구별하며, 양쪽 끝이 모두 필요하면 덱을 쓴다.

2.3.4연습문제

기본

  1. 용량 5, front = 3, size = 4인 원형 큐의 다음 enqueue 위치는?
    답

    \((3 + 4)\%5 = 2\).

응용

  1. "한 칸 비우기" 방식에서 용량 8 배열에 최대 몇 개를 넣을 수 있는가? 원소 수를 front와 rear로 구하는 식은?
    답

    7개이다. 원소 수는 \((rear - front + cap)\%cap\)이다.

  2. 최근 1000개 센서 값의 이동 평균을 표본마다 \(O(1)\)로 갱신하는 방법은?
    답

    크기 1000인 원형 버퍼와 현재 합을 유지한다. 새 값을 넣을 때 가장 오래된 값을 빼고 새 값을 더한 뒤 1000으로 나눈다(전전6의 이동 평균 필터).

심화

  1. 원형 큐를 동적으로 키우려면(가득 차면 두 배) 배열 뒤에 칸을 그냥 붙이면 안 되는 이유와 올바른 방법은?
    답

    감아 돌아 front 앞쪽에 놓인 뒤쪽 원소들의 순서가 깨진다. 새 배열에 front부터 size개를 순서대로 복사하고 front를 0으로 둔다.
