이진 탐색 트리의 탐색, 삽입, 삭제

본문

정렬된 배열에서는 이진 탐색으로 \(\log n\)번 만에 찾지만, 중간에 하나를 넣으려면 뒤를 모두 밀어야 한다. 찾기도 빠르고 넣고 빼기도 빠른 구조는 없을까? 그리고 그 구조는 언제나 빠를까?

먼저 알아야 할 것이진 트리와 중위 순회(3.1절), 이진 탐색(1.1절)을 쓴다.

3.2.1왼쪽은 작고 오른쪽은 크다

모든 노드에서 왼쪽 부분 트리의 키는 모두 그 노드보다 작고, 오른쪽 부분 트리의 키는 모두 큰 이진 트리를 이진 탐색 트리(BST)라 한다. 키는 서로 다르다고 두자. 이 성질 하나에서 두 가지가 나온다. 3.1절의 예제처럼 중위 순회가 키를 정렬된 순서로 내고, 찾을 때 노드 하나와 비교해 한쪽 부분 트리를 통째로 버릴 수 있다.

다시 말해 BST는 정렬된 배열의 이진 탐색을 트리 모양으로 펼친 것이다. 차이는 배열과 달리 노드를 참조로 이었다는 데 있다. 그래서 새 키는 빈자리에 노드를 붙이기만 하면 되고 아무것도 밀 필요가 없다.

3.2.2탐색과 삽입

def search(t, key):
    while t is not None and t.key != key:
        t = t.left if key < t.key else t.right
    return t                       # 없으면 None
def insert(root, key):
    if root is None:
        return Node(key)
    if key < root.key:
        root.left = insert(root.left, key)
    elif key > root.key:
        root.right = insert(root.right, key)
    return root

탐색은 뿌리에서 시작해 찾는 키가 작으면 왼쪽, 크면 오른쪽으로 한 길만 내려간다. 삽입은 같은 길을 내려가다 탐색이 실패한 자리, 곧 빈 자식 자리에 새 잎을 붙인다. 따라서 두 연산의 비교 횟수는 높이 \(h\)에 1을 더한 것 이하이고 \(O(h)\)이다.

3.2.3삭제의 세 경우

삭제는 지울 노드의 자식 수에 따라 나뉜다. 잎이면 그냥 떼어 낸다. 자식이 하나면 그 자식을 자기 자리로 끌어올린다. 어려운 것은 자식이 둘일 때이다. 아무 자식이나 올리면 BST 성질이 깨질 수 있기 때문이다. 그래서 중위 순서에서 바로 다음 키, 곧 오른쪽 부분 트리의 최솟값인 후계자를 찾아 그 키를 지울 노드에 복사하고, 원래 후계자 노드를 오른쪽 부분 트리에서 지운다. 후계자는 최솟값이라 왼쪽 자식이 없으므로, 이 둘째 삭제는 앞의 두 경우로 끝난다.

def delete(root, key):
    if root is None:
        return None
    if key < root.key:
        root.left = delete(root.left, key)
    elif key > root.key:
        root.right = delete(root.right, key)
    else:
        if root.left is None:  return root.right
        if root.right is None: return root.left
        succ = root.right
        while succ.left:
            succ = succ.left
        root.key = succ.key
        root.right = delete(root.right, succ.key)
    return root
예제 3.2.1

3.1절 예제의 트리 50(30(20, 40(35, ·)), 70(60, 80))에서 30(자식 둘), 80(잎), 70(자식 하나)을 차례로 지운 결과를 전위 순회로 적어라.

풀이. 30의 오른쪽 부분 트리 40(35)에서 최솟값은 35이므로 35가 후계자이다. 30 자리에 35를 쓰고 원래의 35를 지우면 전위 순회는 50, 35, 20, 40, 70, 60, 80이다. 이어서 80은 잎이라 떼어 내고, 70은 남은 자식 60을 끌어올린다. 그러면 전위 순회는 50, 35, 20, 40, 60이고 높이는 2이다. 실습 카드의 코드 출력과 같다.

3.2.4높이가 모든 것을 정한다

그런데 탐색, 삽입, 삭제가 모두 \(O(h)\)라는 것은 빠르기가 높이에 달려 있다는 뜻이고, 높이는 키를 넣은 순서에 달려 있다. 그림 1의 왼쪽처럼 섞어 넣으면 일곱 키가 높이 2에 들어가지만, 오른쪽처럼 정렬된 순서로 넣으면 오른쪽으로만 늘어난 사슬이 되어 높이가 \(n - 1 = 6\)이다. 이 때 BST는 연결 리스트와 다를 바 없어 탐색이 \(O(n)\)이 된다. 처음 질문의 둘째 답이 이것이다.

다행히 무작위 순서로 넣으면 높이는 평균적으로 \(\log n\)에 비례한다. 무작위 순서 20가지로 직접 만들어 보면 \(n = 1000\)에서 평균 높이 약 20, 노드의 평균 깊이 약 10.9이고, \(n = 10000\)에서는 약 30.6과 15.8이다(\(\log_2 n\)은 각각 10과 13.3). 하지만 입력 순서를 고를 수 없다면 이 평균에 기댈 수 없다. 4단원의 균형 탐색 트리는 회전으로 높이를 늘 \(O(\log n)\)으로 유지해 이 문제를 없앤다.

흔한 오해BST 탐색은 언제나 \(O(\log n)\)이라고 생각하기 쉽지만, 트리가 균형일 때만 그렇다. 또 같은 키를 허용하려면 "작으면 왼쪽, 크거나 같으면 오른쪽"처럼 규칙을 정해 두어야 탐색이 일관된다.
마무리

왼쪽은 작고 오른쪽은 큰 이진 탐색 트리는 이진 탐색처럼 한 길만 내려가 찾고, 빈자리에 잎을 붙여 넣으며, 자식이 둘인 노드는 후계자로 바꾸어 지운다. 세 연산 모두 \(O(h)\)이어서 찾기와 넣고 빼기가 함께 빠르지만, 정렬된 순서로 넣으면 높이가 \(n - 1\)이 되어 \(O(n)\)으로 떨어진다.

3.2.5연습문제

기본

  1. 빈 BST에 40, 20, 60, 10, 30, 50, 70을 넣으면 높이는? 30을 찾는 비교 횟수는?
    답

    완전히 균형 잡혀 높이는 2이다. 40, 20, 30을 거쳐 3번 비교한다.

응용

  1. 문제 1의 트리에서 40을 지우면 뿌리는? 전위 순회는?
    답

    후계자 50이 뿌리가 된다. 전위 순회는 50, 20, 10, 30, 60, 70이다.

  2. BST에서 \(k\)보다 작은 키 가운데 가장 큰 것(floor)을 \(O(h)\)에 찾는 방법은?
    답

    뿌리부터 내려가며, 키가 \(k\)보다 크거나 같으면 왼쪽으로 가고, 작으면 그 키를 후보로 적고 오른쪽으로 간다. 마지막 후보가 답이다.

심화

  1. 1~\(n\)을 넣는 \(n!\)가지 순서 가운데 높이가 \(n - 1\)(사슬)이 되는 순서는 몇 가지인가?
    답

    매번 남은 키 가운데 최솟값이나 최댓값을 넣어야 하므로 \(2^{n-1}\)가지이다. \(n = 7\)이면 64/5040, 약 1.3%이다.
