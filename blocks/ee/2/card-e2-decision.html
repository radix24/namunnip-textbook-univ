세 수를 정렬하는 결정 트리

예제 · 하한이 꽉 맞는 경우

먼저 예측

서로 다른 세 수 a, b, c를 정렬하는 데 비교가 최악 몇 번 필요할까? 2번으로 되는 방법이 있을까?

생각해 본 뒤 열기

최악 3번이 필요하다. 2번 비교의 결과는 4가지뿐인데 가능한 순서는 6가지라 모두 구별할 수 없다.

문제

삽입 정렬로 a, b, c를 정렬하는 결정 트리를 그리고, 잎의 수와 높이를 하한 \(\lceil\log_23!\rceil\)과 비교하라.

전략

  1. 삽입 정렬의 비교 순서: 먼저 a:b, 그다음 c를 앞의 정렬된 둘과 비교.
  2. 각 잎에 최종 순서를 적고 깊이를 센다.

풀이

  1. 뿌리 a:b. a < b이면 [a, b]가 정렬됨. 다음 b:c → b < c면 잎 a<b<c(깊이 2). 아니면 a:c → a < c면 a<c<b, 아니면 c<a<b(깊이 3). 왼쪽 가지
  2. a > b이면 [b, a]. 다음 a:c → a < c면 b<a<c(깊이 2). 아니면 b:c → b<c<a 또는 c<b<a(깊이 3). 오른쪽 가지
  3. 잎 6개 = 3!, 높이 3 = \(\lceil\log_26\rceil = \lceil2.58\rceil\). 하한이 꽉 맞는다. 정리 5.2.1

의미

이 트리는 삽입 정렬 하나의 결정 트리이지만, 어떤 비교 정렬 알고리즘이든 잎 6개를 가진 이진 트리여야 하므로 높이 3 미만이 불가능하다. 평균 비교 횟수도 (2 + 3 + 3 + 2 + 3 + 3)/6 ≈ 2.67로, 평균 경우의 하한 \(\log_26 \approx 2.58\)에 가깝다.

검산

a = 2, b = 1, c = 3을 넣으면 a:b(아니오) → a:c(예) → 잎 b<a<c = 1, 2, 3. 비교 2번. 맞다.
