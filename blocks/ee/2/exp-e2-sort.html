입력 모양에 따라 달라지는 정렬 비용

탐구 · 네 정렬의 비교 횟수

질문

병합, 퀵(첫 원소 기준), 퀵(무작위 기준), 삽입 정렬은 무작위·정렬됨·역순·같은 값이 많은 입력에서 각각 몇 번 비교할까요?

준비

0~n−1(또는 0, 1, 2만)을 고른 모양으로 늘어놓고 네 알고리즘의 비교 횟수를 셉니다(정해진 시드의 가상 입력). 막대 높이가 비교 횟수, 점선이 n log₂n입니다. 퀵 정렬은 깊은 재귀를 피하려고 스택으로 구현했습니다.

해 보기와 설명

  1. 무작위(n = 1000)병합 8,724, 퀵(첫 원소) 12,076, 퀵(무작위) 11,988, 삽입 255,311. n log₂n = 9,966입니다.
  2. 정렬됨병합 4,932, 퀵(첫 원소) 499,500(최악), 퀵(무작위) 10,210, 삽입 999(최선). 같은 입력이 퀵에는 최악, 삽입에는 최선입니다.
  3. 역순퀵(첫 원소)과 삽입이 모두 499,500으로 최악입니다.
  4. 값 세 가지퀵(첫 원소)은 같은 값을 한쪽으로 몰아 167,850번이지만, 같은 값을 따로 모으는 퀵(무작위, 세 갈래)은 1,666번으로 가장 적습니다(5.1절 연습 4).

연결과 적용

실습 카드의 Python 코드(시드가 달라 무작위 입력의 숫자는 조금 다름)와 같은 경향입니다. 실제 라이브러리는 입력 모양에 강한 방법(Timsort, introsort)을 씁니다.

흔한 오해

  • "한 정렬이 모든 입력에서 가장 빠르다" 이 표처럼 입력 모양마다 순위가 바뀝니다. 최악 경우 보장과 평균 속도를 함께 봐야 합니다.
