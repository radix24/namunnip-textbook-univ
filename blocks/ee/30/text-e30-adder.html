덧셈기와 자리올림 예측

본문

손으로 덧셈을 하면 오른쪽 끝에서부터 자리올림을 하나씩 넘긴다. 하드웨어도 그렇게 하면 64비트 덧셈은 자리올림이 64단을 지나야 끝난다. 프로세서의 핵심 경로에 있는 덧셈기를 이렇게 느리게 둘 수는 없다. 자리올림을 미리 계산할 수 있을까?

먼저 알아야 할 것정적 CMOS 게이트와 논리적 노력(2.1절, 2.2절), 배선 지연(7.1절)을 쓴다.

7.3.1생성과 전파

각 자리에서 생성 신호 \(g_i = a_ib_i\)와 전파 신호 \(p_i = a_i \oplus b_i\)를 정한다. \(g_i = 1\)이면 그 자리가 자리올림을 만들고, \(p_i = 1\)이면 들어온 자리올림을 그대로 넘긴다. 그러면 \(c_{i+1} = g_i + p_ic_i\), 합은 \(s_i = p_i \oplus c_i\)이다. 리플 자리올림 덧셈기는 이 식을 차례로 계산하므로 지연이 \(O(n)\)이다. 그런데 식을 펼치면 \(c_2 = g_1 + p_1g_0 + p_1p_0c_0\)처럼 모든 자리올림을 입력만으로 쓸 수 있다. 다만 비트가 늘수록 항이 많아져 게이트가 커진다.

7.3.2자리올림 예측과 병렬 접두 덧셈기

자리올림 예측(CLA) 덧셈기는 4비트씩 묶어 묶음의 생성 \(G\)와 전파 \(P\)를 계산하고, 묶음 사이에서 다시 같은 식을 쓴다. 이 계층을 되풀이하면 지연이 \(O(\log n)\)이 된다. 일반화하면 \((g, p)\) 쌍에 결합 법칙을 따르는 연산 \((g_h, p_h)\circ(g_l, p_l) = (g_h + p_hg_l, p_hp_l)\)을 정의해, 모든 접두 \((G_{i:0}, P_{i:0})\)을 병렬로 구하는 병렬 접두 덧셈기가 된다. Kogge-Stone 구조는 \(\log_2n\)단으로 가장 빠르지만 배선과 게이트가 많고, Brent-Kung 구조는 단이 약 두 배이지만 면적과 배선이 적다. 따라서 설계 목표(속도, 면적, 전력)에 따라 고른다.

예제 7.3.1

한 단 지연이 \(\tau\)일 때 64비트 리플 덧셈기와 Kogge-Stone 덧셈기의 자리올림 경로 지연을 어림하여라(생성·전파 계산과 합 계산에 각 1단).

풀이. 리플은 \(g, p\) 1단 + 자리올림 64단 + 합 1단으로 약 \(66\tau\)이다. Kogge-Stone은 \(g, p\) 1단 + 접두 \(\log_264 = 6\)단 + 합 1단으로 약 \(8\tau\)이다. 그러므로 8배쯤 빠르다. 대신 접두 단마다 긴 배선이 늘어나, 7.1절의 배선 지연까지 고려해 설계한다.

마무리

덧셈의 자리올림은 생성 \(g = ab\)와 전파 \(p = a \oplus b\)로 \(c_{i+1} = g_i + p_ic_i\)를 따른다. 리플 덧셈기는 이를 차례로 계산해 지연이 비트 수에 비례한다. 자리올림 예측과 병렬 접두 덧셈기는 결합 법칙을 이용해 자리올림을 계층적으로 미리 구해 지연을 \(\log n\)으로 줄이며, 구조마다 속도와 면적·배선의 교환이 있다.

7.3.3연습문제

기본

  1. \(a = 1011\), \(b = 0110\)일 때 각 자리의 \(g\)와 \(p\)를 구하여라(오른쪽이 0번 자리).
    답

    \(g = 0010\), \(p = 1101\).

응용

  1. 연산 \(\circ\)가 결합 법칙을 만족하는 것이 병렬 접두 계산에 왜 중요한지 말하여라.
    답

    결합 법칙이 있어야 묶는 순서를 마음대로 바꾸어 트리 모양으로 동시에 계산할 수 있기 때문이다.
