인터럽트 처리 과정

본문
이 절에서 배울 것
  • 인터럽트 요청부터 복귀까지의 단계를 순서대로 설명한다.
  • 벡터 테이블, 우선순위, 중첩(선점)을 안다.
  • 인터럽트 지연과 ISR을 짧게 써야 하는 이유를 안다.
먼저 알아야 할 것
  • 프로그래밍 모델 (1.1절), 스택.

2.1.1순서(Cortex-M 기준)

  1. 주변 장치가 요청 → 인터럽트 제어기(NVIC)가 우선순위를 비교.
  2. 현재 명령어를 마친 뒤, 하드웨어가 R0~R3, R12, LR, PC, xPSR 8개를 스택에 자동 저장.
  3. 벡터 테이블에서 해당 ISR 주소를 읽어 PC에 넣고, LR에 특수 복귀 값을 넣음.
  4. ISR 실행(원인 플래그를 지움).
  5. BX LR로 특수 값이 PC에 들어가면 하드웨어가 8개를 복원하고 원래 코드로 복귀.

자동 저장 덕분에 ISR을 일반 C 함수로 쓸 수 있습니다. 더 높은 우선순위 인터럽트는 실행 중인 ISR을 선점합니다.

예제 2.1.1

100 MHz 코어, 인터럽트 진입·복귀에 각 12 사이클, ISR 본문 60 사이클이다. 초당 50 000번 인터럽트가 오면 CPU 시간의 몇 %를 쓰는가?

풀이. 한 번에 84 사이클 × 50 000 = 4.2 × 10⁶ 사이클, 4.2%(사이클 수는 가상, Cortex-M3/M4 진입 지연 12 사이클은 확인 필요). ISR이 길면 다른 인터럽트가 늦어지므로, ISR은 플래그만 세우고 무거운 처리는 주 루프나 작업에서 합니다.

흔한 오해(1) "인터럽트는 명령어 중간에도 바로 끊는다": 보통 명령어 경계에서 받습니다(일부 긴 명령어는 예외). (2) "ISR 안에서 원인 플래그를 지우지 않아도 된다": 지우지 않으면 복귀하자마자 다시 들어옵니다.
요약
  1. 요청 → 자동 저장 8개 → 벡터 → ISR → 복원.
  2. 우선순위와 선점.
  3. ISR은 짧게, 플래그 지우기.

2.1.2연습문제

기본

  1. ISR 주소가 적힌 표의 이름은?
    답

    벡터 테이블.

응용

  1. 인터럽트당 200 사이클, 10 kHz, 50 MHz 코어의 CPU 점유율은?
    답

    4%.

심화

  1. 공유 변수를 ISR과 주 루프가 함께 쓸 때 필요한 것은?
    답

    volatile 선언과 필요하면 원자적 접근(인터럽트 금지 구간).
