타이머 인터럽트로 주기 작업 구현

본문
이 절에서 배울 것
  • 타이머의 분주기(PSC)와 자동 재적재 값(ARR)으로 인터럽트 주기를 정한다.
  • 16비트 한계 안에서 PSC, ARR 조합을 찾는다.
  • 주기 작업(LED 점멸, 센서 표본화)의 ISR 구조를 쓴다.
먼저 알아야 할 것
  • 인터럽트 처리 (2.1절).

2.2.1주기 계산

주기 \(T = (PSC + 1)(ARR + 1)/f_{clk}\). 16비트 타이머는 ARR + 1 ≤ 65536이므로 긴 주기에는 분주가 필요합니다. 아래 코드는 16 MHz 입력에서 조합을 찾습니다.

# 16비트 타이머로 원하는 주기를 만드는 분주비(PSC)와 자동 재적재 값(ARR) 찾기
f_clk = 16_000_000          # 타이머 입력 클록 16 MHz
for period in (1e-3, 0.5):  # 1 ms, 0.5 s
    counts = round(f_clk * period)
    for psc in range(1, 65537):
        if counts % psc == 0 and counts // psc <= 65536:
            arr = counts // psc
            break
    print(f"주기 {period} s: 총 {counts} 클록 = 분주 {psc} × 계수 {arr} → PSC = {psc - 1}, ARR = {arr - 1}")

실행 결과(Python 3.12에서 실제 실행):

주기 0.001 s: 총 16000 클록 = 분주 1 × 계수 16000 → PSC = 0, ARR = 15999
주기 0.5 s: 총 8000000 클록 = 분주 125 × 계수 64000 → PSC = 124, ARR = 63999

ISR 예(레지스터 이름은 STM32 계열 예시, 확인 필요):

volatile uint32_t ticks = 0;
void TIM2_IRQHandler(void) {
    if (TIM2->SR & TIM_SR_UIF) {
        TIM2->SR &= ~TIM_SR_UIF;     // 원인 플래그 지우기
        ticks++;                     // 1 ms마다 증가
        if (ticks % 500 == 0) GPIOA->ODR ^= (1u << 5);   // 0.5 s마다 LED 반전
    }
}
예제 2.2.1

1 kHz 표본화가 필요한데 주기가 1 % 이상 흔들리면 안 된다. 주 루프에서 delay()로 기다리는 방식과 타이머 인터럽트를 비교하라.

풀이. delay 방식은 루프 안 다른 일의 시간이 더해져 주기가 흔들립니다. 타이머는 하드웨어가 세므로 ISR 진입 지연(수 μs 이하)만큼만 흔들립니다. 더 정확하게는 타이머가 ADC를 직접 트리거하고 DMA로 저장합니다(4.2절).

흔한 오해(1) "PSC에 분주비를 그대로 넣는다": 레지스터 값은 분주비 − 1입니다. (2) "ticks를 32비트로 세면 영원하다": 1 ms 단위면 약 49.7일에 넘칩니다. 차이 계산을 부호 없는 뺄셈으로 합니다.
요약
  1. T = (PSC + 1)(ARR + 1)/f_clk.
  2. 예: 16 MHz, 1 ms → PSC 0, ARR 15999.
  3. 하드웨어 타이머는 소프트웨어 지연보다 정확.
