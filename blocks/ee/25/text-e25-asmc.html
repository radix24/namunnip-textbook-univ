1.2.1같은 일을 두 언어로

배열 a의 n개 원소 합을 구하는 C 함수와, 이를 손으로 옮긴 Thumb-2 어셈블리입니다(R0 = 주소, R1 = 개수, 결과 R0).

int sum(const int *a, int n) {
    int s = 0;
    for (int i = 0; i < n; i++) s += a[i];
    return s;
}
sum:    MOVS  r2, #0          @ s = 0
loop:   CBZ   r1, done        @ n == 0이면 끝
        LDR   r3, [r0], #4    @ r3 = *a, a += 4 (사후 증가)
        ADDS  r2, r2, r3      @ s += r3
        SUBS  r1, r1, #1      @ n--
        B     loop
done:   MOV   r0, r2          @ 반환값
        BX    lr

원소 하나에 명령어 다섯 개(LDR, ADDS, SUBS, B, CBZ)가 돕니다. 컴파일러 최적화(-O2)는 루프를 펼치거나 비교를 줄여 더 빠른 코드를 만들기도 합니다. 대부분은 C로 쓰고, 시동 코드나 시간이 엄격한 부분만 어셈블리로 씁니다.

예제 1.2.1

32비트 레지스터 reg에서 비트 3을 1로, 비트 7을 0으로, 비트 4를 검사하는 C 식은?

풀이. reg |= (1u << 3); reg &= ~(1u << 7); if (reg & (1u << 4)). 읽고-바꾸고-쓰기 중간에 인터럽트가 같은 레지스터를 바꾸면 값이 덮어써질 수 있어, 비트 설정 전용 레지스터(SET/RESET)나 인터럽트 금지 구간을 씁니다.

흔한 오해(1) "어셈블리가 언제나 C보다 빠르다": 현대 컴파일러가 대부분 더 낫습니다. (2) "int는 언제나 32비트": 플랫폼마다 달라 고정 폭 형식(uint32_t)을 씁니다.
요약
  1. C ↔ 어셈블리 대응(LDR 사후 증가, CBZ, BX lr).
  2. 비트 설정 |=, 해제 &= ~, 검사 &.
  3. 읽고-바꾸고-쓰기의 경쟁 조건 주의.

1.2.2연습문제

기본

  1. reg의 비트 0~3을 모두 0으로 만드는 식은?
    답

    reg &= ~0xFu;

응용

  1. LDR r3, [r0], #4 뒤 r0는 얼마나 바뀌는가?
    답

    4 증가(다음 int).

심화

  1. 위 어셈블리에서 n = 0으로 호출하면 결과는?
    답

    CBZ로 바로 done, 0 반환.
