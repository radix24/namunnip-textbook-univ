비순차 실행이 성능을 높이는 원리

본문
이 절에서 배울 것
  • 데이터 의존이 없는 명령어를 먼저 실행해 지연을 숨기는 원리를 안다.
  • 레지스터 이름 바꾸기가 가짜 의존(WAR, WAW)을 없앰을 안다.
  • 재정렬 버퍼(ROB)가 순서대로 결과를 확정해 정확한 예외를 지키는 것을 안다.
먼저 알아야 할 것
  • 파이프라이닝과 해저드 (전전14 5단원).

5.1.1예

1: LDR  r1, [r2]      @ 캐시 미스: 100 사이클
2: ADD  r3, r1, #1    @ 1에 의존
3: MUL  r4, r5, r6    @ 독립
4: ADD  r7, r4, r8    @ 3에 의존
5: SUB  r1, r9, r10   @ r1을 다시 씀(WAW·WAR)

순차 파이프라인은 2에서 100 사이클 멈춰 3~5도 기다립니다. 비순차 프로세서는 명령어를 대기열에 넣고 피연산자가 준비된 것부터 실행해, 미스 동안 3, 4를 끝냅니다. 5는 r1을 덮어써 1, 2와 이름이 겹칠 뿐 실제 값 의존은 없으므로, 물리 레지스터를 새로 배정(이름 바꾸기)해 먼저 실행할 수 있습니다.

실행은 뒤섞여도 재정렬 버퍼가 원래 순서대로 결과를 확정(커밋)하므로, 중간에 예외가 나면 그 앞 명령까지만 반영된 정확한 상태를 볼 수 있습니다.

예제 5.1.1

위 다섯 명령에서 독립 명령 3, 4, 5가 각 1 사이클이라 할 때, 순차 실행과 이상적 비순차 실행의 총 사이클을 어림하라(미스 100, 나머지 1).

풀이. 순차: 1(100) + 2 + 3 + 4 + 5 ≈ 104. 비순차: 3, 4, 5가 미스 동안 끝나 1(100) + 2 ≈ 101. 숨길 독립 명령이 많을수록(창이 클수록) 이득이 커집니다.

흔한 오해(1) "비순차면 프로그램 결과 순서도 바뀐다": 확정은 순서대로라 단일 스레드 결과는 같습니다. (2) "비순차 실행은 공짜": 대기열, ROB, 이름 바꾸기 하드웨어로 면적과 전력이 큽니다(그래서 저전력 MCU는 순차).
요약
  1. 준비된 명령부터 실행해 지연 숨김.
  2. 이름 바꾸기로 WAR·WAW 제거.
  3. ROB가 순서대로 확정, 정확한 예외.

5.1.2연습문제

기본

  1. 진짜 의존(RAW)의 예는?
    답

    2가 1의 결과 r1을 읽음.

응용

  1. 5가 1과 갖는 해저드 종류는?
    답

    WAW(같은 r1을 씀), 2와는 WAR.

심화

  1. Cortex-M0 같은 MCU가 비순차 실행을 쓰지 않는 이유는?
    답

    면적·전력·결정적 실행 시간이 더 중요하기 때문입니다.
