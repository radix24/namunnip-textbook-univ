소켓으로 클라이언트-서버 프로그램 작성

본문
이 절에서 배울 것
  • TCP 소켓의 서버(bind, listen, accept)와 클라이언트(connect) 순서를 안다.
  • Python으로 대문자 변환 에코 서버를 만들어 한 컴퓨터 안에서 시험한다.
  • 여러 클라이언트 처리(스레드, 비동기)의 필요성을 안다.
먼저 알아야 할 것
  • 계층과 포트 (1.2절), Python 기초.

2.1.1순서

서버: socket → bind(주소, 포트) → listen → accept(연결마다 새 소켓) → recv/send → close. 클라이언트: socket → connect(서버 주소, 포트) → send/recv → close. 아래 코드는 서버를 스레드로 띄우고 같은 프로그램에서 클라이언트로 접속합니다(127.0.0.1, 운영체제가 고른 빈 포트).

import socket, threading
srv = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
srv.bind(("127.0.0.1", 0)); srv.listen(1)
port = srv.getsockname()[1]
def serve():
    conn, addr = srv.accept()
    with conn:
        data = conn.recv(1024)
        conn.sendall(data.upper())
t = threading.Thread(target=serve); t.start()
cli = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
cli.connect(("127.0.0.1", port))
cli.sendall("hello, network".encode())
print("서버 응답:", cli.recv(1024).decode())
cli.close(); t.join(); srv.close()

예제 2.1.1

위 서버가 한 번에 한 클라이언트만 처리한다. 동시에 100명이 접속하면 어떻게 고치는가?

풀이. accept를 반복하며 연결마다 스레드를 만들거나(threading), asyncio로 한 스레드에서 여러 연결을 번갈아 처리합니다. TCP는 바이트 흐름이라 recv 한 번이 보낸 메시지 하나와 일치한다는 보장이 없어, 길이 머리말이나 구분자로 메시지 경계를 정해야 합니다.

흔한 오해(1) "send 한 번 = recv 한 번": TCP는 메시지 경계를 보존하지 않습니다. (2) "서버 소켓으로 데이터를 주고받는다": accept가 돌려준 연결 소켓으로 주고받습니다.
요약
  1. 서버: bind → listen → accept. 클라이언트: connect.
  2. 예: HELLO, NETWORK가 돌아옴(실제 실행).
  3. 동시 처리: 스레드·asyncio. 메시지 경계는 직접 정함.
