HTTP 연결 방식과 응답 시간

본문
이 절에서 배울 것
  • TCP 연결 설정(1 RTT)과 요청-응답(1 RTT)으로 객체당 시간을 어림한다.
  • 비지속·지속·파이프라인 연결의 응답 시간을 비교한다.
  • HTTP/2·3가 지연을 줄이는 방법을 안다.
먼저 알아야 할 것
  • 계층 구조 (1.2절), 소켓 (2.1절).

2.2.1RTT 세기

비지속 연결은 객체마다 TCP 연결(1 RTT) + 요청-응답(1 RTT)으로 2 RTT가 듭니다. 지속 연결은 연결을 한 번만 하고, 파이프라인은 여러 요청을 연달아 보내 객체들을 약 1 RTT에 받습니다(전송 시간 무시).

예제 2.2.1

RTT 20 ms, HTML 하나 + 이미지 10개. 비지속 직렬과 지속 파이프라인의 응답 시간은?

풀이. 비지속: 11 × 2 RTT = 440 ms. 지속 파이프라인: HTML 2 RTT + 이미지 1 RTT = 60 ms. HTTP/2는 한 연결에서 여러 요청을 섞어 보내고, HTTP/3(QUIC)는 연결 설정과 암호화 협상을 합쳐 RTT를 더 줄입니다.

흔한 오해(1) "대역폭만 늘리면 웹이 빨라진다": 작은 객체가 많으면 RTT가 지배합니다. (2) "TCP 연결은 공짜": 설정에 1 RTT, TLS면 더 듭니다.
요약
  1. 비지속: 객체당 2 RTT.
  2. 지속 파이프라인: 2 RTT + 1 RTT.
  3. 예: 440 ms vs 60 ms.

2.2.2연습문제

기본

  1. RTT 50 ms, 객체 1개 비지속 응답은?
    답

    100 ms.

응용

  1. 지속 비파이프라인(객체마다 1 RTT)으로 위 예제는?
    답

    2 RTT + 10 RTT = 240 ms.

심화

  1. 브라우저가 병렬 연결 6개를 쓰면 비지속 응답은(위 예제)?
    답

    HTML 2 RTT + 이미지 2묶음 × 2 RTT = 120 ms.
