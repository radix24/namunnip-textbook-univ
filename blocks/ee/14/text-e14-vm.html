가상 메모리와 주소 변환

본문

컴퓨터에서 여러 프로그램이 동시에 돌아가는데, 각 프로그램은 모두 자기 코드가 주소 0x00400000에서 시작한다고 믿는다. 같은 주소를 여러 프로그램이 쓰는데 어떻게 서로의 데이터를 덮어쓰지 않을까? 프로그램이 쓰는 주소를 실제 메모리 주소로 바꾸는 일은 누가, 어떻게 할까?

먼저 알아야 할 것캐시 주소 분할(6.1절), AMAT(6.2절)를 쓴다.

6.3.1변환

프로그램은 저마다 0부터 시작하는 가상 주소를 쓰고, 운영체제가 이를 페이지라는 일정한 크기(예: 4 KB) 단위로 실제 메모리에 배치한다. 32비트 가상 주소에 4 KB 페이지라면, 아래 12비트는 페이지 안의 위치인 오프셋이고 위 20비트는 가상 페이지 번호(VPN)이다.

운영체제는 프로그램마다 페이지 표를 만든다. 페이지 표는 VPN마다 물리 페이지 번호(PPN)와 유효 비트, 권한 비트를 담는다. 하드웨어는 VPN으로 이 표를 찾아 PPN으로 바꾸고, 오프셋은 그대로 붙인다. 그래서 두 프로그램이 같은 가상 주소를 써도 표가 다르면 서로 다른 물리 페이지로 가며, 처음 질문의 답이 이것이다(그림 1).

예제 6.3.1

가상 주소 0x00403ABC, 페이지 표 항목 PT[0x00403] = PPN 0x1A2(유효). 물리 주소는?

풀이. 아래 12비트, 곧 16진 세 자리가 오프셋이므로 VPN = 0x00403, 오프셋 = 0xABC이다. 따라서 물리 주소는 (0x1A2 ≪ 12) | 0xABC = 0x001A2ABC이다. 오프셋은 바뀌지 않고 그대로 붙는다.

6.3.2TLB

그런데 페이지 표도 메모리에 있다. 매 접근마다 표를 한 번 더 읽으면 메모리 접근이 두 배로 느려진다. 그래서 최근 변환을 담는 작은 연관 캐시인 TLB를 두며, 대부분의 접근은 TLB에서 바로 변환된다.

예를 들어 TLB 적중률 99%, TLB 1사이클, 메모리 100사이클이라 하고 캐시는 무시하자. 실효 시간은 \(0.99(1 + 100) + 0.01(1 + 100 + 100) = 102\)사이클로, TLB가 없을 때의 200사이클의 약 절반이다.

한편 유효 비트가 0이면 그 페이지는 메모리에 없으며, 이를 페이지 부재(page fault)라 한다. 이때 운영체제가 디스크에서 페이지를 읽어 오는 데 수백만 사이클이 걸리므로, 부재율은 아주 작아야 한다. 또 권한 비트는 다른 프로그램의 메모리를 읽거나 코드 영역에 쓰는 것을 막아 프로그램끼리 보호한다.

흔한 실수가상 주소 전체를 표에서 바꾼다고 여기는 실수가 흔하다. 바뀌는 것은 페이지 번호뿐이고 오프셋은 그대로이므로, 4 KB 페이지면 16진 아래 세 자리가 가상 주소와 물리 주소에서 같다. 또 32비트 주소 공간 전체를 단일 단계 표로 만들면 프로그램마다 4 MB가 필요해, 실제로는 쓰는 부분만 만드는 다단계 표를 쓴다.
마무리

가상 주소는 VPN과 오프셋으로, 물리 주소는 PPN과 오프셋으로 이루어진다. TLB는 페이지 표 접근을 생략해 주며, 적중률이 실효 시간을 정한다. 페이지 부재는 매우 비싸고, 권한 비트로 프로그램끼리 보호한다.

6.3.3연습문제

기본

  1. 64비트 가상 주소 중 48비트만 쓰고 페이지 4 KB면 VPN은 몇 비트?
    답

    48 − 12 = 36비트이다.

응용

  1. PT[0x12] = 0x7F일 때 가상 주소 0x00012345의 물리 주소는?
    답

    (0x7F ≪ 12) | 0x345 = 0x0007F345이다.

심화

  1. 단일 단계 페이지 표(32비트 주소, 4 KB 페이지, 항목 4바이트)의 크기는? 다단계 표를 쓰는 이유는?
    답

    2²⁰ × 4 B = 4 MB이다. 표의 대부분이 비어 있으므로 다단계로 나눠 쓰는 부분만 만들면 메모리를 아낀다.
