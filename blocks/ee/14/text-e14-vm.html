가상 메모리와 주소 변환

본문
이 절에서 배울 것
  • 가상 주소를 페이지 번호와 오프셋으로 나누고 페이지 표로 물리 주소를 만든다.
  • TLB가 주소 변환을 빠르게 하는 원리와 실효 접근 시간을 계산한다.
  • 페이지 부재와 보호(권한 비트)의 역할을 안다.
먼저 알아야 할 것
  • 캐시 주소 분할 (6.1절), AMAT (6.2절).

6.3.1변환

프로그램은 저마다 0부터 시작하는 가상 주소를 쓰고, 운영체제가 페이지(예: 4 KB) 단위로 실제 메모리에 배치합니다. 32비트 가상 주소, 4 KB 페이지면 오프셋 12비트, 가상 페이지 번호(VPN) 20비트. 페이지 표는 VPN마다 물리 페이지 번호(PPN)와 유효·권한 비트를 담습니다.

예제 6.3.1

가상 주소 0x00403ABC, 페이지 표 항목 PT[0x00403] = PPN 0x1A2(유효). 물리 주소는?

풀이. VPN = 0x00403, 오프셋 = 0xABC. 물리 주소 = (0x1A2 ≪ 12) | 0xABC = 0x001A2ABC. 오프셋은 그대로 붙습니다.

6.3.2TLB

페이지 표도 메모리에 있어 매 접근마다 한 번 더 읽으면 두 배 느려집니다. 최근 변환을 담는 작은 연관 캐시(TLB)를 두면 대부분 바로 변환됩니다.

예: TLB 적중률 99%, TLB 1사이클, 메모리 100사이클(캐시 무시): 실효 시간 \(0.99(1 + 100) + 0.01(1 + 100 + 100) = 102\)사이클로 TLB가 없을 때(200)의 약 절반입니다.

유효 비트가 0이면 페이지 부재(page fault): 운영체제가 디스크에서 페이지를 읽어 오는데 수백만 사이클이 걸리므로, 부재율이 아주 작아야 합니다. 권한 비트로 다른 프로그램의 메모리를 읽거나 코드 영역에 쓰는 것을 막습니다.

흔한 오해(1) "가상 메모리는 디스크를 메모리처럼 쓰는 것뿐이다": 프로그램마다 독립된 주소 공간과 보호를 주는 것도 핵심입니다. (2) "TLB는 데이터 캐시다": 주소 변환 결과만 담는 캐시입니다.
요약
  1. 가상 주소 = VPN | 오프셋. 물리 주소 = PPN | 오프셋.
  2. TLB로 페이지 표 접근을 생략. 적중률이 실효 시간을 정한다.
  3. 페이지 부재는 매우 비싸고, 권한 비트로 보호.

6.3.3연습문제

기본

  1. 64비트 가상 주소 중 48비트만 쓰고 페이지 4 KB면 VPN은 몇 비트?
    답

    36비트.

응용

  1. PT[0x12] = 0x7F일 때 가상 주소 0x00012345의 물리 주소는?
    답

    0x0007F345.

심화

  1. 단일 단계 페이지 표(32비트 주소, 4 KB 페이지, 항목 4바이트)의 크기는? 다단계 표를 쓰는 이유는?
    답

    2²⁰ × 4 B = 4 MB. 대부분 비어 있으므로 다단계로 쓰는 부분만 만들어 메모리를 아낍니다.
