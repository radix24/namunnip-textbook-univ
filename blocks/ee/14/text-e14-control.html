하드와이어드 제어와 마이크로프로그램 제어

본문
이 절에서 배울 것
  • 제어 장치를 조합 회로·FSM으로 만드는 하드와이어드 방식을 안다.
  • 제어 신호 묶음을 메모리(제어 저장소)에 저장하고 차례로 읽는 마이크로프로그램 방식을 안다.
  • 속도, 유연성, 설계 용이성을 비교한다.
먼저 알아야 할 것
  • 제어 신호 (4.1절), FSM (전전4 6.1절).

4.2.1두 방식

하드와이어드: opcode와 현재 상태(다중 사이클이면 FSM 상태)를 입력으로 제어 신호를 직접 내는 논리 회로. 빠르지만 명령이 많고 복잡하면 회로가 커지고 고치기 어렵습니다.

마이크로프로그램: 한 사이클의 제어 신호 묶음을 마이크로명령으로 만들어 ROM(제어 저장소)에 두고, 기계 명령마다 마이크로명령 몇 개를 차례로 읽어 실행합니다. 명령을 바꾸거나 추가하기 쉽고(ROM만 고침), 복잡한 명령(문자열 복사 등)도 구현할 수 있지만 ROM 접근 때문에 느립니다.

예제 4.2.1

제어 신호가 20개, 다중 사이클 구현에서 기계 명령 평균 4단계, 명령 종류 100개(각 단계 하나씩 다른 마이크로명령)라면 수평 마이크로코드 제어 저장소의 크기는(다음 주소 필드 9비트 포함)?

풀이. 마이크로명령 수 약 400개(공유 단계를 무시한 상한), 폭 20 + 9 = 29비트. 약 400 × 29 = 11,600비트(약 1.4 KB). 공통 단계(인출, 해독)를 공유하면 줄어듭니다.

역사적으로 복잡한 명령 집합(CISC, x86 초기)은 마이크로프로그램, 단순한 RISC는 하드와이어드를 썼습니다. 현대 x86은 자주 쓰는 명령은 하드와이어드로 마이크로 연산(μop)으로 바꾸고, 드문 복잡한 명령만 마이크로코드 ROM을 씁니다. 마이크로코드 갱신으로 출시 후 버그나 보안 문제를 고치기도 합니다(확인 필요: 제조사 문서).

흔한 오해(1) "마이크로프로그램은 소프트웨어다": CPU 내부 하드웨어의 제어 순서이며, 일반 프로그램과 다른 계층입니다. (2) "RISC는 마이크로코드를 전혀 안 쓴다": 대부분 하드와이어드지만 예외 처리 등에 쓰는 경우도 있습니다.
요약
  1. 하드와이어드: 논리 회로로 직접, 빠름, 고치기 어려움.
  2. 마이크로프로그램: 제어 저장소의 마이크로명령, 유연, 느림.
  3. 현대 CPU는 혼합(μop 변환 + 드문 명령 마이크로코드).

4.2.3연습문제

기본

  1. 명령 집합을 출시 후 고치기 쉬운 방식은?
    답

    마이크로프로그램.

응용

  1. 제어 신호 30개, 마이크로명령 512개, 다음 주소 필드 포함 폭은? 저장소 크기는?
    답

    다음 주소 9비트, 폭 39비트, 512 × 39 = 19,968비트.

심화

  1. 수평형과 수직형 마이크로코드의 차이는?
    답

    수평형은 제어 신호마다 한 비트(넓고 빠름), 수직형은 필드를 부호화해 폭을 줄이고 해독기가 필요(좁고 느림).
