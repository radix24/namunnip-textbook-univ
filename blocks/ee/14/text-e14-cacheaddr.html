캐시의 주소 분할

본문
이 절에서 배울 것
  • 블록, 집합, 연관도로 캐시 구조를 정의한다.
  • 주소를 태그, 인덱스, 오프셋으로 나누는 비트 수를 계산한다.
  • 직접 사상과 집합 연관의 충돌 실패 차이를 안다.
먼저 알아야 할 것
  • 2진수와 2의 거듭제곱, 로그(고교 수학 I), 이 절의 탐구 카드(6.2절).

6.1.1구조

블록: 메모리와 캐시가 한 번에 주고받는 단위(예: 64바이트).

연관도: 한 블록이 들어갈 수 있는 자리 수. 1이면 직접 사상, 전체면 완전 연관, 그 사이가 n-way 집합 연관.

집합 수 = 캐시 크기/(블록 크기 × 연관도). 주소(바이트)는

\[ \text{오프셋} = \log_2(\text{블록}),\quad \text{인덱스} = \log_2(\text{집합 수}),\quad \text{태그} = \text{주소 비트} - \text{인덱스} - \text{오프셋}. \]
예제 6.1.1

32 KB, 블록 64 B, 4-way, 32비트 주소. (가) 비트 분할, (나) 주소 0x12345678의 오프셋, 인덱스, 태그.

풀이. (가) 집합 32768/(64 × 4) = 128. 오프셋 6, 인덱스 7, 태그 19비트. (나) 오프셋 = 주소 & 63 = 56(0x38), 인덱스 = (주소 ≫ 6) & 127 = 89(0x59), 태그 = 주소 ≫ 13 = 0x91A2.

6.1.2충돌

직접 사상은 블록마다 자리가 하나라, 같은 인덱스로 가는 두 블록을 번갈아 쓰면 서로 쫓아내 매번 실패합니다(충돌 실패). 연관도를 올리면 같은 집합에 여럿이 함께 있어 줄어듭니다. 대신 태그 비교기가 연관도만큼 필요하고 적중 시간이 조금 늘어납니다. 탐구 카드에서 4 KB 떨어진 두 배열을 직접 사상과 2-way로 비교합니다.

흔한 오해(1) "인덱스 비트 수는 캐시 크기로만 정해진다": 연관도가 올라가면 집합 수가 줄어 인덱스가 줄고 태그가 늘어납니다. (2) "블록을 크게 하면 언제나 좋다": 공간 지역성은 잘 쓰지만 블록 수가 줄어 충돌이 늘고, 실패 벌점(옮길 양)이 커집니다.
요약
  1. 집합 수 = 크기/(블록 × 연관도).
  2. 오프셋 log₂블록, 인덱스 log₂집합, 나머지 태그.
  3. 직접 사상은 충돌 실패, 연관도로 줄인다(비교기·시간 대가).

6.1.3연습문제

기본

  1. 8 KB 직접 사상, 블록 32 B, 32비트 주소의 비트 분할은?
    답

    집합 256: 오프셋 5, 인덱스 8, 태그 19.

응용

  1. 같은 8 KB를 2-way로 하면?
    답

    집합 128: 오프셋 5, 인덱스 7, 태그 20.

심화

  1. 예제 캐시에서 태그 저장에 필요한 비트 수(유효 비트 포함, 블록당)와 전체는?
    답

    블록 512개, (19 + 1) × 512 = 10,240비트(약 1.25 KB).
