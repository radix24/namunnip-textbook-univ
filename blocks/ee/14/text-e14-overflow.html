오버플로 검출과 부호 확장

본문

8비트 정수 100에 50을 더했더니 150이 아니라 −106이 나왔다. 덧셈기가 고장 난 것일까? 같은 8비트 패턴 10010110을 부호 없는 수로 읽으면 150이 맞는데, 하드웨어는 언제 결과가 틀렸다고 알려 줘야 할까? 또 8비트 값을 32비트 레지스터에 넣을 때 빈 비트는 무엇으로 채울까?

먼저 알아야 할 것2의 보수(전전4 1.1절), 정수 산술(3.1절)을 쓴다.

3.3.1같은 비트, 다른 해석

덧셈기는 비트를 더할 뿐, 그 비트가 부호 있는 수인지 부호 없는 수인지 알지 못한다. 2의 보수 덕분에 두 해석 모두 같은 덧셈 회로로 맞는 비트를 얻기 때문이다. 다만 결과가 범위를 넘었는지 판단하는 기준은 해석마다 다르다.

부호 있는 덧셈은 두 피연산자의 부호가 같은데 결과의 부호가 다를 때 오버플로이다. 반면 부호 없는 덧셈은 최상위 비트에서 자리올림이 날 때 범위를 넘는다. 그래서 하드웨어는 같은 덧셈기를 쓰고, 두 경우를 서로 다른 플래그로 알려 준다. 처음 질문의 첫째 답이 이것이다.

또 8비트 값을 32비트로 넓힐 때도 해석이 갈린다. 부호 있는 수는 부호 비트를 위쪽에 복사해 채우는데 이를 부호 확장이라 하고, 부호 없는 수는 0을 채우는데 이를 0 확장이라 한다. 처음 질문의 둘째 답이 이것이다.

예제 3.3.1

8비트 100 + 50과 −100 + (−50)은? 0xF0을 32비트로 부호 확장, 0 확장하면?

풀이. 100 + 50 = 150은 8비트 부호 있는 범위(−128~127) 밖이다. 결과 비트 10010110은 −106으로 읽혀, 양수 + 양수가 음수가 된 오버플로이다(그림 1). 마찬가지로 −150도 범위 밖이어서 결과 01101010은 +106이 되고, 음수 + 음수가 양수가 된 오버플로이다.

0xF0은 부호 있는 수로 −16이다. 부호 확장하면 위 24비트를 1로 채워 0xFFFFFFF0(여전히 −16)이 되고, 0 확장하면 0x000000F0, 곧 240이 된다.

흔한 오해최상위 자리올림이 나면 늘 오버플로라고 여기기 쉽다. 하지만 부호 있는 덧셈에서 −1 + 1 = 0은 자리올림이 나도 결과가 맞다. 부호 있는 오버플로는 자리올림이 아니라 부호의 변화로 판단하며, 부호 비트로 들어오는 자리올림과 나가는 자리올림이 다를 때와 같다.
마무리

부호 있는 덧셈은 같은 부호끼리 더해 부호가 바뀌면 오버플로이다. 부호 없는 덧셈은 최상위 자리올림이 나면 범위를 넘는다. 값을 넓힐 때 부호 있는 수는 부호 비트를 복사하는 부호 확장을, 부호 없는 수는 0 확장을 한다.

3.3.2연습문제

기본

  1. 8비트 127 + 1의 부호 있는 결과는?
    답

    −128이 되어 오버플로이다.

응용

  1. 8비트 200 + 100(부호 없음)의 결과와 오버플로 여부는?
    답

    결과는 44이고, 최상위 자리올림이 나므로 오버플로이다.

심화

  1. lb와 lbu 명령의 차이는?
    답

    둘 다 바이트를 읽지만 lb는 부호 확장, lbu는 0 확장을 한다.
