순차 곱셈기의 레지스터 변화

예제 · 곱 레지스터를 옮기는 구현

먼저 예측

곱셈기가 피승수를 옮기는 대신 곱 레지스터를 옮기면 무엇이 좋을까?

생각해 본 뒤 열기

덧셈기를 2n비트에서 n비트로 줄이고, 곱수를 곱 레지스터 아래 절반에 넣어 레지스터 하나를 아낀다.

문제

4비트 피승수 M = 0110(6), 곱수 Q = 0101(5). 8비트 곱 레지스터 P의 아래 4비트에 Q를 넣고 위 4비트는 0으로 시작한다. 매 단계: P의 맨 아래 비트가 1이면 위 4비트에 M을 더하고(올림 포함), P 전체를 오른쪽으로 1비트 옮긴다. 4단계 후 P는?

전략

  1. 처음 P = 0000 0101.
  2. 단계마다 검사 → 더하기 → 옮기기.

풀이

  1. 단계 1: 아래 비트 1 → 위에 0110 더함: 0110 0101 → 옮김 0011 0010. 1
  2. 단계 2: 아래 비트 0 → 옮김 0001 1001. 2
  3. 단계 3: 아래 비트 1 → 0001 + 0110 = 0111: 0111 1001 → 옮김 0011 1100. 3
  4. 단계 4: 아래 비트 0 → 옮김 0001 1110 = 30. 4

의미

곱수 비트가 오른쪽으로 빠져나가는 자리에 곱의 아래 비트가 차오르므로 레지스터 하나로 충분하다. 덧셈 결과에서 올림이 생기면 옮길 때 맨 위 비트로 들어가야 합니다(올림 비트 포함 옮기기).

검산

6 × 5 = 30 = 0001 1110. 일치한다.

이해 확인

M = 1111(15), Q = 0011(3)이면 결과는?

답

45 = 0010 1101.

확인비트 수

n비트 × n비트 곱셈 결과를 담으려면 최소 몇 비트?
