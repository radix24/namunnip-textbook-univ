TLB와 실효 메모리 접근 시간

본문
이 절에서 배울 것
  • TLB가 페이지 테이블 접근을 줄이는 원리를 안다.
  • TLB 적중률로 실효 접근 시간을 계산한다.
  • TLB가 감당하는 메모리 범위(reach)를 계산한다.
먼저 알아야 할 것
  • 가상 주소 변환 (6.3절).

6.5.1주소 변환도 캐시한다

가상 주소마다 페이지 테이블(다단계면 여러 번)을 읽으면 메모리 접근이 몇 배가 됩니다. 최근 변환을 저장하는 작은 연관 캐시 TLB가 적중하면 바로 물리 주소를 얻습니다.

예제 6.5.1

TLB 조회 1 ns, 메모리 접근 100 ns, 2단계 페이지 테이블(실패 시 2번 더 읽음). TLB 적중률 98%의 실효 접근 시간은?

풀이. 적중: 1 + 100 = 101 ns. 실패: 1 + 200 + 100 = 301 ns. 실효 0.98 × 101 + 0.02 × 301 = 105 ns로, TLB가 없을 때(300 ns)의 약 1/3입니다.

흔한 오해(1) "TLB는 데이터 캐시의 일부": 주소 변환만 저장하는 별도 구조입니다. (2) "적중률 98%면 충분히 작은 손해": 실패 비용이 커서 2%가 4%의 시간 증가를 만듭니다.
요약
  1. 실효 = h(t_TLB + t_mem) + (1 − h)(t_TLB + k·t_mem + t_mem).
  2. 예: 98% → 105 ns.
  3. TLB reach = 항목 수 × 페이지 크기.

6.5.2연습문제

기본

  1. TLB 64항목, 4 KB 페이지의 reach는?
    답

    256 KB.

응용

  1. 같은 TLB에 2 MB 큰 페이지를 쓰면 reach는?
    답

    128 MB.

심화

  1. 적중률 99.5%면 예제의 실효 시간은?
    답

    약 102 ns.
