이 절에서 배울 것
  • 일부분을 빠르게 했을 때 전체 가속이 개선되지 않은 부분에 묶이는 것을 식으로 쓴다.
  • 가속의 상한 \(1/(1 - f)\)를 계산한다.
  • 병렬 처리(코어 수)에 적용해 확장의 한계를 안다.
먼저 알아야 할 것
  • CPU 성능 식 (1.1절).

1.2.1식

원래 실행 시간 중 비율 f인 부분을 s배 빠르게 하면 새 시간은 \((1 - f) + f/s\)(원래를 1로)이므로

\[ \text{전체 가속} = \frac{1}{(1 - f) + f/s} \;\xrightarrow{s \to \infty}\; \frac{1}{1 - f}. \]
예제 1.2.1

실행 시간의 80%가 곱셈인 프로그램. (가) 곱셈기를 10배 빠르게 하면? (나) 100배면? (다) 전체를 4배 빠르게 하려면 곱셈을 몇 배 빠르게 해야 하는가?

풀이. (가) \(1/(0.2 + 0.08) = 3.57\)배. (나) \(1/(0.2 + 0.008) = 4.81\)배. 상한 5배에 거의 닿아, 10배에서 100배로 늘린 노력이 35%만 더 줍니다. (다) \(1/(0.2 + 0.8/s) = 4\) → s = 16. 5배는 불가능합니다.

1.2.2병렬 처리

N코어에서 병렬화 가능한 비율 p이면 가속 \(1/((1 - p) + p/N)\). p = 0.95여도 아무리 많은 코어로 20배를 넘지 못합니다. 그래서 병렬 프로그램에서는 직렬 부분(동기화, 입출력)을 줄이는 것이 핵심입니다. 문제 크기를 함께 키우는 경우는 Gustafson 법칙으로 다룹니다.

흔한 오해(1) "가장 자주 쓰는 부분을 빠르게 하면 된다": 맞지만 상한이 1/(1 − f)라는 것을 함께 봐야 합니다. (2) "코어를 두 배로 하면 두 배 빠르다": 직렬 부분 때문에 줄어듭니다.
요약
  1. 가속 = 1/((1 − f) + f/s), 상한 1/(1 − f).
  2. 개선 효과는 빠르게 포화한다(f = 0.8이면 최대 5배).
  3. 병렬: 1/((1 − p) + p/N). 직렬 부분이 한계.

1.2.3연습문제

기본

  1. f = 0.5, s = 2이면 전체 가속은?
    답

    1/(0.5 + 0.25) = 1.33배.

응용

  1. p = 0.9 프로그램을 8코어로 돌리면 가속은?
    답

    1/(0.1 + 0.1125) = 4.71배.

심화

  1. f = 0.6 부분을 3배, 다른 0.3 부분을 2배 빠르게 하면 전체 가속은?
    답

    새 시간 0.1 + 0.2 + 0.15 = 0.45, 가속 2.22배.
