0.1 + 0.2를 비트로 보기

탐구 · IEEE 754 단정밀도 덧셈

질문

컴퓨터에서 0.1 + 0.2가 정확히 0.3이 아닌 이유를 비트로 확인할 수 있을까?

준비

두 칸에 수를 넣으면 단정밀도(32비트)로 저장된 값과 비트(빨강 부호, 주황 지수, 파랑 가수), 단정밀도 덧셈 결과, 그리고 배정밀도로 더한 결과를 보여 줍니다(3.2절). 진한 칸이 1, 연한 칸이 0이다.

해 보기와 설명

  1. 처음 화면0.1의 저장값 0.100000001, 0.2는 0.200000003. 단정밀도 합 0.300000012로 0.3의 단정밀도 저장값과 같지만, 배정밀도 합은 0.30000000000000004로 0.3과 다르다.
  2. 0.75 + 1.5지수 −1과 0, 가수를 1자리 옮겨 더하면 2.25(지수 1), 비트 0 10000000 00100…(예제 3.2.1).
  3. 큰 수 + 작은 수16777216과 1을 넣으면 합이 16777216 그대로이다. 지수 차이로 1이 가수 밖으로 밀려난다.
  4. 음수−6.5와 0.75를 넣으면 −5.75, 부호 비트 1, 지수 129(2²).

연결과 적용

과학 계산, 그래픽, 머신러닝은 부동소수점을 쓰고, 머신러닝은 16비트(bfloat16, FP16)나 8비트 형식으로 속도와 메모리를 아낀다. 금액처럼 정확해야 하는 계산은 정수(원 단위)나 십진 형식을 쓴다.

흔한 오해

  • "0.1 + 0.2 == 0.3이 거짓이면 컴퓨터가 틀렸다." 2진으로 정확히 나타낼 수 없는 수의 반올림 결과로, 규칙대로 계산한 것이다.
  • "단정밀도가 배정밀도보다 정확하다." 이 예에서 우연히 같아졌을 뿐, 일반적으로 배정밀도가 훨씬 정확하다.
