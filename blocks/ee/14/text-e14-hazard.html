데이터 해저드와 제어 해저드

본문
이 절에서 배울 것
  • 5단계 파이프라인(IF, ID, EX, MEM, WB)에서 해저드의 세 종류를 안다.
  • 데이터 해저드를 전달(forwarding)과 멈춤으로 해결하고, load-use 해저드의 1사이클 멈춤을 계산한다.
  • 분기에 따른 제어 해저드와 예측·명령 재배치를 안다.
먼저 알아야 할 것
  • 단일 사이클 데이터패스 (4.1절), 이 절의 탐구 카드.

5.1.1세 해저드

구조 해저드: 같은 사이클에 같은 자원을 두 명령이 쓰려 함(명령·데이터 메모리를 분리해 해결).

데이터 해저드: 앞 명령의 결과가 레지스터에 쓰이기 전에 뒤 명령이 읽음.

제어 해저드: 분기 결과가 나오기 전에 다음 명령을 가져와야 함.

5.1.2데이터 해저드

전달이 없으면 결과는 WB에서 레지스터에 쓰이고(앞 반주기), 뒤 명령은 ID에서 읽으므로(뒤 반주기) 바로 다음 명령은 2사이클을 기다려야 합니다. ALU 결과를 EX 끝에서 다음 명령 EX 입력으로 바로 보내는 전달 회로를 두면 ALU→ALU는 멈춤이 없습니다. load는 MEM 끝에 값이 나오므로 바로 다음 명령이 쓰면 전달해도 1사이클 멈춤이 필요합니다(load-use).

예제 5.1.1

lw x1,0(x2) / add x3,x1,x4 / sw x3,4(x2) / addi x5,x5,1. (가) 전달 없음, (나) 전달 있음의 전체 사이클. (다) addi를 lw 바로 뒤로 옮기면?

풀이. 이상적 4 + 4 = 8사이클. (가) add가 x1을 2사이클, sw가 x3을 2사이클 기다려 12사이클. (나) load-use 1사이클만 멈춰 9사이클. (다) lw와 add 사이에 의존 없는 addi가 들어가 멈춤 없이 8사이클(전달 있음). 컴파일러의 명령 재배치(스케줄링)가 하드웨어 멈춤을 숨깁니다. 탐구 카드에서 세 경우를 확인합니다.

5.1.3제어 해저드

분기 결과를 EX에서 알면, 분기를 택했을 때 이미 가져온 두 명령을 버려야 합니다(2사이클 손해). 분기 비교를 ID로 당기면 1사이클, 분기 예측(정적: 뒤로 가는 분기는 택함, 동적: 분기 이력 표)으로 맞히면 0사이클입니다.

흔한 오해(1) "전달하면 모든 데이터 해저드가 사라진다": load-use는 1사이클 멈춤이 남습니다. (2) "멈춤은 하드웨어만 해결한다": 컴파일러 재배치로 많이 줄일 수 있습니다.
요약
  1. 구조·데이터·제어 해저드.
  2. 전달: ALU→ALU 멈춤 0, load-use 1사이클. 전달 없으면 2사이클.
  3. 분기: EX 해결 시 2사이클 손해, 예측·ID 비교로 줄임.

5.1.4연습문제

기본

  1. 전달이 있을 때 add x1,.. 바로 다음 sub x2,x1,..의 멈춤은?
    답

    0.

응용

  1. 전달 없이 add x1 다음 다음(두 번째 뒤) 명령이 x1을 쓰면 멈춤은?
    답

    1사이클.

심화

  1. 분기 비율 20%, 택함 60%, 택하면 2사이클 손해(예측 없음)이면 CPI 증가량은?
    답

    0.2 × 0.6 × 2 = 0.24.
