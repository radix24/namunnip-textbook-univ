성능 측정 방법

본문
이 절에서 배울 것
  • 실행 시간을 반복 측정하고 중앙값·백분위로 요약한다.
  • 예열(warm-up)과 측정 오버헤드를 처리한다.
  • 프로파일러로 시간이 쓰이는 곳을 찾는다.
먼저 알아야 할 것
  • 검증 계획 (1.3절), 프로젝트 (5.1절).

5.2.1한 번 재면 안 된다

첫 실행은 캐시가 비어 있고 JIT·드라이버 초기화가 섞여 느립니다. 예열 몇 번 뒤 여러 번 재서 중앙값과 95·99 백분위를 보고합니다. GPU·가속기는 비동기라 동기화한 뒤 시간을 잽니다. 아래는 Python 측정 골격입니다(측정값은 컴퓨터마다 달라 결과는 싣지 않음).

import time, statistics as st
def bench(fn, warmup=5, repeat=50):
    for _ in range(warmup):
        fn()                                  # 예열: 캐시·초기화
    ts = []
    for _ in range(repeat):
        t0 = time.perf_counter()
        fn()
        ts.append((time.perf_counter() - t0) * 1e3)
    ts.sort()
    return st.median(ts), ts[int(0.95 * len(ts)) - 1], ts[-1]
med, p95, worst = bench(lambda: sum(i * i for i in range(100_000)))
print(f"중앙값 {med:.2f} ms, 95% {p95:.2f} ms, 최악 {worst:.2f} ms")
예제 5.2.1

측정값 10, 11, 10, 12, 10, 45, 11, 10 ms를 얻었다. 평균과 중앙값 중 무엇을 보고하고, 45 ms는 어떻게 다루는가?

풀이. 평균 14.9 ms는 45 ms 하나에 끌려 대표성이 없고, 중앙값 10.5 ms가 전형값입니다. 45 ms는 버리지 말고 최악·백분위로 따로 보고하며, 원인(다른 프로세스, 쓰레기 수집, 열 제한)을 찾습니다.

흔한 오해(1) "가장 빠른 값을 보고": 재현되지 않는 최선값이라 오해를 부릅니다. (2) "측정 코드는 결과에 영향이 없다": 타이머 호출, 출력문이 짧은 작업에서는 상당한 몫입니다.
요약
  1. 예열 → 반복 → 중앙값·백분위.
  2. 가속기는 동기화 후 측정.
  3. 이상값은 따로 보고, 원인 조사.
