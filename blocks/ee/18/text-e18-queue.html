큐잉 모델로 지연 추정

본문

초당 1000개를 처리할 수 있는 추론 서버에 요청이 초당 800개 들어온다. 능력이 남는데도 요청이 기다리는 일이 생길까? 요청이 950개, 990개로 늘면 평균 지연은 얼마나 길어지고, 지연 사양을 맞추려면 서버를 얼마나 여유 있게 잡아야 할까?

먼저 알아야 할 것처리량·지연 모델(2.1절)을 쓴다.

2.4.1바쁠수록 기다린다

요청이 초당 평균 λ개씩 무작위로(Poisson) 오고, 하나를 처리하는 시간이 평균 1/μ초인 지수 분포라고 하자. 이런 서버를 M/M/1 큐라 하며, 시스템 안에 머무는 평균 시간은 \(W = 1/(\mu - \lambda)\)이고 이용률은 ρ = λ/μ이다. 처리 능력이 남아도 요청이 무작위로 몰리는 순간에는 줄이 생기므로 기다림은 0이 아니다. 처음 질문의 첫째 답이 이것이다.

이 식을 이용률로 바꿔 쓰면 \(W = (1/\mu)/(1 - \rho)\)이다. 그래서 ρ가 0.5에서 0.9로 가면 지연은 5배가 된다. 아래 코드는 요청률을 바꿔 가며 평균 지연을 계산한다.

mu = 1000.0                      # 초당 1000개 처리 가능
for lam in (500, 800, 900, 950, 990):
    W = 1 / (mu - lam)
    print(f"λ = {lam:4d}/s, 이용률 {lam / mu:.2f}: 평균 지연 {W * 1000:6.1f} ms")

실행 결과(Python 3.12에서 실제 실행)는 다음과 같다.

λ =  500/s, 이용률 0.50: 평균 지연    2.0 ms
λ =  800/s, 이용률 0.80: 평균 지연    5.0 ms
λ =  900/s, 이용률 0.90: 평균 지연   10.0 ms
λ =  950/s, 이용률 0.95: 평균 지연   20.0 ms
λ =  990/s, 이용률 0.99: 평균 지연  100.0 ms
예제 2.4.1

추론 서버 처리 능력 1000개/s, 요청 800개/s의 평균 지연은? 평균 지연을 2 ms 이하로 하려면 처리 능력은?

풀이. W = 1/(1000 − 800) = 1/200 s, 곧 5 ms이다. 2 ms 이하가 되려면 μ − 800 ≥ 500이어야 하므로 μ ≥ 1300개/s이다. 처음 질문의 둘째 답이 이것이다.

즉 처리 능력을 30% 늘리면 지연이 60% 줄어든다. 실행 결과를 보면 이용률이 0.95를 넘는 곳에서 지연이 폭발하듯 늘어나므로(그림 1), 실제 시스템은 이용률을 70~80% 아래로 두고 설계하는 것이 지연에 유리하다. 처음 질문의 셋째 답이 이것이다.

물론 실제 요청은 정확히 Poisson으로 오지 않고, 처리 시간도 지수 분포가 아니다. 그래도 M/M/1 모형은 이용률이 높아질수록 지연이 급히 늘어난다는 성질을 정확히 보여 주므로, 처음 어림에 널리 쓴다. 요청이 한꺼번에 몰리는 경향이 클수록 실제 지연은 이 모형보다 더 커진다.

흔한 오해평균 지연만 맞추면 된다고 여기기 쉽다. 하지만 M/M/1 큐의 지연은 지수 분포여서 꼬리가 길고, 99번째 백분위 지연은 평균의 약 4.6배이다(ln 100 ≈ 4.6). 그래서 실시간 사양(1.3절)을 맞추려면 평균이 아니라 꼬리 지연으로 처리 능력을 잡아야 한다.
마무리

M/M/1 큐의 평균 지연은 W = 1/(μ − λ)이고 이용률은 ρ = λ/μ이다. ρ가 1에 가까워지면 지연이 급증한다. 예를 들어 800/1000이면 5 ms이고, 2 ms로 줄이려면 μ ≥ 1300이 필요하다.

2.4.2연습문제

기본

  1. μ = 100/s, λ = 50/s의 W는?
    답

    1/(100 − 50) = 20 ms이다.

응용

  1. 같은 μ에서 λ = 90/s면?
    답

    1/(100 − 90) = 100 ms이다.

심화

  1. 서버를 두 대로 늘려 각각 λ/2를 받으면(μ 같음) λ = 90의 지연은?
    답

    1/(100 − 45) = 18.2 ms이다.
