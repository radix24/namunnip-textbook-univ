재귀로 문제를 나누어 풀기

본문

하노이 탑에서 원판 64개를 옮기려면 몇 번 움직여야 할까? 원판 하나씩의 움직임을 다 생각하지 않고도, "조금 작은 탑을 옮길 줄 안다면" 하는 가정 하나로 답을 낼 수 있을까?

먼저 알아야 할 것함수(2.2절), 문제 분해(3.1절), 고교 수학의 수학적 귀납법을 쓴다.

3.3.1작은 탑을 옮길 줄 안다면

하노이 탑의 규칙은 두 가지이다. 한 번에 원판 하나만 옮기고, 큰 원판을 작은 원판 위에 놓지 않는다. 원판이 셋만 되어도 손으로 따라가기가 헷갈린다. 그런데 생각을 바꾸어, \(n-1\)개짜리 탑은 이미 옮길 줄 안다고 해 보자.

그러면 \(n\)개는 그림 1의 세 단계로 끝난다. 먼저 위의 \(n-1\)개를 B로 비켜 두고, 맨 아래 큰 원판을 C로 옮긴 다음, B의 \(n-1\)개를 C의 큰 원판 위로 옮긴다. 이 때 큰 원판은 가장 크므로 \(n-1\)개를 옮기는 동안 그 위에 무엇이 놓여도 규칙을 어기지 않는다. 다시 말해 \(n\)개의 문제를 \(n-1\)개의 문제 두 개와 이동 한 번으로 줄였다.

함수가 자기 자신을 부르는 이런 방식을 재귀라 한다. 재귀 함수는 두 부분으로 이루어진다. 바로 답할 수 있는 가장 작은 경우인 기저 사례와, 문제를 한 단계 작게 만들어 자기를 부르는 재귀 단계이다. 원판이 0개이면 할 일이 없다는 것이 기저 사례이다. 수학적 귀납법이 \(n=1\)에서 시작해 \(n-1\)에서 \(n\)으로 넘어가는 것과 같은 짜임이다.

3.3.2코드와 호출 횟수

def hanoi(n, a="A", b="B", c="C", moves=None):
    if moves is None:
        moves = []
    if n == 0:                       # 기저 사례
        return moves
    hanoi(n - 1, a, c, b, moves)     # 위의 n-1개를 B로
    moves.append((a, c))             # 가장 큰 원판을 C로
    hanoi(n - 1, b, a, c, moves)     # n-1개를 C로
    return moves

print("3개:", hanoi(3))
print("원판 수별 이동 횟수:", [len(hanoi(n)) for n in range(1, 8)])

calls = 0
def fib(n):
    global calls
    calls += 1
    return n if n < 2 else fib(n - 1) + fib(n - 2)
print("fib(20) =", fib(20), "호출 수", calls)
3개: [('A', 'C'), ('A', 'B'), ('C', 'B'), ('A', 'C'), ('B', 'A'), ('B', 'C'), ('A', 'C')]
원판 수별 이동 횟수: [1, 3, 7, 15, 31, 63, 127]
fib(20) = 6765 호출 수 21891

위 출력은 Python 3.12에서 실제로 실행한 결과이다. 코드의 세 줄이 그림 1의 세 단계와 하나씩 맞물린다는 것을 확인해 보자. 원판 셋에서 넷째 이동 ('A', 'C')가 큰 원판을 옮기는 순간이고, 그 앞뒤로 세 번씩이 작은 탑 두 개이다.

예제 3.3.1

하노이 탑의 이동 횟수가 \(2^n - 1\)임을 재귀 구조로 보여라. 원판 64개면 몇 번인가?

풀이. \(n\)개를 옮기는 횟수를 \(M_n\)이라 하면, 그림 1에서 \(M_n = 2M_{n-1} + 1\)이고 \(M_1 = 1\)이다. 양변에 1을 더하면 \(M_n + 1 = 2(M_{n-1} + 1)\)이므로 \(M_n + 1\)은 공비 2인 등비수열이고 \(M_1 + 1 = 2\)에서 시작한다. 따라서 \(M_n + 1 = 2^n\), 곧 \(M_n = 2^n - 1\)이다. 실행 결과 1, 3, 7, …, 127과 같다. 원판 64개면 \(2^{64} - 1 \approx 1.8\times10^{19}\)번이며, 1초에 한 번씩 옮겨도 약 5800억 년이 걸린다.

3.3.3같은 계산을 거듭할 때

재귀가 늘 이렇게 깔끔하지는 않다. 피보나치 수 \(F_n = F_{n-1} + F_{n-2}\)를 그대로 재귀로 쓰면 fib(20) 하나에 21,891번이나 호출된다. fib(18)을 \(F_{20}\)에서 한 번, \(F_{19}\)에서 또 한 번 구하는 식으로 같은 값을 계속 다시 계산하기 때문이다. 이럴 때는 한 번 구한 값을 딕셔너리에 적어 두고 다시 물으면 꺼내 쓰는데, 이것을 메모이제이션이라 한다. 그러면 \(n\)마다 많아야 두 번씩, 40번 안팎으로 호출이 줄어든다.

흔한 오해기저 사례가 없어도 언젠가 멈출 것이라 생각하기 쉽지만, 함수는 끝없이 자기를 부르다 RecursionError로 멈춘다. 재귀가 언제나 느리다는 생각도 맞지 않다. 하노이 탑같이 구조가 자연스러운 문제에는 재귀가 가장 명확하며, 느려지는 것은 피보나치처럼 같은 계산을 되풀이할 때이다.
마무리

원판 \(n\)개를 옮기는 일은 \(n-1\)개를 두 번 옮기고 큰 원판을 한 번 옮기는 일로 나뉘므로 \(M_n = 2M_{n-1} + 1\)이 되고, 이를 풀면 \(2^n - 1\)이다. 원판 64개는 약 \(1.8\times10^{19}\)번이다. 재귀는 기저 사례와 한 단계 작은 자기 호출로 이루어지며, 같은 계산이 되풀이되면 메모이제이션으로 줄인다.
