미션 개발 단계: 기획에서 운영까지

본문 · 3.1절
이 절에서 배울 것
  • 우주 미션의 개발 단계(기획, 설계, 제작·시험, 발사·운영, 종료)를 순서대로 말한다.
  • 단계마다의 검토 회의와 그 목적을 안다.
  • 일정과 비용이 늘어나는 흔한 원인을 안다.
먼저 알아야 할 것
  • 과학 요구사항 (2.2절).

10년이 넘는 프로젝트

큰 천체물리 위성은 구상에서 발사까지 10~25년이 걸립니다. JWST는 1990년대 중반 구상되어 2021년에 발사되었습니다. 수천 명이 참여하는 일이 엇나가지 않도록 NASA와 ESA는 개발을 정해진 단계로 나누고, 단계를 넘을 때마다 외부 전문가가 검토합니다.

3.1.1단계 (NASA 기준)

  1. Pre-Phase A (개념 연구): 과학 목표와 대략의 미션 개념, 비용을 정한다.
  2. Phase A (개념과 기술 개발): 요구사항을 정하고 필요한 새 기술을 시험한다. 미션 정의 검토(MDR).
  3. Phase B (예비 설계): 각 부분의 설계를 정한다. 예비 설계 검토(PDR) 뒤 비용과 일정을 확정(기준선)한다.
  4. Phase C (상세 설계와 부품 제작): 도면 수준의 설계와 부품 제작. 상세 설계 검토(CDR).
  5. Phase D (조립, 시험, 발사): 조립, 진동·열진공·전자파 시험, 발사, 초기 점검. 발사 준비 검토.
  6. Phase E (운영): 과학 관측과 자료 공개.
  7. Phase F (종료): 궤도 처리, 자료 보관.

ESA도 0/A/B/C/D/E/F의 비슷한 단계를 씁니다.

3.1.2시험이 중요한 까닭

발사 뒤에는 고칠 수 없으므로 "날 것처럼 시험하라"가 원칙입니다. 발사의 진동과 소음, 우주의 진공과 극한 온도, 방사선을 지상에서 흉내 내어 시험합니다. 허블은 주경을 아주 정밀하지만 틀린 모양으로 깎았는데 전체 광학계를 한 번에 시험하지 않아 발사 뒤에야 알았고, 1993년 수리 임무로 보정 광학계를 달아야 했습니다.

3.1.3일정과 비용

큰 미션은 처음 계획보다 늦어지고 비싸지는 일이 흔합니다. 주요 원인은 다음과 같습니다.

  • 새 기술이 예상보다 늦게 성숙함(JWST의 접히는 거울과 햇빛가리개).
  • 시험에서 발견된 문제를 고치는 시간.
  • 요구사항이 개발 도중 바뀜.
  • 예산 지급이 해마다 늦어져 인력이 비효율적으로 쓰임.

그래서 Phase A에서 핵심 기술의 성숙도(TRL, 1~9단계)를 6 이상(실제와 비슷한 환경에서 시제품 시험)으로 올린 뒤 다음 단계로 가도록 요구합니다.

예제 3.1.1

어떤 미션의 Phase B 기준선 비용이 10억 달러, 일정이 6년입니다. 지연 1년마다 고정 인력비가 연 1.2억 달러씩 든다면 2년 지연의 추가 비용은?

풀이. 2.4억 달러(24% 증가)입니다. 일정 지연이 곧 비용 증가로 이어지는 까닭입니다.

주의 단계와 검토의 이름은 기관과 미션 규모마다 조금씩 다릅니다. 작은 위성(큐브샛)은 단계를 줄이고 빠르게 개발하는 대신 위험을 더 받아들입니다.
요약
  1. Pre-A(개념) → A(기술·요구) → B(예비 설계, PDR, 기준선) → C(상세 설계, CDR) → D(조립·시험·발사) → E(운영) → F(종료).
  2. 발사 뒤에는 고칠 수 없어 실제 환경처럼 시험한다(허블 거울의 교훈).
  3. 지연과 비용 증가의 원인: 기술 미성숙, 시험 문제, 요구 변경, 예산 지연.
  4. 기술 성숙도(TRL)를 확인하며 단계를 넘는다.

3.1.4연습문제

기본

  1. 기준선 비용과 일정이 확정되는 검토는?
    답

    예비 설계 검토(PDR) 뒤, Phase B 끝.

  2. 열진공 시험은 무엇을 흉내 냅니까?
    답

    우주의 진공과 극한 온도 변화.

응용

  1. 허블 주경 오차는 어떤 시험으로 발사 전에 찾을 수 있었습니까?
    답

    주경과 보정 기준 기기를 독립적인 두 장치로 함께 검사하거나, 광학계 전체의 상을 맺어 보는 끝에서 끝까지의 광학 시험.

  2. TRL 3(개념 증명)인 기술을 PDR에 그대로 가져가면 어떤 위험이 있습니까?
    답

    실제 환경에서 동작하지 않거나 성능이 모자랄 수 있어, 상세 설계 단계에서 설계를 크게 바꾸며 비용과 일정이 늘어납니다.
