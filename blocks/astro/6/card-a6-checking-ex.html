남중 고도가 음수로 나온 프로그램 고치기

예제 · 각도와 라디안 · 극한값 검산
문제 해결 전략 · 틀린 프로그램 고치기
  1. 손으로 답을 아는 경우 하나를 넣어 틀렸는지부터 확인한다.
  2. 단위가 바뀌는 곳(각도↔라디안, AU↔m, 등급↔플럭스)을 먼저 의심한다.
  3. 고친 뒤 극한값 몇 개로 다시 확인한다.

문제. 고도 식 \(\sin h = \sin\delta\sin\varphi + \cos\delta\cos\varphi\cos H\)로 서울(위도 37.6°)에서 시리우스(적위 −16.7°)의 남중 고도(\(H = 0\))를 구하는 함수이다. 결과가 이상하다. 원인을 찾아 고치고, 극한값 두 개로 확인하여라.

import math

def altitude_bug(dec, lat, H):
    s = math.sin(dec) * math.sin(lat) + math.cos(dec) * math.cos(lat) * math.cos(H)
    return math.degrees(math.asin(s))

print(f"버그: 시리우스 남중 고도 = {altitude_bug(-16.7, 37.6, 0.0):.2f}°")
버그: 시리우스 남중 고도 = -38.84°

풀이

  1. 답을 아는 경우: 남중 고도는 \(90° - \varphi + \delta = 90 - 37.6 - 16.7 = 35.7°\)이어야 한다. −38.84°는 틀렸다.
    남중일 때의 간단한 식으로 검산.
  2. 원인: math.sin은 라디안을 받는데 각도(°)를 그대로 넣었다. \(\sin(37.6\ \text{rad})\)를 계산한 셈이다.
    단위가 바뀌는 곳을 먼저 의심한다.
  3. 입력을 math.radians로 바꾼다.
    출력은 이미 math.degrees로 바꾸고 있었다. 한쪽만 바꾼 전형적인 실수.
def altitude(dec_deg, lat_deg, H_deg):
    d, p, h = map(math.radians, (dec_deg, lat_deg, H_deg))
    s = math.sin(d) * math.sin(p) + math.cos(d) * math.cos(p) * math.cos(h)
    return math.degrees(math.asin(s))

print(f"고침: 시리우스 남중 고도 = {altitude(-16.7, 37.6, 0.0):.2f}°  (기대 {90 - 37.6 - 16.7:.1f}°)")
print(f"극한: 적도에서 적위 0° 별의 남중 고도 = {altitude(0, 0, 0):.2f}°")
print(f"극한: 북극에서 적위 30° 별, 시간각 6시 = {altitude(30, 90, 90):.2f}°")
고침: 시리우스 남중 고도 = 35.70°  (기대 35.7°)
극한: 적도에서 적위 0° 별의 남중 고도 = 90.00°
극한: 북극에서 적위 30° 별, 시간각 6시 = 30.00°

의미

극한값 두 개는 서로 다른 것을 확인한다. 적도의 천정 통과(90°)는 식의 둘째 항이, 북극에서 고도가 시간각과 상관없이 적위와 같다는 것(30°)은 첫째 항이 맞게 짜였음을 보여 준다. 버그 버전으로 같은 극한값을 넣어 보면 둘 다 틀리게 나온다.

검산

버그 값이 왜 −38.84°인지 확인해 볼 수 있다. 라디안으로 계산하면 \(\sin(-16.7) = 0.84\), \(\sin(37.6) = -0.10\), \(\cos(-16.7) = -0.55\), \(\cos(37.6) = 1.00\)이라 \(\sin h \approx -0.08 - 0.54 = -0.63\), \(h \approx -38.8°\)이다. 원인을 정확히 짚었음을 확인한 셈이다.

이해 확인

함수 끝에 넣을 assert 문 하나를 써 보아라.

답

예: assert abs(altitude(0, 0, 0) - 90) < 1e-9 또는 assert abs(altitude(-16.7, 37.6, 0) - 35.7) < 1e-6.
