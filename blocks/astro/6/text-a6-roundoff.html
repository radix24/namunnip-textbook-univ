부동소수점과 반올림 오차

본문 · 2.1절

Python에 0.1 + 0.2를 넣으면 0.3이 아니라 0.30000000000000004가 나온다. 또 \(x = 10^{-8}\)에서 \(1 - \cos x\)를 계산하면 참값 \(5\times10^{-17}\) 대신 0이 나온다. 컴퓨터가 고장 난 것일까? 계산 결과를 믿으려면 이런 오차가 언제 작고 언제 커지는지 알아야 한다.

먼저 알아야 할 것Python 기초(1.1절)와 삼각함수의 반각 공식을 쓴다.

2.1.1배정밀도 부동소수점

처음 질문의 답부터 말하면, 컴퓨터는 고장 나지 않았다. 실수를 2진법의 유한한 자릿수로 저장하기 때문이다. Python의 실수(float)는 IEEE 754 배정밀도 형식으로, 64비트에 부호 1비트, 지수 11비트, 가수 52비트를 담아 \(\pm(1.\text{가수})_2\times2^{\text{지수}}\)로 나타낸다. 그래서 유효 숫자는 10진법으로 약 15~16자리이고, 크기는 약 \(10^{-308}\)에서 \(10^{308}\)까지이다. 그런데 0.1은 2진법으로 무한소수(0.000110011…)라 가장 가까운 값으로 반올림되어 저장되며, 그 작은 차이가 덧셈 결과에 드러난다.

정의 2.1.1 (기계 엡실론)

1에 더했을 때 1과 구별되는 가장 작은 수 \(\varepsilon_{\text{mach}}\)를 기계 엡실론이라 한다. 배정밀도에서 \(\varepsilon_{\text{mach}} = 2^{-52} \approx 2.2\times10^{-16}\)이다.

어떤 실수든 저장할 때 상대 오차 \(\varepsilon_{\text{mach}}/2\) 정도가 생기며, 이것이 반올림 오차이다.

import sys, math
print(0.1 + 0.2)                  # 0.30000000000000004
print(0.1 + 0.2 == 0.3)           # False
print(sys.float_info.epsilon)     # 2.220446049250313e-16
print(1.0 + 1e-16 == 1.0)         # True
x = 1e-8
print(1 - math.cos(x))            # 0.0
print(2 * math.sin(x / 2) ** 2)   # 5.0000000000000005e-17

2.1.2비슷한 수의 뺄셈

마지막 두 줄이 처음 질문의 둘째 부분이다. \(x = 10^{-8}\)에서 \(1 - \cos x\)의 참값은 \(x^2/2 = 5\times10^{-17}\)이다. 그런데 \(\cos x = 0.99999999999999995\)는 1과 너무 가까워 배정밀도로는 정확히 1로 저장되고, 뺄셈 결과는 0이 된다. 이렇게 비슷한 두 수를 빼면 앞자리들이 지워지고 반올림 오차만 남는데, 이것을 상쇄 오차(자릿수 손실)라 한다. 그림 1처럼 \(x\)가 작을수록 두 수가 가까워져 오차가 커진다.

피하는 방법은 식을 바꾸는 것이다. 반각 공식 \(1 - \cos x = 2\sin^2(x/2)\)는 뺄셈이 없어 정확한 값 \(5.0\times10^{-17}\)을 준다. 같은 까닭으로 math.expm1(x)(\(e^x - 1\))와 math.log1p(x)(\(\ln(1+x)\))처럼 작은 \(x\)에서 정확한 전용 함수가 있다.

2.1.3천문 계산의 예

천문 계산에서도 같은 일이 생긴다. 예를 들어 율리우스일(약 2,460,000일)에 하루의 작은 부분을 더하면 소수 아래 자릿수가 줄어 밀리초 정밀도를 잃는다. 그래서 정밀한 시간은 정수부와 소수부를 따로 저장한다. 또 거의 같은 두 궤도의 위치 차를 구할 때 큰 좌표끼리 빼면 상쇄 오차가 생긴다. 차이를 직접 적분하는 엔케 방법(천우11 3.2절)이 그래서 쓰인다.

예제 2.1.1

이차방정식 \(x^2 - 10^8x + 1 = 0\)의 작은 근을 근의 공식으로 계산하면 무엇이 문제이고, 어떻게 고치는가?

풀이. 작은 근 \((10^8 - \sqrt{10^{16} - 4})/2\)는 거의 같은 두 수의 뺄셈이라 자릿수를 잃는다. 따라서 뺄셈이 없는 큰 근 \(x_1 \approx 10^8\)을 먼저 구한 뒤, 근과 계수의 관계 \(x_1x_2 = 1\)에서 \(x_2 = 1/x_1 = 10^{-8}\)으로 구한다.

흔한 실수실수를 ==로 비교하지 않는다. abs(a - b) < 1e-12처럼 허용 오차를 두거나 math.isclose(a, b)를 쓴다.
마무리

배정밀도 실수는 유효 숫자 약 16자리이고, 저장할 때마다 상대 오차 \(10^{-16}\) 정도가 생기며 그 기준이 기계 엡실론 \(2^{-52} \approx 2.2\times10^{-16}\)이다. 이 작은 오차는 비슷한 두 수를 뺄 때 상쇄 오차로 크게 불어나므로, 반각 공식이나 expm1, log1p처럼 뺄셈을 없앤 식으로 바꾸어 피한다. 실수는 == 대신 허용 오차로 비교한다.

2.1.4연습문제

기본

  1. 1e16 + 1 - 1e16의 결과는 무엇이고, 왜 그런가?
    답

    0.0이다. \(10^{16}\)에서 이웃한 실수의 간격이 2라 1을 더해도 반올림되어 사라진다.

  2. \(\sqrt{x^2+1} - x\)를 큰 \(x\)에서 정확하게 계산하려면 식을 어떻게 바꾸는가?
    답

    분자와 분모에 \(\sqrt{x^2+1} + x\)를 곱해 \(1/(\sqrt{x^2+1} + x)\)로 바꾸면 뺄셈이 없어진다.

응용

  1. 율리우스일 2460000.5를 배정밀도로 저장하면 시간 정밀도는 대략 얼마인가?
    답

    상대 정밀도 \(2.2\times10^{-16}\times2.46\times10^6\)일 \(= 5.4\times10^{-10}\)일, 곧 약 47 μs이다.
