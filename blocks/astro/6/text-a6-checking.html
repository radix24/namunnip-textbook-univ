프로그램을 믿기 전에 검산하는 습관

본문 · 1.3절

공전 주기를 구하는 프로그램이 오류 메시지 없이 깔끔하게 숫자를 냈다. 그런데 지구가 \(10^{-17}\)년 만에 태양을 한 바퀴 돈다고 한다. 이번에는 우연히 지구를 넣어 봐서 알아챘지만, 처음 보는 천체였다면 그대로 믿었을 것이다. 프로그램의 답을 믿어도 되는지 어떻게 확인할까?

먼저 알아야 할 것변수, 함수, 반복문(1.1절)과 케플러 제3법칙(천우1 1.3절)을 쓴다.

1.3.1조용히 틀리는 프로그램

문법이 틀리면 Python은 곧바로 오류를 낸다. 정말 위험한 것은 문법은 맞는데 답이 틀린 프로그램이다. 단위를 하나 빼먹거나 괄호를 잘못 치면 프로그램은 아무 말 없이 엉뚱한 숫자를 낸다. 다음은 긴반지름(AU)으로 공전 주기(년)를 구하려던 함수이다.

import math
G = 6.674e-11       # m^3 kg^-1 s^-2
M_SUN = 1.989e30    # kg
AU = 1.496e11       # m
YEAR = 3.156e7      # s

def period_years_bug(a_au):
    return 2 * math.pi * math.sqrt(a_au**3 / (G * M_SUN)) / YEAR

print(f"지구  P = {period_years_bug(1.0):.3e} 년")   # 1.728e-17 년

AU를 m로 바꾸지 않아 지구가 \(10^{-17}\)년 만에 태양을 도는 답이 나왔다. 그림 1에서 보듯 차이는 빠뜨린 \(\text{AU}^{1.5}\)배이다.

1.3.2네 가지 검산

처음 질문의 답은 검산을 습관으로 만드는 것이다. 검산에는 네 가지가 있고, 저마다 잡는 실수가 다르다. 첫째, 답을 아는 경우를 넣어 본다. 지구는 1년, 태양 표면 중력은 274 m/s²처럼 알려진 값이 나오는지 본다. 둘째, 비례 관계를 본다. \(P \propto a^{3/2}\)이면 \(a\)를 4배로 할 때 주기는 정확히 8배여야 하며, 이 검산은 상수의 값이 틀려도 지수가 맞는지 확인해 준다. 셋째, 극한값을 본다. 이심률이 0이면 원 궤도 결과와 같아야 하고, 질량이 0이면 힘이 0이어야 한다. 넷째, 차원을 따진다. \(\sqrt{a^3/(GM)}\)은 \(\sqrt{\text{m}^3/(\text{m}^3\,\text{s}^{-2})} = \text{s}\)이므로 시간이 맞다. 고친 함수와 검산은 다음과 같다.

def period_years(a_au):
    a = a_au * AU
    return 2 * math.pi * math.sqrt(a**3 / (G * M_SUN)) / YEAR

print(f"지구  P = {period_years(1.0):.4f} 년")
print(f"a를 4배로 했을 때의 비 = {period_years(4.0) / period_years(1.0):.4f} (기대 8)")
for name, a in [("화성", 1.524), ("목성", 5.203), ("해왕성", 30.07)]:
    print(f"{name:4s} a = {a:6.3f} AU  P = {period_years(a):7.2f} 년")
지구  P = 0.9998 년
a를 4배로 했을 때의 비 = 8.0000 (기대 8)
화성   a =  1.524 AU  P =    1.88 년
목성   a =  5.203 AU  P =   11.87 년
해왕성  a = 30.070 AU  P =  164.87 년

지구가 정확히 1이 아니라 0.9998인 것은 상수를 네 자리로 반올림했기 때문이다. 즉 검산은 틀렸는지뿐 아니라 얼마나 정확한지도 알려 준다.

1.3.3검산을 코드에 남기기

한 번 확인하고 지우지 말고 assert 문으로 코드에 남겨 두자. 그러면 나중에 코드를 고쳐도 검산이 자동으로 다시 돈다. 조건이 거짓이면 프로그램이 멈추고 알려 준다.

assert abs(period_years(1.0) - 1.0) < 1e-3, "지구 주기가 1년이 아니다"
assert abs(period_years(4.0) / period_years(1.0) - 8.0) < 1e-9

이렇게 쌓인 검산 묶음을 테스트라 하며, 연구용 코드도 테스트를 함께 두는 것이 좋은 관례이다.

예제 1.3.1

별의 광도를 \(L = 4\pi R^2\sigma T^4\)로 구하는 함수에 \(R\)을 태양 반지름 단위로 그대로 넣었다. 어떤 검산이 이 실수를 잡아내는가?

풀이. 태양(\(R = 1\), \(T = 5772\) K)을 넣으면 \(3.8\times10^{26}\) W가 나와야 하는데, 단위를 바꾸지 않으면 \(4\pi\times1^2\times5.67\times10^{-8}\times5772^4 = 7.9\times10^8\) W가 나온다. 따라서 답을 아는 경우의 검산이 곧바로 잡아낸다. 반면 비례 관계 검산(\(R\)을 2배로 하면 \(L\)이 4배)은 상수배의 실수를 잡지 못한다.

주의검산 하나를 통과했다고 프로그램이 옳은 것은 아니다. 답을 아는 경우는 상수배 실수를, 비례 관계는 지수의 실수를 잡으므로, 성격이 다른 검산을 둘 이상 함께 쓴다.
마무리

문법 오류보다 조용히 틀리는 답이 더 위험하다. 그래서 답을 아는 경우, 비례 관계, 극한값, 차원의 네 가지로 검산하며, 검산마다 잡는 실수가 다르므로 여럿을 함께 쓴다. 검산은 assert로 코드에 남겨 테스트로 쌓아 두면, 코드를 고칠 때마다 자동으로 다시 확인된다.

1.3.4연습문제

기본

  1. 탈출 속력 \(\sqrt{2GM/R}\)을 구하는 함수의 답을 아는 경우 검산을 하나 제안하여라.
    답

    지구(\(M = 5.97\times10^{24}\) kg, \(R = 6.37\times10^6\) m)를 넣어 11.2 km/s가 나오는지 본다.

  2. \(\sqrt{GM/r}\)의 단위를 따져 속도인지 확인하여라.
    답

    \(\sqrt{(\text{m}^3\,\text{kg}^{-1}\,\text{s}^{-2})(\text{kg})/\text{m}} = \sqrt{\text{m}^2/\text{s}^2} = \text{m/s}\)이다.

응용

  1. 궤도 적분 프로그램을 검산할 극한값 하나와 보존량 하나를 제안하여라.
    답

    극한값으로는 이심률 0으로 시작하면 반지름이 일정해야 한다는 것을, 보존량으로는 전체 에너지와 각운동량이 시간에 따라 거의 변하지 않아야 한다는 것을 쓴다(5.2절).

  2. period_years에서 YEAR를 3.156e7 대신 365*24*3600으로 바꾸면 지구의 값은 어떻게 바뀌는가?
    답

    \(365\times86400 = 3.1536\times10^7\) s라 분모가 약 0.07% 작아져, 지구 주기가 약 1.0006년으로 나온다. 1년이 365.25일이기 때문이다.
