계산 시간을 재고 계산량을 어림하기

본문
이 절에서 배울 것
  • 프로그램의 실행 시간을 재고, 크기 \(N\)을 두 배로 할 때 시간이 몇 배가 되는지로 계산량의 차수를 확인한다.
  • 계산량이 \(O(N)\), \(O(N\log N)\), \(O(N^2)\), \(O(N^3)\)인 대표 알고리즘을 안다.
  • 작은 실행으로 큰 계산의 시간을 미리 어림해 계산 계획을 세운다.
  • 병목을 찾아 알고리즘을 바꾸는 것이 코드를 다듬는 것보다 효과가 큼을 안다.
먼저 알아야 할 것
  • Unix 명령과 스크립트 (1.1절), 직접 합산법 (3.1절).

1.3.1시간 재기

Python에서는 time.perf_counter()로 구간의 시간을 재거나, 명령창에서 time python run.py(Unix)로 전체 시간을 잽니다. 한 번만 재면 다른 프로그램의 영향으로 흔들리므로 여러 번 재서 가장 짧은 값이나 중앙값을 씁니다. 함수별로 시간을 나눠 보려면 python -m cProfile run.py 같은 프로파일러를 씁니다.

1.3.2계산량의 차수

N체 직접 합산은 모든 쌍 \(N(N-1)/2\)개를 계산하므로 시간이 \(N^2\)에 비례할 것입니다. 실제로 재 봅니다.

import random, time

def accelerations(pos, eps2=1e-4):
    """직접 합산: 모든 쌍의 중력 가속도 (G = m = 1)"""
    n = len(pos)
    acc = [[0.0, 0.0, 0.0] for _ in range(n)]
    for i in range(n):
        xi, yi, zi = pos[i]
        for j in range(i + 1, n):
            dx, dy, dz = pos[j][0] - xi, pos[j][1] - yi, pos[j][2] - zi
            inv = (dx * dx + dy * dy + dz * dz + eps2) ** -1.5
            acc[i][0] += dx * inv; acc[i][1] += dy * inv; acc[i][2] += dz * inv
            acc[j][0] -= dx * inv; acc[j][1] -= dy * inv; acc[j][2] -= dz * inv
    return acc

random.seed(0)
prev = None
for n in (200, 400, 800):
    pos = [[random.random() for _ in range(3)] for _ in range(n)]
    t0 = time.perf_counter()
    accelerations(pos)
    dt = time.perf_counter() - t0
    ratio = f"  (앞의 {dt / prev:.1f}배)" if prev else ""
    print(f"N = {n:4d}: {dt:.3f} s{ratio}")
    prev = dt
N =  200: 0.054 s
N =  400: 0.261 s  (앞의 4.8배)
N =  800: 1.203 s  (앞의 4.6배)

(시간은 컴퓨터마다 다릅니다. 중요한 것은 비율입니다.) \(N\)을 두 배로 할 때 시간이 약 4배(\(2^2\))가 되므로 \(O(N^2)\)임이 확인됩니다.

차수\(N\)을 2배로 하면예
\(O(N)\)2배합계, 평균, 히스토그램
\(O(N\log N)\)2배 조금 넘게정렬, 고속 푸리에 변환, 트리 코드
\(O(N^2)\)4배N체 직접 합산, 단순한 쌍 찾기
\(O(N^3)\)8배가우스 소거(\(N\times N\) 행렬)

1.3.3큰 계산 미리 어림하기

위 결과에서 \(N = 800\)이 1.2초이면, \(N = 10^5\)은 \((10^5/800)^2 = 15{,}600\)배인 약 5시간이 걸리고, 그것도 한 걸음뿐입니다. 궤도를 1,000걸음 적분하면 약 200일입니다. 이렇게 작은 실행으로 미리 어림하면, 코드를 다듬어 몇 배 빠르게 할지(예: 배열 연산 라이브러리, 컴파일 언어로 수십~수백 배), 알고리즘을 바꿀지(트리 코드 \(O(N\log N)\)이면 \(N = 10^5\)에서 수천 배)를 정할 수 있습니다. 큰 \(N\)에서는 알고리즘의 차수가 상수배 개선을 압도합니다.

예제 1.3.1

\(1000\times1000\) 행렬의 가우스 소거가 0.5초 걸렸습니다. \(4000\times4000\)이면?

풀이. \(O(N^3)\)이므로 \(4^3 = 64\)배, 약 32초. 메모리도 \(N^2\)에 비례해 16배(배정밀도로 8 MB → 128 MB)가 됩니다.

요약
  1. time.perf_counter(), 프로파일러로 재고, 여러 번 재서 흔들림을 줄인다.
  2. \(N\)을 2배로 할 때의 시간 비로 차수를 확인한다(2, 4, 8배 ↔ \(N\), \(N^2\), \(N^3\)).
  3. 작은 실행으로 큰 계산을 어림하고, 필요하면 알고리즘(차수)을 바꾼다.

1.3.4연습문제

기본

  1. \(N\)을 10배로 했더니 시간이 약 100배가 되었습니다. 차수는?
    답

    \(O(N^2)\).

  2. 정렬이 \(N = 10^6\)에서 1초 걸렸다면 \(N = 10^7\)은 대략?
    답

    \(O(N\log N)\): \(10\times\log10^7/\log10^6 = 10\times7/6 \approx 12\)초.

응용

  1. 두 목록(각 \(10^6\)개)에서 가까운 쌍을 찾을 때 모든 쌍을 비교하면 몇 번 비교합니까? 하늘을 칸으로 나눠 같은 칸과 이웃 칸만 비교하면?
    답

    모든 쌍 \(10^{12}\)번. 칸으로 나누면 천체마다 근처 몇 개만 비교해 대략 \(10^6\)~\(10^7\)번으로 줄어듭니다(교차 맞춤 프로그램이 쓰는 방법, 천우7 6.4절).

  2. 위 코드에서 acc[j]를 빼는 줄을 지우고 j 반복을 range(n)(단 \(j \ne i\))으로 바꾸면 시간은 몇 배가 되고, 답은 같습니까?
    답

    쌍마다 두 번 계산하므로 약 2배 느려집니다. 힘의 대칭(작용-반작용)을 쓰지 않을 뿐이라 답은 같습니다(반올림 차이 정도).
