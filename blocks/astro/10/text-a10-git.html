버전 관리와 재현 가능한 계산

본문 · 1.2절
이 절에서 배울 것
  • git으로 코드의 변경 기록을 남기고 되돌린다.
  • 계산 결과를 다시 만들 수 있도록 환경, 입력, 난수 씨앗을 기록한다.
먼저 알아야 할 것
  • Unix 명령 (1.1절).

석 달 뒤의 나는 남이다

논문의 그림을 석 달 뒤 다시 그려야 할 때, 어떤 코드의 어떤 판으로, 어떤 매개변수로 그렸는지 기억하지 못하면 결과를 재현할 수 없습니다. 재현할 수 없는 결과는 과학적 결과로 인정받기 어렵습니다. 버전 관리와 기록은 이를 막는 습관입니다.

1.2.1git의 기본

  • git init: 현재 폴더를 저장소로 만든다.
  • git add 파일, git commit -m "설명": 변경을 기록(커밋)한다. 커밋마다 고유한 번호(해시)가 붙는다.
  • git log, git diff: 기록과 차이를 본다.
  • git checkout 해시 -- 파일: 예전 판의 파일을 되살린다.
  • git branch, git merge: 실험적인 변경을 갈래에서 따로 하고 합친다.
  • .gitignore: 큰 자료 파일이나 결과물은 기록하지 않도록 적어 둔다.

GitHub 같은 원격 저장소에 올리면 백업이 되고 공동 연구자와 함께 쓸 수 있습니다. 커밋 설명은 "무엇을 왜 바꿨는지"를 한 줄로 씁니다(예: "연화 길이를 0.01로 줄임: 근접 조우 에너지 오차 확인용").

1.2.2재현 가능한 계산의 기록

  1. 코드: 결과를 만든 커밋 해시를 결과 파일 머리말이나 로그에 함께 저장한다.
  2. 환경: Python과 라이브러리 판(pip freeze > requirements.txt, conda environment.yml)을 기록한다. 판이 바뀌면 결과가 미세하게 달라질 수 있다.
  3. 입력: 매개변수는 코드에 박지 말고 설정 파일로 두고, 그 파일도 커밋한다. 자료는 출처와 내려받은 날짜를 적는다.
  4. 난수: Monte Carlo 계산은 씨앗을 정해 기록한다(rng = numpy.random.default_rng(42)).
  5. 과정: 손으로 한 단계(파일을 직접 고침 등)를 없애고, 원자료에서 최종 그림까지 스크립트 하나로 다시 만들 수 있게 한다.
예제 1.2.1

MCMC 결과가 어제와 오늘 조금 다릅니다(\(a = 1.810\)과 \(1.840\)). 무엇을 의심해야 합니까?

풀이. 난수 씨앗이 다르면 사슬이 달라 평균이 통계적 요동만큼(이 경우 표준편차 0.07의 일부) 다를 수 있습니다(5.2절 실습에서 씨앗 1과 2의 차이). 씨앗을 고정해 같은 결과가 나오는지 확인하고, 씨앗에 따른 차이가 불확도보다 작은지 봅니다. 그래도 다르면 코드나 입력이 바뀐 것이므로 git diff로 확인합니다.

주의 Jupyter 노트북은 칸을 순서 없이 실행할 수 있어 재현성을 해치기 쉽습니다. 마지막에는 "커널 재시작 후 모두 실행"으로 처음부터 결과가 나오는지 확인하세요.
요약
  1. git: init, add, commit, log, diff, checkout, branch로 코드 변경을 기록하고 되돌린다.
  2. 큰 자료와 결과물은 .gitignore로 제외한다.
  3. 결과와 함께 커밋 해시, 환경 판, 설정, 난수 씨앗을 기록한다.
  4. 원자료부터 그림까지 스크립트 하나로 다시 만들 수 있게 한다.

1.2.3연습문제

기본

  1. 방금 고친 내용을 커밋하기 전에 무엇이 바뀌었는지 보는 명령은?
    답

    git diff.

  2. 100 MB짜리 시뮬레이션 출력을 저장소에 넣지 않으려면?
    답

    .gitignore에 그 파일이나 폴더를 적습니다.

응용

  1. 공동 연구자가 같은 코드로 다른 결과를 얻었습니다. 확인할 것 세 가지는?
    답

    같은 커밋인지, 라이브러리 판이 같은지, 입력·설정·씨앗이 같은지.

  2. 논문 그림 파일 이름에 커밋 해시를 넣는 장점은?
    답

    그림이 어떤 코드 판에서 나왔는지 나중에 바로 알 수 있습니다.
