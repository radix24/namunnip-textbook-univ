Unix/Linux 명령과 스크립트로 계산 자동화하기

본문 · 1.1절

하룻밤 관측으로 영상 400장이 쌓였다. 한 장을 처리하는 데 90초가 걸린다면, 마우스로 하나씩 열어 처리하는 데 꼬박 10시간이 든다. 컴퓨터가 알아서 400장을 차례로, 아니면 여러 장을 한꺼번에 처리하게 할 수는 없을까? 코어를 8개 쓰면 정말 8배 빨라질까?

먼저 알아야 할 것Python 기초(천우6 1.1절)를 쓴다.

천문 자료는 관측 영상 수천 장, 시뮬레이션 출력 수백 GB처럼 크고 많다. 게다가 연구용 계산 서버와 슈퍼컴퓨터는 거의 모두 Linux이고, 화면 없이 터미널로만 접속한다. 전산천문학 수업이 흔히 Unix/Linux 명령으로 시작하는 까닭이다. Windows에서는 WSL이나 Git Bash로 같은 환경을 쓸 수 있다. 처음 질문의 답은 셸 스크립트와 병렬 실행이며, 두 번째 질문의 답은 그림 1이 보여 준다.

1.1.1기본 명령

자주 쓰는 명령은 표 1과 같다. 이 명령들의 힘은 파이프 |로 이어 붙이는 데서 나온다. 파이프는 앞 명령의 출력을 뒤 명령의 입력으로 넘기고, >는 출력을 파일로 저장한다.

표 1. 자주 쓰는 셸 명령
명령하는 일
pwd, ls -l, cd현재 위치 보기, 목록 보기, 이동
mkdir, cp, mv, rm폴더 만들기, 복사, 이동과 이름 바꾸기, 지우기
cat, head, tail, less파일 내용 보기
grep패턴이 들어 있는 줄 찾기
wc -l, sort, uniq, awk줄 세기, 정렬, 중복 제거, 열 단위 처리
예제 1.1.1

관측 기록 파일 log.txt의 각 줄이 "영상이름 필터 노출시간"이다. V 필터 영상의 노출시간 합계를 구하는 명령은 무엇인가?

풀이. grep " V " log.txt | awk '{s += $3} END {print s}'이다. grep이 V 필터 줄만 골라 넘기고, awk가 셋째 열을 더해 끝에 출력한다. 몇만 줄이어도 1초 안에 끝난다.

1.1.2셸 스크립트

같은 명령을 파일마다 되풀이할 때는 스크립트에 적어 둔다. 예를 들어 다음 스크립트는 raw/ 안의 모든 FITS 영상을 처리해 out/에 저장한다.

#!/bin/bash
# reduce.sh: raw/ 안의 모든 FITS 영상을 처리해 out/에 저장
mkdir -p out
for f in raw/*.fits; do
  name=$(basename "$f" .fits)
  python reduce.py "$f" "out/${name}_red.fits" > "out/${name}.log" 2>&1
  echo "끝: $name"
done

그러면 chmod +x reduce.sh로 실행 권한을 주고 ./reduce.sh로 돌린다. 접속이 끊겨도 계속 돌게 하려면 nohup ./reduce.sh &이나 tmux를 쓰고, 계산 서버에서는 Slurm 같은 작업 관리자에 sbatch로 제출한다.

1.1.3나눠서 동시에

한편 파일마다 독립인 작업은 xargs -P 8이나 GNU parallel로 여러 코어에 나눠 동시에 돌릴 수 있다. 다만 디스크 읽기와 쓰기처럼 나눌 수 없는 부분이 있으면, 그 몫이 코어 수와 상관없이 남는다(그림 1). 나눌 수 없는 비율을 \(s\)라 하면 \(p\)개 코어에서 걸리는 시간은 \(T_1[s + (1-s)/p]\)이며, 이를 암달의 법칙이라 한다.

예제 1.1.2

영상 400장을 한 장에 90초씩 처리한다. 한 코어로 차례로 하면, 8코어로 나누면 각각 얼마나 걸리는가?

풀이. 차례로 하면 \(400\times90 = 36{,}000\) s, 곧 10시간이다. 8코어면 이상적으로 1.25시간이다. 하지만 5%를 나눌 수 없다면 \(10\times(0.05 + 0.95/8) = 1.69\)시간이 걸린다.

주의스크립트에서 rm *이나 덮어쓰는 >를 쓰기 전에 echo로 대상 목록을 먼저 출력해 확인한다. rm에는 휴지통이 없다. 그리고 원본 자료는 읽기 전용으로 두고 결과는 다른 폴더에 쓰는 것이 안전하다.
마무리

셸의 기본 명령을 파이프와 방향 바꾸기로 이어 붙이면 큰 자료도 몇 줄로 다룰 수 있다. 반복 작업은 for 반복문을 쓴 셸 스크립트로 자동화하고, 오래 걸리는 작업은 nohup, tmux, 작업 관리자로 돌린다. 독립 작업은 여러 코어에 나누되, 나눌 수 없는 부분이 속도의 상한을 정한다.

1.1.4연습문제

기본

  1. 현재 폴더의 .fits 파일 개수를 세는 명령은 무엇인가?
    답

    ls *.fits | wc -l이다.

응용

  1. catalog.csv에서 셋째 열(등급)이 15보다 밝은(작은) 줄만 세는 명령을 써라(쉼표 구분).
    답

    awk -F, '$3 < 15' catalog.csv | wc -l이다.

  2. 작업 1,000개(각 3분)를 16코어에서 돌리면 대략 얼마나 걸리는가? 나눌 수 없는 부분이 10%라면 어떤가?
    답

    이상적으로 \(1000\times3/16 = 187.5\)분, 약 3시간이다. 10%를 나눌 수 없으면 \(3000\times(0.1 + 0.9/16) = 469\)분, 약 7.8시간이다.
