올림이 줄지어 넘어간다

탐구 · 전가산기로 만든 4비트 덧셈기

질문

컴퓨터는 이진수 두 개를 어떻게 더할까? 손으로 하는 받아올림 덧셈을 게이트로 만들면 어떤 구조가 될까?

복원

전가산기: 합 \(s = a \oplus b \oplus c_{in}\), 올림 \(c_{out} = ab + c_{in}(a \oplus b)\). 전가산기를 이어 붙이면 여러 자리 덧셈기가 된다 (6.2절).

해 보기

  1. 처음 화면은 \(0110 + 0111\) (6 + 7)이다. 맨 오른쪽 \(0 + 1\)은 올림이 없지만, 둘째 자리 \(1 + 1\)에서 올림이 생겨 왼쪽으로 넘어가고, 결과는 \(1101 = 13\)이다.
  2. A를 \(1111\), B를 \(0001\)로 만들어 보자. 올림이 오른쪽 끝에서 왼쪽 끝까지 모든 자리를 거쳐 넘어가고 결과는 \(10000 = 16\)이다. 왼쪽 끝 올림이 4비트를 넘친 자리(오버플로)이다.
  3. 두 수가 같은 자리에 1이 하나도 없으면(예: \(1010 + 0101\)) 올림이 전혀 생기지 않는다. 이때는 덧셈이 비트별 OR과 같다.

설명

  1. 리플 캐리각 자리는 오른쪽 자리의 올림을 기다려야 하므로, 최악의 경우(\(1111 + 0001\)) 올림이 \(n\)자리를 차례로 지나간다. 비트 수에 비례하는 지연이라, 실제 CPU는 올림을 미리 계산하는 회로(올림 예측)로 \(O(\log n)\) 단계에 끝낸다.
  2. 뺄셈도 같은 회로로2의 보수(비트를 뒤집고 1을 더함)를 쓰면 \(A - B = A + \bar B + 1\)이라 덧셈기로 뺄셈도 한다.

판단

"두 4비트 수의 합은 늘 4비트에 들어간다"는 틀린다. \(1111 + 0001\)처럼 합이 15를 넘으면 5번째 비트(올림)가 필요하다. 이를 무시하면 결과가 0000이 되는 오버플로가 생긴다.
