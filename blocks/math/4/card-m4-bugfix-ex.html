테스트로 하나 차이 오류 잡기

예제 · 공식과 비교하는 테스트

먼저 예측

sum(range(1, n))은 1부터 \(n\)까지의 합일까?

예측 확인

아니다. range(1, n)은 \(n - 1\)에서 끝나 1부터 \(n - 1\)까지의 합이다.

다음 함수는 \(1^2 + 2^2 + \cdots + n^2\)을 구하려고 쓴 것이다. 공식 \(\frac{n(n + 1)(2n + 1)}6\)과 비교하는 테스트로 오류를 찾고 고쳐라.

def sum_sq(n):
    return sum(k*k for k in range(1, n))

전략

답을 아는 공식과 여러 \(n\)에서 비교하는 테스트를 씁니다(1.4절). 경계값 \(n = 0, 1\)을 꼭 넣는다.

풀이

  1. for n in range(0, 10):
    assert sum_sq(n) == n*(n+1)*(2*n+1)//6, n
    실패하면 그때의 \(n\)을 보여 준다.
  2. \(n = 1\)에서 AssertionError: 1. sum_sq(1)이 0이다(공식은 1).
    \(n = 0\)은 둘 다 0이라 통과.
  3. range(1, n + 1)로 고치면 모든 테스트 통과.
    끝을 포함하도록.

검산

고친 함수로 sum_sq(10) = 385이고 공식 \(\frac{10\cdot11\cdot21}6 = 385\)과 같다.

의미

"하나 차이(off-by-one)" 오류는 프로그래밍에서 가장 흔한 실수이다. 큰 \(n\)에서는 결과가 그럴듯해 눈으로 찾기 어렵지만, 작은 \(n\)과 경계값의 테스트는 바로 잡아낸다. 수학 공식은 코드를 검증하는 좋은 기준이다.

이해 확인

\(1 + 3 + 5 + \cdots + (2n - 1) = n^2\)을 이용해 홀수의 합 함수를 검사하는 테스트를 써라.

답

for n in range(10): assert sum(range(1, 2*n, 2)) == n*n.
