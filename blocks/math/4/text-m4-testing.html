함수로 나누고 테스트로 확인하기

본문
이 절에서 배울 것
  • 한 가지 일을 하는 함수로 코드를 나누고, 입력과 출력을 분명히 한다.
  • assert로 답을 아는 경우를 검사하는 테스트를 쓴다.
  • 경계값(0, 1, 음수, 빈 리스트)에서 틀리기 쉬움을 알고 테스트에 넣는다.
먼저 알아야 할 것
  • 함수와 반복문 (1.1절), 소수 판정 (1.2절).

1.4.1함수로 나누기

"1000 이하의 쌍둥이 소수 쌍의 개수"를 구한다고 합시다. 한 덩어리로 쓰면 어디가 틀렸는지 찾기 어렵습니다. 소수 판정, 쌍 찾기, 세기를 나눕니다.

def is_prime(n):
    if n < 2:
        return False
    d = 2
    while d * d <= n:
        if n % d == 0:
            return False
        d += 1
    return True

def twin_pairs(N):
    return [(p, p + 2) for p in range(2, N - 1) if is_prime(p) and is_prime(p + 2)]

print(len(twin_pairs(1000)))   # 35

1.4.2assert로 테스트하기

assert 조건은 조건이 거짓이면 프로그램을 멈추고 알려 줍니다. 답을 아는 작은 경우로 함수를 검사합니다.

assert is_prime(2) and is_prime(97)
assert not is_prime(1) and not is_prime(0) and not is_prime(91)   # 91 = 7*13
assert twin_pairs(20) == [(3, 5), (5, 7), (11, 13), (17, 19)]
print("모든 테스트 통과")

특히 경계값을 넣어야 합니다. is_prime에서 n < 2 처리를 빼먹으면 1이 소수로 나오고, while d * d <= n을 <로 쓰면 25 같은 제곱수가 소수로 나옵니다. 둘 다 위 테스트가 잡아냅니다.

1.4.3왜 테스트를 먼저 쓰나

수학에서 정리를 증명하기 전에 작은 예로 확인하듯, 코드도 작은 예로 먼저 확인합니다. 함수를 고칠 때마다 테스트를 다시 돌리면 고친 곳이 다른 곳을 망가뜨리지 않았는지 바로 압니다. 테스트를 한 파일에 모아 두고 pytest 같은 도구로 한꺼번에 돌리는 것이 실제 개발 방식입니다.

흔한 오해(1) 큰 입력에서 결과가 그럴듯하면 맞다고 여긴다. 작은 경우를 손으로 확인해야 한다. (2) 테스트가 통과하면 코드가 옳다고 여긴다. 테스트한 경우에만 맞다는 뜻이라, 경계값과 특이한 경우를 골고루 넣어야 한다.
요약
  1. 한 가지 일을 하는 함수로 나눈다.
  2. assert로 답을 아는 경우를 검사.
  3. 경계값(0, 1, 제곱수, 빈 입력)을 반드시 포함.

1.4.4연습문제

기본

  1. 자연수의 자릿수 합을 구하는 함수 digit_sum(n)을 쓰고 테스트 두 개를 붙여라.
    답

    def digit_sum(n): return sum(int(c) for c in str(n)), assert digit_sum(0) == 0, assert digit_sum(1234) == 10.

응용

  1. is_prime의 while d * d <= n을 while d * d < n으로 바꾸면 어떤 테스트가 실패하는가?
    답

    4, 9, 25 같은 소수의 제곱이 소수로 판정된다. assert not is_prime(25)가 실패한다.

심화

  1. 최대공약수 함수 gcd(a, b)의 성질을 이용한 테스트를 두 가지 생각하여라(특정 값이 아닌 성질).
    답

    (1) gcd(a, b)는 a와 b를 모두 나눈다. (2) gcd(a, b) * lcm(a, b) == a * b. 여러 무작위 a, b에 대해 반복해 검사한다.
