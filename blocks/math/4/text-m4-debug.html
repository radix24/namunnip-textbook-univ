예외 처리와 디버깅

본문

Newton 방법 코드가 어떤 초깃값에서는 멈추지 않고, 어떤 초깃값에서는 0으로 나누다 죽는다. 프로그램이 틀렸을 때 어디서 무엇이 잘못됐는지 어떻게 찾고, 예상되는 실패는 어떻게 다룰까?

먼저 알아야 할 것함수와 assert(1.4절), Newton 방법의 식 \(x_{n+1} = x_n - f(x_n)/f'(x_n)\)을 쓴다.

1.6.1오류 메시지 읽기

파이썬은 실행 중 문제가 생기면 예외를 일으키고 역추적(traceback)을 출력한다. 마지막 줄이 예외의 종류와 메시지이고, 그 위의 줄들은 그 지점까지 함수가 어떻게 불려 왔는지를 아래에서 위로 보여 준다. 그러면 읽는 순서는 마지막 줄의 종류를 먼저 보고, 바로 위의 "내 코드" 줄 번호로 가는 것이다. 자주 보는 것은 ZeroDivisionError, IndexError(리스트 범위 밖), TypeError(자료형이 맞지 않음), KeyError(딕셔너리에 없는 키)이다.

1.6.2예외 처리

미리 예상되는 실패는 프로그램을 죽이지 말고 다루는 편이 낫다. 가령 Newton 방법에서 도함수가 0이 되면 그 초깃값은 실패로 기록하고 다음 초깃값으로 넘어가면 된다.

def newton(f, df, x, tol=1e-12, maxit=50):
    for n in range(maxit):
        d = df(x)
        if d == 0:
            raise ZeroDivisionError(f"{n}번째 반복에서 f'(x) = 0")
        step = f(x) / d
        x -= step
        if abs(step) < tol:
            return x
    raise RuntimeError("수렴하지 않음")

for x0 in [2.0, 0.0, 0.5]:
    try:
        print(x0, newton(lambda x: x**3 - 2*x + 2, lambda x: 3*x**2 - 2, x0))
    except (ZeroDivisionError, RuntimeError) as e:
        print(x0, "실패", e)

이 함수는 실패를 두 종류로 나누어 알려 준다. 도함수가 0이면 ZeroDivisionError, 반복 횟수를 다 써도 멈추지 않으면 RuntimeError이다. 호출하는 쪽은 그림 1의 흐름대로 try로 감싸 예외를 받는다. 예외를 아무 종류나 다 받는 except:는 쓰지 않는다. 오타 같은 진짜 버그까지 조용히 삼켜 버리기 때문이다.

예제 1.6.1

위 코드에서 초깃값 0이 실패하는 이유를 손으로 따라가 보여라.

풀이. \(f(x) = x^3 - 2x + 2\), \(f'(x) = 3x^2 - 2\)에서 \(x_0 = 0\)이면 \(x_1 = 0 - \frac{2}{-2} = 1\)이고, \(x_1 = 1\)에서 \(x_2 = 1 - \frac{1}{1} = 0\)이다. 반복이 0과 1 사이를 영원히 오가므로 RuntimeError가 난다. 오류가 프로그램의 버그가 아니라 수학적 현상(2-주기 궤도)에서 왔다는 것을 확인했으니, 예외로 다루는 것이 맞다.

1.6.3디버깅 도구

원인이 보이지 않을 때는 가설을 세우고 확인한다. 가장 간단한 방법은 반복마다 print(n, x, step)을 넣어 값의 흐름을 보는 것이다. 다음으로 불변식을 assert로 적어 두면 처음 깨지는 곳에서 멈춘다. 더 큰 프로그램에서는 breakpoint()를 넣어 그 지점에서 변수를 들여다보는 디버거(pdb)를 쓴다. 고친 뒤에는 실패했던 입력을 테스트로 남겨 같은 버그가 돌아오지 않게 한다.

마무리

역추적은 마지막 줄의 예외 종류부터 읽고 내 코드의 줄 번호로 거슬러 올라간다. 예상되는 실패는 구체적인 예외 종류로 일으키고 try와 except로 받으며, 원인을 모를 때는 값 출력, assert, 디버거로 가설을 확인한다. Newton 방법의 실패처럼 수학적 현상에서 오는 예외도 있다.
