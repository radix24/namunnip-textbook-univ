C 프로그램의 컴파일과 실행

본문

같은 반복 계산이 Python에서는 느리고 C나 Fortran에서는 수십 배 빠르다. 그 차이는 어디서 올까? C 프로그램은 어떻게 실행 파일로 만들어 돌리며, 오류가 나면 그 메시지를 어떻게 읽어야 할까? 컴파일만 되면 프로그램이 맞다고 할 수 있을까?

먼저 알아야 할 것셸 명령(1.2절)과 반복문, 함수 같은 프로그래밍 기초를 쓴다.

1.3.1컴파일

C와 Fortran은 원시 코드를 기계어로 미리 번역, 곧 컴파일한 실행 파일을 만들어 돌린다. 번역에 시간이 들지만 실행은 빠르다. 반면 Python은 실행할 때마다 한 줄씩 해석하므로 편하지만, 같은 반복문이 수십 배 느릴 수 있다. 그래서 과학계산에서는 핵심 계산을 C나 Fortran으로 짜거나, 3.2절에서 보듯 그렇게 짜인 NumPy 같은 라이브러리를 부른다.

/* sqrt2.c - 바빌로니아 방법으로 √2 */
#include <stdio.h>
#include <math.h>
int main(void) {
    double x = 1.0;
    for (int k = 1; k <= 5; k++) {
        x = 0.5 * (x + 2.0 / x);
        printf("%d %.15f %.1e\n", k, x, fabs(x - sqrt(2.0)));
    }
    return 0;
}
$ gcc -O2 -Wall -o sqrt2 sqrt2.c -lm
$ ./sqrt2
1 1.500000000000000 8.6e-02
2 1.416666666666667 2.5e-03
3 1.414215686274510 2.1e-06
4 1.414213562374690 1.6e-12
5 1.414213562373095 2.2e-16

여기서 -o는 실행 파일 이름, -Wall은 경고를 모두 켜기, -O2는 최적화, -lm은 sqrt와 fabs가 든 수학 라이브러리를 연결하라는 뜻이다. 그림 1처럼 오차가 매번 대략 제곱으로 줄어드는 것은 이 방법이 \(x^2 - 2 = 0\)에 대한 뉴턴 방법이기 때문이며, 이는 5.2절에서 다룬다. 마지막 오차 \(2.2\times10^{-16}\)은 4.2절에서 볼 배정밀도의 한계라서 더 줄지 않는다.

1.3.2오류 읽기

오류에는 세 종류가 있다. 첫째는 컴파일 오류로, 문법이나 타입이 틀려 실행 파일이 만들어지지 않는다. 가령 메시지 sqrt2.c:6:9: error: expected ';'는 6번째 줄 9번째 글자 근처가 문제라는 뜻이다. 뒤의 오류는 앞 오류의 여파인 경우가 많으므로 첫 오류부터 고친다.

둘째는 링크 오류이다. 예를 들어 undefined reference to 'sqrt'는 함수의 정의를 찾지 못했다는 뜻으로, -lm을 빠뜨렸을 때 흔히 나온다.

셋째는 실행 시간 오류로, 컴파일은 되었지만 실행 중에 문제가 생긴 것이다. 배열의 범위를 넘으면 Segmentation fault가 나고, 0으로 나누면 inf나 nan이 출력된다.

Fortran도 같은 흐름이며 gfortran -O2 -o prog prog.f90으로 컴파일한다. 여러 파일로 된 프로그램은 make와 Makefile을 써서 바뀐 파일만 다시 컴파일한다.

흔한 오해경고는 무시해도 된다고 여기기 쉽지만, 초기화하지 않은 변수 같은 경고는 실제 버그인 경우가 많다. 또 컴파일되면 맞는 프로그램이라고 생각하는 것도 틀렸다. 컴파일은 문법만 확인한 것이므로, \(\sqrt2\)처럼 결과를 아는 경우로 검증해야 한다.
마무리

처음 질문에 답하면, C와 Fortran은 미리 기계어로 번역한 실행 파일을 돌리므로 한 줄씩 해석하는 Python보다 빠르며, gcc -O2 -Wall -o 이름 파일 -lm으로 컴파일한다. 오류는 컴파일, 링크, 실행 시간 오류로 나누어 첫 메시지부터 읽는다. 컴파일은 문법만 확인하므로, 그림 1처럼 답을 아는 경우로 결과를 검증해야 한다.

1.3.3연습문제

기본

  1. gcc prog.c만 치면 실행 파일 이름은 무엇이 되는가?
    답

    a.out (Windows에서는 a.exe).

응용

  1. 예제에서 double 대신 float를 쓰면 5번째 줄 오차는 대략 얼마쯤에서 멈추겠는가?
    답

    float의 기계 엡실론이 약 \(1.2\times10^{-7}\)이라 오차가 \(10^{-7}\) 정도에서 더 줄지 않는다.

심화

  1. int a[10]; a[10] = 1;이 컴파일 오류가 아닌 이유와 위험을 설명하여라.
    답

    C는 배열 범위를 검사하지 않아 문법상 문제가 없다. 실행하면 다른 변수의 메모리를 덮어써 엉뚱한 결과나 segfault가 난다. -fsanitize=address로 검사할 수 있다.
