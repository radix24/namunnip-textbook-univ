벡터화: 반복문을 배열 연산으로

본문

백만 개의 수에 사인을 취해 더하는 같은 계산이, 쓰는 방법에 따라 몇십 배나 빠르거나 느려진다. 그 차이는 어디서 올까? 반복문으로 하던 일을 배열 전체에 대한 연산으로 바꾸려면 어떤 도구를 쓰며, 그렇게 바꿀 수 없는 계산은 무엇일까?

먼저 알아야 할 것배열 연산(3.1절), 컴파일 언어와 인터프리터(1.3절)를 쓴다.

3.2.1왜 빠른가

Python 반복문은 원소마다 자료형을 확인하고 함수를 부르는 비용이 든다. 반면 NumPy의 배열 연산은 같은 일을 C로 컴파일된 반복문 하나로 처리하므로, 이 비용이 원소 수에 비례해 쌓이지 않는다. 그래서 같은 계산을 배열 전체에 대한 연산으로 쓰는 것, 즉 벡터화가 과학계산의 기본 기술이다.

import math, time, numpy as np
n = 10**6
t = time.time()                      # 반복문
s = 0.0
for i in range(n):
    s += math.sin(i/n)
print(s/n, time.time() - t)
t = time.time()                      # 벡터화
x = np.arange(n) / n
print(np.sin(x).sum()/n, time.time() - t)

두 방법 모두 \(\int_0^1\sin x\,dx = 1 - \cos1 \approx 0.4596977\)의 왼쪽 리만 합 \(0.4596972734\)를 낸다. 시간은 컴퓨터마다 다르지만, 예를 들어 그림 1처럼 반복문은 1.3초, 벡터화는 0.02초 정도로 수십 배 차이가 난다.

3.2.2자주 쓰는 바꾸기

반복문으로 하던 일 가운데 자주 나오는 것들은 다음과 같이 벡터화한다.

반복문으로 하던 일벡터화
합, 평균, 최댓값x.sum(), x.mean(), x.max()
누적합 \(s_k = \sum_{i\le k}x_i\)np.cumsum(x)
이웃 차이 \(x_{i+1} - x_i\)np.diff(x) 또는 x[1:] - x[:-1]
조건에 따라 다른 값np.where(x > 0, x, 0)
두 벡터의 모든 쌍브로드캐스팅 x[:, None] - y[None, :]
예제 3.2.1

함숫값 배열 f와 간격 h로 사다리꼴 적분 \(h\left(\frac{f_0 + f_n}2 + \sum_{i=1}^{n-1}f_i\right)\)을 벡터화하여 써라.

풀이. 전체 합에서 양 끝의 절반을 빼면 되므로 h*(f.sum() - (f[0] + f[-1])/2) 한 줄이다. 이 식은 6.3절에서 쓴다.

하지만 벡터화할 수 없는 계산도 있다. 뉴턴 반복이나 상미분방정식의 시간 진행처럼 다음 단계가 앞 단계의 결과에 의존하는 점화식은 반복문이 필요하다. 이럴 때는 반복 횟수 자체를 줄이거나, Numba나 Cython으로 계산을 C로 옮긴다.

흔한 오해NumPy를 쓰기만 하면 반복문 안에서도 빠르다고 여기기 쉽지만, for 안에서 원소 하나씩 NumPy 함수를 부르면 오히려 더 느리다. 또 모든 계산을 벡터화할 수 있다고 생각하는 것도 틀렸다. 앞 단계의 결과에 의존하는 점화식은 벡터화할 수 없다.
마무리

처음 질문에 답하면, Python 반복문은 원소마다 자료형 확인과 함수 호출 비용을 치르지만, NumPy의 배열 연산은 C로 된 반복문 하나로 처리하므로 수십 배 빠르다. 합, 누적합, 이웃 차이, 조건 선택, 모든 쌍은 sum, cumsum, diff, where, 브로드캐스팅으로 벡터화한다. 다만 앞 결과에 의존하는 점화식은 벡터화할 수 없다.

3.2.3연습문제

기본

  1. np.cumsum([1, 2, 3, 4])와 np.diff([1, 4, 9, 16])의 결과는?
    답

    [1, 3, 6, 10], [3, 5, 7].

응용

  1. 점 \(n\)개의 좌표 배열 P (\(n\times2\))에서 모든 두 점 사이 거리 행렬을 반복문 없이 구하여라.
    답

    D = np.sqrt(((P[:, None, :] - P[None, :, :])**2).sum(axis=2)).

심화

  1. \(x_{k+1} = \cos x_k\)를 1000번 반복하는 계산은 왜 벡터화할 수 없는가? 시작값 100만 개에 대해 한꺼번에 하는 것은 벡터화할 수 있는가?
    답

    각 단계가 앞 단계 값에 의존한다. 그러나 시작값 100만 개는 서로 독립이라 배열 x = np.cos(x)를 1000번 반복하면 된다(반복문 1000번, 각 단계는 벡터화).
