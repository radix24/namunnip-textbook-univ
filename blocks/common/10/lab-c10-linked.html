배열 대신 포인터로 이으면 무엇이 쉬워질까?

실습 · 연결 리스트

목표

배열은 원소가 메모리에 붙어 있어 \(i\)번째 원소를 바로 꺼낼 수 있지만, 앞이나 가운데에 넣으려면 뒤의 원소를 모두 옮겨야 한다. 연결 리스트는 노드마다 다음 노드의 주소(포인터)를 들고 있어서, 포인터 몇 개만 바꾸면 넣고 뺄 수 있다. 두 구조에서 같은 일을 할 때 드는 일의 양을 비교하고, C로 직접 짜 본다. 성취기준 [공통10-05-04].

준비

  • 노드 하나는 값(왼쪽 칸)과 다음 노드를 가리키는 포인터(오른쪽 칸)로 이루어진다. 마지막 노드의 포인터는 NULL(∅)이다.
  • head는 첫 노드를 가리키는 포인터이다. 이 실습의 연결 리스트는 head만 있고 끝을 가리키는 포인터는 없다.
  • 포인터의 뜻은 5.2절, 구조체는 5.3절에서 배웠다.

절차

  1. 처음 상태(10 → 20 → 30 → 40)에서 "앞에 넣기"를 누르고 두 구조가 한 일을 기록한다.
  2. "가운데 넣기", "뒤에 넣기", "앞에서 빼기"도 차례로 눌러 기록한다.
  3. 아래 C 코드를 컴파일해 실행하고, 출력이 화면의 리스트와 같은지 확인한다.
#include <stdio.h>
#include <stdlib.h>

typedef struct Node { int val; struct Node *next; } Node;

Node *push_front(Node *head, int v) {   /* 앞에 넣기: 포인터 2개 */
    Node *p = malloc(sizeof(Node));
    p->val = v; p->next = head;
    return p;                            /* 새 head */
}
Node *pop_front(Node *head) {           /* 앞에서 빼기 */
    Node *nx = head->next;
    free(head);
    return nx;
}
void print(Node *p) {
    for (; p != NULL; p = p->next) printf("%d ", p->val);
    printf("\n");
}
int main(void) {
    Node *head = NULL;
    for (int v = 40; v >= 10; v -= 10) head = push_front(head, v);
    print(head);                         /* 10 20 30 40 */
    head = push_front(head, 50); print(head);
    head = pop_front(head);      print(head);
    while (head) head = pop_front(head);
    return 0;
}

기대 결과

  • 앞에 넣기(원소 4개일 때): 연결 리스트는 새 노드 1개를 만들고 포인터 2개만 바꾼다. 배열은 원소 4개를 모두 한 칸씩 뒤로 옮긴다.
  • 뒤에 넣기: 연결 리스트는 끝을 찾으려고 head부터 링크를 원소 수만큼 따라가야 한다. 배열은 빈칸이 있으면 옮길 것이 없다.
  • 앞에서 빼기: 연결 리스트는 head만 다음 노드로 바꾸면 되고, 배열은 나머지를 모두 앞으로 옮긴다.
  • C 프로그램의 출력은 10 20 30 40, 50 10 20 30 40, 10 20 30 40 세 줄이다.

분석

  1. 원소가 \(n\)개일 때 각 연산의 일의 양이 \(n\)에 비례하는지, 일정한지 표로 정리해 보자.
  2. \(i\)번째 원소를 읽는 일은 두 구조에서 어떻게 다른가요? 어떤 프로그램에 연결 리스트가 알맞을까?
  3. 끝을 가리키는 포인터(tail)를 하나 더 두면 "뒤에 넣기"가 어떻게 바뀌나요?
