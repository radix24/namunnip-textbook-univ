컴퓨터의 자료 표현과 과학 계산 단원 마무리 연습

문제 7 · 개념·계산·판단 · 힌트 2단계

혼자 풀고, 막히면 힌트 1 → 힌트 2 → 풀이 순서로 여세요. 문제 끝의 코드는 그 문제가 확인하는 성취기준입니다.

  1. 계산13을 2진수로, 16진수 2F를 10진수로 바꾸세요. 또 −5를 8비트 2의 보수로 나타내세요. [06-01]

    힌트 1

    2로 계속 나눈 나머지를 거꾸로 읽습니다. 16진수 F는 15입니다.

    힌트 2

    2의 보수: 5의 비트를 모두 뒤집고 1을 더합니다.

    풀이

    \(13 = 8 + 4 + 1 = 1101_2\). \(2\mathrm F_{16} = 2 \times 16 + 15 = 47\). \(5 = 00000101\), 뒤집으면 \(11111010\), 1을 더해 \(11111011\). 검산: \(11111011 + 00000101 = 1\,00000000\)(넘친 9번째 비트를 버리면 0).

  2. 계산8비트 부호 있는 정수가 나타낼 수 있는 범위는? 127에 1을 더하면 비트로 무슨 일이 일어나나요? [06-01]

    힌트 1

    맨 앞 비트가 부호 역할을 합니다. \(2^8 = 256\)가지 비트 패턴을 음수와 양수가 나눠 씁니다.

    힌트 2

    \(127 = 01111111\).

    풀이

    \(-128\)부터 \(127\)까지. \(01111111 + 1 = 10000000\)이고 이것은 2의 보수로 \(-128\)입니다. 정수 넘침은 오류 메시지 없이 엉뚱한 값을 만드는 경우가 많아 위험합니다.

  3. 개념0.1을 10번 더하는 반복문 s = 0.0; for _ in range(10): s += 0.1의 결과가 정확히 1.0이 아닌 이유를 말하세요. 배정밀도의 기계 엡실론(약 \(2.2\times10^{-16}\))은 무엇을 뜻하나요? [06-01]

    힌트 1

    \(0.1 = 0.0001100110011\ldots_2\)로 끝나지 않는 이진 소수입니다.

    힌트 2

    기계 엡실론은 1과 그다음으로 큰 실수 사이의 간격입니다.

    풀이

    0.1이 가장 가까운 이진 근삿값으로 저장되고, 더할 때마다 반올림이 일어나 결과는 0.9999999999999999입니다. 기계 엡실론은 실수의 상대 정밀도로, 1 근처에서 이보다 작은 차이는 구별하지 못합니다. 그래서 배정밀도의 유효숫자는 약 16자리입니다. (파이썬 3.12부터 sum([0.1]*10)은 보정된 덧셈을 해서 1.0이 나오니, 반복문으로 직접 더해 보세요.)

  4. 실습사다리꼴 공식으로 \(\int_0^1 x^2\,dx\)를 \(n = 10\)으로 계산하는 함수를 쓰고, 정확한 값 1/3과 비교하세요. [06-02]

    힌트 1

    \(T_n = h\left[\dfrac{f(a) + f(b)}2 + \sum_{i=1}^{n-1}f(a + ih)\right]\), \(h = (b - a)/n\).

    힌트 2

    함수를 인자로 넘기면 여러 함수에 쓸 수 있습니다: trap(f, a, b, n).

    풀이 
    def trap(f, a, b, n):
    h = (b - a) / n
    s = (f(a) + f(b)) / 2
    for i in range(1, n):
        s += f(a + i * h)
    return h * s
print(trap(lambda x: x * x, 0, 1, 10))   # 0.335 (조금 큼)

    오차 0.00167. \(x^2\)이 아래로 볼록해 사다리꼴이 곡선 위로 지나가서 값이 큽니다. \(n\)을 두 배로 하면 오차가 약 4분의 1이 됩니다(공통1 5.6절).

  5. 실습이분법으로 \(x^2 = 2\)의 근을 \([1, 2]\)에서 구간 폭이 \(10^{-6}\) 이하가 될 때까지 구하는 프로그램을 쓰고, 몇 번 반복하는지 예측한 뒤 확인하세요. [06-02]

    힌트 1

    가운데 점 m에서 \(m^2 - 2\)의 부호를 보고 근이 있는 반쪽을 남깁니다.

    힌트 2

    한 번에 폭이 절반이 되므로 \(2^{-k} \le 10^{-6}\)인 가장 작은 \(k\).

    풀이 
    lo, hi, k = 1.0, 2.0, 0
while hi - lo > 1e-6:
    m = (lo + hi) / 2
    if m * m < 2:
        lo = m
    else:
        hi = m
    k += 1
print(k, (lo + hi) / 2)   # 20 1.41421365...

    \(2^{20} = 1048576 > 10^6\)이므로 20번. 이분법은 느리지만, 처음 구간에서 부호가 바뀌기만 하면 반드시 근에 다가갑니다(중간값 정리, 공통1 1.4절).

  6. 판단“실수를 많이 더할수록 반올림 오차가 서로 지워져 결과가 더 정확해진다.” 판단하세요. [06-01]

    힌트 1

    0.1을 10번 더한 결과와, 백만 번 더한 결과의 오차를 비교해 보세요.

    힌트 2

    반올림 오차는 덧셈마다 생기고, 큰 수에 작은 수를 더할수록 작은 수의 자리가 많이 잘립니다.

    풀이

    틀렸습니다. 반올림 오차는 한 방향으로 쌓이기도 해서, 더하는 횟수가 많을수록 대체로 커집니다. 0.1을 백만 번 더하면 100000에서 \(10^{-6}\) 정도 어긋납니다. 큰 수 다음에 작은 수를 더하면 손실이 더 큽니다. 정확도가 중요하면 작은 수부터 더하거나 보정된 덧셈(math.fsum)을 씁니다.

  7. 계산정렬된 정수 500개 [0, 1, …, 499]에서 이진 탐색을 할 때, 비교 횟수는 최대 몇 번인가요? 같은 자료에서 선형 탐색은 최대 몇 번인가요? [06-03]

    힌트 1

    한 번 비교할 때마다 남은 후보가 절반 이하로 줄어듭니다.

    힌트 2

    \(2^8 = 256 < 500 \le 2^9 = 512\).

    풀이

    이진 탐색은 최대 9번, 선형 탐색은 최대 500번입니다. 이 절의 binary 함수로 500개 값을 모두 찾아 보면 가장 많이 비교한 경우가 9번입니다. 리스트에 없는 값(예: 1000)을 찾을 때도 9번 만에 끝나고 -1을 돌려줍니다.
