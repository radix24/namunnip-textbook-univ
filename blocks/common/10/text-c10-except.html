예외 처리: 잘못된 입력에 대비하기

본문
이 절에서 배울 것
  • try, except, else, finally가 실행되는 순서를 안다.
  • 잘못된 자료가 섞인 파일을 멈추지 않고 처리한다.
  • 함수가 받을 수 없는 값을 raise로 알린다.
먼저 알아야 할 것
  • 오류 메시지의 종류 (1.3절), 함수 (3.1절), 파일 읽기와 간단한 try (3.2절).

3.4.1예외와 try 문

실행 중에 생기는 오류(1.3절의 실행 오류)를 파이썬에서는 예외라 부릅니다. 예외가 나면 프로그램은 그 자리에서 멈춥니다. 예외가 날 수 있는 부분을 try로 감싸면, 멈추는 대신 except 묶음을 실행하고 계속 갑니다.

try:
    # 예외가 날 수 있는 코드
except ValueError:
    # ValueError가 났을 때
else:
    # 예외가 나지 않았을 때 (선택)
finally:
    # 예외가 나든 안 나든 마지막에 언제나 (선택)
  • except에는 처리할 예외 이름을 적습니다. 여러 개면 except를 여러 번 쓰거나 except (ValueError, ZeroDivisionError):처럼 묶습니다.
  • 이름 없이 except:만 쓰면 모든 예외를 삼켜 버려, 오타(NameError) 같은 내 실수까지 숨깁니다. 처리할 예외만 이름으로 적는 것이 원칙입니다.
  • except ValueError as e:로 받으면 e에 오류 설명이 들어 있어 출력할 수 있습니다.

3.4.2잘못된 줄이 섞인 자료

예제 3.4.1

측정값 파일을 읽었더니 줄마다 아래 문자열이 들어 있었습니다. 숫자로 바꿀 수 있는 줄만 더하고, 바꿀 수 없는 줄의 번호를 모으세요.

lines = ["1.2", "abc", "3.4", "", "5.0", "2,5"]
total, bad = 0.0, []
for no, line in enumerate(lines, start=1):   # 줄 번호를 1부터 붙인다
    try:
        total += float(line)
    except ValueError:
        bad.append(no)
print(total, bad)   # 9.6 [2, 4, 6]

풀이. float("abc"), float(""), float("2,5")는 모두 ValueError를 냅니다. 마지막 것은 소수점 대신 쉼표를 쓴 경우로, 실제 자료에서 자주 나옵니다. try가 없었다면 2번째 줄에서 프로그램이 멈췄을 것입니다. 건너뛴 줄 번호를 남겨 두었으므로, 나중에 원본 파일을 고칠 수 있습니다. 잘못된 줄을 조용히 버리기만 하면 자료가 줄어든 것을 모른 채 결과를 믿게 되므로, 몇 줄을 버렸는지는 꼭 알립니다.

3.4.3else와 finally

def safe_div(a, b):
    try:
        q = a / b
    except ZeroDivisionError:
        print("0으로 나눌 수 없습니다")
        return None
    else:
        print("정상")
        return q
    finally:
        print("끝")

safe_div(1, 0)은 "0으로 나눌 수 없습니다", "끝"을 출력하고 None을 돌려줍니다. safe_div(6, 3)은 "정상", "끝"을 출력하고 2.0을 돌려줍니다. return을 만나도 finally는 먼저 실행됩니다. 그래서 파일 닫기, 장비 연결 끊기처럼 "무슨 일이 있어도 해야 하는 정리"를 finally에 둡니다(파일은 with가 이 일을 대신합니다).

3.4.4raise: 내가 예외를 내기

함수가 받을 수 없는 값이 들어오면, 틀린 답을 돌려주는 것보다 예외를 내서 부른 쪽에 알리는 편이 안전합니다.

예제 3.4.2

운동 에너지 \(E = \frac12 mv^2\)을 돌려주는 함수를 쓰되, 질량이 0 이하이면 ValueError를 내게 하세요. 부르는 쪽에서 그 예외를 받아 메시지를 출력하세요.

def kinetic(m, v):
    if m <= 0:
        raise ValueError(f"질량은 양수여야 합니다: {m}")
    return 0.5 * m * v ** 2

print(kinetic(2, 3))          # 9.0
try:
    kinetic(-1, 3)
except ValueError as e:
    print("오류:", e)         # 오류: 질량은 양수여야 합니다: -1

풀이. 검사 없이 계산하면 \(m = -1\)에서 \(-4.5\)라는 "그럴듯한" 숫자가 나와 논리 오류가 됩니다. raise로 막아 두면 잘못이 생긴 곳에서 바로 드러납니다.

요약
  1. try → 예외가 나면 except, 안 나면 else → 언제나 finally.
  2. 처리할 예외만 이름으로 받는다. 이름 없는 except:는 내 실수까지 숨긴다.
  3. 받을 수 없는 값은 raise ValueError("설명")로 알린다.
