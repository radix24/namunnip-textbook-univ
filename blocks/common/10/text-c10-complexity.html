실행 시간과 계산량

본문

자료가 1000개일 때 1초 걸리던 프로그램이, 자료가 100만 개가 되면 얼마나 걸릴까? 1000초일 수도, 100만 초일 수도, 고작 2초일 수도 있다. 컴퓨터마다 속도가 다른데, 프로그램이 얼마나 빠른지를 공정하게 비교하려면 무엇을 세어야 할까?

먼저 알아야 할 것리스트와 반복문(2.1절, 2.3절), 함수(3.1절), 로그 \(\log_2\)(고교 수학I)를 쓴다.

6.3.1시간 재기

실행 시간은 다음처럼 잰다.

import time
t0 = time.perf_counter()
# 잴 코드
dt = time.perf_counter() - t0      # 초 단위

그런데 같은 코드라도 컴퓨터와 그때의 상황에 따라 시간이 달라진다. 그러므로 여러 번 재거나 입력 크기를 바꾸며 비율을 보는 것이 좋다. 처음 질문의 답으로, 시간 대신 "기본 연산(비교, 덧셈)을 몇 번 하는가"를 세는 방법을 함께 쓰며, 이 횟수를 계산량이라 한다.

6.3.2선형 탐색과 이진 탐색

정렬된 리스트 a에서 값 x의 위치를 찾는 두 방법을 비교하자. 선형 탐색은 앞에서부터 하나씩 비교하므로, 길이가 \(n\)이면 최악의 경우 \(n\)번 비교한다. 반면 이진 탐색은 가운데 원소와 비교해, x가 더 크면 오른쪽 절반, 작으면 왼쪽 절반만 남긴다. 즉 한 번 비교할 때마다 후보가 절반으로 줄어들며, 사전에서 단어를 찾는 방법과 같다.

def binary(a, x):
    lo, hi, steps = 0, len(a) - 1, 0
    while lo <= hi:
        steps += 1
        mid = (lo + hi) // 2
        if a[mid] == x:
            return mid, steps
        elif a[mid] < x:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1, steps        # 없으면 -1
예제 6.3.1

짝수 \(0, 2, 4, \ldots\)를 \(n\)개 담은 리스트에서 마지막 원소를 찾을 때, 선형 탐색과 이진 탐색의 비교 횟수를 \(n = 1000\)과 \(n = 1\,000\,000\)에서 구하여라.

풀이. 선형 탐색은 마지막까지 가야 하므로 1000번, 1000000번이다. 이진 탐색은 후보 수가 \(n \to n/2 \to n/4 \to \cdots\)로 줄어 1이 될 때까지이므로 약 \(\log_2 n\)번이다. 그런데 \(2^{10} = 1024\)이므로 \(n = 1000\)에서 10번, \(2^{20} \approx 10^6\)이므로 \(n = 10^6\)에서 20번이다. 위 코드로 세어 보아도 10번, 20번이 나온다. 리스트에 없는 값(가령 1)을 찾을 때도 같은 10번, 20번 뒤에 -1을 돌려준다.

즉 자료가 1000배 커질 때 선형 탐색은 1000배, 이진 탐색은 10번만 더 늘었다. 그림 1의 16개에서도 이진 탐색은 많아야 5번이면 끝난다. 다만 이진 탐색은 자료가 정렬되어 있어야 쓸 수 있다.

6.3.3계산량의 표기

\(n\)이 클 때 계산량이 무엇에 비례하는지만 남겨 \(O(\cdot)\)로 쓰며, "빅 오"라 읽는다. 이때 상수배와 작은 항은 버린다. 가령 이진 탐색은 \(O(\log n)\)이어서 \(n\)이 두 배가 되면 한 번 더 비교한다. 선형 탐색이나 합 구하기는 \(O(n)\)이어서 \(n\)이 두 배면 두 배가 된다. 그리고 모든 쌍을 비교하는 이중 반복은 \(O(n^2)\)이어서 \(n\)이 두 배면 네 배가 된다.

예제 6.3.2

측정값 \(n\)개에서 차이가 0.001보다 작은 쌍의 수를 세는 함수가 있다. 쌍 \((i, j)\), \(i < j\)를 모두 비교한다. 비교 횟수를 \(n\)으로 나타내고, \(n\)을 1000 → 2000 → 4000으로 늘리면 실행 시간이 어떻게 변할지 예상하여라.

def pairs(xs):
    n, cnt = len(xs), 0
    for i in range(n):
        for j in range(i + 1, n):
            if abs(xs[i] - xs[j]) < 1e-3:
                cnt += 1
    return cnt

풀이. \(i = 0\)일 때 \(n - 1\)번, \(i = 1\)일 때 \(n - 2\)번, …이므로 모두 \(\frac{n(n-1)}{2}\)번, 곧 \(O(n^2)\)이다. 그러므로 \(n\)이 두 배가 될 때마다 시간은 약 네 배가 될 것으로 예상한다. 실제로 이 교재를 쓴 컴퓨터에서 난수 자료로 재 보니 대략 0.25초, 1.2초, 4.0초로, 한 단계마다 3~5배였다(컴퓨터마다 절대 시간은 다르다). 한편 자료를 먼저 정렬하면 이웃한 값끼리만 비교해도 되므로, 정렬 \(O(n\log n)\)에 훑기 \(O(n)\)으로 줄일 수 있다.

마무리

시간은 time.perf_counter()의 차이로 재되 입력 크기를 바꿔 비율을 보고, 처음 질문처럼 공정하게 비교하려면 기본 연산의 횟수인 계산량을 센다. 선형 탐색은 \(O(n)\), 정렬된 자료의 이진 탐색은 \(O(\log n)\), 모든 쌍 비교는 \(O(n^2)\)이며, \(n\)이 두 배일 때 \(O(n^2)\)은 네 배, \(O(\log n)\)은 한 단계만 늘어난다.

6.3.4연습문제

기본

  1. 정렬된 자료 100만 개에서 이진 탐색은 최대 몇 번 비교하는가? 10억 개라면?
    답

    \(2^{20} = 1\,048\,576\)이므로 약 20번. \(2^{30} \approx 1.07\times10^9\)이므로 약 30번.

  2. \(O(n^2)\) 프로그램이 \(n = 1000\)에서 0.3초 걸렸다. \(n = 10000\)이면 대략 얼마나 걸릴까?
    답

    \(n\)이 10배이므로 시간은 100배, 약 30초.
