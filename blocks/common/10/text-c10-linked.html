배열로는 불편한 일

학생 명단을 배열에 이름순으로 저장해 두었는데 새 학생이 들어왔다고 합시다. 이름순을 지키려면 그 자리 뒤의 학생을 모두 한 칸씩 밀어야 합니다. 1만 명이면 1만 번을 옮길 수도 있습니다. 또 배열은 처음에 크기를 정해야 해서, 학생이 몇 명이 될지 모르면 넉넉히 잡거나 더 큰 배열로 옮겨야 합니다. 이 두 문제를 푸는 자료 구조가 연결 리스트입니다. 원소들을 메모리 아무 곳에나 두고, 원소마다 "다음 원소는 저기 있다"는 주소를 들고 있게 합니다.

5.4.1노드와 head

노드: 연결 리스트의 원소 하나. 값과 다음 노드의 주소(포인터)를 함께 가진 구조체입니다.

head: 첫 노드를 가리키는 포인터. 리스트 전체를 이것 하나로 붙잡습니다.

NULL: 아무것도 가리키지 않는 포인터. 마지막 노드의 next와 빈 리스트의 head는 NULL입니다.

#include <stdio.h>
#include <stdlib.h>

typedef struct Node {
    int val;
    struct Node *next;   /* 다음 노드의 주소 */
} Node;

구조체 안에 자기 자신과 같은 형의 포인터를 둔 것에 주목하세요. 구조체 자체를 넣으면 크기가 무한히 커지지만, 포인터는 주소 하나(보통 8바이트)라 괜찮습니다. typedef는 struct Node를 Node로 줄여 부르게 합니다.

5.4.2앞에 넣기와 앞에서 빼기

새 값을 맨 앞에 넣는 순서는 세 단계입니다. 그림을 그리며 따라가 보세요.

  1. 새 노드를 malloc으로 만든다. 지역 변수는 함수가 끝나면 사라지므로, 오래 남아야 하는 노드는 힙에 만들어야 합니다.
  2. 새 노드의 next가 지금의 첫 노드(head)를 가리키게 한다.
  3. head가 새 노드를 가리키게 한다.
Node *push_front(Node *head, int v) {
    Node *p = malloc(sizeof(Node));
    if (p == NULL) return head;   /* 메모리가 모자랄 때 */
    p->val = v;
    p->next = head;
    return p;                     /* 새 head */
}

Node *pop_front(Node *head) {
    if (head == NULL) return NULL;
    Node *nx = head->next;
    free(head);                   /* 다 쓴 노드는 돌려준다 */
    return nx;
}

p->val은 (*p).val을 줄여 쓴 것입니다. 2단계와 3단계의 순서를 바꾸면 안 됩니다. head를 먼저 바꾸면 원래 첫 노드의 주소를 잃어버려 리스트 나머지에 다시 갈 수 없습니다.

예제 5.4.1

빈 리스트에 40, 30, 20, 10을 차례로 앞에 넣고, 처음부터 끝까지 출력하여라.

풀이. 앞에 넣으면 나중에 넣은 것이 앞에 오므로 리스트는 10 → 20 → 30 → 40입니다. 출력은 head에서 시작해 next를 따라가다 NULL에서 멈춥니다.

void print_list(const Node *p) {
    for (; p != NULL; p = p->next)
        printf("%d ", p->val);
    printf("\n");
}

int main(void) {
    Node *head = NULL;
    for (int v = 40; v >= 10; v -= 10)
        head = push_front(head, v);
    print_list(head);              /* 10 20 30 40 */
    while (head != NULL)           /* 모두 해제 */
        head = pop_front(head);
    return 0;
}

5.4.3뒤에 넣기와 가운데 넣기

head만 있는 리스트에서 뒤에 넣으려면 끝 노드를 찾아 head부터 차례로 따라가야 합니다. 원소가 \(n\)개면 링크를 \(n - 1\)번 따라갑니다. 끝을 가리키는 포인터(tail)를 따로 두면 바로 붙일 수 있습니다. 어떤 노드 q 바로 뒤에 넣는 것은 앞에 넣기와 같은 두 줄입니다: 새 노드의 next를 q->next로, q->next를 새 노드로.

5.4.4배열과 비교

할 일 (원소 \(n\)개)배열연결 리스트
\(i\)번째 원소 읽기바로(주소 계산 한 번)링크 \(i\)번 따라가기
맨 앞에 넣기·빼기\(n\)개를 옮김포인터 1~2개
찾은 자리 뒤에 넣기뒤의 원소를 모두 옮김포인터 2개
메모리원소만, 크기를 미리 정함원소마다 포인터 하나 더, 필요할 때 늘림

그래서 자주 읽고 드물게 바꾸는 자료에는 배열이, 앞이나 가운데에서 자주 넣고 빼는 자료(대기열, 편집기의 줄 목록)에는 연결 리스트가 알맞습니다. 이 절 뒤의 실습 카드에서 두 구조의 일을 직접 세어 볼 수 있습니다.

가장 흔한 실수는 세 가지입니다. ① free한 노드를 다시 쓰기 ② 빈 리스트(head가 NULL)에서 head->next를 읽기 ③ free를 하지 않아 메모리가 계속 새기. 빈 리스트와 원소가 하나인 리스트로 꼭 시험해 보세요.

이 절은 POSTECH 프로그래밍과 문제해결(CSED101)의 리스트 장(Forouzan 15장)을 보충한 것입니다. 연결 리스트는 2학년 자료구조 과목에서 스택, 큐, 트리로 이어집니다.

요약
  1. 노드는 값과 다음 노드의 포인터를 가진 구조체이고, head가 첫 노드를, 마지막 next는 NULL을 가리킨다.
  2. 앞에 넣기: 새 노드의 next ← head, head ← 새 노드. 순서를 바꾸면 리스트를 잃는다.
  3. 연결 리스트는 넣고 빼기가 빠르고, 배열은 \(i\)번째 원소 읽기가 빠르다.
  4. malloc으로 만든 노드는 다 쓴 뒤 free한다.

  2. 기본 push_front에서 p->next = head;와 return p; 대신 head를 먼저 바꾸면 무슨 일이 일어나는가?
    답원래 첫 노드의 주소를 잃어 나머지 노드에 다시 갈 수 없고, 그 노드들은 해제할 수도 없게 된다(메모리 누수).
  3. 응용 리스트에서 값이 v인 첫 노드를 지우는 함수를 쓰세요. 첫 노드가 지워질 때를 따로 다루어야 하는 이유는?
    답첫 노드가 지워지면 head 자체가 바뀌므로 새 head를 돌려줘야 한다. 그 밖에는 앞 노드 prev를 들고 다니다가 prev->next = cur->next; free(cur);.
