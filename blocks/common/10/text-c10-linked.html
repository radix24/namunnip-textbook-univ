연결 리스트: 포인터로 이은 자료

본문 · 5.4절

학생 명단을 배열에 이름순으로 저장해 두었는데 새 학생이 들어왔다. 이름순을 지키려면 그 자리 뒤의 학생을 모두 한 칸씩 밀어야 하므로, 1만 명이면 1만 번을 옮길 수도 있다. 또 배열은 처음에 크기를 정해야 해서 학생이 몇 명이 될지 모르면 곤란하다. 원소들을 메모리 아무 곳에나 두고 "다음 원소는 저기 있다"는 주소만 들고 있게 하면 어떨까?

먼저 알아야 할 것배열(5.1절), 포인터(5.2절), 구조체(5.3절)를 쓴다.

5.4.1노드와 head

처음 질문의 자료 구조가 연결 리스트이다. 연결 리스트의 원소 하나를 노드라 하며, 노드는 값과 다음 노드의 주소(포인터)를 함께 가진 구조체이다. 첫 노드를 가리키는 포인터를 head라 하며, 리스트 전체를 이것 하나로 붙잡는다. 그리고 아무것도 가리키지 않는 포인터를 NULL이라 하며, 마지막 노드의 next와 빈 리스트의 head는 NULL이다.

#include <stdio.h>
#include <stdlib.h>

typedef struct Node {
    int val;
    struct Node *next;   /* 다음 노드의 주소 */
} Node;

구조체 안에 자기 자신과 같은 형의 포인터를 둔 것에 주목하자. 구조체 자체를 넣으면 크기가 무한히 커지지만, 포인터는 주소 하나(보통 8바이트)라 괜찮다. 또 typedef는 struct Node를 Node로 줄여 부르게 한다.

5.4.2앞에 넣기와 앞에서 빼기

새 값을 맨 앞에 넣는 순서는 세 단계이다. 먼저 새 노드를 malloc으로 만든다. 지역 변수는 함수가 끝나면 사라지므로, 오래 남아야 하는 노드는 힙에 만들어야 한다. 다음으로 새 노드의 next가 지금의 첫 노드(head)를 가리키게 한다. 끝으로 head가 새 노드를 가리키게 한다. 그림 1에서 단계를 하나씩 넘기며 따라갈 수 있다.

Node *push_front(Node *head, int v) {
    Node *p = malloc(sizeof(Node));
    if (p == NULL) return head;   /* 메모리가 모자랄 때 */
    p->val = v;
    p->next = head;
    return p;                     /* 새 head */
}

Node *pop_front(Node *head) {
    if (head == NULL) return NULL;
    Node *nx = head->next;
    free(head);                   /* 다 쓴 노드는 돌려준다 */
    return nx;
}

p->val은 (*p).val을 줄여 쓴 것이다. 그리고 둘째와 셋째 단계의 순서를 바꾸면 안 된다. head를 먼저 바꾸면 원래 첫 노드의 주소를 잃어버려 리스트 나머지에 다시 갈 수 없다. 그림 1에서 순서를 "잘못된 순서"로 바꾸면 이 일이 벌어진다.

예제 5.4.1

빈 리스트에 40, 30, 20, 10을 차례로 앞에 넣고, 처음부터 끝까지 출력하여라.

풀이. 앞에 넣으면 나중에 넣은 것이 앞에 오므로 리스트는 10 → 20 → 30 → 40이다. 출력은 head에서 시작해 next를 따라가다 NULL에서 멈춘다.

void print_list(const Node *p) {
    for (; p != NULL; p = p->next)
        printf("%d ", p->val);
    printf("\n");
}

int main(void) {
    Node *head = NULL;
    for (int v = 40; v >= 10; v -= 10)
        head = push_front(head, v);
    print_list(head);              /* 10 20 30 40 */
    while (head != NULL)           /* 모두 해제 */
        head = pop_front(head);
    return 0;
}

5.4.3뒤에 넣기와 가운데 넣기

head만 있는 리스트에서 뒤에 넣으려면 끝 노드를 찾아 head부터 차례로 따라가야 한다. 원소가 \(n\)개면 링크를 \(n - 1\)번 따라간다. 그런데 끝을 가리키는 포인터(tail)를 따로 두면 바로 붙일 수 있다. 한편 어떤 노드 q 바로 뒤에 넣는 것은 앞에 넣기와 같은 두 줄이다. 새 노드의 next를 q->next로 하고, q->next를 새 노드로 하면 된다.

5.4.4배열과 비교

두 구조가 같은 일을 하는 데 드는 일의 양을 비교하면 다음과 같다.

할 일 (원소 \(n\)개)배열연결 리스트
\(i\)번째 원소 읽기바로(주소 계산 한 번)링크 \(i\)번 따라가기
맨 앞에 넣기·빼기\(n\)개를 옮김포인터 1~2개
찾은 자리 뒤에 넣기뒤의 원소를 모두 옮김포인터 2개
메모리원소만, 크기를 미리 정함원소마다 포인터 하나 더, 필요할 때 늘림

그래서 자주 읽고 드물게 바꾸는 자료에는 배열이, 앞이나 가운데에서 자주 넣고 빼는 자료(대기열, 편집기의 줄 목록)에는 연결 리스트가 알맞다. 이 절 뒤의 실습 카드에서 두 구조의 일을 직접 세어 볼 수 있다.

흔한 오해노드를 다 쓰고 나면 저절로 정리된다고 생각하기 쉽다. 하지만 C에서는 가장 흔한 실수가 세 가지 있다. free한 노드를 다시 쓰는 것, 빈 리스트(head가 NULL)에서 head->next를 읽는 것, 그리고 free를 하지 않아 메모리가 계속 새는 것이다. 그러므로 빈 리스트와 원소가 하나인 리스트로 꼭 시험해 보아야 한다.
이 절은 리스트(Forouzan 15장)를 보충한 것이다. 연결 리스트는 2학년 자료구조 과목에서 스택, 큐, 트리로 이어진다.
마무리

연결 리스트의 노드는 값과 다음 노드의 포인터를 가진 구조체이고, head가 첫 노드를, 마지막 next는 NULL을 가리킨다. 앞에 넣을 때는 새 노드의 next를 head로 한 뒤 head를 옮기며, 순서를 바꾸면 리스트를 잃는다. 처음 질문처럼 넣고 빼기는 연결 리스트가, \(i\)번째 원소 읽기는 배열이 빠르며, malloc으로 만든 노드는 다 쓴 뒤 free한다.

  3. 응용 리스트에서 값이 v인 첫 노드를 지우는 함수를 써라. 첫 노드가 지워질 때를 따로 다루어야 하는 이유는?
    답첫 노드가 지워지면 head 자체가 바뀌므로 새 head를 돌려줘야 한다. 그 밖에는 앞 노드 prev를 들고 다니다가 prev->next = cur->next; free(cur);.
