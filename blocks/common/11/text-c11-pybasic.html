포트란으로 짠 이차방정식 풀이를 파이썬으로 옮기면 선언이 사라지고 줄 수도 줄어든다. 그런데 옮기다 보면 정수 나눗셈처럼 두 언어가 정반대로 동작하는 곳에서 틀리기 쉽다. 두 언어는 무엇이 같고 무엇이 다를까? 또 근의 공식을 그대로 옮기면 생기는 숨은 문제는 없을까?

먼저 알아야 할 것파이썬 기초(전자계산(1) 1.1절, 1.2절)와 포트란 기초(1.1절, 1.2절)를 쓴다.

전자계산(1)에서 파이썬을 배웠다면 이 절은 복습이다. 여기서는 포트란과 나란히 놓고 차이를 정리한다.

3.1.1동적 자료형

포트란과 C는 변수를 쓰기 전에 자료형을 선언하고, 그 변수에는 그 자료형만 넣는다. 이것을 정적 자료형이라 한다. 반면 파이썬은 선언 없이 값을 대입하면 변수가 생기고, 같은 이름에 다른 자료형의 값을 넣어도 된다. 이것이 동적 자료형이다. 편하지만 오타나 자료형 실수가 실행해 보기 전까지 드러나지 않는다. 두 언어를 나란히 놓으면 다음과 같다.

3.1.2같은 프로그램, 두 언어

예제 3.1.1

이차방정식 \(ax^2 + bx + c = 0\)의 근을 판별식에 따라 구하여라.

풀이. 판별식 \(D = b^2 - 4ac\)의 부호로 세 갈래를 나눈다. 포트란과 파이썬으로 쓰면 다음과 같다.

program quad
  implicit none
  integer, parameter :: dp = kind(1.0d0)
  real(dp) :: a, b, c, D
  read *, a, b, c
  D = b**2 - 4*a*c
  if (D > 0) then
    print *, (-b + sqrt(D))/(2*a), (-b - sqrt(D))/(2*a)
  else if (D == 0) then
    print *, -b/(2*a)
  else
    print *, "실근 없음"
  end if
end program quad
import math
a, b, c = map(float, input().split())
D = b**2 - 4*a*c
if D > 0:
    print((-b + math.sqrt(D))/(2*a), (-b - math.sqrt(D))/(2*a))
elif D == 0:
    print(-b/(2*a))
else:
    print("실근 없음")

포트란의 4*a*c에서 정수 4는 실수 a와 곱해지며 실수로 바뀌므로 괜찮다. 그러나 1/2*a처럼 정수끼리 먼저 나누면 0이 된다.

처음 질문의 숨은 문제는 \(b^2 \gg 4ac\)일 때 나타난다. 이때 \(\sqrt D\)가 \(|b|\)와 거의 같아 \(-b + \sqrt D\)에서 앞자리가 지워지는 상쇄 오차가 생긴다(전자계산(1) 6.1절). 그림 1에서 \(b = 10^4\)이면 근의 공식으로 구한 작은 근의 상대 오차가 이미 \(10^{-9}\) 수준이고, \(b = 10^8\)에서는 \(-7.45\times10^{-9}\)이 나와 참값 \(-1\times10^{-8}\)과 25 % 넘게 어긋난다. 그래서 정밀한 계산에서는 큰 근을 먼저 구한 뒤 근과 계수의 관계 \(x_1x_2 = c/a\)로 작은 근을 따로 구한다.

마무리

포트란은 정적 자료형, 파이썬은 동적 자료형이며, 정수 나눗셈, /=와 !=, 대소문자 구별이 다르다. 처음 질문처럼 같은 알고리즘은 두 언어에서 짜임이 같지만, 정수 나눗셈은 정반대라 옮길 때 조심해야 한다. 근의 공식은 \(b^2 \gg 4ac\)에서 상쇄 오차가 생기므로 작은 근은 \(x_1x_2 = c/a\)로 구한다.
