서브루틴의 인자에는 intent를 적어 들어오는 값과 나가는 값을 컴파일러가 지키게 한다

요령 · 서브루틴 인자

언제 쓰는가

서브루틴과 함수를 만들 때, 인자가 함수 안에서 바뀌어 호출한 쪽 값까지 바뀌는 문제가 생길 때이다.

요령

  1. 인자를 셋으로 나눈다
    읽기만 하면 intent(in), 결과를 돌려주면 intent(out), 읽고 고치면 intent(inout)이다.
  2. 포트란은 참조로 넘긴다
    포트란 인자는 기본적으로 원래 변수 자체가 넘어가므로, 서브루틴 안에서 바꾸면 밖의 값도 바뀐다.
  3. 컴파일러가 막아 준다
    intent(in) 인자에 값을 넣으면 컴파일 오류가 나므로 실수로 입력을 망치지 않는다.
  4. 상수를 넘기지 않는다
    intent(inout)이나 intent(out) 자리에 상수(1.0_dp)를 넘기면 고칠 곳이 없어 오류나 이상한 동작이 난다.

흔한 실수

  • intent를 생략해 입력 배열이 함수 안에서 몰래 바뀌는 것.
  • intent(out) 인자를 읽어서 쓰는 것. 들어올 때 값이 정해져 있지 않는다.

바로 풀어보기

배열 x의 모든 원소에 c를 곱하는 서브루틴 scale(x, c)의 선언부를 써라. call scale(x, 2.0_dp)와 call scale([1.0_dp, 2.0_dp], 2.0_dp)는 각각 괜찮은가요?

답과 풀이

답: x는 intent(inout), c는 intent(in). 첫째는 괜찮고, 둘째는 바꿀 수 없는 상수 배열을 넘겨 안 된다.

subroutine scale(x, c)
  real(dp), intent(inout) :: x(:)
  real(dp), intent(in)    :: c
  x = c * x
end subroutine scale
c는 상수로 넘겨도 읽기만 하므로 괜찮다. 둘째 호출의 배열 상수는 고칠 수 있는 변수가 아니라서, intent(inout) 인자에 넘기면 컴파일러가 막거나 실행 중 오류가 난다.

이 요령으로 풀리는 문제

  • 포트란 부프로그램과 파일 단원 연습 1번, 2번, 3번, 6번
영상 콘티 · 40초
  1. 0~5초주 프로그램의 배열 x 상자와 서브루틴 scale이 화살표로 이어진다.넘겨준 배열은 바뀔까?
  2. 5~13초화살표가 복사본이 아니라 원래 상자를 그대로 가리키고, 서브루틴 안에서 값이 두 배가 되자 바깥 상자도 두 배가 된다.포트란은 원래 변수를 넘긴다.
  3. 13~22초인자 이름 옆에 문 표지판 'in', 'out', 'inout'이 붙는다. c에는 'in' 표지판.들어오는지 나가는지 적다.
  4. 22~31초서브루틴 안에서 c에 값을 넣으려 하자 컴파일러가 빨간 경고로 막는다.컴파일러가 약속을 지키게 한다.
  5. 31~40초상수 배열이 'inout' 문으로 들어가려다 '바꿀 수 없음' 표시에 튕겨 난다.고칠 인자에는 변수를 넘긴다.
