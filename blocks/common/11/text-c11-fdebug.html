컴파일 오류와 실행 중 검사

본문
이 절에서 배울 것
  • 컴파일 오류, 컴파일 경고, 실행 오류를 구별한다.
  • gfortran의 검사 옵션(-Wall, -fcheck=all, -g -fbacktrace)을 켜고 메시지를 읽는다.
  • 배열 범위를 벗어나는 잘못을 실행 중 검사로 잡는다.
먼저 알아야 할 것
  • 포트란 변수와 implicit none (1.1절), DO 반복문 (1.2절), 배열 (1.3절). 파이썬의 오류 종류 (공통10 1.3절).

1.4.1오류가 드러나는 때

파이썬은 한 줄씩 실행하다가 오류를 만나지만, 포트란은 실행 전에 컴파일(프로그램 전체를 기계어로 번역)을 거칩니다. 그래서 오류가 드러나는 때가 셋입니다.

컴파일 오류: 문법이 틀리거나 선언하지 않은 변수를 써서 번역이 안 됩니다. 실행 파일이 만들어지지 않습니다.

컴파일 경고: 번역은 되지만 의심스러운 곳(값을 넣기 전에 쓰는 변수, 쓰지 않는 변수, 정밀도가 줄어드는 대입)을 알려 줍니다. 실행 파일은 만들어지므로 무시하기 쉬운데, 실제 잘못인 경우가 많습니다.

실행 오류: 실행 중에 0으로 나누기, 배열 범위 벗어나기 같은 일이 생깁니다. 포트란은 빠르게 돌리려고 기본적으로 이런 검사를 하지 않아, 멈추지 않고 틀린 값으로 계속 가는 경우가 많습니다. 파이썬과 가장 다른 점입니다.

개발하는 동안에는 검사 옵션을 모두 켜고, 결과가 맞는 것을 확인한 뒤 빠른 실행용 옵션(-O2)으로 다시 컴파일합니다.

gfortran -Wall -Wextra -fcheck=all -g -fbacktrace prog.f90 -o prog
  • -Wall -Wextra: 경고를 더 많이 보여 준다.
  • -fcheck=all: 배열 범위 등을 실행 중에 검사한다. 느려지므로 개발 중에만 쓴다.
  • -g -fbacktrace: 실행 오류가 나면 어느 줄에서 났는지 알려 준다.

1.4.2컴파일 오류 읽기

예제 1.4.1

합을 구하는 프로그램에서 변수 이름을 잘못 쳤습니다. implicit none이 있을 때와 없을 때 무슨 일이 생기는지 설명하세요.

program total_sum
  implicit none
  integer :: i, total
  total = 0
  do i = 1, 10
     totl = total + i      ! total을 totl로 잘못 침
  end do
  print *, total
end program total_sum

풀이. implicit none이 있으면 컴파일러가 선언되지 않은 totl을 찾아 컴파일 오류를 냅니다. gfortran은 줄 번호와 함께 "Symbol 'totl' at (1) has no IMPLICIT type"과 같은 문장으로 알리고, 그 아래에 문제의 줄과 위치 표시 1을 보여 줍니다(문구는 판마다 조금 다를 수 있어 확인 필요). implicit none이 없으면 totl이 저절로 실수형 새 변수가 되어 컴파일이 되고, 실행하면 0이 출력됩니다. 메시지 없이 틀린 답이 나오는 논리 오류로 바뀐 것입니다. 1.1절에서 implicit none을 꼭 쓰라고 한 이유가 이것입니다.

1.4.3배열 범위 검사

예제 1.4.2

크기 10인 배열에 제곱수를 넣으려다 반복 범위를 11까지 잡았습니다. 검사 옵션 없이 컴파일했을 때와 -fcheck=bounds(또는 -fcheck=all)로 컴파일했을 때를 비교하세요.

program squares
  implicit none
  integer :: a(10), i
  do i = 1, 11
     a(i) = i * i
  end do
  print *, a(10)
end program squares

풀이. 검사 없이 컴파일하면 a(11)에 쓰는 값이 배열 바로 뒤의 메모리(다른 변수일 수 있음)를 덮어씁니다. 프로그램이 멈추지 않고 100을 출력할 수도, 엉뚱한 곳의 값이 바뀌어 한참 뒤에 이상한 결과가 나올 수도 있습니다. 어느 쪽이 될지는 컴파일러와 메모리 배치에 달려 있어 예측할 수 없습니다. -fcheck=bounds로 컴파일하면 실행 중에 바로 멈추고, 몇째 줄에서 배열 a의 첨자 11이 상한 10을 넘었다는 메시지를 냅니다(정확한 문구는 확인 필요). 고칠 곳은 do i = 1, 10, 더 좋게는 do i = 1, size(a)입니다.

공통10의 C 배열(5.1절)도 범위를 검사하지 않아 같은 일이 생깁니다. 파이썬 리스트는 언제나 검사해 IndexError를 냅니다. 빠른 언어일수록 검사를 사람이 켜야 합니다.

요약
  1. 컴파일 오류(실행 파일 없음), 경고(의심), 실행 오류(실행 중)를 구별한다.
  2. 개발 중에는 -Wall -Wextra -fcheck=all -g -fbacktrace, 확인 뒤에는 -O2.
  3. implicit none은 오타를 컴파일 오류로, -fcheck=bounds는 범위 초과를 실행 오류로 드러낸다.

1.4.4연습문제

기본

  1. -Wall을 켜고 컴파일했더니 "변수가 초기화되지 않은 채 쓰일 수 있다"는 경고가 나왔습니다. 실행 파일은 만들어졌는데, 그대로 써도 될까요?
    답

    안 됩니다. 값을 넣지 않은 변수에는 메모리에 남아 있던 아무 값이나 들어 있어, 실행할 때마다 결과가 달라질 수 있습니다. 합을 구하는 변수라면 반복 전에 total = 0처럼 처음 값을 꼭 넣습니다.

  2. 예제 1.4.2를 do i = 1, size(a)로 고치면 좋은 점은 무엇인가요?
    답

    배열 크기를 나중에 바꿔도 반복 범위를 따로 고칠 필요가 없어, 크기와 범위가 어긋나는 잘못이 생기지 않습니다.
