포트란 배열

본문

\(1000 \times 1000\) 행렬의 모든 원소를 이중 반복문으로 채우는데, 바깥과 안쪽 반복의 순서만 바꿨더니 실행 시간이 몇 배나 달라졌다. 계산은 똑같은데 왜 그럴까? 그리고 포트란은 C나 파이썬과 배열을 어떻게 다르게 다룰까?

먼저 알아야 할 것DO 반복문(1.2절)과 C 배열(전자계산(1) 5.1절)을 쓴다.

1.3.1선언과 인덱스

포트란 배열은 선언할 때 이름 뒤 괄호에 크기를 적는다.

real(dp) :: T(5), A(3, 3)
integer :: i
T = [20.1_dp, 20.6_dp, 21.3_dp, 22.0_dp, 22.8_dp]
print *, T(1), T(5)       ! 첫째와 마지막: 인덱스는 1부터
print *, T(2:4)           ! 구간: 2, 3, 4번 (끝 포함)
print *, T(5:1:-1)        ! 거꾸로

원소도 괄호로 꺼내며, 인덱스는 기본이 1부터이다(C, 파이썬은 0부터). real(dp) :: B(0:10)처럼 시작 번호를 정할 수도 있다. 또 구간 T(2:4)는 끝을 포함한다.

1.3.2배열 전체 연산

포트란의 큰 장점은 반복문 없이 배열 전체를 한꺼번에 계산할 수 있다는 것이다.

real(dp) :: x(101), y(101)
x = [(0.01_dp * i, i = 0, 100)]   ! 0, 0.01, ..., 1 (암시적 do)
y = sin(x)**2 + x                  ! 원소마다 계산
print *, sum(y) / size(y)          ! 평균
print *, maxval(y), maxloc(y)      ! 최댓값과 그 위치
where (y > 1.0_dp) y = 1.0_dp       ! 조건에 맞는 원소만 바꾸기

이 밖에 sum, product, maxval, minval, size 같은 내장 배열 함수가 있다. 또 dot_product(u, v)는 내적, matmul(A, B)는 행렬 곱, transpose(A)는 전치 행렬을 준다.

1.3.3열 우선 저장과 할당 배열

처음 질문의 답이 여기 있다. 2차원 배열 A(i, j)는 메모리에 열 우선으로, 곧 A(1,1), A(2,1), A(3,1), A(1,2), ... 순서로 놓인다(C는 행 우선). 그림 1에서 메모리 칸을 하나씩 넘기면 첫째 인덱스가 가장 빨리 바뀐다. 컴퓨터는 메모리를 차례로 읽을 때 빠르므로, 이중 반복문에서는 첫째 인덱스를 안쪽 반복에 둔다.

do j = 1, n          ! 바깥: 열
  do i = 1, n        ! 안쪽: 행 (메모리 순서대로)
    A(i, j) = 1.0_dp / (i + j - 1)
  end do
end do

반복 순서를 거꾸로 하면 안쪽 반복이 한 걸음마다 한 열 길이만큼 메모리를 건너뛴다. 그래서 같은 계산이 몇 배 느려질 수 있다. 그림 1에서 저장 방식을 "행 우선"으로 바꾸면, 같은 배열을 C나 NumPy로 다룰 때는 반대로 둘째 인덱스를 안쪽에 두어야 한다는 것을 볼 수 있다.

한편 크기를 실행 중에 정하려면 할당 배열을 쓴다.

real(dp), allocatable :: data(:)
read *, n
allocate(data(n))
! ... 사용 ...
deallocate(data)

아래 실습 카드에서 행 우선과 열 우선의 메모리 순서를 더 비교해 볼 수 있다.

마무리

포트란 배열은 괄호로 쓰고 인덱스는 1부터이며, 구간 a(i:j)는 끝을 포함한다. 반복문 없는 배열 전체 연산과 sum, matmul, where가 편리하다. 처음 질문의 시간 차이는 열 우선 저장 때문이므로 첫째 인덱스를 안쪽 반복에 두고, 크기를 나중에 정하는 배열은 allocatable로 선언한다.
