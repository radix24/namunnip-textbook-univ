서브루틴과 함수

본문

직교 좌표 \((x, y)\)를 극좌표 \((r, \theta)\)로 바꾸는 계산은 결과가 둘이다. 값을 하나만 돌려주는 함수로는 부족한데, 포트란에서는 결과 두 개를 어떻게 받아 올까? 전자계산(1)에서 C 함수는 인수의 복사본만 받았는데, 포트란도 그럴까?

먼저 알아야 할 것포트란 배열(1.3절)과 C 함수와 포인터(전자계산(1) 4.3절, 5.2절)를 쓴다.

2.1.1함수와 서브루틴

포트란의 부프로그램은 두 가지이다. 함수(function)는 값 하나를 돌려주며, 식 안에서 y = f(x)처럼 쓴다. 반면 서브루틴(subroutine)은 돌려주는 값 없이 인수를 바꾸며, call로 부른다. 처음 질문의 극좌표 변환처럼 결과가 여럿이면 서브루틴이 알맞다.

둘을 모듈에 넣고 use로 불러 쓰면, 컴파일러가 인수의 개수와 자료형을 검사해 주어 실수를 줄일 수 있다.

module physics
  implicit none
  integer, parameter :: dp = kind(1.0d0)
contains
  function kinetic(m, v) result(K)
    real(dp), intent(in) :: m, v
    real(dp) :: K
    K = 0.5_dp * m * v**2
  end function kinetic

  subroutine polar(x, y, r, theta)
    real(dp), intent(in)  :: x, y
    real(dp), intent(out) :: r, theta
    r = sqrt(x**2 + y**2)
    theta = atan2(y, x)
  end subroutine polar
end module physics

program main
  use physics
  implicit none
  real(dp) :: r, th
  print *, kinetic(2.0_dp, 3.0_dp)      ! 9.0
  call polar(1.0_dp, 1.0_dp, r, th)
  print *, r, th                        ! 1.414..., 0.785...
end program main

2.1.2intent와 참조에 의한 전달

처음 질문의 둘째 물음에 답하면, 포트란은 C와 다르다. 포트란은 인수를 넘길 때 값을 복사하지 않고 변수 자체(주소)를 넘긴다. 이것을 참조에 의한 전달이라 한다. 그래서 서브루틴이 인수를 바꾸면 부른 쪽의 변수가 바뀌며, C에서 포인터를 넘긴 것과 같은 효과이다. 그림 1에서 단계를 넘기면 서브루틴의 r과 theta가 main의 r과 th 자리에 값을 쓰는 것을 볼 수 있다.

그런데 이 성질 때문에 의도하지 않게 인수를 바꿀 위험도 있다. 그래서 intent로 인수의 쓰임을 밝힌다. intent(in)은 읽기만 하는 인수로, 바꾸려 하면 컴파일 오류가 난다. intent(out)은 결과를 써서 돌려주는 인수이고, intent(inout)은 읽고 바꾸는 인수이다.

배열도 그대로 넘어간다. real(dp), intent(in) :: a(:)처럼 쓰면(형태 가정 배열) 크기를 따로 넘기지 않아도 안에서 size(a)로 알 수 있다. 다만 이렇게 쓰려면 부프로그램이 모듈 안에 있어야 한다.

subroutine normalize(v)
  real(dp), intent(inout) :: v(:)
  v = v / sqrt(sum(v**2))
end subroutine normalize
마무리

function은 값 하나를 돌려주고, subroutine은 call로 불러 인수를 바꾼다. 처음 질문처럼 포트란은 인수를 참조로 넘기므로 서브루틴이 결과 여러 개를 부른 쪽 변수에 직접 써 줄 수 있으며, 실수를 막으려고 intent(in/out/inout)을 적는다. 부프로그램은 module … contains에 모으고 use로 쓴다.
