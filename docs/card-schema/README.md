# 카드 양식 일원화와 학교·학과별 배치 — 설계 시안 (qcard/1)

QURI(대학)와 나뭇잎(고교)의 카드를 한 양식으로 쓰고, 같은 카드를 학교·학과마다 다른 과목 이름과 순서로 보여 주기 위한 설계입니다.
이 문서와 같은 폴더의 `sample.html`(견본), `examples/`(기존 카드를 옮긴 예)가 한 묶음입니다. 실제 사이트 교체는 이 시안이 승인된 뒤 단계별로 합니다(10절).

## 0. 원칙

1. **내용은 한 벌만 둡니다.** 카드 하나와 문항 하나는 저장소 안에 한 번만 있습니다. 학교·학과마다 복사하지 않고, 형식을 둘로 저장하지도 않습니다.
2. **내용과 배치를 나눕니다.** 카드는 자기가 어느 학교·과목·절에 놓이는지 모릅니다. 배치는 배치표가 정합니다(나뭇잎 `curricula/2022.json` 방식을 학교·학과 단위로 넓힘).
3. **필요한 필드만 둡니다.** 빌드나 화면이 쓰지 않는 필드는 두지 않습니다. 옛 형식 호환, 학습 기록 이전용 대응표는 만들지 않습니다(아직 실제 사용자가 없음).
4. **생성물은 고치지 않습니다.** 페이지와 화면용 JSON은 빌드가 만듭니다.

## 1. 전체 구조

```
cards/<분야>/<id>.html         카드 (내용, 학교와 무관)          ─┐
cards/<분야>/<id>.json         문제 묶음 카드 (연습·단원 연습)    │ 공용 풀
exams/<분야>/<모듈>.json       시험 전용 문항                     │
outline/<모듈>.json            풀 목차: 모듈 → 대단원 → 절 → 카드 ─┘
place/<학교>/<학과>.json        학과 배치표: 과목 이름·번호·학기·선수, 각 과목의 단원 = 풀 절 참조 + 학과 전용 카드
        │
   tools/build.py ──▶ c/s/<절>.html            절 페이지 (풀 절마다 한 장, 학과와 무관)
                 ──▶ c/<학교>/<학과>/…          과목 목차·대단원·시험 연습 (학과마다, 작은 목록 페이지)
                 ──▶ data/<학교>-<학과>.json    메인·로드맵·절 페이지가 읽는 학과 배치 요약
```

층은 세 개입니다.

| 층 | 무엇 | 누가 바꾸나 | 학교와 관계 |
|---|---|---|---|
| 카드 | 설명·증명·예제·실습 글과 그림, 문제 | 내용 작성 세션 | 없음 |
| 풀 목차(outline) | 카드를 '교재' 순서로 묶은 것. 절 = 성취기준 하나. 절 사이 선수 링크 | 내용 작성 세션 | 없음 |
| 학과 배치표(place) | 그 학과가 실제로 듣는 과목의 이름·학정번호·학기·이수구분·선수, 과목마다 어느 풀 절을 어떤 순서로 쓰는지, 학과 전용 카드 | 교육과정 담당 | 학교 + 학과 |

풀 목차를 따로 두는 이유: 학과 배치표가 카드 id를 수백 개씩 나열하지 않고 "풀 모듈 `공통1`의 1~10단원"처럼 짧게 참조할 수 있습니다. 같은 미적분 내용을 다섯 학과가 쓰면 카드 목록은 풀 목차에 한 번만 있습니다.

지금의 QURI 과목 코드(`공통1`, `물리3` …)와 성취기준 코드(`공통1-03-02`)는 **풀 모듈과 풀 절의 id로 그대로 씁니다.** 이미 학교와 무관한 '교재 단위'로 쓰이고 있고(연세대 강의계획서를 참고해 만들었을 뿐), 시험 문항의 `std`와 블록의 `sec`가 이 코드를 가리키므로 다시 바꿀 일이 없습니다.

## 2. 카드

### 2-1. 파일

- `cards/<분야>/<id>.html`. 파일 이름 = 카드 id = 최상위 요소의 id. 분야 폴더는 처음 만든 곳이며, 다른 과목에 놓여도 옮기지 않습니다.
- 머리는 스크립트가 필요할 때만 씁니다. **`sec`, `order`, `type`, `data-std`는 없습니다**(배치표가 정함).

```html
<!--card {"scripts": ["simkit", "c3-pendulum"]} -->
<article class="qc" id="lab-c3-pendulum" data-kind="lab">
  <header><h2>진자의 주기는 정말 진폭과 무관할까?</h2><p class="tag">작은 진폭 근사의 한계</p></header>
  …
</article>
```

| 항목 | 위치 | 뜻 |
|---|---|---|
| id | 파일 이름·`article id` | 기록(메모·형광펜·오답)의 열쇠. 공개 뒤에는 바꾸지 않음 |
| kind | `data-kind` | 아래 2-2의 일곱 가지. 렌더러가 배치와 단계 이름을 고르는 데 씀 |
| 제목 | `h2` | 질문이나 주장 |
| tag | `p.tag` | 주제 한 줄. 종류 이름은 렌더러가 붙이므로 쓰지 않음 |
| scripts | 머리 JSON | `js/cards/<이름>.js`. 공용 도구(simkit, lab 등)를 먼저 |

카드 번호(`3.2.1` 같은)와 '먼저 볼 절' 링크는 배치에 따라 다르므로 카드에 쓰지 않습니다. 다른 카드를 가리킬 때는 번호가 아니라 `<a data-card="card-c1-mvt">평균값 정리</a>`처럼 id로 걸고, 빌드가 학과 배치에 맞는 주소로 바꿉니다.

`.json` 카드는 문제 묶음(연습, 단원 연습)입니다. 3절의 문항 스키마를 그대로 씁니다.

```json
{"kind": "practice", "title": "도함수의 정의 연습", "items": [ … ]}
```

### 2-2. 종류와 단계

QURI의 일곱 종류와 나뭇잎의 블록 종류를 아래처럼 합칩니다. '단원 연습'과 '절 소개'는 종류가 아니라 **배치 위치**입니다(같은 연습 카드를 절 끝에 두든 단원 끝에 두든 카드는 같음).

| kind | 이름 | 지금 QURI | 지금 나뭇잎 | 본문 구조 |
|---|---|---|---|---|
| `text` | 본문·읽기 | 본문(4-8) | text(읽기), intro(절 소개) | 줄글. 정의·정리·예제 상자와 끝의 연습문제(문항) |
| `concept` | 개념 | 설명, 탐구 | card(여섯 단계) | (그림) + 단계 + (확인 문제) |
| `proof` | 증명·유도 | 증명, 유도 | — | 정리 → 쓰는 것 → 아이디어 → 단계 증명 → 되짚기 |
| `example` | 예제 | 예제 | — | 문제 → 전략 → 풀이 → 의미 → 검산 |
| `lab` | 실습·실험 | 실습 | card(실험 여섯 단계) | 목표 → 준비 → (조작 그림) → 절차 → 기대 결과 → 분석 |
| `practice` | 연습 | 연습, 단원 마무리 연습 | — | 문항 목록(JSON 카드) |
| `video` | 영상 | — | video | 장면 캔버스 |

단계는 모두 같은 마크업 `section.qc-step` + `h3`(단계 이름)로 씁니다. 단계 이름표는 종류마다 정해 둡니다.

| kind | 단계 이름 (순서) |
|---|---|
| concept (나뭇잎식) | 질문 · 복원 · 설명 · 연결 · 적용 · 판단 |
| concept (QURI 설명식) | 왜 필요한가 · 정의 · 정의를 풀어 읽기 · 예와 반례 · 다른 개념과의 관계 · 흔한 오해 |
| proof | 정리 · 쓰는 것 · 아이디어 · 증명 · 되짚기 · (더 나아가기) |
| example | (먼저 예측) · 문제 · 전략 · 풀이 · 의미 · 검산 · (바꿔 보기) |
| lab (화면 실험) | 목표 · 준비 · 절차 · 기대 결과 · 분석 · (더 해 보기) |
| lab (나뭇잎 실험) | 탐구 문제 · 복원 · 설계 · 분석 · 측정 · 오차·안전 |

두 사이트의 concept 단계는 하나로 억지로 맞추지 않습니다. 고교 카드는 '그림을 조작해 발견'이 중심이고 대학 설명 카드는 '정의를 읽는 법'이 중심이라 단계가 다른 것이 맞습니다. 대신 **마크업과 렌더러는 같고**, 단계 이름만 다릅니다.

### 2-3. 본문 공통 어휘

두 사이트의 클래스(`q-card`·`q-body`·`q-sec`, `card-body`·`steps`·`tag`)를 하나로 줄입니다. 렌더러 CSS(`css/qc.css`)와 스크립트(`js/qc.js`)는 이 어휘만 압니다.

| 마크업 | 뜻 | 지금 QURI | 지금 나뭇잎 |
|---|---|---|---|
| `article.qc[data-kind]` | 카드 | `article.card.q-card` | `article.card` |
| `header > h2`, `p.tag` | 제목, 주제 | `.card-head h2`, `.kind` | 같음 |
| `.qc-fig` | 조작 그림 영역 (canvas, `.ctl`, `.btns`, `.out`) | `.q-sim` | `.card-fig` |
| `section.qc-step > h3` | 단계 | `section.q-sec` | `ol.steps > li > .tag` |
| `.qc-def` `.qc-thm` | 정의·정리 상자 (`span.lb` 이름표) | `.q-def` `.q-thm` | — |
| `ol.qc-proof > li > div + .why` | 근거가 붙은 단계 풀이 | `ol.q-proof` `.q-why` | — |
| `p.qc-prob` | 문제 | `.q-prob` | — |
| `.qc-warn` | 판단·흔한 오해 | `.warn` | `li.warn` |
| `.qc-quiz` | 확인 문제 (`button.opt[data-ok]` + `.why`) | `.quiz` | `.quiz` (같은 형식) |
| `<details>` | 접어 둔 답 | 같음 | 같음 |

수식은 지금처럼 `\( \)`, `\[ \]`(KaTeX)입니다. HTML 안에서 수식 속 `<`는 `&lt;`로 씁니다.

색은 렌더러에 박지 않고 CSS 변수로 받습니다. 사이트는 변수 몇 개만 정합니다.

```css
:root { --qc-accent: #5b4bc4; --qc-accent-2: #e8e4fb; --qc-ink: #1d1b24; --qc-rule: #d9d6e3; --qc-paper: #fbfaff; }  /* QURI */
:root { --qc-accent: #2f7d4f; --qc-accent-2: #e2f1e7; --qc-ink: #1c241f; --qc-rule: #d3ddd6; --qc-paper: #fafcf9; }  /* 나뭇잎 */
```

### 2-4. 학과 전용 카드

카드는 학과 이름을 갖지 않습니다. "수학과 심화 과목에만 나오는 ε-δ 엄밀 증명"은 보통 카드(kind `proof`)이고, **수학과 배치표에만 놓이기 때문에** 수학과 전용이 됩니다. 범위가 학과마다 다르면 카드를 더 잘게 나눠 조합합니다. 예: '테일러 급수' 한 장을 '계산'(모든 학과)과 '나머지 항 추정의 증명'(수학과)으로 나눔.

## 3. 문항 (연습·단원 연습·시험 공용)

연습 카드의 문항, 본문 끝 연습문제, 시험 전용 문항은 모두 같은 항목 스키마를 씁니다. 나뭇잎 `exams/bank/*.json`의 필드 이름(q, choices, answer, alt, sol, type)을 그대로 쓰고, 대학에 필요한 것만 더했습니다.

| 필드 | 필수 | 뜻 |
|---|---|---|
| `id` | ○ | 문항 id. 오답 기록의 열쇠 |
| `type` | ○ | `mc`(객관식, 자동 채점) · `short`(단답, `answer`와 비교하거나 스스로 채점) · `free`(서술, 스스로 채점) |
| `q` | ○ | 문제 HTML |
| `choices` | mc | 보기 HTML 배열 |
| `answer` | ○ | mc: 1부터 센 번호 문자열 `"1"`~`"5"` / short·free: 짧은 답 HTML |
| `alt` |  | short의 다른 허용 답 `"4.5\|9/2"` (나뭇잎과 같음) |
| `sol` | ○ | 풀이 HTML |
| `hints` |  | 힌트 HTML 배열(보통 2개: 방향 → 첫 단계) |
| `lv` |  | `기본` · `응용` · `심화` |
| `ty` |  | `개념` · `계산` · `증명` · `판단` · `적용` · `모형` · `실습` |
| `std` | 시험 문항 | 풀 대단원(`물리1-03`) 또는 풀 절(`물리1-03-02`) 코드 |

- **시험 전용 문항**은 `exams/<분야>/<모듈번호>.json`에 `{"items": […]}`로 둡니다. 파일 하나 = 풀 모듈 하나. `std`가 풀 코드이므로 학과 배치와 무관하고, 어느 학과 과목이든 그 절을 쓰면 그 과목의 시험 연습에 나옵니다(9절).
- 연습 카드의 문항은 `std`가 없습니다. 카드가 놓인 자리가 곧 범위입니다.
- 화면 전용 값(대단원 이름, 절 번호, 링크)은 문항에 넣지 않고 빌드가 배치표에서 붙입니다.
- 나뭇잎과의 차이: `free` 형식(나뭇잎 화면은 아직 mc·short만 그림), `hints`·`lv`·`ty`·`std`. 나뭇잎은 위치를 `sec: "1-1"`로 적는데, 이 스키마로 옮기면 그 과목 성취기준 코드를 `std`에 씁니다. 보기 섞기는 나뭇잎 `tools/bank.py`처럼 저장 단계에서 하거나 공용 렌더러가 풀 때 할 수 있습니다(공용 렌더러로 옮기면 화면에서 섞는 쪽을 권함: 데이터가 하나로 남음).

## 4. 풀 목차 (`outline/<모듈>.json`)

```json
{
  "id": "공통1", "title": "미분적분학 1", "field": "math",
  "units": [
    {"n": "02", "t": "미분", "el": "미분계수, 도함수, 미분 가능성",
     "secs": [
       {"code": "공통1-02-01", "t": "도함수를 정의로 구하고 미분 가능성을 판정할 수 있다.", "ty": "계산",
        "cards": ["text-c1-derivative", "card-c1-derivative", "card-c1-diffrules"], "pre": ["공통1-01-03"]}
     ],
     "review": ["card-c1-r02"]}
  ]
}
```

- `secs[].t`는 성취기준 문장, `pre`는 절 단위 선수(지금 `univ-prereq.md` 연결표)입니다. 이것은 **내용의 의존 관계**라 학교와 무관합니다.
- `review`는 단원 마무리 카드입니다.
- 지금 블록 머리의 `sec`·`order`와 `curricula/univ-*.md`의 대단원·성취기준이 이 파일로 모입니다. 변환은 10절의 변환기가 합니다.
- 모듈 이름(`title`)은 학교와 무관한 교재 이름입니다. 학생에게 보이는 과목 이름은 배치표의 것을 씁니다.

## 5. 학과 배치표 (`place/<학교>/<학과>.json`)

배치의 단위는 **학교 + 학과(전공)** 입니다. 같은 연세대라도 학과마다 과목 이름·학정번호·순서·선수가 다릅니다.

```json
{
  "school": "연세대", "dept": "수학과", "src": "2026 요람 S1 61~64쪽",
  "courses": [
    {"id": "m1016", "name": "미분적분학과벡터해석심화(1)", "no": "MAT1016", "y": 1, "sem": 1, "kind": "대학교양", "cr": 3,
     "units": [
       {"from": "공통1", "n": ["01", "02", "03", "04", "05", "06", "07", "08", "09", "10"]},
       {"t": "실수의 완비성과 엄밀한 극한", "secs": [{"t": "ε-δ로 극한을 증명할 수 있다.", "cards": ["proof-mh1-epsdelta", "proof-mh1-complete"]}]}
     ],
     "exam": "mid+fin"},
    {"id": "m2102", "name": "선형대수(1)", "no": "MAT2102", "y": 2, "sem": 1, "kind": "전공필수", "cr": 3,
     "units": [{"from": "수학1"}], "pre": ["m1016"], "exam": "mid+fin"}
  ]
}
```

| 필드 | 뜻 |
|---|---|
| `courses[].id` | 학과 안에서 과목 id(주소에 씀). 학정번호를 소문자로 줄여 씀 |
| `name`, `no` | 그 학과가 실제로 쓰는 과목명과 학정번호 |
| `y`, `sem`, `kind`, `cr` | 학년, 학기(1·2, 둘 다면 `[1,2]`), 이수구분, 학점 |
| `units` | 단원 목록. 원소는 ① `{"from": 풀 모듈}`(모듈 전체), ② `{"from": 모듈, "n": [대단원 번호…]}`(일부), ③ `{"t": 제목, "secs": [{"t", "cards"}…]}`(학과 전용 단원). 절도 `{"from": "공통1-05", "secs": ["공통1-05-01", "공통1-05-03"]}`처럼 골라 쓸 수 있음 |
| `pre` | 학과 안 선수 과목 id. 후속 과목은 빌드가 거꾸로 계산하므로 적지 않음 |
| `exam` | 시험 방식: `mid+fin` · `fin`(기말만) · `none`(시험 없음). 수강편람 강의계획서의 평가 방법에서 정함 |

같은 풀 내용이 학과마다 이렇게 놓입니다(연세대 2026 요람 S1·S2. 이 대응은 이미 `curricula/univ-common.md`의 변형 과목 표에 있어 변환기가 그대로 읽습니다).

| 풀 모듈 | 수학과 | 천문우주·물리·화학(이과대학) | 전기전자·기계(공과대학) |
|---|---|---|---|
| 공통1 | 미분적분학과벡터해석심화(1) MAT1016 + 엄밀 증명 카드 | 미분적분학과벡터해석(1) MAT1001 | 공학수학(1) MAT1011 |

`c.unis`, `s.u`, 《…》(다른 대학에도 있는 내용) 표시는 이 구조에서 **배치표가 있는지 없는지**로 대체합니다. 다른 학교를 넣을 때는 그 학교 학과의 배치표를 그 학교 수강편람에서 새로 씁니다. 지금 md에 있는 다른 대학 비교 정보는 교육과정 연구 메모로 남기되 빌드에 넣지 않습니다.

## 6. 빌드와 렌더링: 학과별 페이지를 어떻게 만드나

세 방식을 비교했습니다.

| 방식 | 절 페이지 | 용량 | 오프라인·검색 | 학과 전환 |
|---|---|---|---|---|
| A. 학과마다 모든 페이지 정적 생성 | 학과 수만큼 복제 | 공통 1학년 내용이 5~7벌 → 지금 c/의 2~3배 | 좋음 | 주소가 바뀜 |
| B. 모든 화면을 클라이언트에서 그림 | 셸 하나 + 카드 JSON | 가장 작음 | 첫 화면이 느리고 캐시 설계가 복잡, 검색 불리 | 즉시 |
| **C. 내용은 정적 한 벌, 학과 틀은 클라이언트** (권장) | 풀 절마다 한 장(`c/s/<절>.html`) | 지금과 비슷하거나 작음 | 좋음 | 즉시 |

C에서 빌드가 만드는 것:

1. **절 페이지** `c/s/<절>.html` — 풀 절 하나에 한 장. 카드들과 절 단위 선수·후속 링크까지 담고, 과목·학과 문맥은 없습니다.
2. **학과 페이지** `c/<학교>/<학과>/<과목>/index.html`, `<대단원>.html`, `exam.html` — 과목 목차와 대단원 목록, 시험 연습. 목록뿐이라 작습니다. 학과 전용 단원의 절도 같은 절 페이지 형식으로 `c/s/`에 만듭니다.
3. **학과 요약** `data/<학교>-<학과>.json` — 과목명·번호·학기·선수·후속·단원 제목·각 단원이 쓰는 절 코드. 학과 하나에 20~40 KB.
4. **풀 색인** `data/pool.json` — 모듈·대단원·절 제목과 카드 수(검색·전체 교재 보기용).

절 페이지를 열면 `js/place.js`가 고른 학과(localStorage `quri-place` = `"연세대/수학과"`, 또는 주소의 `?p=`)의 요약을 읽어 다음을 채웁니다.

- 위쪽 경로: "수학과 › 미분적분학과벡터해석심화(1) › 2. 미분"
- 절 번호(그 과목 안의 2.1 같은 번호)와 이전·다음 절
- 아래쪽 '이 절을 쓰는 과목': 그 학과에서 이 절을 쓰는 과목들

학과를 고르지 않았거나 그 학과 배치에 없는 절이면 풀 모듈 이름과 풀 순서로 보여 줍니다.

용량 효과: 지금 `js/toc.js` 하나(약 830 KB)를 메인·로드맵이 모두 받습니다. C에서는 고른 학과 요약(수십 KB)과 풀 색인만 받습니다. 절 페이지는 지금과 같은 수이고, 학과 수가 늘어도 학과 페이지(목록)만 늘어납니다.

## 7. 학교·학과 선택 흐름

1. 처음 들어오면(선택 없음) 메인 위쪽에 **"학교와 학과를 고르세요"** 상자가 보입니다. 학교 목록(지금은 연세대 하나)과 학과 단추 7개(수학, 물리, 화학, 천문우주, 응용통계, 전기전자, 기계). 그 아래에는 학과와 무관한 **"교재 전체 보기"**(풀 모듈을 분야별로)가 있어 고르지 않아도 모든 내용에 갈 수 있습니다.
2. 학과를 고르면 저장하고, 메인은 그 학과의 학년·학기 배치도와 과목 목록을 그 학과 과목명·학정번호로 그립니다. 1학년 공통 과목(미적분·일반물리 등)도 그 학과가 듣는 이름으로 나옵니다.
3. 모든 페이지의 머리에 "연세대 · 수학과 ▾" 칩이 있어 어디서든 바꿀 수 있습니다. 바꾸면 그 자리의 절 페이지는 그대로 두고 경로·번호·앞뒤만 다시 그립니다.
4. 로드맵(`roadmap.html`)은 고른 학과의 배치표와 졸업 요건(`univ-requirements.json`)을 씁니다. 지금 로드맵의 학교·학과 고르기 장치는 이 선택을 따릅니다.
5. 공유 주소: `?p=연세대/수학과`가 붙으면 그 학과로 보이되, 사용자의 저장값은 바꾸지 않습니다.

'공통 기초' 탭은 없앱니다. 1학년 공통 과목은 각 학과 배치표에 그 학과 이름으로 들어가고, 내용(풀 모듈 공통1~12)은 '교재 전체 보기'에서 분야별로 찾을 수 있습니다.

## 9. 시험 연습과의 연결

- 시험 전용 문항은 `std`(풀 코드)로만 범위를 가집니다. 빌드는 학과 과목마다 그 과목 단원이 쓰는 풀 절·대단원 목록을 만들고, 거기에 속한 문항을 그 과목 `bank.js`에 넣습니다. 같은 문항이 두 학과 과목에 나와도 파일은 하나입니다.
- 중간·기말 범위: 과목의 단원을 앞뒤 절반으로 나눕니다. 과목 `exam`이 `fin`이면 전 범위 기말만, `none`이면 그 과목의 시험 연습 페이지를 만들지 않습니다.
- 문항 하나가 대단원 코드(`물리1-03`)를 가지면 그 대단원 전체를 쓰는 과목에, 절 코드(`물리1-03-02`)면 그 절을 쓰는 과목에 들어갑니다.

## 12. 장단점과 남은 질문

장점
- 내용 한 벌로 학교·학과 수에 관계없이 확장되고, 학과 추가 비용은 배치표 하나(수 KB)입니다.
- 카드에 위치 정보가 없어 배치를 바꿔도 카드는 안 바뀝니다. 오답·메모 기록은 카드·문항 id에 붙어 학과를 바꿔도 이어집니다.
- 문항 스키마가 하나라 연습·단원 연습·시험 연습·나뭇잎 문제은행이 같은 렌더러를 씁니다.
- 메인이 받는 데이터가 830 KB에서 수십 KB로 줄어듭니다.

단점·위험
- 절 페이지의 경로·번호가 클라이언트에서 채워지므로 자바스크립트 없이는 풀 문맥만 보입니다(내용은 다 보임).
- 풀 목차와 배치표, 두 겹의 순서를 관리해야 합니다. 학과 순서가 풀 순서와 크게 다르면 배치표가 길어집니다.
- 2단계(블록 이동)는 모든 내용 세션을 멈춰야 하는 큰 변경입니다.

결정이 필요한 것
1. 절 페이지 주소를 `c/s/<절 코드>.html`(한글 코드)로 할지, 영문 모듈 id(`calc1-02-01`)를 새로 만들지. 시안은 지금 코드를 그대로 쓰는 쪽(데이터 변경 없음)을 권합니다.
2. 학과를 고르지 않은 첫 화면에서 연세대 수학과 같은 기본값을 줄지, 선택 상자만 보일지. 시안은 선택 상자 + 교재 전체 보기를 권합니다.
3. 과목별 시험 방식(`exam`)을 연세대 수강편람 강의계획서에서 조회해 채울지(사용자 확인 대기 중).
